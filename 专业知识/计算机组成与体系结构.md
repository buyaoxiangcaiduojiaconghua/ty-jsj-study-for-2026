## 知识点 30：计算机系统概述

### 30.1 冯·诺依曼体系结构

**大白话**：冯·诺依曼结构就是"计算机的工作方式说明书"——程序和数据都存内存里，CPU 一条条取出来执行。

**五大部件**：

| 部件 | 功能 | 类比 |
|------|------|------|
| 运算器（ALU） | 做算术和逻辑运算 | 计算器 |
| 控制器（CU） | 指挥各部件协调工作 | 乐队指挥 |
| 存储器 | 存程序和数据 | 仓库 |
| 输入设备 | 从外界获取数据 | 键盘、鼠标 |
| 输出设备 | 把结果展示出来 | 显示器、打印机 |

**核心思想**：**存储程序**——程序和数据以同等地位存在存储器中，按地址访问、顺序执行。

### 30.2 计算机层次结构

```
应用程序层（用户直接用的）
    ↓ 翻译
高级语言层（C/Java/Python）
    ↓ 编译
汇编语言层（助记符）
    ↓ 汇编
操作系统层（管理软硬件）
    ↓ 系统调用
传统机器层（指令集，机器语言）
    ↓ 微程序解释
微程序机器层（硬件直接执行）
```

> 下层是上层的基础，上层是下层的抽象。每一层只关心自己的事。

### 30.3 性能指标

| 指标 | 公式 | 含义 |
|------|------|------|
| 主频 f | 1/T（T为时钟周期） | CPU 每秒振荡多少次 |
| CPI | 总时钟周期数/总指令数 | 每条指令平均需要几个时钟周期 |
| CPU 执行时间 | **IC × CPI × T** | 程序的 CPU 时间 |
| MIPS | 指令条数/(执行时间×10⁶) = f/(CPI×10⁶) | 每秒百万条指令 |
| MFLOPS | 浮点运算次数/(执行时间×10⁶) | 每秒百万次浮点运算 |

> **CPU 执行时间 = IC × CPI × T** 是核心公式，哪里都可能出计算题。

### 30.4 阿姆达尔定律

**问题**：如果我把程序的一部分加速了，整体能快多少？

**公式**：S = 1 / [(1-f) + f/k]

- f = 可改进部分占总时间的比例
- k = 改进部分的加速倍数
- S = 整体加速比

**例题**：某程序 80% 可以并行化，用 4 核 CPU，整体加速比是多少？
- f = 0.8, k = 4
- S = 1 / [(1-0.8) + 0.8/4] = 1 / [0.2 + 0.2] = **2.5 倍**

> **易错点**：即使把 80% 的部分加速到"无限快"，整体加速比也不过 1/(1-0.8) = **5 倍**。改进受限于不可改进部分！

## 知识点 31：数据的机器级表示和运算

### 31.1 进制转换

**二进制 ↔ 八进制**：每 3 位二进制 = 1 位八进制  
**二进制 ↔ 十六进制**：每 4 位二进制 = 1 位十六进制

**十进制转二进制**：整数部分除 2 取余（从下往上读），小数部分乘 2 取整（从上往下读）

### 31.2 原码、反码、补码、移码

**类比**：就像钟表——补码就是把"逆时针转"变成"顺时针转"，用加法代替减法。

| 编码 | 正数 | 负数 | 8 位范围 | 零的表示 |
|------|------|------|---------|---------|
| 原码 | 符号位 0 + 数值 | 符号位 1 + 数值 | -127~+127 | +0=00000000, -0=10000000 |
| 反码 | 同原码 | 符号位不变，其余取反 | -127~+127 | +0=00000000, -0=11111111 |
| **补码** | 同原码 | **反码 + 1** | **-128~+127** | **只有 00000000** |
| 移码 | 补码符号位取反 | 补码符号位取反 | -128~+127 | 10000000 |

> **核心记忆**：补码比原码多一个负数（-128），且零只有一种表示——这是补码最大的优势。

### 31.3 补码溢出判断

**三种方法**：

| 方法 | 判断规则 | 口诀 |
|------|---------|------|
| 单符号位 | 两正数相加得负数→正溢；两负数相加得正数→负溢 | 正正得负溢，负负得正溢 |
| 双符号位（变形补码） | 00=正常，01=正溢，10=负溢 | 两位相同没溢出，不同则溢出 |
| 进位判断 | 最高位进位 ≠ 次高位进位 → 溢出 | 两个进位不一样就溢了 |

### 31.4 IEEE754 浮点数

**格式**：N = (-1)^S × 1.M × 2^(E-bias)

| 类型 | 符号 S | 阶码 E | 尾数 M | 偏移量 bias |
|------|--------|--------|--------|------------|
| 单精度 float | 1 bit | **8 bit** | **23 bit** | **127** |
| 双精度 double | 1 bit | **11 bit** | **52 bit** | **1023** |

> 尾数隐含最高位 1（规格化后），实际尾数是 1.M。

**浮点加减运算步骤**：
1. **对阶**：小阶向大阶看齐（尾数右移，阶码+1）
2. **尾数相加/减**
3. **规格化**：确保尾数 1.xxx 形式
4. **舍入**：0 舍 1 入法、恒置 1 法
5. **判溢出**：阶码超出范围则溢出

> **易错点**：对阶时可能出现"对阶丢失"——尾数右移时低位丢失。

### 31.5 数据校验码

| 校验码 | 能力 | 原理 |
|--------|------|------|
| 奇偶校验 | 检错（奇数位错） | 加一位使 1 的个数为奇/偶 |
| **海明码** | 检错+**纠错 1 位** | 多组奇偶校验，出错位=各组校验位组合 |
| CRC | 检错（极强） | 模 2 除法，余数=校验码 |

### 31.6 常见编码

- **ASCII 码**：`'A'`=65(0x41), `'a'`=97(0x61), `'0'`=48(0x30)
- **汉字编码**：输入码（拼音/五笔）→ 国标码（GB2312）→ 机内码（存储用）

## 知识点 32：多级层次的存储系统

### 32.1 存储层次结构

```
寄存器 → Cache(L1/L2/L3) → 主存(DRAM) → 辅存(SSD/HDD)
← 速度越快，容量越小，价格越贵 →
```

> 全部数据在辅存，常用数据在内存，最常用数据在 Cache，正在用的在寄存器。

### 32.2 SRAM vs DRAM

| 对比 | SRAM（静态） | DRAM（动态） |
|------|------------|------------|
| 存储元 | 六管 MOS 触发器 | 电容 + 单管 |
| 速度 | 快 | 慢 |
| 集成度 | 低 | 高 |
| 功耗 | 大 | 小 |
| 刷新 | 不需要 | **需要刷新** |
| 价格 | 贵 | 便宜 |
| 用途 | **Cache** | **主存** |

> **DRAM 为什么需要刷新？** 电容会漏电，必须定期"补电"（刷新）来保持数据。

### 32.3 DRAM 刷新方式

| 方式 | 做法 | 优缺点 |
|------|------|--------|
| 集中刷新 | 一段时间内集中刷新所有行 | 有"死时间"（刷新时不能读写） |
| 分散刷新 | 每个读写周期后刷新一行 | 无死时间，但刷新太频繁 |
| **异步刷新** | 分散在刷新周期内均匀刷新 | **折中方案，最常用** |

### 32.4 Cache 与主存的映射方式

| 映射方式 | 规则 | 优点 | 缺点 |
|---------|------|------|------|
| **直接映射** | 每个主存块 → 固定 Cache 行 | 简单，成本低 | 冲突多 |
| **全相联映射** | 任意主存块 → 任意 Cache 行 | 冲突少 | 硬件复杂，比较器多 |
| **组相联映射** | 先分组，组内全相联 | **折中方案，最常用** | |

### 32.5 Cache 替换算法

| 算法 | 规则 | 特点 |
|------|------|------|
| 随机（RAND） | 随便踢一个 | 简单，效果不稳定 |
| FIFO | 踢最早进来的 | 简单，但可能踢掉常用块 |
| **LRU** | 踢最久没用的 | 效果好，需要硬件记录访问顺序 |
| LFU | 踢用得最少的 | 考虑频率，但新块可能被误踢 |

### 32.6 Cache 写策略

| 策略 | 写命中时 | 写不命中时 |
|------|---------|-----------|
| **写直达**（Write Through） | 同时写 Cache 和主存 | 直接写主存（非写分配） |
| **写回**（Write Back） | 只写 Cache，标记脏位 | 先把主存块调入 Cache 再写（写分配） |

> 常用组合：**写直达 + 非写分配**（简单）或 **写回 + 写分配**（性能好）

### 32.7 Cache 性能计算

**平均访问时间**：ta = **h × tc + (1-h) × tm**

- h = 命中率（通常 > 90%）
- tc = Cache 访问时间
- tm = 主存访问时间

**例题**：h=0.95, tc=1ns, tm=100ns，求平均访问时间。
- ta = 0.95 × 1 + 0.05 × 100 = 0.95 + 5 = **5.95ns**

### 32.8 TLB（快表）

> TLB 是"页表项的 Cache"——把最近用过的页表项缓存起来，减少访存次数。

**带 TLB 的地址变换**：先查 TLB（命中→快；不命中→查页表→更新 TLB）

## 知识点 33：指令系统

### 33.1 指令格式

> 指令 = **操作码**（OP，告诉 CPU 做什么）+ **地址码**（A，告诉 CPU 操作数在哪）

| 类型 | 地址数 | 说明 |
|------|--------|------|
| 三地址指令 | OP A1 A2 A3 | A1←A2 OP A3 |
| 二地址指令 | OP A1 A2 | A1←A1 OP A2 |
| 单地址指令 | OP A | ACC←ACC OP A（隐含累加器） |
| 零地址指令 | OP | 无操作数（如停机、空操作） |

### 33.2 寻址方式

| 寻址方式 | 操作数在哪 | 访存次数 | 特点 |
|---------|-----------|---------|------|
| **立即寻址** | 指令中直接给出 | 0 | 快，但操作数固定 |
| **直接寻址** | 指令中给地址 | 1 | 简单 |
| **寄存器寻址** | 寄存器中 | 0 | 最快 |
| **间接寻址** | 寄存器的内容指向地址 | 2 | 灵活，但慢 |
| **相对寻址** | EA = PC + 偏移量 | 1 | 用于转移指令 |
| **基址寻址** | EA = 基址寄存器 + 偏移 | 1 | 用于程序重定位 |
| **变址寻址** | EA = 变址寄存器 + 形式地址 | 1 | 用于数组访问 |
| **堆栈寻址** | 栈顶（SP 指向） | 0 | 隐含地址 |

> **基址 vs 变址**：基址寄存器内容不变（面向系统），变址寄存器内容可变（面向用户，如数组下标）。

### 33.3 CISC vs RISC

| 对比 | CISC（复杂指令集） | RISC（精简指令集） |
|------|-------------------|-------------------|
| 指令数量 | **多** | **少** |
| 指令长度 | **可变长** | **定长** |
| 寻址方式 | 多 | 少 |
| 寄存器数量 | 少 | **多** |
| 访存方式 | 指令可直接访存 | **只有 Load/Store 访存** |
| 流水线 | 难实现 | **易实现** |
| 代表 | **x86**（Intel/AMD） | **ARM**、MIPS、RISC-V |

> 考试重点：**CISC 指令可变长、x86；RISC 定长、Load/Store 结构、ARM。**

## 知识点 34：中央处理器（CPU）

### 34.1 CPU 组成

| 部件 | 组成 | 功能 |
|------|------|------|
| 运算器 | ALU + 通用寄存器组 | 算术逻辑运算 |
| 控制器 | CU + **PC**（程序计数器）+ **IR**（指令寄存器）+ **MAR**（地址寄存器）+ **MDR**（数据寄存器）+ PSW（状态字） | 取指令、分析指令、发控制信号 |

> **PC** 存放下一条指令的地址，**IR** 存放当前正在执行的指令。

### 34.2 指令周期

```
取指周期 → 间址周期 → 执行周期 → 中断周期
```

| 时间单位 | 关系 | 说明 |
|---------|------|------|
| 时钟周期 | 最小单位 | CPU 主频的倒数 |
| 机器周期 | 多个时钟周期 | 完成一次总线操作 |
| 指令周期 | 多个机器周期 | 执行一条指令的全过程 |

> **时钟周期 < 机器周期 < 指令周期**

### 34.3 控制器实现

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **硬布线控制器** | 组合逻辑电路直接产生控制信号 | **速度快** | 设计复杂，不易修改 |
| **微程序控制器** | 微指令存入控制存储器（CM），顺序执行 | **灵活**，易修改 | 速度慢（多一次 CM 访问） |

**微程序相关概念**：
- 微命令 → 微操作 → 微指令 → 微程序 → 机器指令
- 一条机器指令 = 一个微程序 = 一段微指令序列

### 34.4 流水线（Pipeline）

**类比**：洗车流水线——一辆车冲水时，前一辆在擦干，后一辆在打泡沫，多条工序同时进行。

**五级流水**：IF（取指）→ ID（译码）→ EX（执行）→ MEM（访存）→ WB（写回）

### 34.5 流水线三种相关（阻塞）

| 相关类型 | 原因 | 解决方法 |
|---------|------|---------|
| **结构相关** | 多条指令争用同一个硬件资源 | 增加资源 |
| **数据相关** | 指令间有数据依赖（RAW 最典型） | 数据旁路/转发（Forwarding） |
| **控制相关** | 分支指令使流水线预取的指令可能无效 | 分支预测、延迟槽 |

> **RAW（读后写）**：指令 A 写结果 → 指令 B 读结果，B 必须等 A 写完。这是最常见的流水线阻塞。

### 34.6 流水线性能计算

| 指标 | 公式 | 说明 |
|------|------|------|
| 吞吐率 p | n / Tk | 单位时间完成的任务数 |
| 加速比 S | T顺序 / T流水 | 不用流水线 vs 用流水线的时间比 |
| 效率 E | S / k | k 为流水线段数 |

**例题**：k=5 段流水线，执行 n=100 条指令，每段 1ns。
- 顺序执行：100 × 5 = 500ns
- 流水线：5 + (100-1) = 104ns（建立时间 + 剩余指令）
- 加速比：500/104 ≈ **4.81**
- 效率：4.81/5 ≈ **96.2%**

## 知识点 35：总线与输入输出系统

### 35.1 总线分类

| 总线类型 | 位置 | 包含 |
|---------|------|------|
| 片内总线 | CPU 内部 | 寄存器之间、ALU 之间 |
| 系统总线 | 主板 | **数据总线 + 地址总线 + 控制总线** |
| 通信总线 | 外部设备 | USB、PCIe、SATA |

### 35.2 总线仲裁（谁先用总线？）

| 方式 | 做法 | 特点 |
|------|------|------|
| **链式查询** | 优先级信号链式传递 | 简单，离仲裁器近的优先，但故障敏感 |
| **计数器定时查询** | 计数器轮询 | 灵活，可改优先级，但线多 |
| **独立请求** | 每个设备独立请求线 | **最快**，但线最多 |

### 35.3 四种 I/O 控制方式

| 方式 | CPU 参与度 | 适用场景 | 数据传送 |
|--------|----------|---------|---------|
| **程序查询** | CPU 全权负责 | 简单嵌入式 | CPU 读状态→CPU 传数据 |
| **程序中断** | CPU 部分参与 | 键盘、鼠标 | 设备就绪→中断 CPU→CPU 传数据 |
| **DMA** | CPU 只参与起止 | 磁盘、网卡 | **DMA 控制器直接传，不经过 CPU** |
| **通道** | CPU 几乎不参与 | 大型主机 | 通道执行通道程序，独立传送 |

> **DMA 与中断的核心区别**：DMA 传送数据时 **CPU 不参与**，中断传送数据时 **CPU 要参与**。

### 35.4 中断系统

| 概念 | 说明 |
|------|------|
| **中断向量** | 中断服务程序的入口地址 |
| **中断隐指令** | CPU 自动完成的三件事：关中断、保存断点（PC/PSW 入栈）、引出中断服务程序 |
| **多重中断** | 高优先级中断可以打断低优先级中断服务 |
| **中断屏蔽字** | 通过设置屏蔽字改变中断优先级 |

### 35.5 DMA 方式

**DMA 传送过程**：预处理（CPU 设置 DMA 控制器）→ 数据传送（DMA 控制器控制）→ 后处理（DMA 发中断，CPU 处理）

**周期窃取**（Cycle Stealing）：DMA 和 CPU 同时访问主存时，DMA 优先，CPU 暂停一个总线周期。

> **DMA 与中断的区别**：DMA 只在传送开始和结束时发中断（共 2 次），中断每一次数据传送都要发中断。

## 知识点 36：并行计算架构

### 36.1 Flynn 分类法

> 按"指令流"和"数据流"的数量对计算机架构分类。

| 分类 | 全称 | 指令流 | 数据流 | 代表 |
|------|------|--------|--------|------|
| **SISD** | 单指令单数据 | 1 | 1 | 传统单核 CPU |
| **SIMD** | 单指令多数据 | 1 | 多 | GPU 向量运算、MMX/SSE 指令 |
| MISD | 多指令单数据 | 多 | 1 | 理论存在，实际罕见 |
| **MIMD** | 多指令多数据 | 多 | 多 | **多核处理器、分布式系统** |

> 考试重点：**SISD = 单核、SIMD = GPU、MIMD = 多核**

### 36.2 多核处理器

| 类型 | 核的结构 | 特点 |
|------|---------|------|
| 同构多核 | 所有核心相同 | 简单，任务均匀分配 |
| 异构多核 | 不同核心（大核+小核） | 性能功耗平衡，ARM big.LITTLE 为代表 |

### 36.3 GPU 通用计算（GPGPU）

- GPU 有**成千上万个小型核心**，适合大规模并行计算
- **CUDA**（NVIDIA）：让 GPU 执行通用计算任务
- 应用：深度学习训练、科学计算、图像处理

### 36.4 分布式计算基础

- **集群**：多个独立计算机通过网络连接，协同工作
- **网格计算**：跨地域、跨组织的资源共享
- 与并行计算的区别：并行计算在多核/多 CPU 内，分布式计算跨机器

## 记忆口诀

- **冯·诺依曼**：存储程序，五大部件（运算器/控制器/存储器/输入/输出）
- **补码范围**：比原码多一个负数，零只有一种

- **Flynn 分类**：单核 SISD、GPU SIMD、多核 MIMD
- **流水线时间**：首条 k 段，后续每条 1 段，n 条总时间 = k+(n-1)
