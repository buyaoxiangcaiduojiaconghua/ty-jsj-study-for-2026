## 24. 系统运行环境和运行机制

### 24.1 什么是操作系统

**大白话**：操作系统就是计算机的"大管家"。你打开电脑、点鼠标、敲键盘、运行程序，背后都是 OS 在帮你协调 CPU、内存、硬盘这些"硬件小弟"干活。

**定义**：操作系统（Operating System，OS）是管理计算机硬件与软件资源的**系统软件**，也是用户与硬件之间的**接口**。它运行在**内核态**，拥有对硬件的最高控制权。

**OS 的四大特征**（高频考点）：

| 特征 | 大白话解释 | 关键理解 |
|------|-----------|---------|
| **并发**（Concurrency） | "同时做多件事" | 宏观上同时运行（如一边听歌一边刷网页），微观上可能是交替执行的（单核 CPU 快速切换）。**注意区分并发和并行：并行是真正同时执行（多核），并发是交替执行。** |
| **共享**（Sharing） | "资源共享" | 多个进程共用 CPU、内存、硬盘等资源。分为互斥共享（打印机，同一时间只能一个人用）和同时共享（磁盘，多个人同时读）。 |
| **虚拟**（Virtual） | "以假乱真" | 把一个物理资源"变"成多个逻辑资源。例如虚拟内存让程序觉得内存比实际大，虚拟 CPU 让每个进程都觉得自己独占 CPU。 |
| **异步**（Asynchrony） | "走走停停" | 进程的执行不是一口气跑到底，而是"走一段，停一下"，以不可预知的速度推进。 |

**操作系统的发展历程**：

| 阶段 | 核心特点 | 解决的问题 |
|------|---------|-----------|
| **手工操作** | 人工插拔线路，CPU 等人 | 无（效率极低） |
| **单道批处理** | 作业成批输入，监督程序自动调度 | 减少人工干预 |
| **多道批处理** | 内存中同时放多道作业，CPU 和 I/O 可以并行工作 | 资源利用率低 |
| **分时系统** | CPU 时间片轮转，多用户交互式 | 响应时间（UNIX 的诞生） |
| **实时系统** | 必须在规定时间内完成响应 | 硬实时（导弹）/ 软实时（视频播放） |

> **小总结**：四大特征是"并发共享虚异步"；发展阶段是"手工--单道--多道--分时--实时"。

### 24.2 内核态 vs 用户态

**大白话**：CPU 有两种模式，就像公司有"老板权限"和"员工权限"：
- **内核态（管态/核心态）**= 老板权限，做什么都行，能直接操作硬件
- **用户态（目态）**= 员工权限，只能做有限操作，想操作硬件必须"请示"老板（系统调用）

**特权指令 vs 非特权指令**：

| 类型 | 含义 | 谁能执行 | 举例 |
|------|------|---------|------|
| **特权指令** | 可能危害系统的特殊指令 | **只有内核态** | 开关中断、修改状态字、I/O 指令、清内存 |
| **非特权指令** | 普通运算操作 | 用户态和内核态都可以 | 加减乘除、寄存器操作、普通访存 |

**对比表格**：

| 维度 | 内核态 | 用户态 |
|------|--------|--------|
| 权限 | 最高，直接访问所有资源 | 受限，不能直接访问硬件 |
| 程序类型 | OS 内核、中断处理程序 | 普通应用程序（浏览器、Word） |
| 状态切换 | -- | 系统调用、中断、异常触发切换 |
| 内存访问 | 访问任意地址 | 只能访问自己的地址空间 |

> **一句话**：用户进程从"用户态"变"内核态"只有三条路 -- **中断、异常、系统调用**。

### 24.3 中断、异常、系统调用

**大白话**：
- **中断**= "突然有人敲门"，来自 CPU 外部，异步的
- **异常**= "你自己绊了一跤"，来自 CPU 内部，同步的
- **系统调用**= "你主动找老板签个字"，进程主动请求 OS 服务

| 维度 | 中断（Interrupt） | 异常（Exception） | 系统调用（System Call） |
|------|------------------|------------------|------------------------|
| **来源** | CPU 外部（I/O 设备、时钟） | CPU 内部（程序错误） | 程序主动调用 |
| **性质** | **异步**（随时可能发生） | **同步**（指令执行引发） | **同步**（有意调用） |
| **返回** | 返回**下一条**指令 | 返回**当前**指令（重试）或终止 | 返回**下一条**指令 |
| **举例** | 键盘输入、网卡收包、时钟中断 | 除零、缺页、非法指令 | read()、write()、fork() |

**异常的三种子类型**：

| 类型 | 大白话 | 处理方式 | 举例 |
|------|--------|---------|------|
| **陷阱（Trap）** | 故意设置的"断点" | 返回下一条 | 调试断点、系统调用本质上是一种陷阱 |
| **故障（Fault）** | 可以修复的错误 | 可能返回当前指令重试 | 缺页异常（加载页面后重新执行） |
| **终止（Abort）** | 无法恢复的致命错误 | 直接终止进程 | 硬件故障、除零错误 |

**中断处理流程**（理解即可）：
> 关中断 -- 保存断点 -- 识别中断源 -- 保存现场 -- 执行中断处理 -- 恢复现场 -- 开中断 -- 返回

> **小总结**：记住"中断外，异常内，系统调用主动请"。

### 24.4 操作系统结构

| 结构 | 核心思想 | 优点 | 缺点 |
|------|---------|------|------|
| **整体式（单体）** | 所有功能塞进一个内核 | 效率高，通信快 | 维护难，一个模块崩溃全死 |
| **层次式** | 自底向上分层，上层调下层 | 结构清晰，易维护 | 层间调用开销大 |
| **微内核** | 内核只保留最基础功能，其他服务在用户态 | 可靠性高，可扩展 | 频繁的用户态-内核态切换，性能低 |
| **模块化** | 内核由可加载模块组成（Linux 用的这种） | 灵活，按需加载 | 模块间耦合要设计好 |

> **典型代表**：Linux 是模块化 + 单体内核；Minix 是微内核；Windows 接近混合（微内核 + 分层）。

### 易错点（知识点 24）

1. **并发 vs 并行**：单核 CPU 上多进程是**并发**（交替执行），多核 CPU 上才是**并行**（同时执行）。
2. **中断 vs 异常**：中断来自外部（异步），异常来自内部（同步）。
3. **系统调用属于陷阱**：系统调用是通过"陷阱指令"（trap）主动陷入内核的。
4. **缺页异常是故障（Fault）**：不是终止，处理完可以继续执行。
5. **微内核的性能劣势**：因为核心服务跑在用户态，通信要经过 IPC，所以比单体内核慢。

## 25. 进程与线程管理

### 25.1 进程是什么

**大白话**：进程就是你打开的一个程序。比如你打开浏览器、打开 Word，每个都是独立的进程。进程是**资源分配的基本单位**。

**进程的定义**：进程（Process）是程序在数据集上的一次运行活动，即**程序的一次执行过程**。

**PCB（进程控制块）**：操作系统用来"记录"每个进程的表格，里面包含：
- 进程 ID（PID）
- 进程状态（就绪、运行、阻塞）
- CPU 寄存器值（上下文）
- 内存分配信息
- 打开文件列表
- 优先级

> **PCB 是进程存在的唯一标志**。

**三状态转换**（最重要的图）：

```
          时间片用完
      ┌──────────────┐
      │              ▼
   就绪(Ready)◄──── 运行(Running)
      ▲              │        │
      │   调度选中    │        │ 等待某事件（I/O等）
      │              │        │
      └──────────────┘        ▼
      等待事件完成         阻塞(Blocked/Waiting)
```

- **就绪（Ready）**：啥都准备好了，就差 CPU
- **运行（Running）**：正在用 CPU
- **阻塞（Blocked）**：在等某个事件（如等 I/O 完成），等到了才能变就绪

> **注意**：阻塞态**不能直接变运行态**，必须先经过就绪态。

---

### 25.2 线程是什么

**大白话**：线程是进程里面的"小工人"。一个车间（进程）里可以有多个工人（线程），大家共享车间里的工具和材料（内存空间）。

**核心区别（最高频考点）**：

| 维度 | 进程 | 线程 |
|------|------|------|
| **资源** | 资源分配的**基本单位** | **不拥有**系统资源，共享进程资源 |
| **调度** | 传统 OS 中的调度单位 | CPU 调度的**基本单位** |
| **独立性** | 独立地址空间，一个挂了不影响其他 | 共享地址空间，一个线程崩可能拖垮整个进程 |
| **通信** | 需要 IPC（进程间通信），代价大 | 直接读写共享变量，代价小 |
| **开销** | 创建/切换开销大 | 创建/切换开销小 |

> **口诀**："进程是资源单位，线程是调度单位。"

---

### 25.3 调度算法

**大白话**：CPU 就像一个理发师，进程就是排队理发的顾客。不同的调度算法就是不同的排队规则。

| 算法 | 全称 | 规则 | 优点 | 缺点 | 是否抢占 |
|------|------|------|------|------|---------|
| **FCFS** | 先来先服务 | 按到达顺序 | 公平、简单 | 长作业让后面短作业等很久（"护航效应"） | 否 |
| **SJF** | 短作业优先 | 谁运行时间短谁先 | 平均等待时间最短 | 长作业可能饿死 | 均可 |
| **高响应比** | 响应比优先 | 优先权 = (等待时间+服务时间)/服务时间 | 照顾短作业 + 不会让长作业饿死 | 每次调度都要计算 | 否 |
| **RR** | 时间片轮转 | 每人一个时间片，轮流 | 公平，适合分时系统 | 时间片太小切换多，太大变 FCFS | 是 |
| **多级反馈队列** | -- | 多个队列，优先级不同；高优先级时间片短，低优先级时间片长；用完时间片降级 | 兼顾长短作业 + 交互式 | 实现复杂 | 是 |

**高响应比优先权公式**：
```
响应比 = (等待时间 + 要求服务时间) / 要求服务时间
      = 1 + (等待时间 / 要求服务时间)
```
- 等待时间越长，响应比越高
- 服务时间越短，响应比越高

> **巧记**："FCFS 按到达，SJF 按长短，RR 按时间片，多级反馈最全面。"

### 25.4 同步与互斥

**大白话**：
- **互斥**= "厕所一次只能进一个人"
- **同步**= "做饭要按顺序：先洗菜，再切菜，最后炒菜"

**关键概念**：
- **临界资源**：一次只能被一个进程使用的资源（如打印机、共享变量）
- **临界区**：进程中访问临界资源的代码段
- **临界区的四个要求**：空闲让进、忙则等待、有限等待、让权等待

**信号量（PV 操作）**：

信号量是一个整数变量，只能通过 P 和 V 两个原子操作来修改。

| 操作 | 全称 | 含义 | 操作 |
|------|------|------|------|
| **P（Wait）** | 荷兰语 Proberen（测试） | 申请资源 | S = S - 1；如果 S < 0，阻塞等待 |
| **V（Signal）** | 荷兰语 Verhogen（增加） | 释放资源 | S = S + 1；如果 S <= 0，唤醒一个等待进程 |

**PV 操作理解**（设信号量初值为资源数量）：
- S > 0：表示还有 S 个可用资源
- S = 0：表示无可用资源，也无等待进程
- S < 0：表示有 |S| 个进程在等待

### 25.5 经典同步问题

**1. 生产者--消费者问题**

```
生产者生产产品放入缓冲区 ---> 缓冲区（有限大小） ---> 消费者从缓冲区取出产品
```

三个信号量：
- `mutex = 1`（互斥访问缓冲区）
- `empty = N`（缓冲区空位数）
- `full = 0`（缓冲区已用数）

**关键步骤**：
```
生产者：                         消费者：
P(empty)  // 有空位吗？          P(full)   // 有产品吗？
P(mutex)  // 锁门                  P(mutex)  // 锁门
放入产品                         取出产品
V(mutex)  // 开门                  V(mutex)  // 开门
V(full)   // 产品数+1             V(empty)  // 空位数+1
```

> **注意**：P 操作的顺序不能错。如果先 P(mutex) 再 P(empty)，可能死锁。

**2. 读者--写者问题**

- 多个读者可以同时读
- 写者必须独占访问
- 写者优先还是读者优先取决于实现

**3. 哲学家进餐问题**

五位哲学家围坐圆桌，中间五根筷子（每两位之间一根），哲学家需要两根筷子才能吃饭。

**死锁解法**：
- 限制最多四个哲学家同时拿起筷子
- 奇数编号先拿左边，偶数编号先拿右边
- 只有两根筷子都可用时才拿起

### 25.6 进程通信（IPC）

| 方式 | 大白话 | 特点 |
|------|--------|------|
| **共享存储** | 两人共用一块白板 | 快，但需要同步机制 |
| **消息传递** | 两人互相发短信 | 不需要同步，适合分布式 |
| **管道（Pipe）** | 一根水管，一头进水一头出水 | 半双工；匿名管道用于父子进程，命名管道用于无关进程 |

**消息传递的两种方式**：

| 方式 | 说明 | 特点 |
|------|------|------|
| **直接通信** | 直接发给目标进程（send(P, msg)） | 需要知道接收方 ID |
| **间接通信** | 发到信箱/消息队列，对方去取 | 解耦，更灵活 |

### 25.7 死锁

**大白话**：死锁就是"你不让我，我不让你，大家都卡住了"。

**四个必要条件**（缺一不可，都满足才可能死锁）：

| 条件 | 说明 | 举例 |
|------|------|------|
| **互斥条件** | 资源一次只能被一个进程使用 | 打印机 |
| **请求与保持** | 已经持有资源，又去申请新资源（不释放手里已有的） | 拿着 A 等 B |
| **不可剥夺** | 不能强行抢其他进程的资源 | 不能抢别人正在用的打印机 |
| **循环等待** | 形成 P1 等 P2、P2 等 P3、...、Pn 等 P1 的环 | A 等 B，B 等 C，C 等 A |

**死锁处理方法**：

| 策略 | 说明 |
|------|------|
| **预防**（Prevention） | 破坏四个必要条件之一（如资源有序分配法破坏循环等待） |
| **避免**（Avoidance） | 银行家算法，动态判断是否安全 |
| **检测与恢复** | 允许死锁发生，检测到后回滚/终止进程 |
| **鸵鸟算法** | 不处理（假装没看见），大多数系统这么干 |

### 25.8 银行家算法

**大白话**：银行家就像银行的贷款审批，只有当贷款不会导致银行破产（系统不会死锁）时才发放。

**核心数据结构**：

| 变量 | 含义 |
|------|------|
| **Available** | 系统当前可用的每种资源数量 |
| **Max** | 每个进程对每种资源的**最大需求** |
| **Allocation** | 每个进程当前已分配的每种资源数量 |
| **Need** | 每个进程还缺多少资源 = **Max - Allocation** |

**安全性算法步骤**：
1. 找 Need[i] <= Work（当前可用）的进程
2. 假设该进程完成：Work = Work + Allocation[i]
3. 重复直到所有进程都完成（安全）或找不到（不安全）

> **公式必记**：Need = Max - Allocation

**资源分配图**：
- 矩形 = 资源，大矩形里的圆点 = 该资源的具体实例
- 圆 = 进程
- 资源 → 进程（有向边）= 进程持有该资源
- 进程 → 资源（有向边）= 进程在等待该资源
- **有环不一定死锁**（资源有多个实例时），但死锁必定有环

### 例题（知识点 25）

**例 1**：某系统中有四个进程 P1-P4，单处理器。P1 运行时等待 I/O 而进入阻塞状态，请问此时 P1 对应的 PCB 会插入哪个队列？

答：阻塞队列（阻塞态对应的队列）。

**例 2**：设系统中有 5 个资源，3 个进程。每个进程最多需要 2 个资源，问系统是否会死锁？

答：不会。最坏情况：每个进程先占 1 个资源，还剩 2 个资源可分配，任意进程再获得 1 个就能运行完释放资源。所以绝对安全。

---

### 易错点（知识点 25）

1. **阻塞态不能直接变运行态**，必须经过就绪态。
2. **高响应比的公式**记得是 (W+T)/T，W 是等待时间，T 是服务时间，也就是 1 + W/T。
3. **P 和 V 是原子操作**，不可被中断。
4. **死锁的四个条件缺一不可**。破坏任何一个都可以预防死锁。
5. **银行家算法**中 Need = Max - Allocation。
6. **资源分配图有环**：资源只有一个实例时有环必死锁；有多个实例时有环不一定死锁。
7. **普通管道是半双工**的，且只能用于有亲缘关系（父子）的进程。

## 26. 内存管理

### 26.1 动态分区分配算法

**大白话**：内存就像停车场，进程就是来停车的大小不一的车。怎么给车分配车位，就是这些算法的核心问题。

**空闲分区链**：OS 把空闲内存区域串成一个链表，分配时从链表中找合适的。

| 算法 | 策略 | 大白话 | 优点 | 缺点 |
|------|------|--------|------|------|
| **首次适应（FF）** | 从头找，找到第一个够大的就分配 | "看到车位就停" | 简单，快速 | 低地址产生大量小碎片 |
| **循环首次适应（NF）** | 从上次分配的位置继续找 | "从上次停的地方再往前找" | 更均匀分布 | 大分区被分得更散 |
| **最佳适应（BF）** | 找最接近需求的（空闲分区从小到大排列） | "找最刚刚好的角落" | 大分区保留下来 | 产生无数极小的碎片 |
| **最坏适应（WF）** | 找最大的空闲分区（从大到小排列） | "专挑最大的车位停" | 剩余部分仍然较大 | 大分区先被用光 |

> **记忆口诀**："首次快，最佳省，最坏留大块，循环接着找。"

---

### 26.2 分页存储管理

**大白话**：把内存（物理存储）和程序地址（逻辑存储）都切成固定大小的"块"。程序的块叫**页（Page）**，内存的块叫**页框/帧（Frame）**。页和页框一样大，操作系统用**页表**记录"逻辑页号对应物理页框是哪个"。

**核心概念**：

| 概念 | 含义 |
|------|------|
| **页（Page）** | 程序地址空间分成的固定大小块 |
| **页框/帧（Frame）** | 物理内存分成的同样大小的块 |
| **页表** | 页号 → 页框号的映射表 |
| **页表项** | 页表中的一行，包含页框号 + 状态位等 |

**地址变换（考点）**：

逻辑地址 = 页号 + 页内偏移（即：逻辑地址 A，页面大小 L，则页号 P = A / L，偏移量 W = A % L）

```
逻辑地址 --> 查页表[页号]拿到页框号 --> 物理地址 = 页框号 * 页面大小 + 偏移量
```

**TLB（快表/转换检测缓冲区）**：
- 是一个高速缓存，存放最近用过的页表项
- 有效访问时间 = 命中率 * 快表访问时间 + 未命中率 * (快表访问时间 + 内存访问时间)
- 引入 TLB 后，访问内存通常需要：查 TLB（快） + 查页表（一次访存） + 访问数据（一次访存）

> **算数题套路**：若命中率为 p，快表访问时间为 t1，内存访问时间为 t2，则平均访问时间 = p * t1 + (1-p) * (t1 + t2) + t2（后面还有一个访问数据的时间）。

**多级页表**：
- 为什么需要？页表本身可能很大，把页表也分页
- 例如两级页表：页目录（外层页表）→ 页表 → 物理地址
- 代价：增加访存次数（两级页表需要三次访存：查页目录 + 查页表 + 访问数据）

---

### 26.3 分段存储管理

**大白话**：程序不是一整块，而是"代码段"、"数据段"、"栈段"这样自然的分段，每段可以不一样大。

| 概念 | 含义 |
|------|------|
| **段号** | 每个段的编号 |
| **段长** | 每个段的长度（可能不同） |
| **段基址** | 该段在内存中的起始地址 |
| **段表** | 段号 → 段基址 + 段长 + 保护信息 |

**逻辑地址 = 段号 + 段内偏移**

**分页 vs 分段（高频考点）**：

| 维度 | 分页 | 分段 |
|------|------|------|
| **划分目的** | 提高内存利用率 | 满足用户编程需要 |
| **大小** | 固定大小（由硬件决定） | 不固定（由程序决定） |
| **地址维度** | 一维（程序员只需给一个地址） | 二维（需给出段号和段内偏移） |
| **对用户可见** | 不可见（用户不知道分了页） | 可见（用户知道有段） |
| **碎片** | 页内碎片（最后一页用不完） | 外部碎片（段与段之间的空隙） |
| **共享保护** | 较难 | 容易（按段共享和保护） |

---

### 26.4 段页式存储管理

**大白话**：先按程序逻辑分段，再把每段分成固定大小的页。结合了两者的优点，但代价是更复杂。

**地址结构**：段号 + 段内页号 + 页内偏移

**地址变换过程**（三次访存）：
1. **第一次访存**：查段表寄存器 → 段表 → 拿到页表基址
2. **第二次访存**：查页表 → 拿到页框号
3. **第三次访存**：访问真正的数据

> **考点**：段页式需要**三次访存**，引入快表（TLB）可以减少到接近一次。

---

### 26.5 虚拟内存

**大白话**：你的程序 10GB，但内存只有 8GB，怎么跑得起来？答案是只把"正在用的那几页"加载到内存里，其他暂时不用的先放硬盘上。这就是虚拟内存的魔力。

**局部性原理**：

| 类型 | 含义 | 举例 |
|------|------|------|
| **时间局部性** | 刚才用过的，马上可能又用 | 循环中的变量反复访问 |
| **空间局部性** | 访问了这里的，旁边的大概率也要访问 | 数组顺序遍历 |

**请求分页**：
- 每个页表项多了几个标志位：状态位（在内存吗）、访问位（最近用过吗）、修改位（被改过吗）、外存地址
- 当访问的页不在内存（状态位=0），触发**缺页中断**
- OS 去磁盘找到该页，加载到内存，然后重新执行刚才那条指令

> **缺页中断属于故障（Fault）**，不是终止。

---

### 26.6 页面置换算法

**大白话**：内存满了，要加载新页面就得踢走旧页面，踢谁呢？这就是页面置换算法。

| 算法 | 策略 | 大白话 | 优缺点 |
|------|------|--------|--------|
| **OPT（最佳）** | 淘汰未来最长时间不再使用的页面 | "赶走以后最不需要的人" | **理论最优，但无法实现**（不能预知未来），用于比较基准 |
| **FIFO** | 淘汰最先加载的页面 | "先来的先走" | 简单但性能差，有 **Belady 异常** |
| **LRU（最近最久未使用）** | 淘汰最近最久没被用过的页面 | "最近没翻牌的先走" | 接近 OPT，但需要硬件支持，开销大 |
| **CLOCK（NRU）** | 循环扫描，访问位=0 的淘汰；访问位=1 的改为 0 | "再给一次机会" | 性能接近 LRU，实现简单 |

**Belady 异常**：
- FIFO 算法中，分配更多物理页面，缺页次数反而增加的奇怪现象
- LRU 和 OPT 不会出现此异常
- **FIFO 是唯一可能出现 Belady 异常的算法**（基于栈的算法不会出现）

**缺页率计算**（高频计算题）：

缺页率 = 缺页次数 / 总访问次数

注意：首次加载也算缺页。缺页中断是"要用的页不在内存"，进程之前从未访问过的页当然是"不在内存的"。

---

### 26.7 抖动（颠簸）与工作集

**大白话**：进程忙着"换页"比"真正干活"还忙，CPU 利用率反而下降。就像开会时不断换人进出会议室，没人真正开会。

**抖动（Thrashing）**：进程频繁地进行页面置换，大部分时间用在换页上而不是执行程序。

**原因**：分配给进程的物理页面太少，不够容纳活跃使用的页面。

**工作集理论**：
- 工作集 = 进程在时间窗口 T 内访问的页的集合
- 工作集反映了进程当前真正需要的内存量
- 解决办法：给进程分配大于工作集的物理页面数

**预防方法**：
- 工作集模型
- 页面故障频率（PFF）策略

> **小总结**：分页解决碎片问题，虚拟内存利用局部性，LRU 接近最优，抖动是因为内存给少了。

---

### 例题（知识点 26）

**例 1**：某系统页面大小为 4KB，逻辑地址为十六进制 0x3BAD。求页号和页内偏移。

解：4KB = 2^12 = 4096 字节，偏移量占 12 位。
逻辑地址 0x3BAD = 0011 1011 1010 1101
页号（高位）= 0011 = 3
页内偏移（低 12 位）= 1011 1010 1101 = 0xBAD

**例 2**：某进程分配 3 个页框，访问序列 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5，用 LRU 算法计算缺页次数。

答：按 LRU 模拟（"最近最久未使用"被淘汰）：
```
1    缺页 [1]
2    缺页 [1,2]
3    缺页 [1,2,3]
4    缺页 [2,3,4]   淘汰 1
1    缺页 [3,4,1]   淘汰 2
2    缺页 [4,1,2]   淘汰 3
5    缺页 [1,2,5]   淘汰 4
1    命中
2    命中
3    缺页 [2,5,3]   淘汰 1
4    缺页 [5,3,4]   淘汰 2
5    命中
```
缺页次数 = 9 次

### 易错点（知识点 26）

1. **分页是系统行为，分段是用户行为**。分页对用户透明，分段对用户可见。
2. **页内碎片 vs 外部碎片**：分页产生页内碎片，分段产生外部碎片。
3. **段页式三次访存**：段表--页表--实际数据。
4. **Belady 异常只发生在 FIFO**，LRU/OPT 不会出现。
5. **缺页中断属于故障**，不是终止。
6. **工作集**是动态变化的。

## 27. 文件管理

### 27.1 文件系统基础

**FCB（文件控制块）**：
- 操作系统用 FCB 来记录每个文件的信息
- FCB 包含：文件名、文件类型、物理位置、文件大小、创建/修改时间、访问权限等
- FCB 的**集合**就是**文件目录**
- **FCB 是文件存在的标志**

**目录结构**：

| 结构 | 说明 | 特点 |
|------|------|------|
| **单级目录** | 所有文件在一个目录里 | 文件名不能重复，查找慢 |
| **两级目录** | 主目录 + 用户目录 | 可以有重名文件 |
| **树形目录** | 多级目录，像大树 | 现代 OS 都用这个（Windows、Linux） |
| **无环图目录** | 树形 + 可以共享（链接） | 实现文件共享 |

**i 节点（索引节点）**：
- UNIX/Linux 使用的概念
- 文件的关键信息放在磁盘上的 i 节点里
- 目录项只保留**文件名 + i 节点号**，非常简洁
- 一个文件对应一个 i 节点，包含文件属性和数据块地址

---

### 27.2 硬链接 vs 软链接（高频考点）

**大白话**：
- **硬链接** = 给同一个"人"起多个名字（多个文件名指向同一个 i 节点）
- **软链接（符号链接）** = 贴一张"路标"纸条，写着"文件在那里"（是一个普通文件，内容是另一个文件路径）

| 维度 | 硬链接 | 软链接（符号链接） |
|------|--------|------------------|
| **本质** | 多个目录项指向同一个 i 节点 | 一个独立文件，内容是目标路径字符串 |
| **i 节点** | 与被链接文件共用同一个 i 节点 | 有自己独立的 i 节点 |
| **跨文件系统** | **不能** | **可以** |
| **链接目录** | **不能**（通常） | **可以** |
| **源文件删除后** | 链接仍然有效（数据还在） | 链接失效（"悬空链接"） |
| **文件大小** | 不额外占用空间 | 占用一个很小的目录项 |
| **常见命令** | `ln source hardlink` | `ln -s source softlink` |

> **口诀**："硬链接同 inode，不能跨区不能链目录；软链接像快捷方式，源文件走了就变空。"

---

### 27.3 磁盘访问时间

**大白话**：读磁盘就像去图书馆找一本书，需要三步：
1. 走到正确的书架前（**寻道时间**）
2. 等书架转盘把书转到眼前（**旋转延迟**）
3. 翻开书阅读（**传输时间**）

```
磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间
```

| 组成部分 | 含义 | 量级 | 优化 |
|---------|------|------|------|
| **寻道时间**（Seek Time） | 磁头移动到目标柱面 | 最大（几毫秒~十几毫秒） | 磁盘调度算法优化 |
| **旋转延迟**（Rotational Latency） | 目标扇区旋转到磁头下 | 平均半圈（几毫秒） | 只能靠高转速 |
| **传输时间**（Transfer Time） | 实际读写数据 | 最小 | 顺序读写 |

> **寻道时间占比最大**，所以磁盘调度算法主要优化它。

---

### 27.4 磁盘调度算法

**大白话**：磁头就像一个电梯，要去各个楼层接人。不同的调度算法就是不同的"电梯策略"。

| 算法 | 策略 | 大白话 | 优缺点 |
|------|------|--------|--------|
| **FCFS** | 按请求顺序 | "谁先叫先去谁那里" | 公平但效率低，磁头可能来回跑 |
| **SSTF** | 每次选离当前位置最近的 | "先去最近那一楼" | 平均寻道短，但远处的可能饿死 |
| **SCAN（电梯）** | 一个方向走到头再反向 | "电梯从底到顶，再从顶到底" | 比较公平，但两端的请求等待时间长 |
| **C-SCAN** | 一个方向走到头，快速回到底部再开始 | "只上不下，到顶后瞬间回底" | 各位置等待时间更均匀 |
| **LOOK** | SCAN 的改进：走到最后一个请求就反向 | "电梯到了最远的需求就回头" | 比 SCAN 更高效 |
| **C-LOOK** | C-SCAN 的改进：到最远请求就快速回起点 | 同 LOOK 但单向 | 高效又均匀 |

> **SCAN 和 LOOK 的区别**：SCAN 走到磁盘最边缘，LOOK 走到最远请求处就回头。C- 表示单向循环。

---

### 27.5 外存空间管理

**位示图法**：
- 用一个二进制位表示一个磁盘块是否空闲：1=已分配，0=空闲（或反过来）
- 就像停车场的车位指示灯
- 优点：简单直观，容易找连续空闲块
- 缺点：位示图本身需要占用内存，大磁盘位示图也大

**成组链接法**（UNIX 经典）：
- 把空闲块分组，每组第一个块存放下一组的块号列表
- 就像串一串珠子，一组一组串起来
- 结合了链式（灵活）和索引（快）的优点

---

### 例题（知识点 27）

**例 1**：假设磁盘有 200 个磁道（0-199），磁头当前在 53 号，请求序列为 98, 183, 37, 122, 14, 124, 65, 67。按 SCAN 算法（向磁道号增加方向移动），求访问顺序。

答：SCAN 从 53 开始向大号走：53→65→67→98→122→124→183→37→14
（到了 199 或者请求末尾 183 之后反向。如果 SCAN 走到头：53→65→67→98→122→124→183→199→37→14）

**例 2**：一个 i 节点可以存放多少个磁盘块地址？假设 i 节点有 10 个直接地址、1 个一级间接、1 个二级间接、1 个三级间接。每个地址 4 字节，每个磁盘块 4KB。

答：
- 直接地址：10 * 4KB = 40KB
- 一级间接：4KB / 4B = 1024 个地址，1024 * 4KB = 4MB
- 二级间接：1024 * 1024 * 4KB = 4GB
- 三级间接：1024^3 * 4KB = 4TB
- 最大文件大小 = 40KB + 4MB + 4GB + 4TB ≈ 4TB

---

### 易错点（知识点 27）

1. **硬链接不能跨文件系统**、不能链接目录、共享同一个 i 节点。
2. **软链接**删除源文件后变成死链接。
3. **寻道时间**占磁盘访问时间的**大头**。
4. **SCAN 和 LOOK** 的区别在于 SCAN 走到最边缘，LOOK 走到最远请求即回头。
5. **SSTF 可能造成饥饿**（远处请求始终得不到服务）。
6. **FCB 是文件存在的标志**。

### 自测题（知识点 27）

## 28. 设备管理

### 28.1 I/O 控制方式（四种对比）

**大白话**：CPU 怎么跟外部设备（键盘、硬盘、网卡等）打交道？经历了四个进化阶段，越来越让 CPU 从繁琐的 I/O 中解放出来。

| 方式 | 工作流程 | CPU 参与度 | 适用场景 | 大白话 |
|------|---------|-----------|---------|--------|
| **程序查询** | CPU 不断轮询设备状态，"好了没？好了没？" | **全程参与** | 简单低速设备 | CPU 像个老妈子，反复问"饭好了没" |
| **中断驱动** | 设备完成时发中断信号通知 CPU | **只在开始和中断时** | 低速到中速设备 | 设备自己喊"好了！"，CPU 来取就行 |
| **DMA** | 专门的 DMA 控制器负责数据传输，CPU 只发指令 | **只在开始和结束时** | 高速块设备（磁盘） | 雇个搬运工（DMA），CPU 只管下命令 |
| **通道（I/O 通道）** | 更高级的处理器，可执行自己的通道程序 | **极少参与** | 大型机 | 雇个经理，自己调度 I/O |

**对比总结**：

| 维度 | 程序查询 | 中断 | DMA | 通道 |
|------|---------|------|-----|------|
| 数据传送单位 | 字/字节 | 字/字节 | 块（多字节） | 块/多块 |
| 并行性 | CPU 和 I/O 串行 | CPU 和 I/O 并行 | CPU 和 I/O 并行 | CPU 和 I/O 高度并行 |
| CPU 开销 | 极高 | 中等 | 低 | 最低 |
| 复杂性 | 最简单 | 中等 | 较复杂 | 最复杂 |

> **进化路线**：程序查询（CPU 等人）→ 中断（CPU 被通知） → DMA（CPU 下命令） → 通道（CPU 基本不管）

### 28.2 SPOOLing 假脱机

**大白话**：几个人都要用打印机，如果一个人占了打印机别人就得等。SPOOLing 就是把要打印的内容先存到磁盘上的"打印队列"里，打印机慢慢打，别的用户不用等着。

**全称**：Simultaneous Peripheral Operations On-Line（同时外围设备联机操作）

**核心思想**：
- 用磁盘（快速设备）模拟慢速的独占设备
- 将独占设备变成**共享设备**

**三个组成部分**：

| 组件 | 作用 | 大白话 |
|------|------|--------|
| **输入井 / 输出井** | 磁盘上的缓冲区 | "打印仓库" |
| **输入进程 / 输出进程** | 负责从井中取数据和写数据 | "仓库管理员" |
| **井管理程序** | 控制作业进入井和从井出去 | "调度员" |

**打印机共享是 SPOOLing 的经典实现**：
> 用户提交打印 → 系统把数据写入磁盘输出井 → 后台输出进程排队打印 → 用户不用等

---

### 28.3 缓冲区

**大白话**：CPU 处理数据的速度和 I/O 设备的速度差了几个数量级。缓冲就像一个"转接口"，平缓两边速度的差异。

| 类型 | 原理 | 处理时间 | 优缺点 |
|------|------|---------|--------|
| **单缓冲** | 一个缓冲区，I/O 和 CPU 交替使用 | Max(C, T) + M | 简单，但缓冲区不能同时读写 |
| **双缓冲** | 两个缓冲区，一个装数据时另一个处理数据 | Max(C, T) | I/O 和处理可以并行，效率翻倍 |
| **循环缓冲** | 多个缓冲区组成环 | 约等于 Max(C, T) | 适合大流量场景 |

> 其中 C = CPU 处理时间，T = I/O 传输时间，M = 缓冲区搬移时间

**单缓冲 vs 双缓冲**：

```
单缓冲：
时间轴：T → C → T → C → ...
       I/O  处理  I/O  处理
       （不能同时进行）

双缓冲：
       Buffer1: T(装第一块)      → C(处理第一块) T(装第三块) ...
       Buffer2:      T(装第二块)      → C(处理第二块) ...
时间轴：T → T+C → T+C → ...
      （I/O 和 CPU 可以同时工作！）
```

> **结论**：双缓冲可以消除 CPU 和 I/O 之间的等待，使得处理时间趋近于 Max(C, T)。

### 例题（知识点 28）

**例 1**：用户进程在打印文件时，通过 SPOOLing 系统将打印内容暂存到磁盘，然后用户可以继续做其他事情。这种将独占设备改造为共享设备的技术称为？

答：SPOOLing 假脱机技术。

**例 2**：DMA 方式和中断方式的主要区别是什么？

答：中断方式每传送一个字就需要 CPU 介入一次；DMA 方式只在整块数据传送开始和结束时需要 CPU 介入，中间由 DMA 控制器自行完成。DMA 适合高速块设备（磁盘），中断适合低速字符设备。

---

### 易错点（知识点 28）

1. **DMA 传送的是数据块**，不是单个字节。
2. **SPOOLing 的核心**是用磁盘模拟独占设备，变独占为共享。
3. **双缓冲可以让 I/O 和 CPU 并行**，单缓冲不行。
4. **通道有自己的指令**（通道程序），比 DMA 更独立。

## 29. 操作系统安全与保护

### 29.1 CIA 三要素

**大白话**：信息安全的三个核心目标，就像寄信的三条要求：
- 信不能被别人偷看（机密性）
- 信的内容不能被篡改（完整性）
- 信要准时送到（可用性）

| 要素 | 英文 | 含义 | 大白话 | 实现技术 |
|------|------|------|--------|---------|
| **机密性** | Confidentiality | 未授权者不能读 | "不能偷看" | 加密、访问控制 |
| **完整性** | Integrity | 未授权者不能改 | "不能篡改" | 校验和、数字签名、Hash |
| **可用性** | Availability | 授权用户随时能用 | "不能罢工" | 备份、冗余、DDoS 防护 |

> **口诀**：CIA -- 机密不让看，完整不让改，可用不能停。

---

### 29.2 访问控制

**大白话**：谁能看什么文件、谁能改什么文件，这就是访问控制。

| 类型 | 全称 | 原理 | 大白话 | 特点 |
|------|------|------|--------|------|
| **DAC** | 自主访问控制 | 文件所有者自己决定谁能访问 | "我的文件我做主" | 灵活但安全性一般 |
| **MAC** | 强制访问控制 | 系统统一给每个主体和客体贴安全标签，按等级控制 | "保安按证件放行" | 安全性高，用于军事 |
| **RBAC** | 基于角色的访问控制 | 按岗位角色分配权限 | "你的职位决定你能看什么" | 企业最常用 |

**对比表**：

| 维度 | DAC | MAC | RBAC |
|------|-----|-----|------|
| 决策者 | 文件所有者 | 系统管理员（策略） | 系统管理员（角色） |
| 权限粒度 | 文件级 | 极其细粒度 | 角色级 |
| 灵活性 | 高 | 低 | 中 |
| 安全性 | 低 | **最高** | 高 |
| 典型场景 | Linux 文件权限（chmod） | 军事系统、SELinux | 企业系统 |

---

### 29.3 其他安全机制

**身份认证**：验证"你是谁"

| 方式 | 大白话 | 举例 |
|------|--------|------|
| 你知道什么（Knowledge） | 密码、PIN 码 | 登录密码 |
| 你有什么（Possession） | 实物 | U 盾、手机验证码 |
| 你是什么（Inherence） | 生理特征 | 指纹、人脸、虹膜 |
| 你在哪里（Location） | 地点 | IP 地址、GPS 定位 |

**多因素认证**：同时用两种以上方式，如密码 + 短信验证码。

**恶意软件防护**：

| 类型 | 说明 | 特点 |
|------|------|------|
| **病毒** | 感染正常程序，传播并破坏 | 需要宿主程序 |
| **蠕虫** | 自我复制，通过网络传播 | 不需要宿主 |
| **木马** | 伪装成正常程序，偷偷干坏事 | 欺骗用户安装 |
| **勒索软件** | 加密用户文件，索要赎金 | 近年高发 |

**安全审计**：记录安全相关事件日志，事后追踪"谁在什么时候做了什么"。

### 例题（知识点 29）

**例 1**：Linux 中 `chmod 644 file.txt` 属于哪种访问控制？

答：DAC（自主访问控制），文件所有者自己设置权限。

**例 2**：某系统根据用户的部门职务自动分配相应的文件访问权限，这属于哪种访问控制？

答：RBAC（基于角色的访问控制）。

---

### 易错点（知识点 29）

1. **机密性不等于完整性**：加密保证机密性，但加密的文件仍然可能被篡改（破坏完整性），需要额外的校验机制。
2. **MAC vs DAC**：MAC 是系统强制的一刀切规则，DAC 是文件所有者自己说了算。
3. **RBAC 是使用最广泛的**企业级访问控制模型。
4. **病毒需要宿主，蠕虫不需要**。

## 附录：高频计算题速查

### 1. 银行家算法判断安全序列

**步骤**：
1. 算出每个进程的 Need = Max - Allocation
2. 初始 Work = Available
3. 找一个 Need[i] <= Work 的进程
4. Work += Allocation[i]，标记该进程已完成
5. 重复 3-4，若全部进程都能完成则安全

### 2. 页面置换缺页率计算

**步骤**：
1. 记录访问序列和初始状态
2. 按置换算法规则模拟
3. 首次出现、不在内存的都算缺页
4. 缺页率 = 缺页次数 / 总访问次数

### 3. 磁盘调度序列模拟

**步骤**：
1. 明确当前磁头位置和移动方向
2. 按算法规则选取下一个请求
3. 计算每次移动距离
4. 总寻道距离 = 各次移动距离之和

### 4. 有效访问时间（EAT）

```
EAT = 命中率 * (TLB时间 + 内存访问时间) + (1 - 命中率) * (TLB时间 + 页表访问时间 + 内存访问时间)
```

> 页表访问时间 = 一级页表访存时间 * 级数（若有多级页表）
