## 知识点 45：人工智能基础

### 知识点 45：1 人工智能是什么？

人工智能（Artificial Intelligence，简称 AI）就是让计算机模仿人类的智能行为——学习、推理、感知、决策。

**类比**：教小孩认猫——先给他看很多猫的图片（这就是"数据"），他慢慢总结出猫的特征（"学习"），以后看见没见过的猫也能认出来（"泛化"）。AI 也是这个道理。

**三个层次划分**：

| 层次 | 含义 | 现状 |
|------|------|------|
| 弱人工智能（ANI） | 只会做一件特定的事 | 当前所有 AI 都在这个层次（AlphaGo、ChatGPT 都是） |
| 强人工智能（AGI） | 像人一样什么都能干的通用智能 | 尚未实现，是研究目标 |
| 超人工智能（ASI） | 在所有领域超过人类的智能 | 科幻范畴 |

> 考试记忆诀窍：当前所有 AI 都是弱人工智能（ANI），不是强人工智能（AGI）。

### 知识点 45：2 人工智能发展简史

```
1956 达特茅斯会议 → "人工智能"术语诞生
     ↓ （推理期：逻辑证明、问题求解）
1980s 专家系统兴起 → 用规则库模拟专家决策
     ↓ （知识期：知识工程）
1990s 浅层机器学习 → SVM、决策树、随机森林
     ↓ （传统机器学习期）
2012 - 深度学习爆发 → AlexNet 在 ImageNet 夺冠
2016 - AlphaGo 战胜李世石
     ↓
2022 ChatGPT → 大模型时代
2023- GPT-4、文心一言、通义千问等 → 大模型全面应用
```

> 考试记忆诀窍："1956 诞生 → 1980s 专家系统 → 2012 深度学习爆发 → 2022 大模型元年"

### 知识点 45：3 机器学习三大范式

机器学习的核心公式：**数据 + 算法 = 模型**（模型遇到新数据时能做出预测或决策）

#### 知识点 45：3.1 监督学习（Supervised Learning）

有"标准答案"（标签）的训练方式。

**类比**：老师教你做题，每道题都告诉你正确答案。做多了你就掌握了规律，遇到新题也能做出来。

| 要素 | 说明 |
|------|------|
| 输入 | 带标签的训练数据（特征 + 标签） |
| 目标 | 学到从"输入"到"输出"的映射关系 |
| 常见任务 | **分类**、**回归** |
| 例子 | 垃圾邮件识别、房价预测、图像分类 |

**分类 vs 回归**：
- **分类（Classification）**：预测结果是离散的类别。如：这是猫还是狗？→ 猫/狗（有限的几个选项）
- **回归（Regression）**：预测结果是连续的数值。如：这房子卖多少钱？→ 500万（可以取任何数值）

> 记忆诀窍：分类 = 选择题（ABCD），回归 = 填空题（填数字）

#### 知识点 45：3.2 无监督学习（Unsupervised Learning）

没有"标准答案"，让算法自己从数据中发现规律。

**类比**：给你一堆水果但不告诉你是谁买的，你自己按照颜色、大小、形状把苹果放一筐、橘子放一筐。

| 要素 | 说明 |
|------|------|
| 输入 | 无标签的数据（只有特征，没有标签） |
| 目标 | 发现数据内部的隐藏结构或分布 |
| 常见任务 | **聚类**、**降维** |
| 例子 | 用户分群、异常检测、推荐系统"猜你喜欢" |

**聚类 vs 降维**：
- **聚类（Clustering）**：把相似的样本归为一组。如：把消费者分成高消费/中消费/低消费三群
- **降维（Dimensionality Reduction）**：把数据的特征数量压缩，保留核心信息。如：把人脸照片 1000 维数据压缩到 100 维，方便计算

#### 知识点 45：3.3 强化学习（Reinforcement Learning）

没有正确答案，算法通过和环境的互动，"试错"来学习最佳策略。

**类比**：训练小狗——做对了给零食（奖励），做错了不理它（惩罚）。狗狗会自己总结出怎么做才能得到更多零食。

| 要素 | 说明 |
|------|------|
| 核心概念 | **智能体（Agent）** 在 **环境（Environment）** 中执行 **动作（Action）**，获得 **奖励（Reward）** |
| 目标 | 找到让长期累积奖励最大的策略 |
| 典型例子 | AlphaGo 下围棋、自动驾驶、游戏 AI |

> 强化学习不需要你预先准备"正确答案"，它自己边试边学。

#### 三种学习方式对比

| 对比维度 | 监督学习 | 无监督学习 | 强化学习 |
|----------|---------|-----------|---------|
| 有没有标签 | 有 | 没有 | 没有（但有奖励信号） |
| 学习方式 | 模仿正确答案 | 自己找规律 | 试错 + 奖励 |
| 典型任务 | 分类、回归 | 聚类、降维 | 游戏、机器人控制 |
| 类比 | 有答案的习题册 | 自己整理书架 | 训狗 |

### 知识点 45：4 深度学习三大网络结构

#### 知识点 45：4.1 CNN（卷积神经网络）

**专攻：图像处理**

**核心思想**：用"卷积核"（一个小窗口）在图片上滑动，提取局部特征。

**类比**：你在看一张猫的照片——不是一次性看整张照片，而是先看耳朵（局部特征），再看眼睛，再看尾巴，最后综合判断"这是一只猫"。

| 关键概念 | 含义 |
|----------|------|
| 卷积层（Convolution） | 用卷积核滑动，提取特征 |
| 池化层（Pooling） | 压缩数据，保留最重要的信息 |
| 全连接层（FC） | 做最后的分类判断 |

**CNN 典型应用**：图像分类、人脸识别、医学影像分析、自动驾驶中的物体检测

> 记忆诀窍：CNN = 卷积核扫图 → 提取特征 → 做分类，核心就是"局部感知"

#### 知识点 45：4.2 RNN（循环神经网络）

**专攻：序列数据处理**（数据前后有顺序关系）

**核心思想**：有一个"记忆单元"，把前一步的输出传递给后一步。

**类比**：你读一句话不会把每个字孤立理解，而是用前文来帮助理解后文的含义。"我今天心情很好，所以___"→ 你知道后面大概率是正面词汇。

| 变体 | 含义 |
|------|------|
| RNN（基础） | 能记住前面的信息，但太长的序列记不住（梯度消失） |
| LSTM（长短期记忆） | 有了"遗忘门"和"记忆门"，能处理长序列 |
| GRU | LSTM 的简化版，效果差不多但参数更少 |

**RNN/LSTM 典型应用**：机器翻译、语音识别、文本生成、时间序列预测（股票走势）

> 记忆诀窍：RNN = 有记忆的神经网络，适合"前后有关系"的数据

#### 知识点 45：4.3 Transformer

**目前最主流的深度学习架构，ChatGPT/BERT 的基础**

**核心创新**：**自注意力机制（Self-Attention）**——让模型知道一句话里哪个词和哪个词有关系。

**类比**：读这句话："小明把苹果给了小红，她很高兴"。Transformer 的注意力机制能自动判断"她"指的是"小红"而不是"小明"。

| 关键概念 | 含义 |
|----------|------|
| 自注意力 | 计算句子中每个词与其他所有词的关联度 |
| 多头注意力 | 从多个角度同时做注意力，不同"头"关注不同关系 |
| 位置编码 | 因为 Transformer 不像 RNN 那样天然有序，所以要额外告诉它词的顺序 |
| Encoder-Decoder | Encoder 理解输入，Decoder 生成输出 |

**为什么 Transformer 替代了 RNN？**
- 可以**并行计算**（RNN 必须按顺序算，Transformer 可以同时算所有位置）
- 解决了长距离依赖问题（注意力机制直接连接任意两个词）

> 记忆诀窍：Transformer = 注意力机制 + 并行计算，是 GPT/BERT 的底层架构

#### 三大网络结构对比

| 网络结构 | 擅长处理 | 核心机制 | 代表应用 |
|----------|---------|---------|---------|
| CNN | 图像 | 卷积 + 池化 | 人脸识别、物体检测 |
| RNN/LSTM | 序列（有时间顺序） | 循环记忆单元 | 翻译、语音识别 |
| Transformer | 序列（通用） | 自注意力 | GPT、BERT、ChatGPT |

### 知识点 45：5 人工智能主要应用领域

#### 知识点 45：5.1 自然语言处理（NLP）

让计算机理解、生成人类语言。

| 任务 | 含义 | 例子 |
|------|------|------|
| 分词 | 把句子切成词 | "我爱北京天安门" → "我/爱/北京/天安门" |
| 情感分析 | 判断文本情感倾向 | 好评？差评？中性？ |
| 机器翻译 | 把一种语言翻译成另一种 | 中→英 翻译 |
| 文本分类 | 把文章归类 | 新闻分类：体育/财经/娱乐 |

#### 知识点 45：5.2 语音识别（ASR）

把人的说话声音转成文字。

**流程**：声波 → 提取声学特征 → 声学模型（音素识别）→ 语言模型（纠错）→ 文字输出

**典型应用**：语音助手（Siri/小爱）、语音输入法、会议转写

#### 知识点 45：5.3 文字识别（OCR）

把图片中的文字提取出来。

**流程**：图片 → 文字区域检测（找到字在哪）→ 文字识别（认出是什么字）→ 后处理纠错

**典型应用**：身份证识别、车牌识别、扫描文档转 Word

#### 知识点 45：5.4 图像识别（Computer Vision）

让计算机"看懂"图像。

| 任务层级 | 含义 | 例子 |
|----------|------|------|
| 图像分类 | 判断图片里是什么 | 这是一只猫 |
| 目标检测 | 找到图片里有什么、在哪 | 框出所有人脸 |
| 图像分割 | 把图片中每个像素分类 | 自动驾驶中分离道路和行人 |

### 知识点 45：6 大模型：GPT 与 BERT

大模型（Large Language Model, LLM）是指参数规模巨大的深度学习模型，通过海量文本数据训练，具备强大的语言理解和生成能力。

#### GPT（Generative Pre-trained Transformer）

| 特点 | 说明 |
|------|------|
| 架构 | Transformer 的 **Decoder** 部分（单向生成） |
| 训练方式 | 自回归（从左到右，根据前文预测下一个词） |
| 核心能力 | **文本生成**——写文章、写代码、对话 |
| 代表模型 | GPT-3、GPT-4、ChatGPT |

**类比**：GPT 像一个接龙高手——给一个开头，它不停地续写，生成一段完整文字。

#### BERT（Bidirectional Encoder Representations from Transformers）

| 特点 | 说明 |
|------|------|
| 架构 | Transformer 的 **Encoder** 部分（双向理解） |
| 训练方式 | 双向（同时看上下文，从左+从右预测中间的词） |
| 核心能力 | **文本理解**——分类、问答、实体识别 |
| 代表模型 | BERT、RoBERTa、ALBERT |

**类比**：BERT 像一个阅读理解高手——给它一篇文章，它能回答关于文章内容的各种问题。

#### GPT vs BERT 对比

| 对比维度 | GPT | BERT |
|----------|-----|------|
| 方向 | 单向（从左到右） | 双向（同时看左右） |
| Transformer 部分 | Decoder 为主 | Encoder 为主 |
| 擅长 | **生成**文字 | **理解**文字 |
| 典型任务 | 对话、写作、代码生成 | 情感分析、完形填空、问答 |
| 一句话记忆 | "接着说" | "读懂了再答" |

#### 预训练 + 微调

大模型的开发分为两个阶段：

1. **预训练（Pre-training）**：在海量无标注数据上训练，学习通用的语言知识（耗时耗钱，通常大厂完成）
2. **微调（Fine-tuning）**：在特定任务的小数据集上再做训练，让模型适配具体业务（成本低，速度快）

**类比**：预训练 = 先把一个人教育成"高中生"（通用知识）。微调 = 让他参加某个岗位的岗前培训（专业化）。

#### 提示工程（Prompt Engineering）

不重新训练模型，而是通过巧妙设计输入提示（Prompt），引导大模型产出更好的结果。

**例子**：
- 差提示："写一封邮件"（太模糊）
- 好提示："你是一位专业的商务助理。请用正式礼貌的语气，写一封邮件给客户王总，提醒他明天下午 3 点有签约会议，地点在公司 12 楼会议室。邮件不超过 100 字。"（角色 + 任务 + 约束）

## 知识点 46：物联网基础

### 知识点 46：1 物联网是什么？

物联网（Internet of Things，简称 IoT）就是把各种物理设备（传感器、家电、车辆、穿戴设备等）通过网络连接起来，实现"物与物"之间的数据交换和智能控制。

**核心公式**：传感器 + 网络 + 数据处理 = 物联网

**类比**：智能手机是人联网（人→手机→互联网→人），物联网是物联网（温度传感器→网关→互联网→空调控制器——温度高了自动开空调，人不用管）。

**物联网 vs 互联网**：

| 对比维度 | 互联网 | 物联网 |
|----------|--------|--------|
| 连接主体 | 人 ↔ 人 | 物 ↔ 物，物 ↔ 人 |
| 数据来源 | 人输入的 | 传感器自动采集的 |
| 终端设备 | 电脑、手机 | 传感器、智能家电、工业设备 |
| 数据量 | GB/TB 级 | PB/EB 级（海量） |

### 知识点 46：2 物联网三层架构

这是考试的核心考点，必须记住三层及其职责。

```
┌──────────────────────────────────┐
│          应用层（最上层）           │  智能家居、智慧城市、工业物联网……
│    处理数据 + 提供服务 + 人机交互    │  "做什么？"
└──────────────────────────────────┘
              ↕
┌──────────────────────────────────┐
│          网络层（中间层）           │  WiFi、4G/5G、NB-IoT、LoRa、ZigBee……
│    数据传输 + 路由 + 通信协议       │  "怎么传？"
└──────────────────────────────────┘
              ↕
┌──────────────────────────────────┐
│          感知层（最下层）           │  传感器、RFID、摄像头、GPS……
│    数据采集 + 物体识别 + 信息感知    │  "用什么感知？"
└──────────────────────────────────┘
```

| 层次 | 别称 | 核心功能 | 典型设备/技术 | 大白话 |
|------|------|---------|-------------|--------|
| 感知层 | 传感层 | 数据采集 + 物体识别 | 温度传感器、RFID 标签、摄像头、GPS | "眼睛和耳朵" |
| 网络层 | 传输层 | 数据传输 + 路由转发 | WiFi、4G/5G、NB-IoT、LoRa、ZigBee | "神经系统" |
| 应用层 | 处理层 | 数据处理 + 提供应用 | 智慧家居 APP、工业监控平台 | "大脑" |

> 记忆口诀："下面感知、中间传输、上面应用"——自下而上，信息越来越抽象。

### 知识点 46：3 传感器与传感网络

#### 传感器（Sensor）

把物理世界的信息转化成电信号的设备——物联网的"五官"。

| 传感器类型 | 检测对象 | 应用场景 |
|-----------|---------|---------|
| 温度传感器 | 温度 | 智能空调、冷链物流 |
| 湿度传感器 | 湿度 | 农业大棚、粮仓监测 |
| 光照传感器 | 光线强度 | 智能灯光、农业补光 |
| 加速度传感器 | 运动/振动 | 计步器、地震监测 |
| GPS 模块 | 地理位置 | 车辆跟踪、物流追踪 |
| 图像传感器 | 画面 | 人脸识别门禁、安防监控 |

#### 无线传感网络（WSN）

Wireless Sensor Network，由大量微型传感器节点自组织形成的无线网络。

| 特点 | 说明 |
|------|------|
| 自组织 | 节点能自己组建网络，不需要人工配置 |
| 多跳路由 | 数据通过多个节点"接力"传输到汇聚节点 |
| 低功耗 | 传感器节点通常靠电池供电，必须省电 |
| 大规模 | 一个网络可能有成百上千个节点 |

### 知识点 46：4 物联网常见通信协议与标准

#### 按传输距离分类

| 类别 | 典型协议 | 传输距离 | 典型应用 |
|------|---------|---------|---------|
| 近距离 | RFID、NFC | 厘米~几米 | 门禁卡、移动支付 |
| 中距离 | WiFi、ZigBee | 几十米~百米 | 智能家居 |
| 远距离（LPWAN） | LoRa、NB-IoT | 几千米 | 智慧城市、农业监测 |

#### 协议详解

**MQTT（消息队列遥测传输）**
- 基于 **发布/订阅** 模式的轻量级通信协议
- 特点：协议开销极小，适合低带宽、不可靠网络环境
- 典型应用：传感器数据传输、即时通讯推送

> 记忆：MQTT = "即时通讯的消息推送"——设备 A 发布消息，设备 B 订阅后就收到了。

**CoAP（受限应用协议）**
- 专为资源受限设备设计的类 HTTP 协议
- 基于 UDP，比 HTTP 更轻量
- 支持 RESTful 风格交互

> 记忆：CoAP = "瘦版的 HTTP"，给内存和带宽都很小的设备用。

**ZigBee**
- 低速率、低功耗、低成本的无线通信标准
- 基于 IEEE 802.15.4
- 支持自组网（Mesh 网络，网状拓扑）
- 典型应用：智能家居（小米智能家居用的就是 ZigBee）

> 记忆：ZigBee = "低功耗版的 WiFi"，适合智能灯泡、插座等小设备。

**LoRa（远距离低功耗广域网）**
- 特点：**远距离 + 超低功耗**（电池能用几年）
- 工作在非授权频谱（免费频段）
- 典型应用：智能抄表（水表/电表）、农业大田监测

> 记忆：LoRa = "乡村广播"——距离远但传输量小。

**NB-IoT（窄带物联网）**
- 基于蜂窝网络（运营商基站），由 4G/5G 网络支持
- 特点：覆盖广、连接多、功耗低
- 典型应用：智能停车、智慧路灯、环境监测

> 记忆：NB-IoT = "运营商的物联网网络"——类似手机信号，用运营商的基站。

**LoRa vs NB-IoT 对比**：

| 对比维度 | LoRa | NB-IoT |
|----------|------|--------|
| 部署方 | 自行部署网关 | 运营商基站 |
| 频谱 | 免费频段 | 授权频段（需要运营商 SIM 卡） |
| 成本 | 初次部署高，后续免费 | 持续按流量/连接付费 |
| 适用场景 | 私有园区、偏远农田 | 城市、运营商覆盖区域 |

#### RFID 与 NFC

**RFID（射频识别）**
- 通过无线电波自动识别目标并读取数据
- 三部组成：标签（贴在物体上）、阅读器（读取数据）、天线（收发信号）
- 距离：几厘米到几十米（依标签类型而定）
- 典型应用：物流仓储管理、ETC 不停车收费、门禁卡

> 记忆：RFID = "电子标签"，不需要"看见"就能读取。

**NFC（近场通信）**
- RFID 的一个子类，13.56MHz，距离极短（< 10cm）
- 支持 **双向通信**（普通 RFID 通常只是单向读取）
- 三种工作模式：卡模拟模式、读写器模式、点对点模式
- 典型应用：Apple Pay/手机支付、门禁/公交卡、手机一碰传

**RFID vs NFC**：

| 对比维度 | RFID | NFC |
|----------|------|-----|
| 通信距离 | 几厘米~几十米 | < 10cm |
| 通信方向 | 多为一对多、单向 | 一对一、双向 |
| 频率 | 多种频段（低频/高频/超高频） | 固定 13.56MHz |
| 典型场景 | 仓储批量盘点 | 手机支付 |

> 记忆诀窍：NFC 是 RFID 的"加强版、近距离、支持双向通信"的子集。

## 知识点 47：大数据基础

### 知识点 47：1 大数据是什么？

大数据（Big Data）是指数据量太大、太复杂，传统工具无法在合理时间内处理的数据集合。

**一句话**：大到传统数据库/Excel 搞不定的数据，就叫大数据。

### 知识点 47：2 大数据的 5V 特征

| 特征（英文） | 中文 | 含义 |
|------------|------|------|
| **Volume** | 大量 | 数据量巨大，PB/EB 级别 |
| **Velocity** | 高速 | 数据生成速度快，需要实时或准实时处理 |
| **Variety** | 多样 | 数据类型多样：结构化（表格）+ 半结构化（XML/JSON）+ 非结构化（图片/视频/文本） |
| **Value** | 低价值密度 | 海量数据中有价值的信息比例低，需要"沙里淘金" |
| **Veracity** | 真实性/准确性 | 数据质量参差不齐，需要清洗和验证 |

> 记忆口诀："大数据 5 个 V"——Volume 量、Velocity 速、Variety 多样、Value 价值密度低、Veracity 不准

**类比**：
- Volume = 一座山（数据量大）
- Velocity = 山还在不停长（数据不断涌入）
- Variety = 山里有石头、泥土、树、动物（各种类型的数据）
- Value = 山里只有几块金子（有价值的信息很少，需要挖掘）
- Veracity = 里面还有假石头和垃圾（数据有噪声、不准确）

### 知识点 47：3 数据处理全流程

```
数据采集 → 数据预处理 → 数据分析 → 数据挖掘 → 可视化
```

#### 知识点 47：3.1 数据采集

从各种来源把数据汇聚起来。

| 采集方式 | 说明 | 例子 |
|----------|------|------|
| 日志采集 | 从服务器日志中收集用户行为数据 | 网页点击日志、APP 操作日志 |
| 传感器采集 | 从物联网设备收集物理数据 | 温度、湿度、定位 |
| 网络爬虫 | 自动从网页抓取数据 | 电商比价、舆情监控 |
| API 接口 | 通过程序接口获取数据 | 调用第三方开放平台获取数据 |

#### 知识点 47：3.2 数据预处理

**原始数据 = 脏数据**（有缺失、有重复、有错误），必须先"洗干净"。

| 操作 | 含义 | 大白话 |
|------|------|--------|
| 数据清洗 | 处理缺失值、异常值、重复数据 | "去脏东西"：填空白、删重复、修错误 |
| 数据集成 | 把多个来源的数据合并到一起 | "拼积木"：把 A 表和 B 表合在一起 |
| 数据变换 | 统一数据格式、做归一化处理 | "统一度量衡"：把单位统一，把范围压缩 |
| 数据规约 | 压缩数据量，保持核心信息不丢 | "浓缩精华"：去冗余，减少数据量 |

> 口诀：洗→合→变→缩（清洗 → 集成 → 变换 → 规约）

#### 知识点 47：3.3 数据分析

| 分析类型 | 含义 | 核心问题 |
|----------|------|---------|
| 描述性分析 | 描述"发生了什么" | 昨天销售额是多少？ |
| 诊断性分析 | 分析"为什么会发生" | 为什么昨天销售额下降？ |
| 预测性分析 | 预测"未来会发生什么" | 下个月销售额会是多少？ |
| 规范性分析 | 建议"应该怎么办" | 要怎么做才能提升下月销售额？ |

> 记忆：描述 → 诊断 → 预测 → 建议（由浅到深，越来越高级）

#### 知识点 47：3.4 数据模型

数据模型是数据组织和存储的蓝图，决定了数据如何被结构化以便分析。最常见的是**维度建模**。

| 模型类型 | 核心思想 | 特点 |
|----------|---------|------|
| **维度建模** | 围绕业务过程，将数据分为**事实表**（存度量值）和**维度表**（存描述信息） | 查询快、易于理解，数据仓库主流方法 |
| **星型模型** | 一个事实表连接多个维度表，维度表只与事实表关联，不互相连接 | 结构简单，查询效率高，但维度表数据冗余大 |
| **雪花模型** | 星型模型的规范化版本，维度表可以进一步拆分成子维度表 | 减少冗余，但查询时需要更多 JOIN，性能略低 |

> 类比：星型 = 一个中心枢纽（事实表）直接连各个卫星（维度表）；雪花 = 卫星还有自己的卫星。

**事实表 vs 维度表**：

| 类型 | 存什么 | 特点 | 类比 |
|------|--------|------|------|
| 事实表 | 业务度量值（金额、数量、次数） | 数据量大、增长快、多为数值 | 账本——记录每一笔交易 |
| 维度表 | 描述性信息（时间、地点、产品、客户） | 数据量相对小、变化慢、多为文本 | 字典——查"这是什么" |

#### 知识点 47：3.5 数据挖掘

从大量数据中发现隐藏的模式和规律。

| 挖掘方法 | 含义 | 典型场景 |
|----------|------|---------|
| 关联规则 | 发现事物之间的关联关系 | "买了尿布的人通常也买啤酒"（购物篮分析） |
| 分类 | 判断数据属于哪一类 | 判断一笔交易是正常还是欺诈 |
| 聚类 | 把相似的数据归为一组 | 把消费者分为不同群体进行精准营销 |
| 回归 | 预测连续数值 | 根据房屋面积、地段预测房价 |

**关联规则的经典概念**：
- **支持度（Support）**：A 和 B 同时出现的概率。如：100 笔订单中，同时买了尿布和啤酒的有 20 笔，支持度 = 20%
- **置信度（Confidence）**：买了 A 的人中有多少也买了 B。如：买尿布的人中 80% 也买了啤酒，置信度 = 80%

> 记忆：支持度 = "多常见"；置信度 = "多可靠"

#### 知识点 47：3.6 数据可视化

用图表把数据呈现出来，让人一眼看懂。

| 图表类型 | 适用场景 |
|----------|---------|
| 折线图 | 展示数据随时间变化的趋势 |
| 柱状图/条形图 | 对比各类别的数据大小 |
| 散点图 | 展示两个变量之间的关系 |
| 热力图 | 展示密度/强度分布（深色=高，浅色=低） |
| 仪表盘（Dashboard） | 多指标的一站式监控面板 |

### 知识点 47：4 大数据平台概念

#### 知识点 47：4.1 Hadoop 生态

Hadoop 是大数据处理的"鼻祖"框架，核心是三个组件：

| 组件 | 全称 | 功能 | 类比 |
|------|------|------|------|
| **HDFS** | Hadoop Distributed File System | 分布式文件存储（把大文件拆成小块存到多台机器上） | "超大仓库"——把一个大搬家车的货分散放到多个仓库 |
| **MapReduce** | Map + Reduce | 分布式计算模型（Map = 拆分任务分给多台机器算，Reduce = 汇总结果） | "分锅做饭"——洗菜员、切菜员、炒菜员各干各的，最后汇总成一桌菜 |
| **YARN** | Yet Another Resource Negotiator | 资源管理和任务调度 | "项目经理"——统一分配 CPU、内存给各个任务 |

**HDFS 核心特点**：
- 数据分块存储（默认 128MB 一块），每块存多个副本（默认 3 份）
- **一次写入，多次读取**：写完后不改，适合存日志、存数据分析的原始数据
- 不适合低延迟访问，不适合大量小文件

**MapReduce 计算流程**：
```
数据输入 → Map 阶段（拆分 + 并行处理）→ Shuffle 阶段（中间结果混洗）→ Reduce 阶段（汇总 + 输出结果）
```

> 考试记忆：Hadoop 三件套——HDFS（存）、MapReduce（算）、YARN（管资源）

#### 知识点 47：4.2 Spark

Spark 是比 MapReduce 更快的新一代大数据计算框架。

| 对比维度 | Hadoop MapReduce | Spark |
|----------|-----------------|-------|
| 计算方式 | 磁盘 I/O（中间结果写磁盘，慢） | 内存计算（中间结果放内存，快） |
| 速度 | 慢 | 快（比 MapReduce 快 10~100 倍） |
| 适用场景 | 批量离线处理 | 批量处理 + 实时流处理 + 机器学习 |
| 编程语言 | Java 为主 | 支持 Java/Scala/Python/R |

**Spark 核心模块**：
- **Spark Core**：基础计算引擎
- **Spark SQL**：用 SQL 查询大数据
- **Spark Streaming**：实时流数据处理
- **MLlib**：机器学习库
- **GraphX**：图计算

> 记忆：Spark = "内存版 MapReduce"——核心优势就是快，因为数据在内存里算，不到磁盘上兜一圈。

## 常见易错陷阱

1. **当前所有 AI 都是弱人工智能（ANI），不是强人工智能（AGI）**
2. **监督学习需要标签，无监督学习不需要标签**——这是两者最本质的区别
3. **分类输出离散类别，回归输出连续数值**——不要搞混
4. **CNN 用于图像，RNN/LSTM 用于序列**——不要交叉使用
5. **GPT 是单向生成，BERT 是双向理解**——GPT = "接着说"，BERT = "读懂再答"
6. **物联网三层：感知层在最下面、网络层在中间、应用层在最上面**——顺序不能乱
7. **NFC 是 RFID 的子集**——距离更短、支持双向通信
8. **LoRa 用免费频段、NB-IoT 用运营商基站**——部署方式完全不同
9. **大数据的 Value 是指"价值密度低"，不是价值高**——容易被误解
10. **Hadoop 的 HDFS 是"一次写入、多次读取"**——不适合频繁修改的文件
11. **Spark 比 MapReduce 快是因为内存计算**——不是算法更优，而是减少磁盘 I/O
12. **Map = 拆分处理，Reduce = 汇总结果**——方向不要搞反

1. 物联网三层架构分别是什么？每层的核心功能和大白话类比是什么？

<details><summary>参考答案</summary>

1. 物联网三层架构（自下而上）：

   - RFID：电子标签，无线射频识别，距离几厘米到几十米，多为单向一对多通信，用于仓储物流
   - NFC：RFID 的子集，距离 < 10cm，支持双向一对一通信，频率固定 13.56MHz，用于手机支付/公交卡

</details>

   - Variety（多样）：数据类型多样，结构化 + 半结构化 + 非结构化
   - Value（低价值密度）：注意不是"价值高"，而是"价值密度低"——海量数据中有价值的信息比例很低，需要"沙里淘金"
   - Veracity（真实性/准确性）：数据质量参差不齐，需要清洗验证
2. 数据预处理四步骤：清洗 → 集成 → 变换 → 规约（洗→合→变→缩）
   Hadoop 三大核心组件：
   - HDFS（分布式文件系统）：负责存储，大文件分块存到多台机器，每块存多副本（默认 3 份），"一次写入、多次读取"
   - MapReduce（分布式计算）：Map 拆分任务并行处理，Reduce 汇总结果
   - YARN（资源管理）：统一分配 CPU、内存给各个任务，相当于"项目经理"

</details>

### 一、人工智能（AI）考点补充

#### 考点 1：过拟合 vs 欠拟合

这是考试中极易混淆的概念，务必区分清楚。

| 概念 | 含义 | 表现 | 解决方法 |
|------|------|------|---------|
| **过拟合（Overfitting）** | 模型把训练数据"背"下来了，连噪声和异常点都记住了 | 训练集上表现极好，测试集上表现很差（泛化能力差） | 增加训练数据、正则化（L1/L2）、Dropout、早停法（Early Stopping）、降低模型复杂度 |
| **欠拟合（Underfitting）** | 模型太简单，连训练数据的基本规律都没学到 | 训练集和测试集上表现都很差 | 增加模型复杂度、增加特征、减少正则化、延长训练时间 |

**类比**：
- 过拟合 = 死记硬背的学生——只会做原题，题目稍微变一下就不会了
- 欠拟合 = 根本没听课的学生——原题和变式题都不会做

> 记忆口诀："过拟合 = 训练好测试差，欠拟合 = 两边都差"

#### 考点 2：偏差 vs 方差

| 概念 | 含义 | 关联 |
|------|------|------|
| **偏差（Bias）** | 模型预测值与真实值之间的差距，反映模型的"准不准" | 高偏差 → 欠拟合 |
| **方差（Variance）** | 模型在不同训练集上预测结果的波动程度，反映模型的"稳不稳" | 高方差 → 过拟合 |

**偏差-方差权衡（Bias-Variance Tradeoff）**：模型复杂度增加 → 偏差降低，方差升高。最优模型在偏差和方差之间取平衡点。

> 记忆：偏差 = 打靶打在靶心外面（偏了），方差 = 打靶子弹到处乱飞（不稳）

#### 考点 3：常见激活函数

| 激活函数 | 公式特点 | 优点 | 缺点 | 适用场景 |
|----------|---------|------|------|---------|
| **Sigmoid** | 输出 0~1，S 形曲线 | 平滑、可解释为概率 | 容易梯度消失，输出不以 0 为中心 | 二分类输出层 |
| **Tanh** | 输出 -1~1，S 形曲线 | 输出以 0 为中心 | 仍有梯度消失问题 | RNN 隐藏层 |
| **ReLU** | f(x) = max(0, x) | 计算简单，缓解梯度消失，收敛快 | 神经元可能"死亡"（负数输出恒为 0） | 最常用的隐藏层激活函数 |
| **Softmax** | 输出多分类概率分布（所有输出之和 = 1） | 适合多分类 | 计算量大 | 多分类输出层 |

> 记忆：Sigmoid/Tanh = S 形曲线但会梯度消失；ReLU = 大于 0 就原样输出，小于 0 就输出 0；Softmax = 多选一，谁大选谁

#### 考点 4：常见损失函数

| 损失函数 | 用途 | 一句话 |
|----------|------|--------|
| 均方误差（MSE） | 回归任务 | 预测值和真实值差值的平方求平均 |
| 交叉熵损失（Cross Entropy） | 分类任务 | 衡量两个概率分布之间的差异 |
| 二分类交叉熵（BCE） | 二分类 | 交叉熵的特例，只有两个类别 |

#### 考点 5：精确率 vs 召回率

| 指标 | 含义 | 公式 | 关注点 |
|------|------|------|--------|
| **精确率（Precision）** | 预测为正的样本中，真正为正的比例 | TP / (TP + FP) | "查得准不准" |
| **召回率（Recall）** | 真正的正样本中，被预测为正的比例 | TP / (TP + FN) | "查得全不全" |
| **F1 分数** | 精确率和召回率的调和平均值 | 2 × P × R / (P + R) | 综合衡量 |

**类比**：
- 精确率 = 警察抓了 10 个人，其中 8 个是真罪犯 → 精确率 = 80%
- 召回率 = 总共 20 个罪犯，警察只抓到了 8 个 → 召回率 = 40%

> 记忆：精确率 = 不冤枉好人，召回率 = 不放过坏人

#### 考点 6：生成式 AI 与判别式 AI

| 对比维度 | 生成式 AI（Generative） | 判别式 AI（Discriminative） |
|----------|------------------------|----------------------------|
| 核心思想 | 学习数据的联合分布 P(X, Y)，能"创造"新数据 | 学习决策边界 P(Y\|X)，只做"判断" |
| 能力 | 生成新内容（文本、图片、代码） | 分类、预测、识别 |
| 代表 | GPT、Stable Diffusion、GAN | 逻辑回归、SVM、决策树、CNN 分类器 |

> 考试注意：ChatGPT/GPT 是生成式 AI，不是判别式。这是近年热点，常出现在单选题中。

#### 考点 7：AI 热点应用（近年热点）

| 热点方向 | 典型应用 | 涉及技术 |
|----------|---------|---------|
| AIGC（AI 生成内容） | ChatGPT 对话、AI 绘画、AI 作曲 | 大语言模型（LLM）、扩散模型（Diffusion）、GAN |
| 自动驾驶 | 环境感知、路径规划、决策控制 | 计算机视觉、强化学习、传感器融合 |
| 智能客服 | 自动问答、意图识别、情绪分析 | NLP、语音识别、情感计算 |
| AI 医疗 | 医学影像辅助诊断、药物研发 | 图像分割、深度学习 |
| 具身智能 | 人形机器人、机械臂操作 | 强化学习、多模态感知 |

### 二、物联网（IoT）考点补充

#### 考点 1：边缘计算 vs 雾计算 vs 云计算

这是重要且易混淆的对比考点。

| 概念 | 计算位置 | 响应速度 | 适用场景 | 一句话 |
|------|---------|---------|---------|--------|
| **云计算（Cloud Computing）** | 数据中心（远端） | 慢（几百毫秒） | 大规模数据分析、模型训练 | 所有数据都送到"云端"处理 |
| **雾计算（Fog Computing）** | 网络边缘（局域网网关/路由器） | 中等 | 本地数据分析、过滤 | 在"局域网网关"处先处理一波 |
| **边缘计算（Edge Computing）** | 设备端/最近端 | 极快（毫秒级） | 实时控制、图像实时处理 | 数据直接在"设备旁边"就处理了 |

**类比**：一栋楼的摄像头
- 云计算 = 所有视频传到几千里外的数据中心分析 → 延迟大
- 雾计算 = 在楼里的局域网服务器先分析 → 快一些
- 边缘计算 = 摄像头自带芯片直接在本地分析 → 最快

> 记忆：数据越靠近数据源头处理，速度越快，延迟越低。三者不是取代关系，而是互相配合。

#### 考点 2：物联网安全

| 安全问题 | 说明 |
|---------|------|
| 设备认证 | 确保只有合法设备能接入网络 |
| 数据加密 | 传输中的数据（传感器数据）必须加密，防止窃听 |
| 固件安全 | 终端设备固件需防篡改、可远程升级 |
| 隐私保护 | 传感器采集的个人数据（位置、健康数据）需合规保护 |
| DDoS 攻击 | 大量 IoT 设备被劫持形成僵尸网络（如 Mirai 病毒） |

#### 考点 3：蓝牙 vs ZigBee vs WiFi 对比

| 协议 | 速率 | 功耗 | 距离 | 典型场景 |
|------|------|------|------|---------|
| 蓝牙（BLE） | 低 | 极低 | ~10m | 穿戴设备、耳机 |
| ZigBee | 低 | 极低 | ~100m（Mesh） | 智能家居传感器网络 |
| WiFi | 高 | 高 | ~100m | 视频传输、上网 |

#### 考点 4：物联网热点应用（近年热点）

| 热点 | 说明 |
|------|------|
| 智慧城市 | 智能交通、智慧路灯、环境监测，NB-IoT 为主力连接技术 |
| 工业物联网（IIoT） | 工厂设备预测性维护、数字孪生（Digital Twin） |
| 车联网（V2X） | 车与车、车与路的通信，依赖 5G + 边缘计算 |
| 智能穿戴 | 健康监测手环/手表，心率、血氧、睡眠监测 |
| 数字孪生 | 在虚拟世界中创建物理实体的实时数字镜像，用于仿真和优化 |

### 三、大数据考点补充

#### 考点 1：批处理 vs 流处理 vs 实时处理

| 处理类型 | 处理方式 | 延迟 | 代表框架 | 典型场景 |
|----------|---------|------|---------|---------|
| **批处理（Batch）** | 先攒一批数据，再统一处理 | 分钟~小时级 | Hadoop MapReduce | 日终报表、月度统计 |
| **流处理（Stream）** | 数据来一条处理一条（真正实时） | 毫秒~秒级 | Storm、Flink | 实时风控、股票交易 |
| **微批处理（Micro-batch）** | 小批次实时处理（折中方案） | 秒~分钟级 | Spark Streaming | 近实时日志分析 |

> 记忆：批处理 = 攒一筐再洗，流处理 = 来一个洗一个

#### 考点 2：Lambda 架构 vs Kappa 架构

| 架构 | 核心思想 | 优点 | 缺点 |
|------|---------|------|------|
| **Lambda 架构** | 同时维护"批处理层"（保证准确性）+ "速度层"（保证实时性）+ "服务层"（合并结果） | 兼顾准确性和实时性 | 需要维护两套代码，运维复杂 |
| **Kappa 架构** | 只用流处理，所有数据都当作流来处理，批处理是流处理的"回放" | 架构简单，一套代码 | 对消息队列依赖高，历史数据重算代价大 |

> 记忆：Lambda = 批+流两套，Kappa = 全部用流

#### 考点 3：数据仓库 vs 数据湖 vs 数据集市

| 概念 | 存什么 | 数据质量 | 用户 |
|------|--------|---------|------|
| **数据仓库（Data Warehouse）** | 经过清洗、结构化后的"干净"数据 | 高 | 业务分析师、决策层 |
| **数据湖（Data Lake）** | 所有原始数据（结构化 + 半结构化 + 非结构化） | 低（原始状态） | 数据科学家、算法工程师 |
| **数据集市（Data Mart）** | 数据仓库的子集，面向特定业务部门 | 高 | 某个业务部门 |

**类比**：
- 数据湖 = 一个大水库，什么水都往里放（原生态）
- 数据仓库 = 自来水厂，把水库的水净化处理后供人使用
- 数据集市 = 某个小区的直饮水站，只服务特定人群

#### 考点 4：OLTP vs OLAP

| 对比维度 | OLTP（联机事务处理） | OLAP（联机分析处理） |
|----------|---------------------|---------------------|
| 关注点 | 日常业务操作（增删改查） | 数据分析与决策支持 |
| 操作类型 | 大量短事务（INSERT/UPDATE/DELETE） | 大量复杂查询（SELECT + 聚合） |
| 数据特点 | 当前数据，实时更新 | 历史数据，定期更新 |
| 数据库类型 | 关系型数据库（MySQL、Oracle） | 数据仓库（Hive、ClickHouse） |
| 一句话 | "处理业务" | "做分析" |

> 记忆：OLTP = 收银台（一笔一笔交易处理），OLAP = 财报分析（汇总分析大量数据）

#### 考点 5：ETL vs ELT

| 对比维度 | ETL（传统） | ELT（现代） |
|----------|------------|------------|
| 顺序 | 先转换（Transform）→ 再加载（Load） | 先加载（Load）→ 再转换（Transform） |
| 转换位置 | 在中间 ETL 服务器完成 | 在目标数据仓库中完成 |
| 适用场景 | 数据量较小、计算资源有限的传统数仓 | 云数仓、大数据平台（靠数仓自身的算力） |
| 原始数据 | 不保留在数仓中 | 保留在数仓中（数据湖理念） |

> 记忆：ETL = 先洗再存，ELT = 先存再洗

#### 考点 6：CAP 定理与 NoSQL

分布式系统无法同时满足三个特性，只能三选二：

| 特性 | 含义 | 放弃后的问题 |
|------|------|------------|
| **C（一致性）** | 所有节点在同一时刻数据一致 | 可能读到旧数据 |
| **A（可用性）** | 系统始终能响应请求（不宕机） | 某些情况下可能无法访问 |
| **P（分区容错性）** | 网络出问题时系统仍能运行 | 分布式系统必须保证 P，所以只能在 C 和 A 之间选 |

> 考试关键：**分布式系统必须保证 P（分区容错性）**，所以实际选择是 CP 或 AP。

| 数据库类型 | CAP 选择 | 代表 |
|-----------|----------|------|
| 传统关系型数据库（单机） | CA（无 P） | MySQL、Oracle |
| MongoDB、HBase | CP | MongoDB、HBase |
| Cassandra、DynamoDB | AP | Cassandra、DynamoDB |

#### 考点 7：大数据热点应用（近年热点）

| 热点 | 说明 |
|------|------|
| 数据中台 | 统一数据服务，打破数据孤岛，提供"OneData"体系 |
| 用户画像（User Profile） | 基于用户行为数据打标签，支撑精准推荐 |
| 实时计算 | Flink 成为主流流计算引擎，用于实时风控、实时大屏 |
| 数据治理 | 数据质量、元数据管理、数据血缘、数据安全 |
| 隐私计算 | 联邦学习、多方安全计算，在保护隐私前提下利用数据 |

### 四、跨领域综合考点

#### 考点 1：AI + IoT = AIoT（人工智能物联网）

AIoT 是 AI 和 IoT 融合的产物，让物联网设备不仅"感知"，还能"思考"。

| 应用场景 | AI 角色 | IoT 角色 |
|----------|--------|---------|
| 智能音箱 | 语音识别 + NLU（理解你说的话） | 麦克风阵列 + 联网控制家电 |
| 智能摄像头 | 人脸识别 + 行为分析 | 图像传感器 + 联网报警 |
| 预测性维护 | 机器学习分析设备数据预测故障 | 振动/温度传感器采集数据 |

#### 考点 2：大数据 + AI = 数据驱动 AI

大数据是 AI 的"燃料"——AI 模型需要海量数据来训练，数据量越大，模型效果通常越好。

> 记忆：IoT 产生数据 → 大数据平台存储和处理数据 → AI 利用数据做智能决策，三者形成闭环。

#### 考点 3：典型考题样例

**单选题示例**：

1. 以下属于无监督学习的是（）。
   A. 垃圾邮件分类 B. 房价预测 C. 客户聚类分析 D. AlphaGo 下围棋
   > 答案：C。A 是分类（监督学习），B 是回归（监督学习），D 是强化学习。

2. 物联网三层架构中，负责数据采集的是（）。
   A. 应用层 B. 网络层 C. 感知层 D. 传输层
   > 答案：C。感知层 = 传感器采集数据，是最底层。

3. 大数据的 5V 特征中，指"价值密度低"的是（）。
   A. Volume B. Velocity C. Variety D. Value
   > 答案：D。注意 Value 不是"价值高"，而是"价值密度低"。

4. 以下哪种协议工作在授权频段、需要运营商 SIM 卡？（）
   A. LoRa B. ZigBee C. NB-IoT D. WiFi
   > 答案：C。NB-IoT 基于运营商基站，需要 SIM 卡。LoRa 用免费频段。

5. Hadoop 生态中，负责资源管理和任务调度的组件是（）。
   A. HDFS B. MapReduce C. YARN D. HBase
   > 答案：C。YARN = "项目经理"。

**判断题示例**：

1. 当前 ChatGPT 属于强人工智能（AGI）。（）
   > 答案：错误。ChatGPT 是弱人工智能（ANI），只会做特定任务。AGI 尚未实现。

2. NFC 是 RFID 的一个子集，支持双向通信。（）
   > 答案：正确。NFC 是 RFID 的高频子类，距离更短但支持双向通信。

3. 监督学习和无监督学习最本质的区别在于是否有标签数据。（）
   > 答案：正确。有标签 = 监督学习，无标签 = 无监督学习。

4. Spark 比 MapReduce 快是因为算法更优。（）
   > 答案：错误。Spark 快是因为基于内存计算，减少了磁盘 I/O，不是算法更优。

5. 大数据预处理中，数据清洗的目的是把数据压缩变小。（）
   > 答案：错误。数据清洗是处理缺失值、异常值、重复数据。把数据压缩变小是"数据规约"。

### 五、易混淆概念终极对比速查

#### AI 领域

| 易混淆组合 | 关键区别 |
|-----------|---------|
| 过拟合 vs 欠拟合 | 过拟合 = 训练好测试差（太复杂）；欠拟合 = 训练和测试都差（太简单） |
| 偏差 vs 方差 | 偏差 = 不准（瞄准偏了）；方差 = 不稳（子弹乱飞） |
| 分类 vs 回归 | 分类 = 离散类别（选择题）；回归 = 连续数值（填空题） |
| 聚类 vs 分类 | 聚类 = 无监督，没标签自己分；分类 = 有监督，有标签学完后分 |
| 精确率 vs 召回率 | 精确率 = 查得准不准；召回率 = 查得全不全 |
| GPT vs BERT | GPT = 单向 Decoder，生成；BERT = 双向 Encoder，理解 |
| 生成式 vs 判别式 | 生成式 = 能创造新内容；判别式 = 只做判断 |
| CNN vs RNN vs Transformer | CNN = 图像（卷积）；RNN = 序列（循环记忆）；Transformer = 序列（注意力） |
| Sigmoid vs Softmax | Sigmoid = 二分类输出；Softmax = 多分类输出 |
| 强化学习 vs 监督学习 | 强化学习 = 试错+奖励（无标签）；监督学习 = 有标签模仿 |

#### 物联网领域

| 易混淆组合 | 关键区别 |
|-----------|---------|
| 感知层 vs 网络层 vs 应用层 | 感知层 = 采数据（最下）；网络层 = 传数据（中间）；应用层 = 用数据（最上） |
| RFID vs NFC | RFID = 长距离，单向；NFC = 短距离（<10cm），双向，RFID 的子集 |
| LoRa vs NB-IoT | LoRa = 免费频段，自建网关；NB-IoT = 运营商基站，需要 SIM 卡 |
| MQTT vs CoAP | MQTT = 发布/订阅模式；CoAP = 类 HTTP 的 RESTful 风格，基于 UDP |
| ZigBee vs 蓝牙 | ZigBee = Mesh 自组网，智能家居；蓝牙 = 点对点，穿戴设备 |
| 边缘计算 vs 雾计算 | 边缘 = 设备端/最近；雾 = 局域网网关；云 = 数据中心 |
| 传感器 vs 执行器 | 传感器 = 感知（输入）；执行器 = 动作（输出，如马达、开关） |

#### 大数据领域

| 易混淆组合 | 关键区别 |
|-----------|---------|
| 5V 之 Value | 不是"价值高"，而是"价值密度低"，需要沙里淘金 |
| 批处理 vs 流处理 | 批处理 = 攒一筐再处理（慢）；流处理 = 来一条处理一条（快） |
| Lambda vs Kappa 架构 | Lambda = 批+流两套；Kappa = 全部用流一套 |
| 数据仓库 vs 数据湖 | 数据仓库 = 洗干净的结构化数据；数据湖 = 所有原始数据都存 |
| OLTP vs OLAP | OLTP = 处理业务交易（增删改）；OLAP = 做数据分析（查询聚合） |
| ETL vs ELT | ETL = 先转换再加载；ELT = 先加载再转换 |
| Hadoop vs Spark | Hadoop = 基于磁盘（慢）；Spark = 基于内存（快 10~100 倍） |
| HDFS vs MapReduce | HDFS = 存文件；MapReduce = 算数据 |
| 事实表 vs 维度表 | 事实表 = 存数据（金额、次数）；维度表 = 存描述（时间、地点、产品） |
| 星型模型 vs 雪花模型 | 星型 = 维度表不拆分；雪花 = 维度表再拆分（规范化） |
| CAP 之 CP vs AP | 分布式系统必须保证 P，数据库在 C 和 A 之间取舍 |
