## 知识点 30：计算机系统概述

### 30.1 冯·诺依曼体系结构

**大白话**：冯·诺依曼结构就是"计算机的工作方式说明书"——程序和数据都存内存里，CPU 一条条取出来执行。

**五大部件**：

| 部件 | 功能 | 类比 |
|------|------|------|
| 运算器（ALU） | 做算术和逻辑运算 | 计算器 |
| 控制器（CU） | 指挥各部件协调工作 | 乐队指挥 |
| 存储器 | 存程序和数据 | 仓库 |
| 输入设备 | 从外界获取数据 | 键盘、鼠标 |
| 输出设备 | 把结果展示出来 | 显示器、打印机 |

**核心思想**：**存储程序**——程序和数据以同等地位存在存储器中，按地址访问、顺序执行。

**大白话类比**：冯·诺依曼结构就像"厨房做菜"——菜谱（程序）和食材（数据）都放在冰箱（存储器）里，厨师（CPU）从冰箱里取出菜谱和食材，按步骤做菜。菜谱和食材在冰箱里地位平等，都是"存着的东西"，不会因为"这是菜谱"就特殊对待。

**"存储程序"思想为什么重要？** 在冯·诺依曼之前，程序是"硬连线"的——换个程序就得重新接线。有了存储程序，换个程序就是换一段存入内存的数据，计算机从此变得"通用"了。

### 30.2 计算机层次结构

```
应用程序层（用户直接用的）
    ↓ 翻译
高级语言层（C/Java/Python）
    ↓ 编译
汇编语言层（助记符）
    ↓ 汇编
操作系统层（管理软硬件）
    ↓ 系统调用
传统机器层（指令集，机器语言）
    ↓ 微程序解释
微程序机器层（硬件直接执行）
```

> 下层是上层的基础，上层是下层的抽象。每一层只关心自己的事。

**大白话类比**：层次结构就像"寄快递"——你只关心"把包裹交给快递员"，不用管快递员怎么分拣、卡车怎么运、飞机怎么飞。每一层帮你屏蔽了下层的细节。

### 30.3 性能指标

| 指标 | 公式 | 含义 |
|------|------|------|
| 主频 f | 1/T（T为时钟周期） | CPU 每秒振荡多少次 |
| CPI | 总时钟周期数/总指令数 | 每条指令平均需要几个时钟周期 |
| CPU 执行时间 | **IC × CPI × T** | 程序的 CPU 时间 |
| MIPS | 指令条数/(执行时间×10⁶) = f/(CPI×10⁶) | 每秒百万条指令 |
| MFLOPS | 浮点运算次数/(执行时间×10⁶) | 每秒百万次浮点运算 |

> **CPU 执行时间 = IC × CPI × T** 是核心公式，哪里都可能出计算题。

**大白话类比**：性能指标就像"搬砖"——
- **主频** = 你每分钟能弯腰多少次（频率越高，干活越快）
- **CPI** = 搬一块砖平均需要弯腰几次（CPI 越低越好，CPI=1 就是一次弯腰搬一块）
- **CPU 执行时间** = 搬完所有砖需要的总时间 = 砖的数量 × 每块砖弯腰次数 × 每次弯腰时间
- **MIPS** = 每秒能搬多少块砖（百万块为单位）

**CPU 时间计算例题**：
- 已知：程序有 1000 条指令，CPI=2，主频 1GHz（T=1ns）
- CPU 时间 = 1000 × 2 × 1ns = **2000ns = 2微秒**

### 30.4 阿姆达尔定律

**问题**：如果我把程序的一部分加速了，整体能快多少？

**公式**：S = 1 / [(1-f) + f/k]

- f = 可改进部分占总时间的比例
- k = 改进部分的加速倍数
- S = 整体加速比

**例题**：某程序 80% 可以并行化，用 4 核 CPU，整体加速比是多少？
- f = 0.8, k = 4
- S = 1 / [(1-0.8) + 0.8/4] = 1 / [0.2 + 0.2] = **2.5 倍**

> **易错点**：即使把 80% 的部分加速到"无限快"，整体加速比也不过 1/(1-0.8) = **5 倍**。改进受限于不可改进部分！

## 知识点 31：数据的机器级表示和运算

### 31.1 进制转换

**二进制 ↔ 八进制**：每 3 位二进制 = 1 位八进制  
**二进制 ↔ 十六进制**：每 4 位二进制 = 1 位十六进制

**十进制转二进制**：整数部分除 2 取余（从下往上读），小数部分乘 2 取整（从上往下读）

#### 进制转换详细计算例题

**例 1：十进制整数 → 二进制（除 2 取余法）**

把十进制 57 转二进制：

```
57 ÷ 2 = 28 ... 余 1  ← 最低位
28 ÷ 2 = 14 ... 余 0
14 ÷ 2 = 7  ... 余 0
7 ÷ 2 = 3  ... 余 1
3 ÷ 2 = 1  ... 余 1
1 ÷ 2 = 0  ... 余 1  ← 最高位
```

**从下往上读**：57₁₀ = **111001**₂

验算：1×32 + 1×16 + 1×8 + 0×4 + 0×2 + 1×1 = 32+16+8+1 = 57 ✓

**例 2：十进制小数 → 二进制（乘 2 取整法）**

把十进制 0.625 转二进制：

```
0.625 × 2 = 1.25  → 取整 1  ← 小数点后第一位
0.25  × 2 = 0.5   → 取整 0
0.5   × 2 = 1.0   → 取整 1  ← 最后一位
```

**从上往下读**：0.625₁₀ = **0.101**₂

验算：1×0.5 + 0×0.25 + 1×0.125 = 0.5+0.125 = 0.625 ✓

**例 3：十进制带小数 → 二进制**

把 57.625 转二进制：整数部分 57→111001，小数部分 0.625→0.101
结果：57.625₁₀ = **111001.101**₂

**例 4：二进制 → 十六进制（每 4 位一组）**

把 1101 1010 0011 ₂ 转十六进制：

```
1101 1010 0011
  ↓    ↓    ↓
  D    A    3
```

结果：**0xDA3**（或写作 DA3H）

**例 5：十六进制 → 二进制**

把 0x3F7 转二进制：

```
3  → 0011
F  → 1111
7  → 0111
```

结果：**0011 1111 0111**₂

**进制转换口诀**：
- 十进制转 N 进制：整数除 N 取余（倒读），小数乘 N 取整（顺读）
- N 进制转十进制：按权展开相加
- 二进制 ↔ 八进制：3 位一组
- 二进制 ↔ 十六进制：4 位一组
- 八进制 ↔ 十六进制：先转二进制做中转

**例 6：补码计算例题**

已知 8 位补码，求十进制值：

(1) **[X]补 = 1001 0110**，求 X 的真值

```
符号位=1，是负数
补码转原码：补码末位-1取反（或先取反+1）
取反（符号位除外）：1001 0110 → 1110 1001
+1：1110 1001 + 1 = 1110 1010
原码 = 1110 1010 = -(64+32+8+2) = -106
```

所以 X = **-106**

(2) **[X]补 = 0110 1001**，求 X 的真值

```
符号位=0，是正数，补码=原码
0110 1001 = 64+32+8+1 = 105
```

所以 X = **105**

(3) **计算 -37 + 22 的补码运算**（8 位）

```
-37 的补码：
  37 = 0010 0101
  取反：1101 1010
  +1：1101 1011

22 的补码：
  22 = 0001 0110

相加：
  1101 1011
+ 0001 0110
-----------
  1111 0001

符号位=1，是负数
取反+1：0000 1110 + 1 = 0000 1111 = 15
结果 = -15
```

验算：-37 + 22 = -15 ✓

(4) **判断溢出：-100 + (-50)**（8 位补码）

```
-100 的补码：1001 1100
-50 的补码： 1100 1110

相加：
  1001 1100
+ 1100 1110
-----------
1 0110 1010  ← 最高位进位=1，次高位进位=0

两个负数相加，结果符号位却变成了 0（正数）
→ 负溢！
```

原因：-100 + (-50) = -150，超出 8 位补码的表示范围（-128~+127）。

### 31.2 原码、反码、补码、移码

**类比**：就像钟表——补码就是把"逆时针转"变成"顺时针转"，用加法代替减法。

**大白话类比**：把时钟拨回 3 小时（-3），和往前拨 9 小时（+9），在 12 小时钟表上的效果是一样的。补码就是这个道理——用"正向加"代替"反向减"，硬件只需要加法器不需要减法器。

| 编码 | 正数 | 负数 | 8 位范围 | 零的表示 |
|------|------|------|---------|---------|
| 原码 | 符号位 0 + 数值 | 符号位 1 + 数值 | -127~+127 | +0=00000000, -0=10000000 |
| 反码 | 同原码 | 符号位不变，其余取反 | -127~+127 | +0=00000000, -0=11111111 |
| **补码** | 同原码 | **反码 + 1** | **-128~+127** | **只有 00000000** |
| 移码 | 补码符号位取反 | 补码符号位取反 | -128~+127 | 10000000 |

> **核心记忆**：补码比原码多一个负数（-128），且零只有一种表示——这是补码最大的优势。

### 31.3 补码溢出判断

**三种方法**：

| 方法 | 判断规则 | 口诀 |
|------|---------|------|
| 单符号位 | 两正数相加得负数→正溢；两负数相加得正数→负溢 | 正正得负溢，负负得正溢 |
| 双符号位（变形补码） | 00=正常，01=正溢，10=负溢 | 两位相同没溢出，不同则溢出 |
| 进位判断 | 最高位进位 ≠ 次高位进位 → 溢出 | 两个进位不一样就溢了 |

### 31.4 IEEE754 浮点数

**格式**：N = (-1)^S × 1.M × 2^(E-bias)

**大白话类比**：浮点数就是"科学计数法的计算机版"——十进制科学计数法把 12345 写成 1.2345×10⁴，IEEE754 把二进制数写成 1.XXX×2^E。S 是正负号，M 是有效数字，E 是指数。这样不管很大（如 10³⁸）还是很小（如 10⁻³⁸）的数，都能用同样长的二进制位表示。

| 类型 | 符号 S | 阶码 E | 尾数 M | 偏移量 bias |
|------|--------|--------|--------|------------|
| 单精度 float | 1 bit | **8 bit** | **23 bit** | **127** |
| 双精度 double | 1 bit | **11 bit** | **52 bit** | **1023** |

> 尾数隐含最高位 1（规格化后），实际尾数是 1.M。

**浮点加减运算步骤**：
1. **对阶**：小阶向大阶看齐（尾数右移，阶码+1）
2. **尾数相加/减**
3. **规格化**：确保尾数 1.xxx 形式
4. **舍入**：0 舍 1 入法、恒置 1 法
5. **判溢出**：阶码超出范围则溢出

> **易错点**：对阶时可能出现"对阶丢失"——尾数右移时低位丢失。

### 31.5 数据校验码

| 校验码 | 能力 | 原理 |
|--------|------|------|
| 奇偶校验 | 检错（奇数位错） | 加一位使 1 的个数为奇/偶 |
| **海明码** | 检错+**纠错 1 位** | 多组奇偶校验，出错位=各组校验位组合 |
| CRC | 检错（极强） | 模 2 除法，余数=校验码 |

### 31.6 常见编码

- **ASCII 码**：`'A'`=65(0x41), `'a'`=97(0x61), `'0'`=48(0x30)
- **汉字编码**：输入码（拼音/五笔）→ 国标码（GB2312）→ 机内码（存储用）

## 知识点 32：多级层次的存储系统

### 32.1 存储层次结构

```
寄存器 → Cache(L1/L2/L3) → 主存(DRAM) → 辅存(SSD/HDD)
← 速度越快，容量越小，价格越贵 →
```

> 全部数据在辅存，常用数据在内存，最常用数据在 Cache，正在用的在寄存器。

**大白话类比**：存储层次就像"你工作时找东西"——
- **寄存器** = 你手里正拿着的东西（0 延迟，但手只能拿几样）
- **Cache** = 你桌上的东西（伸手就拿，容量有限）
- **主存（内存）** = 你身后的书架（站起来走两步，容量大一些）
- **辅存（硬盘）** = 公司仓库（要走很远，但容量巨大）

你常用的东西放桌上，偶尔用的放书架，很少用的存仓库。这就是"局部性原理"——程序也是按这个规律访问数据的。

**局部性原理**：
- **时间局部性**：刚用过的东西，可能马上又要用（比如循环变量）
- **空间局部性**：用了一个东西，它旁边的可能也要用（比如数组遍历）

### 32.2 SRAM vs DRAM

| 对比 | SRAM（静态） | DRAM（动态） |
|------|------------|------------|
| 存储元 | 六管 MOS 触发器 | 电容 + 单管 |
| 速度 | 快 | 慢 |
| 集成度 | 低 | 高 |
| 功耗 | 大 | 小 |
| 刷新 | 不需要 | **需要刷新** |
| 价格 | 贵 | 便宜 |
| 用途 | **Cache** | **主存** |

> **DRAM 为什么需要刷新？** 电容会漏电，必须定期"补电"（刷新）来保持数据。

**大白话类比**：DRAM 的电容就像"漏水的杯子"——即使放着不动，里面的水（电荷）也会慢慢漏掉。所以必须定期往杯子里加水（刷新），不然数据就丢了。SRAM 用的触发器就像"带盖子的密封杯"，不漏水，不需要刷新，但做起来更复杂更贵。

### 32.3 DRAM 刷新方式

| 方式 | 做法 | 优缺点 |
|------|------|--------|
| 集中刷新 | 一段时间内集中刷新所有行 | 有"死时间"（刷新时不能读写） |
| 分散刷新 | 每个读写周期后刷新一行 | 无死时间，但刷新太频繁 |
| **异步刷新** | 分散在刷新周期内均匀刷新 | **折中方案，最常用** |

### 32.4 Cache 与主存的映射方式

| 映射方式 | 规则 | 优点 | 缺点 |
|---------|------|------|------|
| **直接映射** | 每个主存块 → 固定 Cache 行 | 简单，成本低 | 冲突多 |
| **全相联映射** | 任意主存块 → 任意 Cache 行 | 冲突少 | 硬件复杂，比较器多 |
| **组相联映射** | 先分组，组内全相联 | **折中方案，最常用** | |

**大白话类比**：Cache 映射就像"办公室工位分配"——
- **直接映射** = 每个人有固定工位。张三只能坐 3 号位，即使 3 号位被占了也只能等，别的空位不能用。简单但冲突多。
- **全相联映射** = 自由工位，来了随便坐哪都行。灵活但需要前台系统（硬件比较器）记录每个人坐哪，成本高。
- **组相联映射** = 分部门，每个部门有 4 个工位。张三在技术部，技术部 4 个工位里随便坐。折中方案——比固定工位灵活，比自由工位简单。

### 32.5 Cache 替换算法

| 算法 | 规则 | 特点 |
|------|------|------|
| 随机（RAND） | 随便踢一个 | 简单，效果不稳定 |
| FIFO | 踢最早进来的 | 简单，但可能踢掉常用块 |
| **LRU** | 踢最久没用的 | 效果好，需要硬件记录访问顺序 |
| LFU | 踢用得最少的 | 考虑频率，但新块可能被误踢 |

**大白话类比**：Cache 满了要踢人，就像"冰箱满了要扔掉一些东西"——
- **随机** = 闭眼随便扔一个（简单粗暴）
- **FIFO** = 扔最早放进来的（先买的先扔，可能会把常用的鸡蛋扔掉）
- **LRU** = 扔最久没动过的（最合理，但需要记住每样东西多久没动）
- **LFU** = 扔用得次数最少的（新买的调料只用过一次就被扔了，也未必合理）

### 32.6 Cache 写策略

| 策略 | 写命中时 | 写不命中时 |
|------|---------|-----------|
| **写直达**（Write Through） | 同时写 Cache 和主存 | 直接写主存（非写分配） |
| **写回**（Write Back） | 只写 Cache，标记脏位 | 先把主存块调入 Cache 再写（写分配） |

> 常用组合：**写直达 + 非写分配**（简单）或 **写回 + 写分配**（性能好）

### 32.7 Cache 性能计算

**平均访问时间**：ta = **h × tc + (1-h) × tm**

- h = 命中率（通常 > 90%）
- tc = Cache 访问时间
- tm = 主存访问时间

**例题**：h=0.95, tc=1ns, tm=100ns，求平均访问时间。
- ta = 0.95 × 1 + 0.05 × 100 = 0.95 + 5 = **5.95ns**

#### Cache 命中率计算题专项训练

**题 1：基础命中率计算**

某计算机 Cache 命中率 h=0.98，tc=2ns，tm=80ns。求：
(1) 平均访问时间 ta
(2) 使用 Cache 后的加速比（相对于全部访问主存）

**解答**：
(1) ta = h × tc + (1-h) × tm = 0.98×2 + 0.02×80 = 1.96 + 1.6 = **3.56ns**

(2) 不用 Cache 时每次访问都是 tm=80ns
加速比 = 80/3.56 ≈ **22.47 倍**

**题 2：命中率变化对性能的影响**

tc=1ns，tm=100ns。分别计算 h=0.90、h=0.95、h=0.99 时的平均访问时间，并分析命中率每提升 1% 带来的收益。

**解答**：

| 命中率 h | ta = h×1 + (1-h)×100 | 相比上一档提升 |
|---------|----------------------|--------------|
| 0.90 | 0.9 + 10 = **10.9ns** | — |
| 0.95 | 0.95 + 5 = **5.95ns** | 快 45.4% |
| 0.99 | 0.99 + 1 = **1.99ns** | 快 66.6% |

> 结论：命中率从 90% 提到 99%，性能提升约 **5.5 倍**。失效率（1-h）每降低一半，ta 中未命中部分就减半——**失效率才是关键指标**。

**题 3：tc 和 tm 变化的影响**

某系统 Cache 命中率 h=0.95。

场景 A：tc=2ns, tm=50ns
场景 B：tc=2ns, tm=200ns（主存慢了 4 倍）
场景 C：tc=5ns, tm=50ns（Cache 慢了 2.5 倍）

分别计算三种场景的 ta，并分析哪个参数变化对性能影响更大。

**解答**：

场景 A：ta = 0.95×2 + 0.05×50 = 1.9 + 2.5 = **4.4ns**

场景 B：ta = 0.95×2 + 0.05×200 = 1.9 + 10 = **11.9ns**（相比 A 慢了 2.7 倍）

场景 C：ta = 0.95×5 + 0.05×50 = 4.75 + 2.5 = **7.25ns**（相比 A 慢了 1.65 倍）

> 结论：当命中率很高时，**Cache 访问时间 tc 的变化对性能影响更大**（因为命中部分占主导）；主存时间 tm 虽大但只有不命中时才会用到。但 tm 越大，失效率的影响越显著。

**题 4：多级 Cache 平均访问时间**

某系统有 L1 Cache 和 L2 Cache：
- L1 命中率 h1 = 0.90，t1 = 1ns
- L2 命中率 h2 = 0.95（L1 不命中时，L2 的命中率），t2 = 10ns
- 主存 tm = 100ns

**大白话**：L1 没命中 → 去 L2 找 → L2 也没命中 → 去主存找。一级一级往下找。

**公式**：ta = h1×t1 + (1-h1)×h2×(t1+t2) + (1-h1)×(1-h2)×(t1+t2+tm)

> 注意：L1 不命中后，要先花 t1 时间发现不命中，再花 t2 时间访问 L2。

**解答**：

ta = 0.90×1 + 0.10×0.95×(1+10) + 0.10×0.05×(1+10+100)
   = 0.9 + 0.095×11 + 0.005×111
   = 0.9 + 1.045 + 0.555
   = **2.5ns**

> 如果不分层，全部用主存：每次 100ns。两级 Cache 把访问时间压缩到了 2.5ns，加速约 40 倍。

**题 5：综合——给定 ta 反推命中率**

已知 tc=1ns, tm=100ns，要求平均访问时间不超过 2ns，Cache 命中率至少需要多少？

**解答**：

ta = h×1 + (1-h)×100 ≤ 2
h + 100 - 100h ≤ 2
100 - 99h ≤ 2
99h ≥ 98
h ≥ 98/99 ≈ **0.9899**

> 命中率至少需要 **98.99%**。可见 Cache 命中率要求极其苛刻。

### 32.8 TLB（快表）

> TLB 是"页表项的 Cache"——把最近用过的页表项缓存起来，减少访存次数。

**带 TLB 的地址变换**：先查 TLB（命中→快；不命中→查页表→更新 TLB）

## 知识点 33：指令系统

### 33.1 指令格式

> 指令 = **操作码**（OP，告诉 CPU 做什么）+ **地址码**（A，告诉 CPU 操作数在哪）

| 类型 | 地址数 | 说明 |
|------|--------|------|
| 三地址指令 | OP A1 A2 A3 | A1←A2 OP A3 |
| 二地址指令 | OP A1 A2 | A1←A1 OP A2 |
| 单地址指令 | OP A | ACC←ACC OP A（隐含累加器） |
| 零地址指令 | OP | 无操作数（如停机、空操作） |

### 33.2 寻址方式

| 寻址方式 | 操作数在哪 | 访存次数 | 特点 |
|---------|-----------|---------|------|
| **立即寻址** | 指令中直接给出 | 0 | 快，但操作数固定 |
| **直接寻址** | 指令中给地址 | 1 | 简单 |
| **寄存器寻址** | 寄存器中 | 0 | 最快 |
| **间接寻址** | 寄存器的内容指向地址 | 2 | 灵活，但慢 |
| **相对寻址** | EA = PC + 偏移量 | 1 | 用于转移指令 |
| **基址寻址** | EA = 基址寄存器 + 偏移 | 1 | 用于程序重定位 |
| **变址寻址** | EA = 变址寄存器 + 形式地址 | 1 | 用于数组访问 |
| **堆栈寻址** | 栈顶（SP 指向） | 0 | 隐含地址 |

> **基址 vs 变址**：基址寄存器内容不变（面向系统），变址寄存器内容可变（面向用户，如数组下标）。

### 33.3 CISC vs RISC

| 对比 | CISC（复杂指令集） | RISC（精简指令集） |
|------|-------------------|-------------------|
| 指令数量 | **多** | **少** |
| 指令长度 | **可变长** | **定长** |
| 寻址方式 | 多 | 少 |
| 寄存器数量 | 少 | **多** |
| 访存方式 | 指令可直接访存 | **只有 Load/Store 访存** |
| 流水线 | 难实现 | **易实现** |
| 代表 | **x86**（Intel/AMD） | **ARM**、MIPS、RISC-V |

> 考试重点：**CISC 指令可变长、x86；RISC 定长、Load/Store 结构、ARM。**

**大白话类比**：CISC 和 RISC 就像"两种餐厅"——
- **CISC（x86）** = 大酒楼，菜单上什么菜都有（指令多），每道菜做法不一（指令长度可变），厨师啥都会做但上菜慢（流水线难实现）
- **RISC（ARM）** = 快餐店，菜单精简（指令少），所有菜做法统一（指令定长），流程标准化出餐快（流水线易实现）

这就是为什么手机（用 ARM）比电脑（用 x86）省电——RISC 指令简单，硬件做起来也简单省电。

## 知识点 34：中央处理器（CPU）

### 34.1 CPU 组成

| 部件 | 组成 | 功能 |
|------|------|------|
| 运算器 | ALU + 通用寄存器组 | 算术逻辑运算 |
| 控制器 | CU + **PC**（程序计数器）+ **IR**（指令寄存器）+ **MAR**（地址寄存器）+ **MDR**（数据寄存器）+ PSW（状态字） | 取指令、分析指令、发控制信号 |

> **PC** 存放下一条指令的地址，**IR** 存放当前正在执行的指令。

### 34.2 指令周期

```
取指周期 → 间址周期 → 执行周期 → 中断周期
```

| 时间单位 | 关系 | 说明 |
|---------|------|------|
| 时钟周期 | 最小单位 | CPU 主频的倒数 |
| 机器周期 | 多个时钟周期 | 完成一次总线操作 |
| 指令周期 | 多个机器周期 | 执行一条指令的全过程 |

> **时钟周期 < 机器周期 < 指令周期**

### 34.3 控制器实现

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **硬布线控制器** | 组合逻辑电路直接产生控制信号 | **速度快** | 设计复杂，不易修改 |
| **微程序控制器** | 微指令存入控制存储器（CM），顺序执行 | **灵活**，易修改 | 速度慢（多一次 CM 访问） |

**微程序相关概念**：
- 微命令 → 微操作 → 微指令 → 微程序 → 机器指令
- 一条机器指令 = 一个微程序 = 一段微指令序列

### 34.4 流水线（Pipeline）

**类比**：洗车流水线——一辆车冲水时，前一辆在擦干，后一辆在打泡沫，多条工序同时进行。

**五级流水**：IF（取指）→ ID（译码）→ EX（执行）→ MEM（访存）→ WB（写回）

### 34.5 流水线三种相关（阻塞）

| 相关类型 | 原因 | 解决方法 |
|---------|------|---------|
| **结构相关** | 多条指令争用同一个硬件资源 | 增加资源 |
| **数据相关** | 指令间有数据依赖（RAW 最典型） | 数据旁路/转发（Forwarding） |
| **控制相关** | 分支指令使流水线预取的指令可能无效 | 分支预测、延迟槽 |

> **RAW（读后写）**：指令 A 写结果 → 指令 B 读结果，B 必须等 A 写完。这是最常见的流水线阻塞。

**大白话类比**：流水线三种阻塞就像"流水线食堂"——
- **结构相关** = 只有一个微波炉，两个人同时要用。解决办法：多买一个微波炉（增加硬件资源）。
- **数据相关（RAW）** = 厨师 A 炒完菜，厨师 B 才能装盘。B 必须等 A 炒完。解决办法：A 炒完直接递过去，不用等摆上桌（数据旁路/转发 Forwarding）。
- **控制相关** = 服务员还不知道客人要吃什么（分支还没确定），厨房已经开始做了。如果猜错了，做好的菜全倒掉。解决办法：培训服务员提前猜（分支预测），或者趁等待时间先做点别的（延迟槽）。

### 34.6 流水线性能计算

| 指标 | 公式 | 说明 |
|------|------|------|
| 吞吐率 p | n / Tk | 单位时间完成的任务数 |
| 加速比 S | T顺序 / T流水 | 不用流水线 vs 用流水线的时间比 |
| 效率 E | S / k | k 为流水线段数 |

**例题**：k=5 段流水线，执行 n=100 条指令，每段 1ns。
- 顺序执行：100 × 5 = 500ns
- 流水线：5 + (100-1) = 104ns（建立时间 + 剩余指令）
- 加速比：500/104 ≈ **4.81**
- 效率：4.81/5 ≈ **96.2%**

#### 流水线加速比计算题专项训练

**通用公式回顾**：
- 顺序执行时间：T顺 = n × k × Δt（n 条指令，k 段，每段 Δt）
- 流水线执行时间：T流 = k×Δt + (n-1)×Δt = (k + n - 1)×Δt
- 加速比：S = T顺/T流 = (n×k) / (k+n-1)

**题 1：不同段数的流水线**

某流水线每段 Δt=1ns，执行 n=200 条指令。分别计算 k=3、k=5、k=8 时的加速比和效率。

**解答**：

| 段数 k | T顺 = n×k | T流 = k+n-1 | 加速比 S | 效率 E=S/k |
|--------|-----------|-------------|----------|-----------|
| 3 | 200×3=600 | 3+199=202 | 600/202≈**2.97** | 2.97/3≈**99.0%** |
| 5 | 200×5=1000 | 5+199=204 | 1000/204≈**4.90** | 4.90/5≈**98.0%** |
| 8 | 200×8=1600 | 8+199=207 | 1600/207≈**7.73** | 7.73/8≈**96.6%** |

> 结论：段数越多，加速比越接近段数 k（当 n 很大时，S ≈ k）。但效率会略微下降（段数越多，建立时间占比越大）。

**题 2：不同指令数**

某 6 段流水线，每段 Δt=2ns。分别计算 n=10、n=100、n=1000 时的加速比。

**解答**：

| 指令数 n | T顺(×Δt) | T流(×Δt) | 加速比 S |
|----------|-----------|-----------|----------|
| 10 | 10×6=60 | 6+9=15 | 60/15=**4.00** |
| 100 | 100×6=600 | 6+99=105 | 600/105≈**5.71** |
| 1000 | 1000×6=6000 | 6+999=1005 | 6000/1005≈**5.97** |

> 结论：**指令数越多，加速比越接近段数 k=6**。因为建立时间（k-1 段）的影响被摊薄了。指令数太少时，流水线优势不明显（n=10 时加速比只有 4）。

**题 3：含阻塞的流水线**

某 5 段流水线，每段 Δt=1ns，执行 100 条指令。其中有 10 条指令因数据相关，每条需要额外阻塞 2 个时钟周期。

**解答**：

无阻塞时的流水线时间：T流 = 5 + 99 = 104ns

10 条指令各阻塞 2 周期，共增加 20 个时钟周期。

含阻塞的流水线时间：T流_阻塞 = 104 + 20 = **124ns**

顺序执行时间：T顺 = 100×5 = 500ns

含阻塞的加速比：S = 500/124 ≈ **4.03**

无阻塞的加速比：S = 500/104 ≈ 4.81

> 10% 的指令阻塞 2 周期，加速比从 4.81 降到 4.03，**性能损失约 16%**。可见流水线阻塞对性能影响很大。

**题 4：多周期段的流水线（瓶颈段）**

某流水线分 4 段：IF=1ns, ID=2ns, EX=3ns, WB=1ns。各段时间不等。执行 50 条指令。

**关键**：流水线时钟周期必须取**最长段的时间**，即 Δt = max(1,2,3,1) = **3ns**。

**解答**：

T顺 = 50 × (1+2+3+1) = 50×7 = 350ns

T流 = 3×4 + (50-1)×3 = 12 + 147 = 159ns

加速比 S = 350/159 ≈ **2.20**

> 流水线时钟周期由最慢段决定——这就是"瓶颈段"。优化瓶颈段（如将 3ns 段拆成两个 1.5ns 段）能大幅提升流水线性能。

**题 5：超流水线——段内还有细分**

某 CPU 主频 2GHz（T=0.5ns），经典五级流水线（IF/ID/EX/MEM/WB）。执行 1000 条指令。

**解答**：

T顺 = 1000×5×0.5 = 2500ns

T流 = (5+999)×0.5 = 1004×0.5 = 502ns

加速比 S = 2500/502 ≈ **4.98**

吞吐率 = 1000/502 ≈ **1.99 条/ns** ≈ **1990 MIPS**

> 当 n 很大时，加速比接近段数 k=5，吞吐率接近 1/Δt = 2 条/ns。

## 知识点 35：总线与输入输出系统

### 35.1 总线分类

| 总线类型 | 位置 | 包含 |
|---------|------|------|
| 片内总线 | CPU 内部 | 寄存器之间、ALU 之间 |
| 系统总线 | 主板 | **数据总线 + 地址总线 + 控制总线** |
| 通信总线 | 外部设备 | USB、PCIe、SATA |

### 35.2 总线仲裁（谁先用总线？）

| 方式 | 做法 | 特点 |
|------|------|------|
| **链式查询** | 优先级信号链式传递 | 简单，离仲裁器近的优先，但故障敏感 |
| **计数器定时查询** | 计数器轮询 | 灵活，可改优先级，但线多 |
| **独立请求** | 每个设备独立请求线 | **最快**，但线最多 |

**大白话类比**：总线仲裁就像"会议室发言"——
- **链式查询** = 坐成一排，话筒从前往后传，谁有话说就接话筒。离主持人近的人有优先权。但如果中间有人打瞌睡（故障），后面的人都拿不到话筒。
- **计数器定时查询** = 主持人喊号"1 号有话吗？2 号有话吗？"轮流问。公平但慢（要一个个问）。
- **独立请求** = 每个人面前有个按钮，谁按了主持人立刻知道。最快，但每人一根线，布线成本高。

### 35.3 四种 I/O 控制方式

| 方式 | CPU 参与度 | 适用场景 | 数据传送 |
|--------|----------|---------|---------|
| **程序查询** | CPU 全权负责 | 简单嵌入式 | CPU 读状态→CPU 传数据 |
| **程序中断** | CPU 部分参与 | 键盘、鼠标 | 设备就绪→中断 CPU→CPU 传数据 |
| **DMA** | CPU 只参与起止 | 磁盘、网卡 | **DMA 控制器直接传，不经过 CPU** |
| **通道** | CPU 几乎不参与 | 大型主机 | 通道执行通道程序，独立传送 |

> **DMA 与中断的核心区别**：DMA 传送数据时 **CPU 不参与**，中断传送数据时 **CPU 要参与**。

#### 中断 vs DMA 详细对比表

| 对比维度 | 程序中断方式 | DMA 方式 |
|---------|------------|---------|
| **数据传送路径** | 外设 → CPU 寄存器 → 主存（CPU 中转） | 外设 → 主存（DMA 控制器直接控制，不经过 CPU） |
| **CPU 参与程度** | 每次数据传送 CPU 都要介入 | 只在传送开始和结束时各发一次中断 |
| **中断发生时机** | 每个数据传送都产生中断 | 整块数据传送完成后才产生一次中断 |
| **传送单位** | 通常以字/字节为单位 | 以数据块为单位（批量传送） |
| **适用场景** | 低速设备（键盘、鼠标、串口） | 高速设备（磁盘、网卡、显卡） |
| **传送速度** | 慢（CPU 每次要保存/恢复现场） | 快（硬件直接控制，不需 CPU 干预） |
| **对 CPU 的影响** | 占用 CPU 时间，频繁打断 CPU | 几乎不占用 CPU（CPU 可以继续执行其他程序） |
| **硬件复杂度** | 简单（只需中断控制器） | 复杂（需要 DMA 控制器） |
| **总线控制权** | 始终由 CPU 控制 | 传送时 DMA 控制器获得总线控制权 |
| **传送过程** | 中断响应→保存现场→CPU 执行传送→恢复现场→返回 | 预处理（CPU 设置）→ DMA 传送（独立）→ 后处理（发中断） |

**大白话类比**：
- **程序中断** = 老板（CPU）每收到一份文件就亲自送去档案室。每送一份工作就打断一次。
- **DMA** = 老板安排一个专职跑腿（DMA 控制器），告诉他"把这堆文件全搬去档案室"。老板继续干活，跑腿搬完所有文件后才回来说一声"搬完了"。

#### 中断系统详细说明

**中断全过程（从发生到返回）**：

```
第 1 步：外设发出中断请求
第 2 步：CPU 执行完当前指令后响应中断
第 3 步：CPU 自动执行"中断隐指令"（关中断、保存断点、取中断向量）
第 4 步：执行中断服务程序
第 5 步：恢复现场、开中断、返回原程序
```

**中断优先级**：当多个中断同时发生时，CPU 先响应**优先级最高**的。

**中断嵌套（多重中断）**：高优先级中断可以打断正在执行的低优先级中断服务程序。

**中断屏蔽字设置例题**：

设 4 个中断源 A、B、C、D，优先级从高到低为 A>B>C>D。写出各中断源的屏蔽字（1 表示屏蔽，0 表示不屏蔽）。

| 中断源 | 屏蔽 A | 屏蔽 B | 屏蔽 C | 屏蔽 D | 说明 |
|--------|--------|--------|--------|--------|------|
| A | 1 | 1 | 1 | 1 | A 优先级最高，屏蔽所有 |
| B | 0 | 1 | 1 | 1 | B 只能被 A 打断 |
| C | 0 | 0 | 1 | 1 | C 能被 A、B 打断 |
| D | 0 | 0 | 0 | 1 | D 能被所有打断 |

> 规律：比自己优先级高的不屏蔽（0），比自己优先级低（或相等）的屏蔽（1）。

### 35.4 中断系统

| 概念 | 说明 |
|------|------|
| **中断向量** | 中断服务程序的入口地址 |
| **中断隐指令** | CPU 自动完成的三件事：关中断、保存断点（PC/PSW 入栈）、引出中断服务程序 |
| **多重中断** | 高优先级中断可以打断低优先级中断服务 |
| **中断屏蔽字** | 通过设置屏蔽字改变中断优先级 |

### 35.5 DMA 方式

**DMA 传送过程**：预处理（CPU 设置 DMA 控制器）→ 数据传送（DMA 控制器控制）→ 后处理（DMA 发中断，CPU 处理）

**周期窃取**（Cycle Stealing）：DMA 和 CPU 同时访问主存时，DMA 优先，CPU 暂停一个总线周期。

> **DMA 与中断的区别**：DMA 只在传送开始和结束时发中断（共 2 次），中断每一次数据传送都要发中断。

## 知识点 36：并行计算架构

### 36.1 Flynn 分类法

> 按"指令流"和"数据流"的数量对计算机架构分类。

| 分类 | 全称 | 指令流 | 数据流 | 代表 |
|------|------|--------|--------|------|
| **SISD** | 单指令单数据 | 1 | 1 | 传统单核 CPU |
| **SIMD** | 单指令多数据 | 1 | 多 | GPU 向量运算、MMX/SSE 指令 |
| MISD | 多指令单数据 | 多 | 1 | 理论存在，实际罕见 |
| **MIMD** | 多指令多数据 | 多 | 多 | **多核处理器、分布式系统** |

> 考试重点：**SISD = 单核、SIMD = GPU、MIMD = 多核**

**大白话类比**：Flynn 分类就像"老师布置作业"——
- **SISD（单指令单数据）** = 老师说"做第 3 题"，全班只有一个人，他自己做第 3 题（单核 CPU）
- **SIMD（单指令多数据）** = 老师说"做第 3 题"，全班 1000 个人同时做第 3 题（GPU 同时处理 1000 个像素，但做的是同一件事）
- **MISD（多指令单数据）** = 多个老师对同一份作业打分——理论上存在，实际上没人这么干
- **MIMD（多指令多数据）** = 老师给不同的人布置不同的题，大家同时做（多核 CPU，每个核独立执行不同任务）

### 36.2 多核处理器

| 类型 | 核的结构 | 特点 |
|------|---------|------|
| 同构多核 | 所有核心相同 | 简单，任务均匀分配 |
| 异构多核 | 不同核心（大核+小核） | 性能功耗平衡，ARM big.LITTLE 为代表 |

### 36.3 GPU 通用计算（GPGPU）

- GPU 有**成千上万个小型核心**，适合大规模并行计算
- **CUDA**（NVIDIA）：让 GPU 执行通用计算任务
- 应用：深度学习训练、科学计算、图像处理

### 36.4 分布式计算基础

- **集群**：多个独立计算机通过网络连接，协同工作
- **网格计算**：跨地域、跨组织的资源共享
- 与并行计算的区别：并行计算在多核/多 CPU 内，分布式计算跨机器

## 附录：计算题公式速查

### 一、CPU 性能公式

| 公式 | 含义 | 说明 |
|------|------|------|
| **CPU 时间 = IC × CPI × T** | CPU 执行一个程序的总时间 | IC=指令条数，CPI=每条指令平均时钟数，T=时钟周期 |
| **T = 1/f** | 时钟周期 = 主频的倒数 | f=1GHz → T=1ns |
| **MIPS = f / (CPI × 10⁶)** | 每秒百万条指令 | 也可写成 MIPS = IC/(CPU时间×10⁶) |
| **MFLOPS = 浮点操作数/(CPU时间×10⁶)** | 每秒百万次浮点运算 | 浮点密集型程序的性能指标 |
| **CPI = 总时钟周期数/总指令数** | 平均每条指令的时钟周期数 | 不同指令 CPI 不同，取加权平均 |

**CPU 时间计算例题**：
- 某程序有 2×10⁶ 条指令，CPI=1.5，主频 3GHz（T=1/3 ns）
- CPU 时间 = 2×10⁶ × 1.5 × (1/3)ns = 1×10⁶ ns = **1ms**

### 二、阿姆达尔定律

| 公式 | 含义 |
|------|------|
| **S = 1 / [(1-f) + f/k]** | 整体加速比 |
| **S_max = 1/(1-f)** | 当 k→∞ 时的极限加速比 |

- f = 可改进部分占总时间的比例
- k = 改进部分的加速倍数

**关键结论**：即使把某部分加速到无限快（k→∞），整体加速比也不超过 1/(1-f)。改进受限于不可改进部分。

### 三、Cache 命中率公式

| 公式 | 含义 |
|------|------|
| **ta = h × tc + (1-h) × tm** | 单级 Cache 平均访问时间 |
| **ta = h1×t1 + (1-h1)×h2×(t1+t2) + (1-h1)×(1-h2)×(t1+t2+tm)** | 两级 Cache 平均访问时间 |

- h/h1/h2 = 命中率
- tc/t1/t2 = Cache 访问时间
- tm = 主存访问时间

**失效率** = 1-h（Cache 不命中的概率）。高命中率下，失效率才是关键——失效率减半，ta 中未命中部分就减半。

### 四、流水线公式

| 公式 | 含义 | 说明 |
|------|------|------|
| **T流 = k×Δt + (n-1)×Δt = (k+n-1)×Δt** | n 条指令流水线执行时间 | k=段数，Δt=每段时间（取最长段） |
| **T顺 = n × k × Δt** | n 条指令顺序执行时间 | 不用流水线 |
| **S = T顺/T流 = (n×k)/(k+n-1)** | 流水线加速比 | 当 n→∞ 时，S≈k |
| **E = S/k** | 流水线效率 | 理想情况 E=1 |
| **吞吐率 p = n/T流** | 单位时间完成指令数 | 当 n→∞ 时，p≈1/Δt |

**各段时间不等时**：Δt 取最长段的时间（瓶颈段），流水线时钟周期由最慢段决定。

**含阻塞**：T流_阻塞 = T流 + 阻塞总时钟数

### 五、其他常用公式

| 公式 | 含义 |
|------|------|
| **补码转原码** | 负数补码：取反+1；正数补码=原码 |
| **浮点数真值** | N = (-1)^S × 1.M × 2^(E-bias) |
| **海明码** | 2^k ≥ n+k+1（k=校验位数，n=数据位数） |
| **磁盘容量** | 磁头数 × 柱面数 × 每道扇区数 × 每扇区字节数 |
| **磁盘平均存取时间** | 寻道时间 + 旋转延迟（半圈时间）+ 传输时间 |

### 六、公式使用场景速查

| 题目类型 | 用什么公式 | 关键参数 |
|---------|-----------|---------|
| 算程序执行时间 | CPU 时间 = IC×CPI×T | 注意单位统一 |
| 算 MIPS | f/(CPI×10⁶) | f 用 Hz，CPI 是小数 |
| 提高了某部分性能整体快多少 | 阿姆达尔 S = 1/[(1-f)+f/k] | f 是比例不是绝对值 |
| 算 Cache 平均访问时间 | ta = h×tc+(1-h)×tm | 注意 h 是小数不是百分比 |
| 算流水线执行时间 | (k+n-1)×Δt | 各段时间不等时取最长段 |
| 算流水线加速比 | (n×k)/(k+n-1) | n 大时约等于 k |
| 算补码值 | 正数直接算，负数取反+1 | 先看符号位 |
| 判断溢出 | 双符号位法 / 进位判断法 | 正正得负溢，负负得正溢 |

## 记忆口诀

- **冯·诺依曼**：存储程序，五大部件（运算器/控制器/存储器/输入/输出）
- **补码范围**：比原码多一个负数，零只有一种
- **IEEE754 单精度**：**1-8-23-127**（符号-阶码-尾数-偏移量）
- **Cache 映射**：直接→固定座位、全相联→随便坐、组相联→先分组再随便坐
- **CISC vs RISC**：Cx86 复杂可变长，ARM 精简全定长
- **Flynn 分类**：单核 SISD、GPU SIMD、多核 MIMD
- **流水线时间**：首条 k 段，后续每条 1 段，n 条总时间 = k+(n-1)
