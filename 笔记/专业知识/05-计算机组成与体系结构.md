## 知识点 30：计算机系统概述

> **考点星级**：CPU性能公式=必考⭐⭐⭐ | 阿姆达尔定律=必考⭐⭐⭐ | 冯诺依曼=中频⭐

### 30.1 冯·诺依曼体系结构

**大白话**：冯·诺依曼结构就是"计算机的工作方式说明书"——程序和数据都存内存里，CPU 一条条取出来执行。

**五大部件**：

| 部件 | 功能 | 类比 |
|------|------|------|
| 运算器（ALU） | 做算术和逻辑运算 | 计算器 |
| 控制器（CU） | 指挥各部件协调工作 | 乐队指挥 |
| 存储器 | 存程序和数据 | 仓库 |
| 输入设备 | 从外界获取数据 | 键盘、鼠标 |
| 输出设备 | 把结果展示出来 | 显示器、打印机 |

**核心思想**：**存储程序**——程序和数据以同等地位存在存储器中，按地址访问、顺序执行。

**大白话类比**：冯·诺依曼结构就像"厨房做菜"——菜谱（程序）和食材（数据）都放在冰箱（存储器）里，厨师（CPU）从冰箱里取出菜谱和食材，按步骤做菜。菜谱和食材在冰箱里地位平等，都是"存着的东西"，不会因为"这是菜谱"就特殊对待。

**"存储程序"思想为什么重要？** 在冯·诺依曼之前，程序是"硬连线"的——换个程序就得重新接线。有了存储程序，换个程序就是换一段存入内存的数据，计算机从此变得"通用"了。

#### 冯·诺依曼结构的特点（6 个核心特征）

| 特征 | 说明 |
|------|------|
| **1. 存储程序** | 程序和数据以同等地位存于存储器中，按地址访问 |
| **2. 指令顺序执行** | 由程序计数器 PC 控制，通常按顺序一条条执行（除非遇到跳转指令） |
| **3. 二进制编码** | 指令和数据都用二进制表示，计算机只认识 0 和 1 |
| **4. 五大部件** | 运算器、控制器、存储器、输入设备、输出设备 |
| **5. 以运算器为中心** | 早期的冯·诺依曼机以运算器为中心，I/O 设备和存储器之间的数据传送都要经过运算器 |
| **6. 指令 = 操作码 + 地址码** | 每条指令由操作码（做什么）和地址码（操作数在哪）组成 |

#### 冯·诺依曼瓶颈

> "冯·诺依曼瓶颈"是指 CPU 和存储器之间的通道（总线）带宽有限，CPU 的高速和存储器的相对低速形成了"剪刀差"——CPU 经常要等存储器把数据送过来。

**解决方案**：
- **Cache（高速缓存）**：在 CPU 和主存之间加一层小容量高速存储器，利用局部性原理缓存常用数据
- **多级存储层次**：寄存器→Cache→主存→辅存，逐级缓冲速度差
- **哈佛结构**：指令和数据分开存储，使用独立总线，可以同时取指令和取数据（但冯·诺依曼结构是统一存储）

#### 冯·诺依曼结构真题自测

**真题 1**：冯·诺依曼计算机中，指令和数据在存储器中的存放方式是（ ）。

- A. 指令和数据分开存放在不同的存储器中
- B. 指令和数据以同等地位存放在同一存储器中
- C. 指令存放在 ROM 中，数据存放在 RAM 中
- D. 指令存放在 Cache 中，数据存放在主存中

**答案**：B。冯·诺依曼结构的核心思想是"存储程序"——指令和数据以同等地位存放在同一存储器中，按地址访问。

**真题 2**：以下哪个不是冯·诺依曼计算机的特点？（ ）

- A. 采用存储程序方式
- B. 指令由操作码和地址码组成
- C. 指令和数据分开存储，拥有独立总线
- D. 按地址访问存储器，顺序执行指令

**答案**：C。C 描述的是哈佛结构的特点，不是冯·诺依曼结构。

**真题 3**：冯·诺依曼计算机的"冯·诺依曼瓶颈"是指（ ）。

- A. 指令集过于复杂，导致译码瓶颈
- B. CPU 和存储器之间的通道带宽有限，CPU 经常等待存储器
- C. 运算器速度太慢，拖累整体性能
- D. 输入输出设备速度太慢

**答案**：B。冯·诺依曼瓶颈是指 CPU 与存储器之间的总线带宽限制，CPU 高速与存储器相对低速之间的矛盾。

#### 冯·诺依曼常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **冯·诺依曼 vs 哈佛** | 冯·诺依曼是统一存储，哈佛是指令/数据分开存储 | 看到"分开存储"→ 哈佛，看到"统一存储"→ 冯·诺依曼 |
| **"存储程序"≠"存在硬盘里"** | 存储程序是指程序和数据都以同等地位存在**主存**中 | 不是存在辅存（硬盘），是主存 |
| **现代 CPU 并非纯冯·诺依曼** | 现代 CPU 内部 L1 Cache 采用哈佛结构（I-Cache/D-Cache 分离） | 外部统一内存 + 内部分离缓存 = 混合架构 |
| **五大部件 vs 三大部件** | 冯·诺依曼强调五大部件，但现代计算机常按三大部件（CPU+内存+I/O）理解 | 考试按五大部件回答 |
| **"以运算器为中心"≠"以 CPU 为中心"** | 早期冯·诺依曼以运算器为中心，现代计算机以存储器为中心 | 注意区分"早期冯·诺依曼"和"现代计算机" |

#### 记忆口诀

- **冯·诺依曼核心**："存储程序五大件，统一编址顺序行"
- **五大部件**："运送存输入——运算器、控制器、存储器、输入设备、输出设备"
- **冯·诺依曼 vs 哈佛**："冯统一（共享内存），哈分开（独立总线）"
- **冯·诺依曼瓶颈**："CPU 快，内存慢，中间加个 Cache 缓"

#### 冯·诺依曼结构 vs 哈佛结构


| 对比维度 | 冯·诺依曼结构 | 哈佛结构 |
|---------|-------------|---------|
| 程序和数据存储 | **存在同一存储器中** | **分开存储**（指令存储器 + 数据存储器） |
| 总线 | 共享一套总线 | 独立的两套总线（指令总线 + 数据总线） |
| 并行性 | 不能同时取指令和取数据 | **可同时取指令和取数据** |
| 灵活性 | **高**（程序和数据可互换） | 低（指令和数据物理分离） |
| 典型应用 | PC、服务器（x86） | 嵌入式系统（DSP、单片机如 8051、ARM Cortex-M） |
| 缓存结构 | 统一缓存或分离缓存（现代 CPU L1 通常分离） | 天然分离 |

> **现代 CPU 的做法**：现代高性能 CPU（如 x86、ARM Cortex-A）在外部采用冯·诺依曼结构（统一内存），但在 L1 Cache 层面采用哈佛结构（I-Cache 和 D-Cache 分离），同时取指令和数据，兼顾了灵活性和速度。

#### 计算机的工作过程——以执行一条 ADD 指令为例

```
1. 取指令：PC → MAR → 地址总线 → 主存 → 数据总线 → MDR → IR
   （把 PC 指向的地址送到主存，读出的指令放进指令寄存器）

2. 译码：IR 中的操作码 → 控制器译码
   （控制器看到"这是 ADD 指令"，知道接下来要做什么）

3. 取操作数：IR 中的地址码 → MAR → 主存 → MDR → ALU 输入端
   （从内存中取出要加的数据）

4. 执行：ALU 进行加法运算

5. 写回：结果写回寄存器或内存

6. PC + 1 → PC（指向下一条指令）
```

### 30.2 计算机层次结构

```
应用程序层（用户直接用的——如 Word、浏览器）
    ↓ 翻译（编译/解释）
高级语言层（C / Java / Python — 程序员在这里写代码）
    ↓ 编译（编译器翻译成汇编）
汇编语言层（助记符 — ADD R1, R2 — 人类勉强能读懂的机器语言）
    ↓ 汇编（汇编器翻译成机器码）
操作系统层（管理软硬件资源 — 进程调度、内存管理、文件系统）
    ↓ 系统调用（OS 提供的接口）
传统机器层（指令集架构 ISA — 机器语言，二进制指令）
    ↓ 微程序解释（硬件直接执行）
微程序机器层（微指令 — 硬件直接执行的最底层，控制信号）
```

> 下层是上层的基础，上层是下层的抽象。每一层只关心自己的事。

**大白话类比**：层次结构就像"寄快递"——你只关心"把包裹交给快递员"，不用管快递员怎么分拣、卡车怎么运、飞机怎么飞。每一层帮你屏蔽了下层的细节。

**各层详解**：

| 层次 | 别名 | 核心功能 | 谁来管 |
|------|------|---------|--------|
| 微程序机器层 | 第 0 层 | 硬件直接执行微指令，发出控制信号 | 硬件设计者 |
| 传统机器层 | 第 1 层 / ISA 层 | 执行机器指令，CPU 理解的最底层 | 硬件 + 操作系统 |
| 操作系统层 | 第 2 层 | 资源管理、进程调度、文件系统、设备驱动 | 操作系统 |
| 汇编语言层 | 第 3 层 | 助记符代替二进制，方便编写底层程序 | 汇编器 |
| 高级语言层 | 第 4 层 | C/Java/Python 等高级语言 | 编译器/解释器 |
| 应用程序层 | 第 5 层 | 用户直接使用的软件 | 应用开发者 |

**虚拟机的概念**：
- 从某一层往上看，下面所有层就像一个"虚拟机器"，屏蔽了底层细节
- 比如：从高级语言层看，下面就是一个"能执行 C/Java 代码的虚拟机"，程序员不需要知道 CPU 具体怎么工作
- 这个思想是现代计算机体系结构分层设计的核心——**每层只关心自己的抽象，不关心下面的实现**

### 30.3 性能指标

| 指标 | 公式 | 含义 |
|------|------|------|
| 主频 f | 1/T（T为时钟周期） | CPU 每秒振荡多少次 |
| CPI | 总时钟周期数/总指令数 | 每条指令平均需要几个时钟周期 |
| CPU 执行时间 | **IC × CPI × T** | 程序的 CPU 时间 |
| MIPS | 指令条数/(执行时间×10⁶) = f/(CPI×10⁶) | 每秒百万条指令 |
| MFLOPS | 浮点运算次数/(执行时间×10⁶) | 每秒百万次浮点运算 |

> **CPU 执行时间 = IC × CPI × T** 是核心公式，哪里都可能出计算题。

**大白话类比**：性能指标就像"搬砖"——
- **主频** = 你每分钟能弯腰多少次（频率越高，干活越快）
- **CPI** = 搬一块砖平均需要弯腰几次（CPI 越低越好，CPI=1 就是一次弯腰搬一块）
- **CPU 执行时间** = 搬完所有砖需要的总时间 = 砖的数量 × 每块砖弯腰次数 × 每次弯腰时间
- **MIPS** = 每秒能搬多少块砖（百万块为单位）

#### 性能指标深度解析

**（1）主频 f 与时钟周期 T**

```
T = 1/f
f = 1GHz → T = 1ns
f = 2GHz → T = 0.5ns
f = 3GHz → T = 1/3 ns ≈ 0.333ns
```

> 主频越高，时钟周期越短，每个基本操作越快。但主频不是性能的唯一决定因素——CPI 同样重要。

**（2）CPI 的影响因素**

CPI 不是固定的——不同指令有不同的 CPI：
- 简单指令（加法、移位）：CPI ≈ 1
- 复杂指令（乘法、除法）：CPI 可能 > 10
- 访存指令（Load/Store）：CPI 取决于 Cache 命中情况

**平均 CPI 的计算**：
```
CPI_avg = Σ(CPI_i × 指令i出现的比例)
```

**（3）CPU 执行时间公式的变形**

| 变形公式 | 用途 |
|---------|------|
| Tcpu = IC × CPI × T | 基本公式 |
| Tcpu = (总时钟周期数) × T | 已知总时钟周期数时使用 |
| Tcpu = IC / (MIPS × 10⁶) | 已知 MIPS 时反推 |
| Tcpu = IC × CPI / f | 已知主频时使用 |

**（4）MIPS 和 MFLOPS 的局限性**

- **MIPS 不能跨指令集比较**：不同 ISA 的指令功能不同，MIPS 高的 CPU 不一定更快
- **MFLOPS 只衡量浮点性能**：适用于科学计算，不适合整数密集型应用
- **峰值 MIPS vs 实际 MIPS**：厂商宣传的是峰值，实际程序跑出来的远低于峰值

**（5）其他常见性能指标**

| 指标 | 含义 | 公式 |
|------|------|------|
| **响应时间** | 从任务开始到完成的总时间 | 包括 CPU 时间 + I/O 等待 + 其他开销 |
| **吞吐率** | 单位时间完成的任务数 | 任务数 / 总时间 |
| **IPC** | 每时钟周期执行的指令数（CPI 的倒数） | IPC = 1/CPI |
| **SPEC 分数** | 标准性能评估（业界标准基准测试） | 几何平均归一化值 |

**CPU 时间计算例题**：
- 已知：程序有 1000 条指令，CPI=2，主频 1GHz（T=1ns）
- CPU 时间 = 1000 × 2 × 1ns = **2000ns = 2微秒**

#### 性能指标例题专项（5 道）

**例题 1：基础 CPU 时间计算**

某程序有 2×10⁶ 条指令，CPI=1.5，主频 3GHz。求 CPU 执行时间。

**解答**：T = 1/3GHz = 1/3 ns
CPU 时间 = 2×10⁶ × 1.5 × (1/3)ns = 1×10⁶ ns = **1ms**

**例题 2：已知 MIPS 反推 CPU 时间**

某 CPU 主频 2GHz，运行某程序时 MIPS=400。程序有 8×10⁶ 条指令。求 CPU 时间。

**解答**：MIPS = f/(CPI×10⁶) → 400 = 2×10⁹/(CPI×10⁶) → CPI = 5
T = 0.5ns
CPU 时间 = 8×10⁶ × 5 × 0.5ns = 20×10⁶ns = **20ms**
或：CPU 时间 = IC/(MIPS×10⁶) = 8×10⁶/(400×10⁶) = 0.02s = **20ms**

**例题 3：平均 CPI 计算**

某程序中有三类指令：A 类占 40%，CPI=1；B 类占 35%，CPI=2；C 类占 25%，CPI=4。求平均 CPI。

**解答**：CPI_avg = 0.4×1 + 0.35×2 + 0.25×4 = 0.4 + 0.7 + 1.0 = **2.1**

**例题 4：主频和 CPI 同时变化**

CPU-A：主频 2GHz，CPI=1.5。CPU-B：主频 3GHz，CPI=2.5。哪个 CPU 执行同一程序更快？

**解答**：同一程序 IC 相同，比较 CPU 时间。
CPU-A：T_A = IC × 1.5 × 0.5ns = 0.75×IC ns
CPU-B：T_B = IC × 2.5 × 0.333ns = 0.833×IC ns
0.75 < 0.833 → **CPU-A 更快**

> 主频高不一定更快！CPU-B 主频高 50%，但 CPI 也高 67%，综合下来反而更慢。这就叫"主频不是一切"。

**例题 5：MFLOPS 计算**

某程序执行了 5×10⁸ 次浮点运算，耗时 2 秒。求 MFLOPS。

**解答**：MFLOPS = 5×10⁸/(2×10⁶) = 250 MFLOPS

### 30.4 阿姆达尔定律

**问题**：如果我把程序的一部分加速了，整体能快多少？

**公式**：S = 1 / [(1-f) + f/k]

- f = 可改进部分占总时间的比例
- k = 改进部分的加速倍数
- S = 整体加速比

**大白话类比**：你家到公司 10 公里路程，前 8 公里是高速（可以开很快），后 2 公里是市区（只能慢慢开）。即使把高速路段改成"无限快"（0 时间），你还是要花 2 公里市区的时间——整体时间受限于不可改进的部分。

#### 阿姆达尔定律 5 道例题

**例题 1**：某程序 80% 可以并行化，用 4 核 CPU，整体加速比是多少？
- f = 0.8, k = 4
- S = 1 / [(1-0.8) + 0.8/4] = 1 / [0.2 + 0.2] = **2.5 倍**

> **易错点**：即使把 80% 的部分加速到"无限快"，整体加速比也不过 1/(1-0.8) = **5 倍**。改进受限于不可改进部分！

**例题 2**：某系统 CPU 时间占 60%，I/O 时间占 40%。CPU 性能提升 3 倍，整体加速比？

- f = 0.6, k = 3
- S = 1/[(1-0.6) + 0.6/3] = 1/[0.4 + 0.2] = 1/0.6 ≈ **1.67 倍**

**例题 3**：某程序 90% 可并行化。用 16 核 CPU，加速比是多少？极限加速比是多少？

- S(16核) = 1/[(1-0.9) + 0.9/16] = 1/[0.1 + 0.05625] = 1/0.15625 ≈ **6.4 倍**
- S_max = 1/(1-0.9) = 1/0.1 = **10 倍**

> 即使 90% 可并行，用 16 核也只能加速 6.4 倍（远不到 16 倍）。极限也只有 10 倍。

**例题 4**：给定目标反推资源

某程序 75% 可并行化，希望整体加速比达到 3 倍，至少需要多少核？

- S = 1/[(1-0.75) + 0.75/k] ≥ 3
- 1/[0.25 + 0.75/k] ≥ 3
- 0.25 + 0.75/k ≤ 1/3
- 0.75/k ≤ 0.0833
- k ≥ 0.75/0.0833 = **9 核**

**例题 5**：改进某部件后的加速比

某计算机系统，浮点运算占总时间的 50%。如果将浮点运算加速 10 倍，整体加速比是多少？如果浮点运算可以无限加速，加速比极限是多少？
- f = 0.5, k = 10
- S = 1/[(1-0.5) + 0.5/10] = 1/[0.5 + 0.05] = 1/0.55 ≈ **1.82 倍**
- S_max = 1/(1-0.5) = 1/0.5 = **2 倍**

> 浮点运算快了 10 倍，整体只快 1.82 倍！因为浮点运算只占 50%，另外 50% 没动。**这就是为什么优化要找准瓶颈——把不占大头的部分加速很多倍，整体效果有限。**

#### 阿姆达尔定律的工程启示

1. **优化瓶颈优先**：把时间占比最大的部分作为优化目标
2. **并行化不是万能药**：即使 99% 可并行，极限加速比也只有 100 倍
3. **串行部分是硬伤**：1% 的串行代码可以使 1000 核的加速比降到只有 91 倍
4. **多核时代的真相**：对于大多数程序，从 4 核到 8 核的加速效果远不如从 1 核到 4 核

#### 阿姆达尔定律常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **f 是小数不是百分比** | f=80% → 公式中用 0.8，不是 80 | 代入前先除以 100 |
| **f 是比例不是绝对值** | f 取决于程序的执行时间分布，不是固定值 | 不同程序、不同输入，f 可能不同 |
| **S_max 很容易算错** | S_max = 1/(1-f)，记住是 1 除以串行比例 | 不要把 f 和 1-f 搞反 |
| **加速比 ≤ min(k, 1/(1-f))** | 实际加速比受两者中较小者的限制 | 多核时先算 1/(1-f)，如果比 k 小，加再多核也没用 |
| **阿姆达尔定律假设问题规模不变** | 实际上数据量大了，并行部分占比可能增加（古斯塔夫森定律） | 阿姆达尔定律是保守估计 |

## 知识点 31：数据的机器级表示和运算

> **考点星级**：⭐

### 31.1 进制转换
> **重要子考点**：补码运算=高频⭐⭐ | IEEE754转换=必考⭐⭐⭐

**二进制 ↔ 八进制**：每 3 位二进制 = 1 位八进制  
**二进制 ↔ 十六进制**：每 4 位二进制 = 1 位十六进制

**十进制转二进制**：整数部分除 2 取余（从下往上读），小数部分乘 2 取整（从上往下读）

#### 进制转换详细计算例题

**例 1：十进制整数 → 二进制（除 2 取余法）**

把十进制 57 转二进制：

```
57 ÷ 2 = 28 ... 余 1  ← 最低位
28 ÷ 2 = 14 ... 余 0
14 ÷ 2 = 7  ... 余 0
7 ÷ 2 = 3  ... 余 1
3 ÷ 2 = 1  ... 余 1
1 ÷ 2 = 0  ... 余 1  ← 最高位
```

**从下往上读**：57₁₀ = **111001**₂

验算：1×32 + 1×16 + 1×8 + 0×4 + 0×2 + 1×1 = 32+16+8+1 = 57 ✓

**例 2：十进制小数 → 二进制（乘 2 取整法）**

把十进制 0.625 转二进制：

```
0.625 × 2 = 1.25  → 取整 1  ← 小数点后第一位
0.25  × 2 = 0.5   → 取整 0
0.5   × 2 = 1.0   → 取整 1  ← 最后一位
```

**从上往下读**：0.625₁₀ = **0.101**₂

验算：1×0.5 + 0×0.25 + 1×0.125 = 0.5+0.125 = 0.625 ✓

**例 3：十进制带小数 → 二进制**

把 57.625 转二进制：整数部分 57→111001，小数部分 0.625→0.101
结果：57.625₁₀ = **111001.101**₂

**例 4：二进制 → 十六进制（每 4 位一组）**

把 1101 1010 0011 ₂ 转十六进制：

```
1101 1010 0011
  ↓    ↓    ↓
  D    A    3
```

结果：**0xDA3**（或写作 DA3H）

**例 5：十六进制 → 二进制**

把 0x3F7 转二进制：

```
3  → 0011
F  → 1111
7  → 0111
```

结果：**0011 1111 0111**₂

**进制转换口诀**：
- 十进制转 N 进制：整数除 N 取余（倒读），小数乘 N 取整（顺读）
- N 进制转十进制：按权展开相加
- 二进制 ↔ 八进制：3 位一组
- 二进制 ↔ 十六进制：4 位一组
- 八进制 ↔ 十六进制：先转二进制做中转

**例 6：补码计算例题**

已知 8 位补码，求十进制值：

(1) **[X]补 = 1001 0110**，求 X 的真值

```
符号位=1，是负数
补码转原码：补码末位-1取反（或先取反+1）
取反（符号位除外）：1001 0110 → 1110 1001
+1：1110 1001 + 1 = 1110 1010
原码 = 1110 1010 = -(64+32+8+2) = -106
```

所以 X = **-106**

(2) **[X]补 = 0110 1001**，求 X 的真值

```
符号位=0，是正数，补码=原码
0110 1001 = 64+32+8+1 = 105
```

所以 X = **105**

(3) **计算 -37 + 22 的补码运算**（8 位）

```
-37 的补码：
  37 = 0010 0101
  取反：1101 1010
  +1：1101 1011

22 的补码：
  22 = 0001 0110

相加：
  1101 1011
+ 0001 0110
-----------
  1111 0001

符号位=1，是负数
取反+1：0000 1110 + 1 = 0000 1111 = 15
结果 = -15
```

验算：-37 + 22 = -15 ✓

(4) **判断溢出：-100 + (-50)**（8 位补码）

```
-100 的补码：1001 1100
-50 的补码： 1100 1110

相加：
  1001 1100
+ 1100 1110
-----------
1 0110 1010  ← 最高位进位=1，次高位进位=0

两个负数相加，结果符号位却变成了 0（正数）
→ 负溢！
```

原因：-100 + (-50) = -150，超出 8 位补码的表示范围（-128~+127）。

### 31.2 原码、反码、补码、移码

**类比**：就像钟表——补码就是把"逆时针转"变成"顺时针转"，用加法代替减法。

**大白话类比**：把时钟拨回 3 小时（-3），和往前拨 9 小时（+9），在 12 小时钟表上的效果是一样的。补码就是这个道理——用"正向加"代替"反向减"，硬件只需要加法器不需要减法器。

| 编码 | 正数 | 负数 | 8 位范围 | 零的表示 |
|------|------|------|---------|---------|
| 原码 | 符号位 0 + 数值 | 符号位 1 + 数值 | -127~+127 | +0=00000000, -0=10000000 |
| 反码 | 同原码 | 符号位不变，其余取反 | -127~+127 | +0=00000000, -0=11111111 |
| **补码** | 同原码 | **反码 + 1** | **-128~+127** | **只有 00000000** |
| 移码 | 补码符号位取反 | 补码符号位取反 | -128~+127 | 10000000 |

> **核心记忆**：补码比原码多一个负数（-128），且零只有一种表示——这是补码最大的优势。

#### 四种编码深度对比

**（1）为什么移码能比较大小？**

移码 = 补码的符号位取反，使得数值的大小关系和编码的大小关系一致：

```
补码：   -128 = 1000 0000, -127 = 1000 0001, ..., -1 = 1111 1111
移码：   -128 = 0000 0000, -127 = 0000 0001, ..., -1 = 0111 1111,
         0 = 1000 0000, +1 = 1000 0001, ..., +127 = 1111 1111

移码可以直接按无符号数比较大小：
  0000 0000 < 1000 0000 < 1111 1111
  -128      < 0         < +127        ← 正确的！
```

**（2）四种编码的数值对照表**（8 位）

| 十进制 | 原码 | 反码 | 补码 | 移码 |
|--------|------|------|------|------|
| +127 | 0111 1111 | 0111 1111 | 0111 1111 | 1111 1111 |
| +126 | 0111 1110 | 0111 1110 | 0111 1110 | 1111 1110 |
| ... | ... | ... | ... | ... |
| +1 | 0000 0001 | 0000 0001 | 0000 0001 | 1000 0001 |
| +0 | 0000 0000 | 0000 0000 | 0000 0000 | 1000 0000 |
| -0 | 1000 0000 | 1111 1111 | 无 | 无 |
| -1 | 1000 0001 | 1111 1110 | 1111 1111 | 0111 1111 |
| ... | ... | ... | ... | ... |
| -127 | 1111 1111 | 1000 0000 | 1000 0001 | 0000 0001 |
| -128 | 无法表示 | 无法表示 | **1000 0000** | **0000 0000** |

#### 补码的优势（为什么计算机用补码？）

| 优势 | 说明 |
|------|------|
| **1. 零唯一** | 原码/反码有 +0 和 -0 两个零，浪费编码；补码只有一个零 |
| **2. 减法统一为加法** | [X-Y]补 = [X]补 + [-Y]补，ALU 只需加法器，硬件简单 |
| **3. 多一个负数** | 8 位补码范围 -128~+127，比原码多一个 -128 |
| **4. 符号位参与运算** | 补码运算时符号位和数值位一起算，不需要额外处理 |

### 31.3 补码溢出判断

**三种方法**：

| 方法 | 判断规则 | 口诀 |
|------|---------|------|
| 单符号位 | 两正数相加得负数→正溢；两负数相加得正数→负溢 | 正正得负溢，负负得正溢 |
| 双符号位（变形补码） | 00=正常，01=正溢，10=负溢 | 两位相同没溢出，不同则溢出 |
| 进位判断 | 最高位进位 ≠ 次高位进位 → 溢出 | 两个进位不一样就溢了 |

### 31.4 IEEE754 浮点数

**格式**：N = (-1)^S × 1.M × 2^(E-bias)

**大白话类比**：浮点数就是"科学计数法的计算机版"——十进制科学计数法把 12345 写成 1.2345×10⁴，IEEE754 把二进制数写成 1.XXX×2^E。S 是正负号，M 是有效数字，E 是指数。这样不管很大（如 10³⁸）还是很小（如 10⁻³⁸）的数，都能用同样长的二进制位表示。

| 类型 | 符号 S | 阶码 E | 尾数 M | 偏移量 bias |
|------|--------|--------|--------|------------|
| 单精度 float | 1 bit | **8 bit** | **23 bit** | **127** |
| 双精度 double | 1 bit | **11 bit** | **52 bit** | **1023** |

> 尾数隐含最高位 1（规格化后），实际尾数是 1.M。

#### IEEE754 单精度浮点数——十进制转 32 位二进制（详细步骤）

**核心公式**：N = (-1)^S × 1.M × 2^(E - 127)

**位布局**（32 位从高位到低位）：
```
| 31 | 30 ... 23 | 22 ... 0 |
| S  |  E (8位)  | M (23位) |
```

**标准转换 6 步**：

| 步骤 | 操作 | 说明 |
|------|------|------|
| **第 1 步** | 确定符号位 S | 正数 S=0，负数 S=1 |
| **第 2 步** | 十进制转二进制 | 整数部分除 2 取余（倒读），小数部分乘 2 取整（顺读） |
| **第 3 步** | 规格化到 1.M × 2^e 形式 | 移动小数点，确保小数点前只有 1 位且为 1 |
| **第 4 步** | 计算阶码 E | E = e + 127（单精度）或 e + 1023（双精度），转 8 位二进制 |
| **第 5 步** | 提取尾数 M | 去掉规格化后的 1. 部分，只保留小数部分，右边补 0 到 23 位 |
| **第 6 步** | 拼接 S-E-M | 符号 1 位 + 阶码 8 位 + 尾数 23 位 |

**完整示例 1：将 -12.625 转为 IEEE754 单精度**

```
第 1 步：S = 1（负数）

第 2 步：转二进制
  整数 12：12÷2=6余0, 6÷2=3余0, 3÷2=1余1, 1÷2=0余1 → 1100₂
  小数 0.625：0.625×2=1.25取1, 0.25×2=0.5取0, 0.5×2=1.0取1 → 0.101₂
  12.625₁₀ = 1100.101₂

第 3 步：规格化（小数点左移 3 位）
  1100.101₂ = 1.100101₂ × 2³
  实际指数 e = 3

第 4 步：E = 3 + 127 = 130 = 1000 0010₂

第 5 步：M = 100101（去掉 1.），补 0 到 23 位
  M = 1001010 00000000 00000000

第 6 步：拼接
  S     E          M
  1  | 1000 0010 | 1001010 00000000 00000000
  = 1100 0001 0100 1010 0000 0000 0000 0000
  = 0xC14A0000
```

**完整示例 2：将 0.15625 转为 IEEE754 单精度**

```
第 1 步：S = 0（正数）

第 2 步：转二进制
  整数 0：0₂
  小数 0.15625：
    0.15625×2=0.3125取0
    0.3125×2=0.625取0
    0.625×2=1.25取1
    0.25×2=0.5取0
    0.5×2=1.0取1
  0.15625₁₀ = 0.00101₂

第 3 步：规格化（小数点右移 3 位）
  0.00101₂ = 1.01₂ × 2⁻³
  实际指数 e = -3

第 4 步：E = -3 + 127 = 124 = 0111 1100₂

第 5 步：M = 01（去掉 1.），补 0 到 23 位
  M = 0100000 00000000 00000000

第 6 步：拼接
  S     E          M
  0  | 0111 1100 | 0100000 00000000 00000000
  = 0011 1110 0010 0000 0000 0000 0000 0000
  = 0x3E200000
```

**完整示例 3：将 263.3 转为 IEEE754 单精度（注意：小数部分可能无限循环）**

```
第 1 步：S = 0（正数）

第 2 步：转二进制
  整数 263：263÷2=131余1, 131÷2=65余1, 65÷2=32余1, 32÷2=16余0,
           16÷2=8余0, 8÷2=4余0, 4÷2=2余0, 2÷2=1余0, 1÷2=0余1
  → 1 0000 0111₂
  小数 0.3：0.3×2=0.6取0, 0.6×2=1.2取1, 0.2×2=0.4取0,
            0.4×2=0.8取0, 0.8×2=1.6取1, 0.6×2=1.2取1, ...
  → 0.0100110011...₂（无限循环）
  263.3₁₀ ≈ 100000111.0100110011₂

第 3 步：规格化（小数点左移 8 位）
  100000111.0100110011₂ = 1.000001110100110011... × 2⁸
  e = 8

第 4 步：E = 8 + 127 = 135 = 1000 0111₂

第 5 步：M = 00000111010011001100110（取 23 位，末尾舍入）
  （注意：23 位以后的部分需要舍入处理）

第 6 步：拼接
  S     E          M
  0  | 1000 0111 | 00000111010011001100110
  = 0100 0011 1000 0011 1010 0110 0110 0110
  = 0x4383A666

> 由于 0.3 的小数部分在二进制中是无限循环的，所以 263.3 在 IEEE754 中是一个近似值，不是精确值。这就是为什么 0.1+0.2 ≠ 0.3 在大多数编程语言中成立——浮点数无法精确表示某些十进制小数。
```

#### IEEE754 单精度浮点数——32 位二进制转十进制

**完整示例：将 0xC1480000 转为十进制**

```
第 1 步：十六进制转二进制
  0xC1480000 = 1100 0001 0100 1000 0000 0000 0000 0000

第 2 步：拆分 S-E-M
  S = 1（负数）
  E = 1000 0010₂ = 130
  M = 1001000...0

第 3 步：计算实际指数
  e = E - 127 = 130 - 127 = 3

第 4 步：还原尾数（加回隐含的 1）
  1.M = 1.1001₂ = 1 + 0.5 + 0 + 0 + 0.0625 = 1.5625

第 5 步：计算真值
  N = (-1)^S × 1.M × 2^e = (-1)^1 × 1.5625 × 2³ = -1.5625 × 8 = -12.5
```

#### IEEE754 特殊值速查

| 条件 | 含义 | S/E/M 特征 |
|------|------|-----------|
| E=0, M=0 | ±0 | S=0→+0, S=1→-0 |
| E=0, M≠0 | 非规格化数 | 实际尾数 = 0.M（非 1.M），实际指数固定为 -126 |
| 1 ≤ E ≤ 254 | 规格化数 | 实际尾数 = 1.M，实际指数 = E - 127 |
| E=全1(255), M=0 | ±∞（无穷大） | S=0→+∞, S=1→-∞ |
| E=全1(255), M≠0 | NaN（非数） | 如 0/0、∞-∞ 的结果 |

> **注意**：规格化数的阶码范围是 1~254（不是 0~255）。E=0 和 E=255 被保留用于非规格化数和特殊值。

#### IEEE754 单精度浮点数的表示范围

| 类型 | 绝对值范围 | 有效位数 |
|------|-----------|---------|
| 规格化数 | 约 ±1.18×10⁻³⁸ ~ ±3.40×10³⁸ | 约 7 位十进制有效数字 |
| 非规格化数 | 约 ±1.40×10⁻⁴⁵ ~ ±1.18×10⁻³⁸ | 逐渐减少 |

> 单精度浮点数大约能精确表示 7 位十进制有效数字。超过 7 位的精度可能会丢失。

#### 浮点加减运算——详细步骤

**为什么需要专门的运算步骤？** 浮点数的加减不能直接像整数那样做——两个浮点数的指数可能不同，就像"1.2×10³ + 3.4×10²"不能直接加，需要先对齐指数。

**五步运算流程**：

```
对阶 → 尾数求和 → 规格化 → 舍入 → 判溢出
```

**完整示例：计算 0.5 + (-0.4375) 的浮点加减**

```
第 0 步：将两个数转为 IEEE754 格式

X = 0.5₁₀ = 0.1₂ = 1.0₂ × 2⁻¹
  S=0, E=-1+127=126=0111 1110₂, M=000...0
  X浮 = 0 01111110 00000000000000000000000

Y = -0.4375₁₀ = -0.0111₂ = -1.11₂ × 2⁻²
  S=1, E=-2+127=125=0111 1101₂, M=1100...0
  Y浮 = 1 01111101 11000000000000000000000

第 1 步：对阶（小阶向大阶看齐）
  X 的阶码 = 126, Y 的阶码 = 125
  Y 的阶码小 → Y 的尾数右移 (126-125)=1 位，Y 阶码 = 126
  Y 的尾数 = 1.11 → 右移 1 位 → 0.111（低位丢失一个 1）
  （对阶后 Y 尾数 = 0.1110...0）

第 2 步：尾数求和
  X 的尾数 = 1.000...0
  Y 的尾数 = -0.111...0（注意符号位为负）
  结果 = 1.000...0 - 0.111...0 = 0.001...0

第 3 步：规格化
  0.001...0 → 左移 2 位 → 1.0...0 × 2^(-2)
  阶码 = 126 - 2 = 124

第 4 步：舍入
  结果恰好精确，不需要舍入

第 5 步：判溢出
  阶码 124 在 1~254 范围内，无溢出

最终结果：0.5 + (-0.4375) = 0.0625
IEEE754 格式：0 01111100 00000000000000000000000
```

#### 浮点加减运算中的舍入方法

| 方法 | 规则 | 特点 |
|------|------|------|
| **0 舍 1 入** | 被舍弃部分最高位为 0 则舍，为 1 则入 | 类似十进制四舍五入，最常用 |
| **恒置 1 法** | 无论舍去什么，保留部分最低位置 1 | 简单，但可能有偏 |
| **截断法（朝 0 舍入）** | 直接截断，舍去多余位 | 最简单，但误差最大 |
| **朝 +∞ 舍入** | 结果向正无穷方向舍入 | 用于区间运算 |
| **朝 -∞ 舍入** | 结果向负无穷方向舍入 | 用于区间运算 |
| **就近舍入（偶数舍入）** | 舍入到最近值，.5 时舍入到偶数最低位 | **IEEE754 默认方式**，最精确 |

> **IEEE754 默认舍入方式**：就近舍入（Round to Nearest, Ties to Even）。当被舍部分恰好为 0.5 时，舍入到最低位为偶数的方向。这比"四舍五入"更公平——避免了统计上的偏向。

#### 浮点数加减运算常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **对阶方向** | 小阶向大阶看齐，尾数右移 | 口诀："小数跟大数，尾数右移" |
| **对阶丢失** | 尾数右移时低位丢失，造成精度损失 | 对阶差越大，精度损失越大 |
| **大数吃小数** | 两个浮点数指数差太大时，小数可能被完全吃掉 | 如 1.0×10¹⁰ + 1.0×10⁻¹⁰ ≈ 1.0×10¹⁰ |
| **规格化方向** | 尾数可能左规（结果 < 1）或右规（结果 ≥ 2） | 加减后尾数可能溢出需要右规 |
| **阶码溢出** | 规格化后阶码可能超出范围 | 上溢 → 置 ∞，下溢 → 置 0 或非规格化数 |
| **舍入后的再规格化** | 舍入可能导致尾数溢出（如 1.111...1 入成 10.000...0） | 舍入后需再检查是否需要规格化 |

### 31.5 数据校验码

| 校验码 | 能力 | 原理 |
|--------|------|------|
| 奇偶校验 | 检错（奇数位错） | 加一位使 1 的个数为奇/偶 |
| **海明码** | 检错+**纠错 1 位** | 多组奇偶校验，出错位=各组校验位组合 |
| CRC | 检错（极强） | 模 2 除法，余数=校验码 |

#### 奇偶校验——基础概念

**大白话类比**：奇偶校验就像"点人数"——给每个小组加一个"组长"，组长负责保证自己组里 1 的人数符合规定（奇数个或偶数个）。如果传输后人数不对了，组长就能发现出了问题。但组长不知道具体谁出了问题，只能"发现错了"。

**两种类型**：

| 类型 | 规则 | 校验位值 | 能检出什么 |
|------|------|---------|-----------|
| **奇校验** | 1 的总个数为奇数 | 补 0 或 1 使总 1 数为奇数 | 偶数个位出错 |
| **偶校验** | 1 的总个数为偶数 | 补 0 或 1 使总 1 数为偶数 | 奇数个位出错 |

> **奇偶校验的盲区**：如果有偶数个位同时出错，奇偶校验发现不了（偶数个错→1 的奇偶性不变）。所以只能检错不能纠错，且只能检奇数位错。

**奇偶校验例题**：
- 数据 1011 0010（4 个 1），若采用偶校验，校验位应该是多少？
  - 4 个 1 已经是偶数 → 校验位 = **0**（不需要补 1）
- 数据 1011 0011（5 个 1），若采用奇校验，校验位应该是多少？
  - 5 个 1 已经是奇数 → 校验位 = **0**（不需要补 1）

#### 海明码详解——校验位计算公式

**大白话类比**：海明码就像"分组点名"——把数据分成多个小组，每个组有一个组长（校验位）。如果某个组出错了，通过对各组的出错情况做"交叉定位"，就能精确找到哪个位置的数据出错了，直接把它翻过来纠错。

**核心公式**：2^k ≥ n + k + 1

- k = 校验位的位数
- n = 数据位的位数
- n + k + 1 中的 +1 表示"没有错误"这种情况

**海明码构建步骤**（以 4 位数据 1010 为例）：

```
第 1 步：确定校验位数 k
  2^k ≥ 4 + k + 1
  k=1: 2 < 6  ✗
  k=2: 4 < 7  ✗
  k=3: 8 ≥ 8  ✓ → k = 3

第 2 步：确定校验位位置
  校验位放在 2^0, 2^1, 2^2 位置，即第 1, 2, 4 位
  数据位放在其余位置，即第 3, 5, 6, 7 位

  位号: 7  6  5  4  3  2  1
  内容: D4 D3 D2 P3 D1 P2 P1

第 3 步：计算每个校验位
  P1 负责校验位号二进制最低位为 1 的位：1,3,5,7
  P2 负责校验位号二进制第 2 位为 1 的位：2,3,6,7
  P3 负责校验位号二进制第 3 位为 1 的位：4,5,6,7

  数据 1010：D1=1, D2=0, D3=1, D4=0
  P1 = D1⊕D2⊕D4 = 1⊕0⊕0 = 1
  P2 = D1⊕D3⊕D4 = 1⊕1⊕0 = 0
  P3 = D2⊕D3⊕D4 = 0⊕1⊕0 = 1

第 4 步：拼接海明码
  位号: 7  6  5  4  3  2  1
  内容: 0  1  0  1  1  0  1
  海明码 = 0101101
```

**纠错原理**：接收端重新计算校验位，与接收到的校验位比较。如 P1 和 P3 出错 → 出错位 = 1+4 = 5（位号 5）。

**海明码纠错例题**：
已知发送的海明码为 0101101，接收端收到的海明码为 0101100（第 1 位翻转）。接收端如何纠错？

```
接收端重新计算校验位：
  位号: 7  6  5  4  3  2  1
  收到: 0  1  0  1  1  0  0  ← 小心：P1 收到了 0

重新计算：
  P1_新 = D1⊕D2⊕D4 = 1⊕0⊕0 = 1
  P2_新 = D1⊕D3⊕D4 = 1⊕1⊕0 = 0
  P3_新 = D2⊕D3⊕D4 = 0⊕1⊕0 = 1

校验位比较：
  P1: 收到0 ≠ 计算1 → P1 出错，指错值 = 1
  P2: 收到0 = 计算0 → P2 正确，指错值 = 0
  P3: 收到1 = 计算1 → P3 正确，指错值 = 0

指错字 = 0×4 + 0×2 + 1×1 = 1 → 第 1 位出错！
将第 1 位 0 翻转为 1 → 纠错后 = 0101101
```

#### CRC（循环冗余校验码）详解

**大白话类比**：CRC 就像"除法验算"——把一整段数据当作一个超大的二进制数，除以一个固定的"除数"（生成多项式），得到的"余数"就是校验码。接收方用同样的除数再做一次除法，如果余数不为 0，说明数据在传输中出错了。这个方法极其可靠，能检测出几乎所有常见的错误模式。

**核心思想**：模 2 除法求余数，余数 = 校验码。

**关键概念**：

| 概念 | 说明 | 例子 |
|------|------|------|
| **生成多项式 G(x)** | 收发双方约定的"除数"，阶数 r 决定校验码位数 | G(x) = x³ + x + 1 → r=3，校验码 3 位 |
| **模 2 运算** | 无进位/借位的二进制运算，加减都用异或（XOR） | 1+1=0（不进位），1-1=0（不借位） |
| **模 2 除法** | 用异或代替减法做除法，每一步看最高位是否为 1 | 最高位为 1→商 1 做异或；最高位为 0→商 0 右移 |

**CRC 编码步骤**（以 4 位数据 1010，G(x)=x³+x+1 为例）：

```
第 1 步：确定生成多项式对应的二进制除数
  G(x) = x³ + x + 1 = 1·x³ + 0·x² + 1·x¹ + 1·x⁰
  二进制除数 = 1011（r=3，共 r+1=4 位）

第 2 步：数据后补 r 个 0
  原始数据 1010 → 补 3 个 0 → 1010000

第 3 步：模 2 除法
  1010000 ÷ 1011

  1010000
  1011↓↓↓   ← 异或
  ──────
  0001000
     1011   ← 对齐最高位1
     ────
     000110
        000
        ───
         110

  余数 = 110（3 位）

第 4 步：将余数替换掉补的 0
  发送数据 = 原始数据 + 余数 = 1010 110
```

**CRC 校验步骤**（接收端）：
```
接收端收到：1010 110
用同样的除数 1011 做模 2 除法：
  1010110 ÷ 1011 → 余数 = 000

余数为 0 → 数据正确！
余数非 0 → 数据出错！
```

**CRC 例题**：

**例题 1**：数据 1101，生成多项式 G(x)=x³+x²+1，求 CRC 码。

```
第 1 步：G(x) = 1·x³ + 1·x² + 0·x¹ + 1·x⁰ → 除数 = 1101，r=3
第 2 步：数据后补 3 个 0：1101 000
第 3 步：模 2 除法
  1101000 ÷ 1101
  1101000
  1101↓↓↓
  ──────
  0000000
    ↑ 被整除了！
  余数 = 000
第 4 步：CRC 码 = 1101 000
```

**例题 2**：已知 CRC 码为 1001 110（G(x)=x³+x²+1），接收端如何校验？

```
除数 = 1101
1001110 ÷ 1101

1001110
1101↓↓↓
──────
10001
1101↓
────
 1101
 1101
 ────
 0000

余数 = 0 → 数据正确！
```

#### 三种校验码对比

| 对比维度 | 奇偶校验 | 海明码 | CRC |
|---------|---------|--------|-----|
| 检错能力 | 弱（只能检奇数位错） | 强（检 2 位错） | **极强**（检突发错误） |
| 纠错能力 | **无** | **纠 1 位错** | 无 |
| 冗余位数量 | 1 位 | 约 log₂n 位 | 生成多项式阶数 r 位 |
| 实现复杂度 | 最简单 | 中等 | 中等（用移位寄存器实现简单） |
| 主要用途 | 内存校验 | 内存 ECC | 网络传输、磁盘存储 |
| 核心原理 | 统计 1 的个数 | 分组奇偶 + 交叉定位 | 模 2 除法取余数 |

#### 数据校验码真题自测

**真题 1**：若数据位 n=8，采用海明码检错纠错，至少需要（ ）位校验位。

- A. 3
- B. 4
- C. 5
- D. 6

**答案**：B。解析：2^k ≥ 8+k+1→k=3时 8<12✗；k=4时 16≥13✓。至少需要 **4 位**。

**真题 2**：CRC 校验中，生成多项式 G(x) 的阶数为 r，则校验码的位数为（ ）。

- A. r-1
- B. r
- C. r+1
- D. 2r

**答案**：B。生成多项式的阶数 r 就是校验码的位数（余数的位数 = 除数的位数 - 1 = r）。

**真题 3**：下列关于奇偶校验的说法中，正确的是（ ）。

- A. 奇偶校验可以检测并纠正 1 位错误
- B. 奇偶校验可以检测所有奇数位错误，但不能检测偶数位错误
- C. 奇偶校验可以检测所有偶数位错误，但不能检测奇数位错误
- D. 奇偶校验可以检测所有错误

**答案**：B。奇偶校验只能检测奇数位错误，偶数位错误会相互抵消，奇偶性不变。

#### 常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **海明码校验位放在 2^i 位置** | 校验位 P1/P2/P3 放在位号 1/2/4，不是连续的 | 口诀："1、2、4、8...校验位占位号" |
| **海明码公式的 +1 不能忘** | 2^k ≥ n+k+1，+1 表示"无错"状态 | 忘记 +1 会少算 1 位校验位 |
| **CRC 模 2 除法的"减法"用异或** | 模 2 除法不是普通除法，不进位不借位 | 1-1=0、1+1=0，都用异或 |
| **CRC 余数位数 = r** | 生成多项式阶数 r=3，余数就是 3 位 | 不要和除数位数 r+1 混淆 |
| **奇偶校验偶数位错检测不到** | 两个位同时翻转，1 的个数的奇偶性不变 | 奇偶校验不是万能的 |

#### 记忆口诀

- **海明码**："2^k ≥ n+k+1，多一个 1 表无错；校验位放 2 的幂，分组交叉定位错"
- **CRC**："模 2 除法求余数，余数就是校验码；接收端再做除法，余数为 0 才正确"
- **奇偶校验**："奇校验补成奇数，偶校验补成偶数；只能检奇数位错，偶数位错查不出"
- **三种校验总结**："奇偶看个数，海明能纠错，CRC 最强检"

### 31.6 字符编码

#### 31.6.1 ASCII 码——基础编码

**大白话类比**：ASCII 码就像"给字符发身份证号"——每个英文字母、数字、符号都有一个唯一的编号，计算机通过编号来识别和存储字符。A 的编号是 65，B 是 66，小写 a 是 97，数字 0 是 48。

**ASCII 码核心规则**（7 位标准 ASCII，0~127）：

| 字符类别 | 码值范围 | 规律 |
|---------|---------|------|
| 控制字符 | 0~31（0x00~0x1F） | 不可显示（回车、换行、退格等） |
| 空格 | 32（0x20） | 最小的可显示字符 |
| 数字 '0'~'9' | 48~57（0x30~0x39） | '0'=48，'1'=49，...，'9'=57 |
| 大写字母 'A'~'Z' | 65~90（0x41~0x5A） | 'A'=65，'B'=66，...，'Z'=90 |
| 小写字母 'a'~'z' | 97~122（0x61~0x7A） | 'a'=97，'b'=98，...，'z'=122 |
| DEL（删除） | 127（0x7F） | 最后一个控制字符 |

**ASCII 码三条铁律（必背）**：
- **'A' = 65（0x41）** ← 大写字母起始
- **'a' = 97（0x61）** ← 小写字母起始
- **'0' = 48（0x30）** ← 数字起始

**重要规律**：
- 大写字母和小写字母的 ASCII 码相差 **32**（'a' - 'A' = 97 - 65 = 32）
- 同一类字符的 ASCII 码是连续的：'A'~'Z' 连续，'a'~'z' 连续，'0'~'9' 连续
- 大小写转换：大写 + 32 = 小写（十进制），大写 | 0x20 = 小写（二进制）

**ASCII 码例题**：
- 'D' 的 ASCII 码是多少？ → 'A'=65，'D' = 'A' + 3 = **68**
- 'f' 的 ASCII 码是多少？ → 'a'=97，'f' = 'a' + 5 = **102**
- '8' 的 ASCII 码是多少？ → '0'=48，'8' = '0' + 8 = **56**

#### 31.6.2 汉字编码——三层编码体系

**大白话类比**：汉字编码就像"翻译三步曲"——
- **输入码**（拼音/五笔）= 你用什么方式"叫"这个字
- **国标码/区位码** = 这个字在"国家标准字典"里的编号
- **机内码** = 计算机内部存储时实际用的编号（防止和 ASCII 码冲突）

**四码关系图**：

```
输入码（拼音/五笔/郑码）
    ↓ 输入法转换
区位码（GB2312 的 94×94 表格：区号+位号）
    ↓ 区号+32、位号+32
国标码（GB2312 标准编码）
    ↓ 每个字节最高位置 1（+0x80）
机内码（计算机内部存储用）
```

**四码转换公式**：

| 转换 | 公式 | 说明 |
|------|------|------|
| 区位码 → 国标码 | 国标码 = 区位码 + 0x2020 | 区号、位号各加 32（0x20） |
| 国标码 → 机内码 | 机内码 = 国标码 + 0x8080 | 每个字节最高位置 1（+0x80） |
| 区位码 → 机内码 | 机内码 = 区位码 + 0xA0A0 | 区号、位号各加 160（0xA0） |

**为什么要加 0x8080？** 机内码的高位置 1 是为了和 ASCII 码区分。ASCII 码的范围是 0x00~0x7F（最高位为 0），汉字机内码每个字节最高位都是 1，这样计算机就能区分"这个字节是 ASCII 字符还是汉字的一部分"。

**汉字编码例题**：

某汉字的区位码为 1601（第 16 区第 01 位），求其国标码和机内码。

```
区位码：16 01 → 十六进制: 0x10 0x01

国标码 = 区位码 + 0x2020
  = (0x10+0x20) (0x01+0x20) = 0x30 0x21

机内码 = 国标码 + 0x8080
  = (0x30+0x80) (0x21+0x80) = 0xB0 0xA1
```

#### 31.6.3 GB2312 编码体系

| 概念 | 含义 |
|------|------|
| **GB2312** | 中国国家标准简体中文字符集，收录 6763 个汉字 |
| **区位码** | 94 区 × 94 位的矩阵，区号 1~94，位号 1~94 |
| **一级汉字** | 3755 个常用汉字，按拼音排序（16~55 区） |
| **二级汉字** | 3008 个次常用汉字，按部首排序（56~87 区） |
| **GBK** | GB2312 的扩展，收录 21886 个汉字 |
| **GB18030** | 最新的国标编码标准，收录 70244 个汉字 |

#### 31.6.4 Unicode 与 UTF-8

**大白话类比**：Unicode 就像"全球字符大字典"——给世界上所有语言的所有字符都分配一个唯一的编号（码点）。UTF-8 是 Unicode 的一种实现方式，用 1~4 个字节来表示一个字符，英文用 1 字节（和 ASCII 兼容），中文用 3 字节。

| 编码 | 字节数 | 兼容 ASCII | 主要用途 |
|------|--------|-----------|---------|
| **ASCII** | 1 字节 | — | 英文 |
| **GB2312/GBK** | 2 字节 | 否（高位=1） | 中文（中国大陆） |
| **UTF-8** | 1~4 字节（中文 3 字节） | **是** | 国际化、互联网 |
| **UTF-16** | 2 或 4 字节 | 否 | Windows 内部编码 |

**UTF-8 编码规则**：

| Unicode 范围 | UTF-8 字节数 | 字节格式 |
|-------------|------------|---------|
| U+0000 ~ U+007F | 1 字节 | 0xxxxxxx |
| U+0080 ~ U+07FF | 2 字节 | 110xxxxx 10xxxxxx |
| U+0800 ~ U+FFFF | 3 字节 | 1110xxxx 10xxxxxx 10xxxxxx |
| U+10000 ~ U+10FFFF | 4 字节 | 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx |

**编码例题**：
- 'A' 的 UTF-8 编码：U+0041，在 U+0000~U+007F 范围，用 1 字节 → 0x41（和 ASCII 完全一致）
- '中' 的 UTF-8 编码：U+4E2D，在 U+0800~U+FFFF 范围，用 3 字节

#### 字符编码常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **ASCII 码三条必背值** | 'A'=65, 'a'=97, '0'=48 | 用"65-97-48"牢记 |
| **大小写差 32** | 'a' - 'A' = 32，二进制位 5 翻转 | 大写位 5=0，小写位 5=1 |
| **区位码→国标码各加 32** | 是区号和位号各加 0x20，不是整体加 | 分开加，不是合起来加 |
| **国标码→机内码各加 128** | 每个字节最高位从 0 变成 1 | 加 0x80 就是最高位置 1 |
| **GB2312 用 2 字节，UTF-8 中文用 3 字节** | 不同编码体系，存储同一汉字字节数不同 | 不要混淆 GB2312 和 UTF-8 的字节数 |
| **ASCII 是 7 位编码，但存储占 1 字节** | 标准 ASCII 只用 7 位（0~127），但实际存储占 1 字节 | 扩展 ASCII 用了 8 位（128~255） |

#### 记忆口诀

- **ASCII 核心**："A65 a97，0 是 48；大小写差 32，数字连续排"
- **汉字编码**："区位+32 得国标，国标+128 机内码；机内高位全变 1，区分 ASCII 有妙法"
- **Unicode vs UTF-8**："Unicode 给编号，UTF-8 管存储；英文 1 字节中文 3，兼容 ASCII 最方便"

## 知识点 32：多级层次的存储系统

> **考点星级**：Cache映射=必考⭐⭐⭐ | 其余概念=中频⭐

### 32.1 存储层次结构

```
寄存器 → Cache(L1/L2/L3) → 主存(DRAM) → 辅存(SSD/HDD)
← 速度越快，容量越小，价格越贵 →
```

> 全部数据在辅存，常用数据在内存，最常用数据在 Cache，正在用的在寄存器。

**大白话类比**：存储层次就像"你工作时找东西"——
- **寄存器** = 你手里正拿着的东西（0 延迟，但手只能拿几样）
- **Cache** = 你桌上的东西（伸手就拿，容量有限）
- **主存（内存）** = 你身后的书架（站起来走两步，容量大一些）
- **辅存（硬盘）** = 公司仓库（要走很远，但容量巨大）

你常用的东西放桌上，偶尔用的放书架，很少用的存仓库。这就是"局部性原理"——程序也是按这个规律访问数据的。

**局部性原理**：
- **时间局部性**：刚用过的东西，可能马上又要用（比如循环变量）
- **空间局部性**：用了一个东西，它旁边的可能也要用（比如数组遍历）

### 32.2 SRAM vs DRAM

| 对比 | SRAM（静态） | DRAM（动态） |
|------|------------|------------|
| 存储元 | 六管 MOS 触发器 | 电容 + 单管 |
| 速度 | 快 | 慢 |
| 集成度 | 低 | 高 |
| 功耗 | 大 | 小 |
| 刷新 | 不需要 | **需要刷新** |
| 价格 | 贵 | 便宜 |
| 用途 | **Cache** | **主存** |

> **DRAM 为什么需要刷新？** 电容会漏电，必须定期"补电"（刷新）来保持数据。

**大白话类比**：DRAM 的电容就像"漏水的杯子"——即使放着不动，里面的水（电荷）也会慢慢漏掉。所以必须定期往杯子里加水（刷新），不然数据就丢了。SRAM 用的触发器就像"带盖子的密封杯"，不漏水，不需要刷新，但做起来更复杂更贵。

### 32.3 DRAM 刷新方式

| 方式 | 做法 | 优缺点 |
|------|------|--------|
| 集中刷新 | 一段时间内集中刷新所有行 | 有"死时间"（刷新时不能读写） |
| 分散刷新 | 每个读写周期后刷新一行 | 无死时间，但刷新太频繁 |
| **异步刷新** | 分散在刷新周期内均匀刷新 | **折中方案，最常用** |

### 32.4 Cache 与主存的映射方式

#### 三种映射方式详解

| 映射方式 | 规则 | 优点 | 缺点 |
|---------|------|------|------|
| **直接映射** | 每个主存块 → 固定 Cache 行 | 简单，成本低 | 冲突多 |
| **全相联映射** | 任意主存块 → 任意 Cache 行 | 冲突少 | 硬件复杂，比较器多 |
| **组相联映射** | 先分组，组内全相联 | **折中方案，最常用** | |

**大白话类比**：Cache 映射就像"办公室工位分配"——
- **直接映射** = 每个人有固定工位。张三只能坐 3 号位，即使 3 号位被占了也只能等，别的空位不能用。简单但冲突多。
- **全相联映射** = 自由工位，来了随便坐哪都行。灵活但需要前台系统（硬件比较器）记录每个人坐哪，成本高。
- **组相联映射** = 分部门，每个部门有 4 个工位。张三在技术部，技术部 4 个工位里随便坐。折中方案——比固定工位灵活，比自由工位简单。

#### 三种映射方式的地址结构

**（1）直接映射——地址划分**

```
主存地址 = | Tag（标记）| 行号（Line）| 块内偏移（Offset）|
```

- **块内偏移（Offset）**：块大小 = 2^b → 占 b 位
- **行号（Line）**：Cache 行数 = 2^c → 占 c 位
- **Tag（标记）**：主存地址总位数 - c - b

**（2）全相联映射——地址划分**

```
主存地址 = | Tag（标记）| 块内偏移（Offset）|
```

- 没有行号字段，Tag 和所有 Cache 行的 Tag 同时比较
- Tag 位数 = 主存地址总位数 - b

**（3）组相联映射——地址划分**

```
主存地址 = | Tag（标记）| 组号（Set）| 块内偏移（Offset）|
```

- Cache 组数 = 总块数 / 路数（每组的块数）→ 组号占 log₂(组数) 位
- Tag 位数 = 主存地址总位数 - 组号位数 - b

#### Cache 地址映射计算例题

**例题 1：直接映射地址计算**

主存容量 128MB，按字节编址。Cache 容量 8KB，每块 32B。求标记 Tag 位数。

```
① 主存地址总位数：128MB = 2^27 → 27 位
② 块内偏移：32B = 2^5 → 5 位
③ Cache 行数：8KB/32B = 256 = 2^8 → 行号 8 位
④ Tag = 27 - 8 - 5 = 14 位
```

**例题 2：组相联映射地址计算**

主存 256MB，Cache 64KB，每块 16B，4 路组相联。

```
① 块内偏移：16B = 2^4 → 4 位
② Cache 总块数：64KB/16B = 4096 = 2^12 块
③ 组数：4096/4 = 1024 = 2^10 → 组号 10 位
④ 主存地址总位数：256MB = 2^28 → 28 位
⑤ Tag = 28 - 10 - 4 = 14 位
```

**例题 3：全相联映射地址计算**

主存 64MB，Cache 每块 64B，全相联映射。

```
① 块内偏移：64B = 2^6 → 6 位
② 主存地址总位数：64MB = 2^26 → 26 位
③ Tag = 26 - 6 = 20 位
④ 需要 20 位的比较器与所有 Cache 行同时比较
```

### 32.5 Cache 替换算法

| 算法 | 规则 | 特点 |
|------|------|------|
| 随机（RAND） | 随便踢一个 | 简单，效果不稳定 |
| FIFO | 踢最早进来的 | 简单，但可能踢掉常用块 |
| **LRU** | 踢最久没用的 | 效果好，需要硬件记录访问顺序 |
| LFU | 踢用得最少的 | 考虑频率，但新块可能被误踢 |

**大白话类比**：Cache 满了要踢人，就像"冰箱满了要扔掉一些东西"——
- **随机** = 闭眼随便扔一个（简单粗暴）
- **FIFO** = 扔最早放进来的（先买的先扔，可能会把常用的鸡蛋扔掉）
- **LRU** = 扔最久没动过的（最合理，但需要记住每样东西多久没动）
- **LFU** = 扔用得次数最少的（新买的调料只用过一次就被扔了，也未必合理）

#### LRU 替换算法详解（组相联中的实现）

对于 4 路组相联，LRU 需要记录组内 4 块的使用顺序：
- 用 2 位二进制计数器（00~11）记录每块上次被访问的"时间戳"
- 每次访问命中时更新计数器
- 替换时选择计数值最大（最久未用）的块

**LRU 替换示例**（4 路组相联，组内初始为空）：

```
访问序列：A → B → C → D → A → E

步骤1: A 装入 → 组内: [A,空,空,空]
步骤2: B 装入 → 组内: [A,B,空,空]
步骤3: C 装入 → 组内: [A,B,C,空]
步骤4: D 装入 → 组内: [A,B,C,D]（满）
步骤5: A 命中 → 更新 A 为最新访问
步骤6: E 装入 → 替换最久未用的 B → 组内: [A,E,C,D]
```

#### FIFO 替换示例

```
访问序列：A → B → C → D → A → E

步骤1: A 装入 → 组内: [A,空,空,空]
步骤2: B 装入 → 组内: [A,B,空,空]
步骤3: C 装入 → 组内: [A,B,C,空]
步骤4: D 装入 → 组内: [A,B,C,D]（满）
步骤5: A 命中 → FIFO 不更新顺序，组内仍: [A,B,C,D]
步骤6: E 装入 → 替换最早进入的 A → 组内: [E,B,C,D]
```

> **关键区别**：LRU 在命中时会更新访问顺序，FIFO 不会。所以步骤 5 命中 A 后，LRU 把 A 标记为最新，而 FIFO 不改变顺序——导致步骤 6 时 LRU 替换 B，FIFO 替换 A。

#### Cache 替换算法真题

**真题 1**：某 Cache 采用 4 路组相联映射，共 4 组，每组 4 块。初始为空，访问序列为：1, 2, 3, 4, 1, 5, 1, 2, 3, 4, 5, 1。若采用 LRU 替换算法，求命中次数。（假设地址 1~5 映射到同一组）

```
逐次模拟（同一组内，4 路）：

序号 访问  组内状态（最近→最久）    命中/缺失
1    1     [1,_,_,_]               缺失
2    2     [2,1,_,_]               缺失
3    3     [3,2,1,_]               缺失
4    4     [4,3,2,1]               缺失（满）
5    1     [1,4,3,2]               命中！
6    5     [5,1,4,3]               缺失（替换最久未用的 2）
7    1     [1,5,4,3]               命中！
8    2     [2,1,5,4]               缺失（替换 3）
9    3     [3,2,1,5]               缺失（替换 4）
10   4     [4,3,2,1]               缺失（替换 5）
11   5     [5,4,3,2]               缺失（替换 1）
12   1     [1,5,4,3]               缺失（替换 2）

命中次数 = 2 次（第 5 次和第 7 次）
命中率 = 2/12 ≈ 16.7%
```

**真题 2**：下列关于 Cache 替换算法的说法中，正确的是（ ）。

- A. FIFO 算法的命中率总是高于 LRU 算法
- B. LRU 算法利用了时间局部性原理，命中率通常优于 FIFO
- C. 随机替换算法的命中率总是最低的
- D. LFU 算法不会出现"新块被误踢"的问题

**答案**：B。LRU 利用时间局部性（最近用过的很可能再用），命中率通常优于 FIFO；随机替换在某些特殊情况下可能优于 FIFO；LFU 的新块因为访问次数少容易被误踢。

**真题 3**：下列哪种替换算法可能出现 Belady 异常？（ ）

- A. LRU
- B. FIFO
- C. LFU
- D. 随机替换

**答案**：B。Belady 异常是指增加页框数反而导致缺页次数增多，FIFO 算法可能出现此异常，LRU 和 CLOCK 算法不会。

#### Cache 替换算法常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **LRU 命中后要更新顺序** | 命中后该块变成"最新"，FIFO 不更新 | LRU 命中=更新位置，FIFO 命中=位置不变 |
| **FIFO 有 Belady 异常** | 增加块数反而命中率降低 | LRU 和最佳置换没有此异常 |
| **LFU 新块劣势** | 刚调入的块访问次数少，容易被踢 | LFU 对"新热点"不友好 |
| **随机替换有时意外好** | 在某些访问模式下，随机可能比 FIFO 好 | 不要绝对化"随机最差" |

#### 记忆口诀

- **替换算法**："FIFO 踢最早，LRU 踢最久，LFU 踢最少，随机闭眼搞"
- **LRU vs FIFO**："LRU 命中就更新，FIFO 命中原地等"
- **Belady 异常**："FIFO 加页反增缺，LRU 加页只受益"

### 32.6 Cache 写策略

| 策略 | 写命中时 | 写不命中时 |
|------|---------|-----------|
| **写直达**（Write Through） | 同时写 Cache 和主存 | 直接写主存（非写分配） |
| **写回**（Write Back） | 只写 Cache，标记脏位 | 先把主存块调入 Cache 再写（写分配） |

> 常用组合：**写直达 + 非写分配**（简单）或 **写回 + 写分配**（性能好）

#### 写策略深入对比

| 对比维度 | 写直达（Write Through） | 写回（Write Back） |
|---------|----------------------|-------------------|
| 写操作延迟 | 大（每次写都要等主存） | 小（只写 Cache） |
| 主存流量 | 大（每次写都访问主存） | 小（只在替换脏块时写回） |
| 一致性 | 好（Cache 和主存始终一致） | 差（需要额外机制保证一致性） |
| 实现复杂度 | 简单 | 复杂（需要脏位管理） |
| 适用场景 | 单处理器、小 Cache | 多处理器、大 Cache |

**脏位（Dirty Bit）**：写回策略中，每个 Cache 块有一个"脏位"标记。如果该块被修改过（和主存不一致），脏位=1；替换时如果脏位=1，需要先写回主存。

### 32.7 Cache 性能计算

**平均访问时间**：ta = **h × tc + (1-h) × tm**

- h = 命中率（通常 > 90%）
- tc = Cache 访问时间
- tm = 主存访问时间

**例题**：h=0.95, tc=1ns, tm=100ns，求平均访问时间。
- ta = 0.95 × 1 + 0.05 × 100 = 0.95 + 5 = **5.95ns**

#### Cache 命中率计算题专项训练

**题 1：基础命中率计算**

某计算机 Cache 命中率 h=0.98，tc=2ns，tm=80ns。求：
(1) 平均访问时间 ta
(2) 使用 Cache 后的加速比（相对于全部访问主存）

**解答**：
(1) ta = h × tc + (1-h) × tm = 0.98×2 + 0.02×80 = 1.96 + 1.6 = **3.56ns**

(2) 不用 Cache 时每次访问都是 tm=80ns
加速比 = 80/3.56 ≈ **22.47 倍**

**题 2：命中率变化对性能的影响**

tc=1ns，tm=100ns。分别计算 h=0.90、h=0.95、h=0.99 时的平均访问时间，并分析命中率每提升 1% 带来的收益。

**解答**：

| 命中率 h | ta = h×1 + (1-h)×100 | 相比上一档提升 |
|---------|----------------------|--------------|
| 0.90 | 0.9 + 10 = **10.9ns** | — |
| 0.95 | 0.95 + 5 = **5.95ns** | 快 45.4% |
| 0.99 | 0.99 + 1 = **1.99ns** | 快 66.6% |

> 结论：命中率从 90% 提到 99%，性能提升约 **5.5 倍**。失效率（1-h）每降低一半，ta 中未命中部分就减半——**失效率才是关键指标**。

**题 3：tc 和 tm 变化的影响**

某系统 Cache 命中率 h=0.95。

场景 A：tc=2ns, tm=50ns
场景 B：tc=2ns, tm=200ns（主存慢了 4 倍）
场景 C：tc=5ns, tm=50ns（Cache 慢了 2.5 倍）

分别计算三种场景的 ta，并分析哪个参数变化对性能影响更大。

**解答**：

场景 A：ta = 0.95×2 + 0.05×50 = 1.9 + 2.5 = **4.4ns**

场景 B：ta = 0.95×2 + 0.05×200 = 1.9 + 10 = **11.9ns**（相比 A 慢了 2.7 倍）

场景 C：ta = 0.95×5 + 0.05×50 = 4.75 + 2.5 = **7.25ns**（相比 A 慢了 1.65 倍）

> 结论：当命中率很高时，**Cache 访问时间 tc 的变化对性能影响更大**（因为命中部分占主导）；主存时间 tm 虽大但只有不命中时才会用到。但 tm 越大，失效率的影响越显著。

**题 4：多级 Cache 平均访问时间**

某系统有 L1 Cache 和 L2 Cache：
- L1 命中率 h1 = 0.90，t1 = 1ns
- L2 命中率 h2 = 0.95（L1 不命中时，L2 的命中率），t2 = 10ns
- 主存 tm = 100ns

**大白话**：L1 没命中 → 去 L2 找 → L2 也没命中 → 去主存找。一级一级往下找。

**公式**：ta = h1×t1 + (1-h1)×h2×(t1+t2) + (1-h1)×(1-h2)×(t1+t2+tm)

> 注意：L1 不命中后，要先花 t1 时间发现不命中，再花 t2 时间访问 L2。

**解答**：

ta = 0.90×1 + 0.10×0.95×(1+10) + 0.10×0.05×(1+10+100)
   = 0.9 + 0.095×11 + 0.005×111
   = 0.9 + 1.045 + 0.555
   = **2.5ns**

> 如果不分层，全部用主存：每次 100ns。两级 Cache 把访问时间压缩到了 2.5ns，加速约 40 倍。

**题 5：综合——给定 ta 反推命中率**

已知 tc=1ns, tm=100ns，要求平均访问时间不超过 2ns，Cache 命中率至少需要多少？

**解答**：

ta = h×1 + (1-h)×100 ≤ 2
h + 100 - 100h ≤ 2
100 - 99h ≤ 2
99h ≥ 98
h ≥ 98/99 ≈ **0.9899**

> 命中率至少需要 **98.99%**。可见 Cache 命中率要求极其苛刻。

### 32.8 虚拟存储器（Virtual Memory）

> 虚拟存储器是"给每个程序一个假象"——每个程序都觉得"整个内存都是我一个人的"，但实际上操作系统在背后偷偷把程序切成页，常用的放内存，不常用的放硬盘。

**核心思想**：将主存和辅存统一编址，形成逻辑上的"大内存"。
- **虚拟地址（逻辑地址）**：程序员看到的地址，每个程序从 0 开始
- **物理地址（实地址）**：主存中实际的物理位置
- **地址转换**：虚拟地址 → 物理地址（由 MMU 硬件完成）

**大白话类比**：虚拟存储器就像"图书馆的借阅系统"——
- 你（程序）认为整个图书馆的书（数据）都在你桌上
- 实际上你桌上只有 10 本（内存），其他 10000 本在书库里（硬盘）
- 你需要哪本，管理员（MMU）就去书库取来，替换掉桌上不用的
- 你完全不用管书在桌上还是书库里——这就是"虚拟"的含义

#### 页式虚拟存储器

**核心概念**：

| 概念 | 含义 | 谁决定大小 |
|------|------|-----------|
| **页（Page）** | 虚拟地址空间的分块，大小固定 | 系统设计决定（通常 4KB） |
| **页框/页帧（Page Frame）** | 物理内存的分块，与页大小相同 | 等于页大小 |
| **页表（Page Table）** | 记录每页对应的页框号，存在主存中 | 每个进程一张页表 |
| **页表项（PTE）** | 页表中的一条记录，包含页框号 + 控制位 | 每页一条 |

**页式地址转换过程**：

```
虚拟地址 = | 页号 P | 页内偏移 W |

第 1 步：用页号 P 查页表，找到对应的页表项
第 2 步：从页表项中取出页框号 F
第 3 步：物理地址 = 页框号 F × 页大小 + 页内偏移 W
       （实际就是拼接：物理地址 = | 页框号 F | 页内偏移 W |）
```

**页表项（PTE）的结构**：

| 字段 | 含义 |
|------|------|
| **页框号** | 该页在物理内存中的位置 |
| **有效位（Valid/Present）** | 1=该页在内存中，0=该页在磁盘上（缺页） |
| **修改位（Dirty）** | 1=该页被修改过，替换时需要写回磁盘 |
| **访问位（Accessed）** | 1=该页最近被访问过，用于页面替换算法 |
| **保护位（Protection）** | 读/写/执行权限 |

**缺页中断（Page Fault）**：当访问的页有效位=0（不在内存中）时，触发缺页中断，操作系统将该页从磁盘调入内存。如果内存已满，先替换掉一页。

#### 页面替换算法

| 算法 | 规则 | 特点 |
|------|------|------|
| **FIFO** | 替换最早调入的页 | 简单，但可能替换常用页（Belady 异常） |
| **LRU** | 替换最久未用的页 | 效果好，但硬件实现成本高 |
| **CLOCK（NRU）** | 循环扫描，给"第二次机会" | **近似 LRU，实际最常用** |
| **OPT（最佳）** | 替换未来最久才用的页 | 理论上最优，但无法实现（需要预知未来） |

**Belady 异常**：FIFO 算法中，增加页框数反而导致缺页次数增多——这违反直觉。LRU 和 CLOCK 不会出现这个异常。

#### 段式与段页式

| 方式 | 划分方式 | 地址结构 | 优点 | 缺点 |
|------|---------|---------|------|------|
| **页式** | 固定大小页 | 页号 + 页内偏移 | 简单，无外部碎片 | 不考虑程序逻辑，一页可能跨函数 |
| **段式** | 按逻辑段（代码段、数据段、堆栈段） | 段号 + 段内偏移 | 符合程序逻辑，便于共享和保护 | 段大小不一，有外部碎片 |
| **段页式** | 先分段，段内再分页 | 段号 + 段内页号 + 页内偏移 | 兼有两者的优点 | 地址转换最复杂（查两次表） |

### 32.9 TLB（快表/Translation Lookaside Buffer）

> TLB 是"页表项的 Cache"——把最近用过的页表项缓存起来，减少访存次数。

**为什么需要 TLB？** 页表存在主存中，每次访问内存都先要查页表（至少 1 次额外访存），这严重拖慢速度。TLB 把常用的页表项放在 CPU 内部的高速缓存中，绝大多数情况不需要去主存查页表。

**带 TLB 的地址变换流程**：

```
第 1 步：CPU 发出虚拟地址
第 2 步：用页号查 TLB
    ├─ TLB 命中 → 直接得到页框号 → 拼接物理地址 → 访问内存
    └─ TLB 不命中 → 查页表（访存）→ 得到页框号 → 更新 TLB → 拼接物理地址
```

**TLB 的关键参数**：

| 参数 | 典型值 | 说明 |
|------|--------|------|
| TLB 条目数 | 64~1024 条 | 条目数越少，不命中率越高 |
| 命中时间 | 0.5~1 个时钟周期 | TLB 命中几乎不增加延迟 |
| 不命中时间 | 10~100 个时钟周期 | 需要查页表（访存） |
| 命中率 | > 99% | 实际程序中 TLB 命中率极高 |

**TLB 和 Cache 的访问组合**：

| 方式 | 做法 | 说明 |
|------|------|------|
| **串行访问** | 先 TLB 转换地址 → 再用物理地址访问 Cache | 简单，但 TLB 不命中时延迟大 |
| **并行访问** | 用虚拟地址的页内偏移部分直接访问 Cache 索引，同时 TLB 转换 | Cache 用虚拟索引+物理 Tag，速度快 |

**TLB 平均访问时间**：
```
ta = TLB命中率 × (TLB访问时间 + Cache访问时间)
   + TLB不命中率 × (TLB访问时间 + 页表访问时间 + Cache访问时间)
```

## 知识点 33：指令系统

> **考点星级**：CISCvsRISC=高频⭐⭐ | 寻址方式=中频⭐

### 33.1 指令格式——操作码与地址码

> 指令 = **操作码**（OP，告诉 CPU 做什么）+ **地址码**（A，告诉 CPU 操作数在哪）

**指令字长**：一条指令占多少位，可以是定长或变长。定长指令所有指令长度一样（如 MIPS 的 32 位）；变长指令长度不一（如 x86 从 1 字节到 15 字节）。

#### 按地址码数量分类（4 种指令格式）

| 类型 | 格式 | 执行操作 | 特点 | 适用场景 |
|------|------|---------|------|---------|
| **三地址指令** | OP A1, A2, A3 | (A1) ← (A2) OP (A3) | 最直观，但指令长 | 早期计算机（如 IBM 360） |
| **二地址指令** | OP A1, A2 | (A1) ← (A1) OP (A2) | **最常用**：结果覆盖一个源操作数 | x86、ARM 等现代处理器 |
| **单地址指令** | OP A | ACC ← (ACC) OP (A) | 隐含累加器 ACC，指令短 | 早期 8 位微处理器（如 8080） |
| **零地址指令** | OP | 无操作数（如 HALT, NOP） | 指令最短，特殊用途 | 停机、空操作、子程序返回 |

**具体例子**：
- 计算 `D = (A + B) × C` 的各种指令格式实现：

```
三地址指令实现：
ADD D, A, B    ; D ← A + B
MUL D, D, C    ; D ← D × C

二地址指令实现：
MOV R1, A      ; R1 ← A（先把操作数装入寄存器）
ADD R1, B      ; R1 ← R1 + B
MUL R1, C      ; R1 ← R1 × C
MOV D, R1      ; D ← R1（存回内存）

单地址指令实现（需要 ACC 累加器）：
LOAD A         ; ACC ← A
ADD B          ; ACC ← ACC + B
MUL C          ; ACC ← ACC × C
STORE D        ; D ← ACC
```

> 核心洞察：地址数越少，每条指令越短，但完成同一计算需要的指令条数越多。二地址指令是性价比最高的折中方案。

#### 操作码设计方案

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **定长操作码** | 操作码固定位数（如高 6 位） | 译码简单，速度快 | 指令数受限 |
| **扩展操作码** | 操作码长度可变，短操作码可扩展为多条长操作码 | 支持更多指令 | 译码复杂 |

**扩展操作码例题**：
设指令字长 16 位，地址码各占 6 位，采用扩展操作码。
- 三地址指令：操作码占 16-6×3=4 位，最多 2⁴=16 条（可少用留扩展空间）
- 若三地址指令只用 15 条（0000~1110），剩下的 1111 作为扩展标志
- 二地址指令：操作码占 4+6=10 位，最多 2⁶=64 条（以 1111 开头的前缀）
- 依此类推，一地址指令和零地址指令可以更多

### 33.2 寻址方式详解（9 种）

**核心概念**：形式地址 A（指令中给出的地址码）→ 通过寻址方式 → 得到有效地址 EA（操作数的真实位置）。

#### 为什么要这么多寻址方式？

**大白话**：就像你找人可以有不同的方式——"他就站在你面前"（立即寻址）、"他在 3 号房间"（直接寻址）、"他留了张纸条说去了 5 号房间"（间接寻址）、"他走在队伍的第 i 个位置"（变址寻址）、"你从当前地方往东走 100 米"（相对寻址）。不同场景用不同的找法，CPU 也一样——不同的程序场景需要不同的寻址方式。

#### 立即寻址

| 项目 | 内容 |
|------|------|
| **含义** | 操作数**直接写在指令中**（就是指令的一部分） |
| **有效地址** | 不需要计算，操作数 = 指令中的立即数字段 |
| **访存次数** | **0 次**（取指令时操作数已经拿到了） |
| **优点** | 最快，取指令同时拿到操作数 |
| **缺点** | 操作数固定（编译时确定）、受指令字长限制 |
| **用途** | 赋初值（如 `MOV AX, 5`）、增量（`ADD AX, 1`） |
| **具体例子** | `ADD R1, #100` ← 把常数 100 加到 R1，100 就在指令中 |

#### 直接寻址

| 项目 | 内容 |
|------|------|
| **含义** | 指令中直接给出操作数在内存中的地址 |
| **有效地址** | EA = A（地址码就是有效地址） |
| **访存次数** | 1+1=2（取指令 1 次 + 取操作数 1 次） |
| **优点** | 简单直观，不需要额外计算 |
| **缺点** | 寻址范围受限（地址码字段位数决定的）、不适合程序浮动 |
| **用途** | 访问全局变量、固定地址的数据 |
| **具体例子** | `LOAD R1, 0x1000` ← 从内存地址 0x1000 读出数据装入 R1 |

#### 寄存器寻址

| 项目 | 内容 |
|------|------|
| **含义** | 操作数在寄存器中，指令中给寄存器编号 |
| **有效地址** | 不需要访存，操作数就在指定寄存器里 |
| **访存次数** | 0 次（寄存器是 CPU 内部的，不计访存） |
| **优点** | **速度最快**，指令短（寄存器编号只需几位） |
| **缺点** | 寄存器数量有限（RISC 通常 32 个，x86 早期只有 8 个） |
| **用途** | 几乎所有的运算操作数 |
| **具体例子** | `ADD R1, R2` ← R1←R1+R2，两个操作数都在寄存器中 |

#### 间接寻址

| 项目 | 内容 |
|------|------|
| **含义** | 指令给的地址码是一个"中间值"——它指向的地址里存放的才是操作数的地址 |
| **有效地址** | EA = (A)，先读地址码 A 的地址，取出的内容才是真正地址 |
| **访存次数** | 1+1+1=3（取指令 + 取地址 + 取操作数） |
| **优点** | 灵活，可以实现指针访问 |
| **缺点** | **访存次数多，速度慢** |
| **用途** | 指针、动态数据结构（链表） |
| **具体例子** | `LOAD R1, @0x1000` ← 先去 0x1000 地址读出"2000"，再去 0x2000 读出数据的值 |

#### 寄存器间接寻址

| 项目 | 内容 |
|------|------|
| **含义** | 寄存器里存的是操作数的地址（不是操作数本身） |
| **有效地址** | EA = (Ri)，寄存器的内容就是有效地址 |
| **访存次数** | 1 次（取指令后，用寄存器里的地址去访存取操作数） |
| **优点** | 比直接间接寻址少一次访存，比寄存器寻址灵活 |
| **缺点** | 需要先给寄存器装入地址值 |
| **用途** | 循环遍历数组（地址在寄存器中递增即可） |
| **具体例子** | `LOAD R1, (R2)` ← R2 里存放的是地址，去那个地址取数据装到 R1 |

#### 相对寻址

| 项目 | 内容 |
|------|------|
| **含义** | 以程序计数器 PC 为基准，加上指令中的偏移量 |
| **有效地址** | **EA = (PC) + A**（PC 内容 + 指令中的偏移量） |
| **访存次数** | 取决于目标（取指令 + 若跳转则取新指令） |
| **优点** | **程序可浮动**：代码不管加载到内存哪个位置都能正确跳转 |
| **缺点** | 偏移量有范围限制（受指令字段位数制约） |
| **用途** | **转移指令、分支跳转**（if-else、循环） |
| **具体例子** | `JMP +8` ← PC←PC+8，跳转到当前指令后 8 个字节处 |
| **关键细节** | 取指后 PC 已自动加 1（或加指令长度），偏移量 A 用补码表示（可正可负） |

#### 基址寻址

| 项目 | 内容 |
|------|------|
| **含义** | 以基址寄存器为基准 + 形式地址 = 有效地址 |
| **有效地址** | **EA = (BR) + A**（BR 存基地址，A 是偏移量） |
| **访存次数** | 1 次（取指令后访存取操作数） |
| **优点** | 程序重定位、支持多道程序（不同程序用不同 BR 值即可） |
| **缺点** | 需要专门的基址寄存器 |
| **用途** | **操作系统进行程序重定位**、分段管理 |
| **具体例子** | 程序 A 的 BR=0x5000，LOAD 操作数偏移 A=0x0100，真正地址=0x5100 |

#### 变址寻址

| 项目 | 内容 |
|------|------|
| **含义** | 以形式地址为基准 + 变址寄存器内容 = 有效地址 |
| **有效地址** | **EA = A + (IX)**（A 是形式地址/数组起始地址，IX 存偏移/下标） |
| **访存次数** | 1 次 |
| **优点** | **数组访问的完美方案**——变址寄存器做下标，自动递增 |
| **缺点** | 需要专门的变址寄存器 |
| **用途** | **数组遍历、字符串处理** |
| **具体例子** | 数组 data[0] 的起始地址 A=0x2000，IX=3 时 EA=0x2003(即 data[3]) |

> **基址 vs 变址 对比**（此为重点辨析）：
> - **基址寻址**：BR 的内容是**不变的**（给了基准地址），偏移量 A 可变 → **面向操作系统**，解决程序重定位
> - **变址寻址**：形式地址 A 是**不变的**（数组首地址），变址寄存器 IX 可变 → **面向用户程序**，解决数组和循环
> - 记忆口诀："基址不变 A 可变（OS 做重定位），变址不变成 A 首（程序员写数组）"

#### 堆栈寻址

| 项目 | 内容 |
|------|------|
| **含义** | 操作数隐含在栈顶，由 SP（栈指针）指向 |
| **有效地址** | EA = (SP)，即栈顶的地址 |
| **访存次数** | 0（push/pop 通过 SP 隐含操作） |
| **优点** | 不用在指令中指定操作数地址，指令最短 |
| **缺点** | 只能操作栈顶数据，不适用于随机访问 |
| **用途** | 子程序调用（保存/返回地址）、函数参数传递、表达式求值 |
| **具体例子** | `PUSH R1` ← (SP)←(SP)-1，((SP))←R1（入栈）；`POP R1` ← R1←((SP))，(SP)←(SP)+1（出栈） |

#### 九种寻址方式总结表

| 寻址方式 | 公式 | 访存次数 | 速度 | 主要用途 |
|---------|------|---------|------|---------|
| 立即寻址 | 操作数=指令中立即数 | 0 | 最快 | 赋常量 |
| 寄存器寻址 | 操作数=(Ri) | 0 | 最快 | 通用计算 |
| 直接寻址 | EA=A | 1 | 中 | 全局变量 |
| 相对寻址 | EA=(PC)+A | 0(或1) | 中 | 分支跳转 |
| 基址寻址 | EA=(BR)+A | 1 | 中 | 程序重定位（OS） |
| 变址寻址 | EA=A+(IX) | 1 | 中 | 数组遍历（用户） |
| 寄存器间接寻址 | EA=(Ri) | 1 | 中 | 指针遍历 |
| 堆栈寻址 | EA=(SP) | 0 | 快 | 函数调用 |
| 间接寻址 | EA=(A) | 2 | 最慢 | 复杂指针 |

### 33.3 CISC vs RISC——10 维度详细对比

| 对比维度 | CISC（复杂指令集） | RISC（精简指令集） |
|---------|-------------------|-------------------|
| 1. 指令数量 | **多**（几百到上千条） | **少**（几十到一百多条） |
| 2. 指令长度 | **可变长**（1~15 字节） | **定长**（如 32 位） |
| 3. 指令格式 | 格式多样，不规则 | **格式规整**，操作码位置固定 |
| 4. 寻址方式 | 多种（10+ 种） | 少（通常 3~5 种） |
| 5. 寄存器数量 | 少（x86 早期 8 个通用寄存器） | **多**（MIPS/ARM 32 个，RISC-V 32 个） |
| 6. 访存方式 | 运�指令可直接访存 | **只有 Load/Store 指令访存** |
| 7. 流水线实现 | **难**（指令长度不一，冲突多） | **易**（指令规整，可高效流水） |
| 8. 硬件复杂度 | 复杂（微程序控制器为主） | 简�（硬布线控制器为主） |
| 9. 编译优化 | 相对容易（一条指令做很多事） | 需要编译器配合优化（指令序列短但条数多） |
| 10. 功耗 | 高（硬件复杂 → 功耗大） | **低**（硬件简单 → 功耗小） |
| 代表架构 | **x86**（Intel/AMD） | **ARM**、MIPS、RISC-V |
| 典型应用 | PC、服务器 | 手机（ARM）、嵌入式、IoT |

> **考试重点**：CISC → x86 → 可变长 → 指令可直接访存；RISC → ARM → 定长 → 只有 Load/Store 访存。

**大鱼类比**：CISC 和 RISC 就像"两种厨房"——
- **CISC（x86）** = 大酒楼厨房：什么工具都有（指令多），每个厨师拿不同尺寸的锅（指令长度可变），什么菜都能做但上菜慢（流水线难搞），费煤气（功耗高）
- **RISC（ARM）** = 快餐厨房：工具精简但高效（指令少），所有锅统一大小（定长），流水线出餐快（易流水线），省煤气（功耗低）——这就是为什么手机（ARM）比笔记本（x86）续航更长。

**为什么现在 CISC 和 RISC 的界限模糊了？**
- 现代 x86（CISC）处理器内部会把复杂指令"拆"成简单的微操作（类似 RISC），内部也采用流水线和超标量技术
- 现代 ARM（RISC）处理器也加入了一些复杂指令（如 NEON SIMD 扩展）
- 结论：微架构层面的差异大于指令集层面的差异

### 33.4 指令执行流程——5 个阶段详解

> 每条机器指令的执行都要经历以下标准流程（对应经典五段流水线）：

```
取指令(IF) → 译码/取数(ID) → 执行(EX) → 存储器访问(MEM) → 写回(WB)
```

| 阶段 | 名称 | 做什么 | 涉及部件 |
|------|------|------|---------|
| **IF** | Instruction Fetch（取指） | PC 指向的地址取指令放入 IR，PC+1 | PC→MAR→存储器→MDR→IR |
| **ID** | Instruction Decode（译码/取数） | 译码操作码、读寄存器操作数 | IR→CU 译码，读通用寄存器 |
| **EX** | Execute（执行） | ALU 进行运算、计算有效地址 | ALU、寄存器 |
| **MEM** | Memory Access（存储器访问） | Load/Store、分支完成 | MAR→MDR、存储器 |
| **WB** | Write Back（写回） | 结果写回寄存器 | 寄存器堆 |

**详细步骤说明——以 `ADD R1, [0x1000]` 为例**：
1. **IF**：PC 的值送到 MAR，读内存，指令从 MDR 进入 IR，PC←PC+1
2. **ID**：CU 译码，发现这是 ADD 指令；读 R1 的值到 ALU 输入 A 端；准备读 0x1000 地址的数据
3. **EX**：0x1000 送 MAR，读内存，MDR 得到操作数，送入 ALU 输入 B 端；ALU 执行 R1 + 操作数
4. **MEM**：本条指令不需要访存（结果不进内存），此阶段空闲（"气泡"）
5. **WB**：ALU 结果写回 R1

> **不是所有指令都需要 5 个阶段**。如 `ADD R1, R2`（寄存器-寄存器运算）只需要 IF→ID→EX→WB，MEM 阶段空过。Load/Store 指令才必须经过 MEM。

### 33.5 指令系统——5 道例题 + 易错陷阱 + 记忆口诀

#### 例题 1：寻址方式识别

下列指令分别属于哪种寻址方式？
(1) `ADD R1, #5` → **立即寻址**（操作数 5 直接在指令中）
(2) `ADD R1, R2` → **寄存器寻址**（操作数在 R2 中）
(3) `LOAD R1, (R2)` → **寄存器间接寻址**（R2 存的是地址）
(4) `JMP +100` → **相对寻址**（PC+100，用于转移）
(5) `PUSH R1` → **堆栈寻址**（操作数隐含在栈顶）

#### 例题 2：访存次数计算

设指令本身已取出（取指不算），以下各条指令需要额外访存几次？
(1) `ADD R1, R2` → **0 次**（寄存器寻址）
(2) `ADD R1, #5` → **0 次**（立即寻址）
(3) `ADD R1, 0x100` → **1 次**（直接寻址，去 0x100 取操作数）
(4) `ADD R1, (R2)` → **1 次**（寄存器间接寻址，去 R2 指向的地址取数据）
(5) `ADD R1, @0x100` → **2 次**（间接寻址：先去 0x100 取地址，再去那个地址取数据）

#### 例题 3：扩展操作码设计

指令字长 16 位，地址码字段占 4 位。三地址指令最多 15 条，此时二地址指令最多多少条？

**解答**：
- 三地址：操作码 = 16−4×3 = 4 位，最多 16 条。留 15 条（0000~1110），剩余 1111 做扩展标志
- 二地址：操作码 = 4+4 = 8 位（前 4 位固定为 1111 + 后 4 位地址码借用做操作码），最多 **2⁴ = 16 条**
- 若二地址也不够用，同理可扩展到一地址

#### 例题 4：基址寻址 vs 变址寻址

某程序基址寄存器 BR=0x2000，变址寄存器 IX=3。
(1) 基址寻址 `LOAD R1, 0x0100(BR)` → EA = 0x2000 + 0x0100 = **0x2100**
(2) 变址寻址 `LOAD R1, 0x0100(IX)` → EA = 0x0100 + 3 = **0x0103**

问：基址寻址中"BR 不变"适合什么场景？ → **程序重定位（OS 功能）**
问：变址寻址中"A 不变"适合什么场景？ → **数组遍历（用户程序）**

#### 例题 5：CISC/RISC 综合判断

判断以下描述分别属于 CISC 还是 RISC：
(1) 用微程序控制器实现 → **CISC**（复杂指令用微程序更灵活）
(2) 只有 Load/Store 指令可以访存 → **RISC**
(3) 代表架构是 x86 → **CISC**
(4) 指令长度 32 位固定 → **RISC**
(5) 寻址方式超过 10 种 → **CISC**

#### 易错陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **立即寻址 = 0 次访存** | 操作数直接在指令中，取指令时一起拿到 | 注意题目问的是"取操作数"还是"取指令+取操作数" |
| **间接寻址 vs 寄存器间接寻址** | 间接寻址 = 访存 2 次（先去内存找地址，再取数据）；寄存器间接 = 访存 1 次（寄存器就有地址） | 前者指令中给地址→内存→再读数据，后者寄存器→地址→读数据 |
| **基址 vs 变址方向搞反** | 基址：BR 不变、A 可变（面向 OS）；变址：A 不变、IX 可变（面向用户） | 口诀："基址不变 A 可变，变址不变成 A 首" |
| **相对寻址中 PC 的值** | 取指后 PC 已经 +1，此时 PC 指向下一条指令 | 偏移量是基于 PC+1 后的值计算的 |
| **二地址指令会破坏源操作数** | `ADD A,B` → A←A+B，A 的原值被覆盖 | 需要保留原值时，先用 MOV 复制到别处 |
| **扩展操作码的"留扩展"** | 长指令留下一个编码不分配给短指令，作为"扩展标志" | 扩展标志占用了一条短指令的编码空间 |

#### 记忆口诀

- **寻址方式记忆**："立即寄存器最快，直接间接走内存，基址重定变址组，相对跳转堆栈隐"
- **CISC/RISC**："C 长多变杂（CISC 变长多杂），R 短定精简（RISC 定长短精）"
- **指令格式**："三地最直二最实，单地隐含零特殊"
- **基址/变址**："OS 管基址（BR不变），用户写变址（IX可变）"
- **5 段流水**："取译执访写，IF→ID→EX→MEM→WB"

## 知识点 34：中央处理器

> **考点星级**：流水线加速比=必考⭐⭐⭐ | 其余概念=中频⭐

### 34.1 CPU 组成——三大核心模块

| 部件 | 子组成部分 | 功能 | 
|------|-----------|------|
| **运算器（数据通路）** | ALU（算术逻辑单元）+ 通用寄存器组 + ACC（累加器）+ 暂存寄存器 + PSW（程序状态字/标志寄存器） | 执行算术/逻辑运算、移位操作 |
| **控制器** | CU（控制单元）+ **PC**（程序计数器）+ **IR**（指令寄存器）+ ID（指令译码器）+ 时序发生器 | 取指令、译码、发控制信号、控制执行顺序 |
| **寄存器组** | 通用寄存器（R0~Rn）+ 专用寄存器（PC/IR/MAR/MDR/SP/PSW） | 暂存数据和状态 |

**关键专用寄存器详解**：

| 寄存器 | 全称 | 存什么 | 作用 |
|--------|------|------|------|
| **PC** | Program Counter（程序计数器） | 下一条要执行的指令的地址 | 控制程序顺序执行 |
| **IR** | Instruction Register（指令寄存器） | 当前正在执行的指令内容 | 保存指令供译码 |
| **MAR** | Memory Address Register（存储器地址寄存器） | 要访问的内存地址 | CPU 和主存之间的地址桥梁 |
| **MDR** | Memory Data Register（存储器数据寄存器） | 从主存取出的或准备写入主存的数据 | CPU 和主存之间的数据桥梁 |
| **SP** | Stack Pointer（栈指针） | 栈顶地址 | 函数调用/中断时保存和恢复上下文 |
| **PSW** | Program Status Word（程序状态字/标志寄存器） | 状态标志（ZF/CF/OF/SF 等） | 保存运算结果的特征和 CPU 状态 |

**PSW 中常见标志位**：
- **ZF（零标志）**：结果为 0 时置 1
- **CF（进位/借位标志）**：加减法有进位或借位时置 1
- **OF（溢出标志）**：有符号数运算结果溢出时置 1
- **SF（符号标志）**：结果为负时置 1
- **IF（中断允许标志）**：为 1 时允许响应可屏蔽中断

### 34.2 数据通路——CPU 内的"高速公路"

> 数据通路是指 CPU 内部各部件之间传输数据的路径。不同总线结构影响执行效率。

#### 三种总线结构对比

| 结构 | 特点 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| **单总线** | 所有部件共享一条内部总线 | 结构简单，成本低 | 同一时刻只能传一个数据（需分时使用），速度最慢 | 早期 CPU |
| **双总线** | 两条内部总线（如操作数总线 + 结果总线） | 可同时传两个数据 | 硬件成本增加 | 现代 CPU 常见方案 |
| **三总线** | 三条内部总线（两个源操作数各一条 + 结果一条） | **速度最快**，可同时取两个操作数并写回结果 | 硬件成本最高，布线复杂 | 高性能处理器 |

**数据通路执行 `ADD R1, R2` 的过程（单总线结构）**：
1. R1→暂存器 A（通过总线）
2. R2→暂存器 B（通过总线，此时总线被占用不能同时传）
3. ALU 计算 A+B
4. ALU 结果→R1（通过总线写回）

> 单总线结构需要 4 个步骤完成一条双操作数运算，双总线/三总线可以更快。

### 34.3 指令周期——时间单位层次

```
指令周期 > 机器周期（总线周期） > 时钟周期（T 周期）
```

| 时间单位 | 定义 | 关系 | 示例（主频 2GHz） |
|---------|------|------|-----------------|
| **时钟周期 T** | CPU 主频的倒数，最小时间单位 | 1 个 T = 1 次振荡 | T = 1/(2×10⁹) = **0.5ns** |
| **机器周期** | 完成一次总线操作（如一次访存）所需时间 | 1 个机器周期 = 多个 T（通常 2~6 个 T） | 若 4T = **2ns** |
| **指令周期** | 执行一条指令的全过程 | 1 个指令周期 = 多个机器周期 | 取指+译码+执行+... |

**指令周期各阶段**：

```
取指周期 → （间址周期）→ 执行周期 → （中断周期）
```

> 括号中的阶段不一定每条指令都经历。如直接寻址不需要间址周期，没有中断发生时不需要中断周期。

**各周期的具体动作**：

| 周期 | CPU 做什么 | PC 变化 | 访存次数 |
|------|-----------|--------|---------|
| **取指周期** | PC→MAR→读内存→MDR→IR | PC←PC+1 | 1 次（读指令） |
| **间址周期** | 指令地址码→MAR→读内存→MDR→得到有效地址 | PC 不变 | 1 次（取地址） |
| **执行周期** | ALU 运算/传送数据/执行跳转 | 顺序：PC 不变；跳转：PC←新地址 | 视指令而定 |
| **中断周期** | 保存断点（PC 入栈）→关中断→转入中断服务程序 | PC←中断向量地址 | 2 次（写栈、取中断向量） |

#### 指令周期中的标志触发器

CPU 内部使用几个标准的触发器来标记当前处于哪个阶段：

| 触发器 | 含义 | 什么时候为 1 |
|--------|------|------------|
| **FE（取指标志）** | 当前处于取指周期 | 默认=1，取指完成后清 0 |
| **IND（间址标志）** | 需要间址周期 | 指令需要间接寻址时置 1 |
| **EX（执行标志）** | 当前处于执行周期 | 取指（和间址）完成后置 1 |
| **INT（中断标志）** | 需要中断周期 | 有中断请求且 CPU 允许响应时置 1 |

**四级时序系统（以微程序控制器为例）**：

```
工作周期（取指/间址/执行/中断）
  └→ 节拍（机器周期，如 T0~T3，每个机器周期含多个时钟周期）
       └→ 状态（时钟周期，即 T 周期）
            └→ 微操作信号
```

**时序例题**：

某 CPU 主频 2GHz，每个机器周期为 4T。取指周期需要 2 个机器周期，执行周期需要 3 个机器周期。执行 100 条指令至少需要多少时间？（假设无间址和中断）

```
T = 1/2GHz = 0.5ns
1 机器周期 = 4T = 2ns
取指 = 2×2ns = 4ns, 执行 = 3×2ns = 6ns
每条指令 = 4+6 = 10ns
100 条 = 1000ns = 1μs（顺序执行）
若采用流水线（5段），≈ (5+99)×2ns = 208ns，加速约 4.8 倍
```

### 34.4 控制器设计——硬布线 vs 微程序

> 控制器的核心任务：根据指令译码结果，在正确的时刻发出正确的控制信号。

#### 详细对比表

| 对比维度 | 硬布线控制器 | 微程序控制器 |
|---------|------------|------------|
| **实现原理** | **组合逻辑电路**直接产生控制信号 | 控制信号以**微指令**形式存入 ROM（控制存储器 CM） |
| **设计方式** | 根据指令真值表设计逻辑电路 | 用微程序编写，像"指令的指令" |
| **执行速度** | **快**（直接硬件电路，无额外访存） | **慢**（需访问 CM，多一次读取开销） |
| **灵活性** | **差**（改指令需改电路板） | **好**（改指令只需改程序） |
| **修改难度** | **难**（重新设计、布线） | **易**（修改微程序即可） |
| **硬件成本** | 电路复杂且不规则，芯片面积大 | 需要额外的 CM（但电路规整） |
| **典型应用** | **RISC** 处理器（如 ARM、MIPS） | **CISC** 处理器（如 x86 早期） |
| **规律性** | 差（电路不规则，难以 VLSI 实现） | **好**（结构规整，适合 VLSI） |

> 口诀："硬快难改RISC用，微慢易改CISC用"

#### 微程序控制器核心概念（重要）

```
微命令 → 微操作 → 微指令 → 微程序 → 一条机器指令的完整实现
（最小控制信号 → 一组控制信号 → 一条微指令 → 一系列微指令）
```

**关键定义**：

| 概念 | 定义 | 例子 |
|------|------|------|
| **微命令** | 控制部件向执行部件发出的**最小控制信号** | "打开寄存器 R1 的输出门"、"ALU 做加法" |
| **微操作** | 由微命令控制完成的最基本操作 | "R1 内容送 ALU 输入 A 端" |
| **微指令** | 同一时钟周期内可以**并行执行**的一组微命令 | 一条微指令可能同时执行"R1→A、R2→B、ALU 做加法、结果→R3" |
| **微程序** | 完成一条机器指令所需的**微指令序列** | 如 ADD 指令的微程序 = {微指令1, 微指令2, ...} |
| **控制存储器（CM）** | 存放所有微程序的只读存储器（ROM） | 相当于"微程序版本库" |

**微指令的编码方式**：

| 方式 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **直接编码（直接控制）** | 微指令中每一位直接控制一个微命令 | 速度快，并行度高 | 微指令字太长 |
| **字段直接编码** | 将互斥的微命令分组，每组独立编码 | 缩短微指令字长 | 需要译码，略慢 |
| **字段间接编码** | 一组编码的结果影响另一组的含义 | 进一步压缩 | 译码复杂，用得少 |
| **混合编码** | 结合以上方式的折中方案 | 平衡字长和速度 | — |

#### 微指令 vs 机器指令

| 对比 | 微指令 | 机器指令 |
|------|--------|---------|
| 层次 | 硬件控制层（微程序机器层） | 软件-硬件接口层（传统机器层） |
| 执行者 | 控制器内部执行 | CPU 整体执行 |
| 对应关系 | 多条微指令 = 1 条机器指令 | 1 条机器指令 = 1 个微程序 |
| 程序员可见？ | **不可见**（硬件实现细节） | **可见**（汇编指令） |
| 存储位置 | 控制存储器 CM（CPU 内部 ROM） | 主存储器 |

### 34.5 指令流水线——5 段标准流水线

**类比**：洗车流水线——一辆车冲水时，前一辆在擦干，后一辆在打泡沫，多条工序同时进行。

#### 经典五级流水线时空图

```
时钟周期:  C1  C2  C3  C4  C5  C6  C7  C8  C9
指令1:     IF  ID  EX  MEM WB
指令2:         IF  ID  EX  MEM WB
指令3:             IF  ID  EX  MEM WB
指令4:                 IF  ID  EX  MEM WB
指令5:                     IF  ID  EX  MEM WB
```

> 稳定后每个周期完成一条指令（吞吐率≈1 条/周期）。

#### 流水线三种冲突（Hazard）

| 冲突类型 | 英文名 | 原因 | 场景举例 | 解决方法 |
|---------|--------|------|---------|---------|
| **结构相关** | Structural Hazard | 多条指令同时争用同一硬件资源 | 第 n 条 IF（取指）和第 n-3 条 MEM（访存）同时访问内存 | ①增加硬件资源（如分离 I-Cache 和 D-Cache）②流水线停顿（插入气泡） |
| **数据相关** | Data Hazard | 后一条指令需要前一条指令的结果 | `ADD R1,R2,R3`→`SUB R4,R1,R5`（SUB 需要 R1 的值，但 ADD 还没写回） | ①**数据旁路/转发（Forwarding）**——结果直接从 EX 阶段输出端传给下一条的输入②编译器调度重排③流水线停顿 |
| **控制相关** | Control Hazard | 分支指令改变了程序流程，预取的指令可能无效 | `BEQ R1,R2,loop`（如果跳转，已经取进来的后续指令全白取） | ①分支预测（静态/动态）②延迟转移（延迟槽）③流水线刷新（清空误取的指令） |

**数据相关的三种子类型**：

| 类型 | 英文 | 含义 | 举例 |
|------|------|------|------|
| **RAW（读后写）** | Read After Write | J 要读的数据在 I 写之前 → J 必须等 I 写完 | `R1←R2+R3`; `R4←R1+R5`（J 等 I 写 R1） |
| WAR（写后读） | Write After Read | J 要写的位置是 I 要读的数据 → 乱序执行时才出现 | `R4←R1+R5`; `R1←R2+R3`（J 不能比 I 早写 R1） |
| WAW（写后写） | Write After Write | J 和 I 要写同一个位置 → 乱序执行时才出现 | `R1←R2+R3`; `R1←R4+R5`（写的顺序不能乱） |

> **RAW 是最常见的数据相关**（顺序流水线中 WAR 和 WAW 通常不会发生）。解决方法核心 = Forwarding（数据旁路/转发）。

**分支预测的两种策略**：
- **静态预测**：永远预测不跳转（简单但准确率低）
- **动态预测**：用分支历史表（BHT）记录历史跳转情况，根据历史预测未来（准确率高 > 90%）

### 34.6 流水线性能计算——3 指标详解 + 3 道例题

#### 三个核心指标

| 指标 | 公式 | 含义 | 理想极限 |
|------|------|------|---------|
| **吞吐率 TP** | n / Tk（条/单位时间） | 单位时间完成的任务数 | 当 n→∞ 时，TP≈1/Δt |
| **加速比 S** | T顺序 / T流水 | 用流水线比不用的速度提升倍数 | 当 n→∞ 时，S≈k |
| **效率 E** | S / k 或 n个任务占用时间/总时空面积 | 流水线中各段的利用率 | 理想 E=1（100%） |

**通用公式回顾**：
- 顺序执行时间：T顺 = n × k × Δt（n 条指令，k 段，每段 Δt）
- 流水线执行时间：T流 = k×Δt + (n-1)×Δt = (k+n-1)×Δt
- 加速比：S = T顺/T流 = (n×k)/(k+n-1)
- 效率：E = S/k（= n/(k+n-1)）
- 吞吐率：TP = n/T流 = n/((k+n-1)×Δt)

#### 例题 1：不同段数的流水线

某流水线每段 Δt=1ns，执行 n=200 条指令。分别计算 k=3、k=5、k=8 时的加速比和效率。

**解答**：

| 段数 k | T顺 = n×k | T流 = k+n-1 | 加速比 S | 效率 E=S/k | 吞吐率 TP(条/ns) |
|--------|-----------|-------------|----------|-----------|------------------|
| 3 | 200×3=600 | 3+199=202 | 600/202≈**2.97** | 2.97/3≈**99.0%** | 200/202≈0.99 |
| 5 | 200×5=1000 | 5+199=204 | 1000/204≈**4.90** | 4.90/5≈**98.0%** | 200/204≈0.98 |
| 8 | 200×8=1600 | 8+199=207 | 1600/207≈**7.73** | 7.73/8≈**96.6%** | 200/207≈0.97 |

> 结论：段数越多，加速比越接近段数 k（当 n 很大时，S≈k）。但效率略降（建立时间占比变大）。

#### 例题 2：多周期段（瓶颈段）的流水线

某流水线分 4 段：IF=1ns, ID=2ns, EX=3ns, WB=1ns。各段时间不等。执行 50 条指令。求加速比。

**关键**：流水线时钟周期必须取**最长段的时间**，即 Δt = max(1,2,3,1) = **3ns**。

**解答**：
- T顺 = 50 × (1+2+3+1) = 50×7 = 350ns
- T流 = 3×4 + (50-1)×3 = 12 + 147 = 159ns
- 加速比 S = 350/159 ≈ **2.20**
- 效率 E = 2.20/4 = **55%**

> EX 段的 3ns 成为瓶颈，导致效率只有 55%。优化方案：将 EX 段拆成两个 1.5ns 段 → 变成 5 段各 2ns 流水线，效率大幅提升。

#### 例题 3：含阻塞的流水线——数据相关影响

某 5 段流水线，每段 Δt=1ns，执行 100 条指令。其中 10 条指令因数据相关（RAW），每条需要额外阻塞 2 个时钟周期。

**解答**：
- 无阻塞 T流 = 5 + 99 = 104ns
- 10 条各阻塞 2 周期 = 额外 20 个时钟周期
- 含阻塞 T流_阻塞 = 104 + 20 = **124ns**
- T顺 = 100×5 = 500ns
- 含阻塞加速比 S = 500/124 ≈ **4.03**
- 无阻塞加速比 S0 = 500/104 ≈ 4.81
- 性能损失：(4.81−4.03)/4.81 ≈ **16.2%**

> 仅 10% 的指令阻塞 2 个周期，性能就损失约 16%。这就是为什么数据旁路（Forwarding）如此重要——它几乎消除了数据相关的阻塞。

#### 流水线高级话题——超标量与超流水线

**超标量（Superscalar）**：每个时钟周期可以发射多条指令（如双发射、四发射）

```
双发射流水线时空图（理想情况）：

时钟:   C1  C2  C3  C4  C5  C6
指令1:  IF  ID  EX  MEM WB
指令2:  IF  ID  EX  MEM WB
指令3:      IF  ID  EX  MEM WB
指令4:      IF  ID  EX  MEM WB
指令5:          IF  ID  EX  MEM WB
指令6:          IF  ID  EX  MEM WB

每个周期发射 2 条指令 → 吞吐率 ≈ 2 条/周期
```

**超流水线 vs 超标量对比**：

| 类型 | 做法 | n 条指令时间 | 加速比(理想) |
|------|------|------------|------------|
| **基本流水线** | k 段，每段 Δt | (k+n-1)×Δt | ≈k（n大时） |
| **超流水线** | 每段再细分 m 级（如 5→10 段） | (k×m+n-1)×(Δt/m) | ≈k×m（但建立时间更长） |
| **超标量** | 每周期发射 w 条指令 | (k+n/w-1)×Δt | ≈k×w（受指令间依赖限制） |

**超标量的限制因素**：
1. **指令间依赖**：后面的指令可能需要前面的结果
2. **分支指令**：分支指令打乱了顺序发射
3. **资源冲突**：多条指令同时需要同一个功能部件
4. **实际 IPC**：4 发射超标量的实际 IPC 往往只有 2~3

**动态调度技术**：

| 技术 | 含义 | 核心思想 |
|------|------|---------|
| **乱序执行（Out-of-Order）** | 指令不按程序顺序执行，数据就绪就执行 | 打破顺序限制，提高指令级并行度 |
| **寄存器重命名（Register Renaming）** | 用更多物理寄存器消除 WAR/WAW 伪相关 | 逻辑寄存器→物理寄存器映射 |
| **保留站（Reservation Station）** | Tomasulo 算法，指令等待操作数就绪 | 分布式调度，类似"看板" |
| **重排序缓冲区（ROB）** | 保存乱序执行的结果，按程序顺序提交 | 保证精确异常和中断 |

**乱序执行示例**：

```
原始指令序列：
1. LOAD R1, [addr1]     （访存，较慢）
2. ADD R3, R4, R5        （和指令1无依赖，可先执行）
3. SUB R6, R1, R2        （需要R1，必须等指令1完成）

乱序执行后的实际顺序：
1. LOAD R1, [addr1]      （发射→等待内存）
2. ADD R3, R4, R5        （发射→立即执行）
   （等待R1就绪...）
3. SUB R6, R1, R2        （R1就绪后立即执行）

提交顺序（ROB保证）：1 → 2 → 3（与程序顺序一致）
```

### 34.7 CPU——5 道例题 + 易错陷阱 + 记忆口诀

#### 例题 1：数据通路执行步骤

在单总线 CPU 中，执行 `ADD R1, R2`（R1←R1+R2）需要哪些步骤？

**解答（单总线结构，需要 4 步）**：
1. R1 → 暂存器 A（通过总线）
2. R2 → 暂存器 B（通过总线，需分时）
3. ALU 计算 A+B
4. ALU 结果 → R1（通过总线写回）

若为三总线结构，第 1、2、4 步可并行，只需 1~2 步。

#### 例题 2：微程序 vs 硬布线

为什么 RISC 处理器通常用硬布线控制器而 CISC 用微程序控制器？

**解答**：
- RISC 指令少且规整，硬布线电路可行且速度快
- CISC 指令多且复杂，如果全部用硬布线实现，逻辑电路过于庞大且不易修改，用微程序更灵活
- 硬布线执行一条指令只需一级（直接电路），微程序需要先查 CM 再执行，多一次开销

#### 例题 3：流水线加速比计算

某 6 段流水线，执行 80 条指令，每段 Δt=2ns。求 T顺、T流、加速比 S、效率 E、吞吐率 TP。

**解答**：
- T顺 = 80×6×2 = 960ns
- T流 = (6+79)×2 = 85×2 = 170ns
- S = 960/170 ≈ **5.65**
- E = 5.65/6 ≈ **94.1%**
- TP = 80/170 ≈ **0.47 条/ns** = 470 MIPS

#### 例题 4：含数据相关的流水线时空图

假设 5 段流水线，`ADD R1,R2,R3` 后紧跟 `SUB R4,R1,R5`。
(1) 若不使用 Forwarding，需要停顿几个周期？
(2) 若使用 Forwarding，需要停顿几个周期？

**解答**：
(1) 不用 Forwarding：ADD 在 WB 阶段才写回 R1，SUB 的 EX 阶段需要 R1。SUB 必须在 ID 阶段（译码读 R1）之后停顿，直到 ADD 的 WB 之后。实际需要停顿 **2 个周期**。
(2) 用 Forwarding：ADD 的 EX 阶段输出结果直接旁路给 SUB 的 EX 阶段输入，**不需要停顿**（或只需 1 个周期）。

#### 例题 5：取指周期时间

某 CPU 主频 2GHz，每个机器周期为 4T。取指周期需要 2 个机器周期，执行周期需要 3 个机器周期。执行 100 条指令至少需要多少时间？

**解答**：
- T = 1/2GHz = 0.5ns
- 1 机器周期 = 4T = 2ns
- 取指周期 = 2 机器周期 = 4ns
- 执行周期 = 3 机器周期 = 6ns
- 每条指令至少：取指 + 执行 = 10ns（无间址周期和中断周期）
- 100 条指令最少时间 = 100 × 10ns + 取指重叠部分... 顺序执行 = **1000ns = 1μs**

若采用流水线（5 段），时间 ≈ (5+99)×2ns = 208ns，加速约 4.8 倍。

#### 易错陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **PC 指向下一条指令** | 取指后 PC 自动 +1，此时 PC 已经不是当前指令的地址了 | 相对寻址以取指后的 PC 为基准 |
| **硬布线 = 快 + 难改** | 两者不能兼得 | 口诀："硬快难改 RISC 用，微慢易改 CISC 用" |
| **微程序需要控制存储器（CM）** | CM 是 ROM，存微程序 | 微程序控制器多一级 CM 访问，所以慢 |
| **各段时间不等时 Δt 取最长段** | 拒绝取平均值或中位值 | "桶的容量由最短的木板决定，流水线的节奏由最慢的段决定" |
| **瓶颈段决定一切** | 一个 3ns 的段 + 三个 1ns 的段，整体按 3ns 走 | 优化瓶颈段收益最大 |
| **加速比极限是段数 k** | 即使 n→∞，S→k，不可能超过 k | 题目若给 S>k 的结果重新检查 |
| **RAW 是核心、Forwarding 是王道** | 这三个缩写中最常考的就是 RAW 和 Forwarding 的关系 | RAW 有数据依赖→Forwarding 解决 |
| **n 小时的加速比** | n=10, k=5 → S≈3.57，远小于 k=5 | 建立时间 (k-1) 段在小 n 时占比大 |

#### 记忆口诀

- **CPU 组成**："运算 ALU，控制 PC-IR，数据通路连各部"
- **硬布线 vs 微程序**："硬快难改瘦（RISC），微慢易改胖（CISC）"
- **微程序层次**："微命→微操→微指→微程→机器指令"
- **流水线冲突**："结构争资源，数据有依赖，控制猜不准——加硬、转发、预测"
- **流水线公式**："首条 k 段整，后续 1 段过，n 条总时间 = k+(n-1)"
- **五段流水**："取译执访写，IF→ID→EX→MEM→WB"

## 知识点 35：总线与输入输出系统

> **考点星级**：总线=中频⭐ | 中断/DMA=中频⭐

### 35.1 总线的基本概念

> 总线（Bus）是计算机中连接各部件的**公共信息传输线**。同一时刻，一条总线只能被一组设备使用（独占性），但多个设备可以分时共享。

**总线的核心参数**：
- **总线宽度**：数据线数量（如 32 位、64 位），决定每次传输的数据量
- **总线频率**：总线时钟频率（如 100MHz），决定传输速度
- **总线带宽（传输速率）**：宽度 × 频率 = 每秒传输字节数（如 32bit×100MHz = 400MB/s）

### 35.2 总线分类——按位置和功能分三级

| 总线类型 | 位置 | 功能 | 包含/举例 |
|---------|------|------|------|
| **片内总线** | CPU 芯片内部 | 连接运算器、控制器、寄存器 | ALU 与寄存器之间的数据通路 |
| **系统总线** | 主板上 | 连接 CPU、主存、I/O 接口 | **数据总线（DB）+ 地址总线（AB）+ 控制总线（CB）** |
| **通信总线（I/O总线）** | 计算机与外部设备之间 | 连接外部设备 | USB、PCIe、SATA、Thunderbolt |

**系统总线的三根线详解**：

| 总线 | 英文 | 传输内容 | 方向 | 宽度典型值 |
|------|------|---------|------|-----------|
| **数据总线 DB** | Data Bus | 实际数据 | 双向（CPU↔内存/I/O） | 32 位、64 位 |
| **地址总线 AB** | Address Bus | 内存/I/O 地址 | 单向（CPU→内存/I/O） | 32 位→4GB 寻址空间（2³²） |
| **控制总线 CB** | Control Bus | 控制信号（读/写/中断等） | 各信号方向不同 | 十几到几十根 |

> 地址总线宽度 n 位 → 最大寻址空间 = 2ⁿ。32 位地址总线 → 最多 4GB 内存（2³² = 4G）。64 位 → 理论上 2⁶⁴ = 16EB。

### 35.3 总线结构——单总线/双总线/三总线

| 结构 | 连接方式 | 优点 | 缺点 | 典型应用 |
|------|---------|------|------|---------|
| **单总线结构** | CPU、主存、I/O 全挂在一条系统总线上 | 结构最简单，成本最低，扩展容易 | 同一时刻只能传一组数据，I/O 和 CPU 争用总线→**性能瓶颈** | 早期微型计算机 |
| **双总线结构** | 系统总线（CPU-主存）+ I/O 总线（CPU-I/O） | 主存访问和 I/O 操作互不干扰 | 结构略复杂，CPU 仍是 I/O 的瓶颈 | 现代 PC 的基础架构 |
| **三总线结构** | 局部总线（CPU-Cache）+ 系统总线（主存）+ 扩展总线（I/O） | 速度分级，各总线独立工作，**性能最高** | 硬件最复杂，需要总线桥接 | 现代高性能计算机 |

**三总线结构中增加"局部总线"的意义**：CPU 和 Cache 之间的数据传输频率最高，用局部总线独立出来，不和慢速的 I/O 设备争用系统总线。同时通过"总线桥"连接各级总线，不同速度的设备各自挂在不同速度的总线上。

### 35.4 总线仲裁——谁先用总线？

> 多个设备同时请求使用总线时，需要一个"裁判"来决定谁先用。

#### 集中式仲裁（一个中央仲裁器）

| 方式 | 工作原理 | 优点 | 缺点 | 线数 |
|------|---------|------|------|------|
| **链式查询（菊花链）** | 优先级信号沿设备链传递，"我不用就传给下一个" | 最简单，线最少 | ①**对故障敏感**（中间设备坏→后面全不能用）②优先级固定不可改 | 3 根 |
| **计数器定时查询** | 中央仲裁器用计数器轮询设备号，"1 号用吗？2 号用吗？" | 可动态改变优先级（改初始计数值） | 轮询耗时，设备多时效率低 | 约 log₂N+2 根 |
| **独立请求** | 每个设备有独立的总线请求线和总线授权线 | **响应最快**，可灵活编程优先级 | **线最多**，硬件复杂 | 2N+1 根 |

#### 分布式仲裁

> 没有中央仲裁器，每个设备自己根据某种策略判断能否使用总线。例如采用"自举式"（每个设备有唯一优先级编号，比较后最高优先级胜出）。

**集中式 vs 分布式对比**：

| 对比维度 | 集中式仲裁 | 分布式仲裁 |
|---------|----------|----------|
| 可靠性 | 单点故障→整个仲裁失效 | **高**（没有单点） |
| 硬件成本 | 简单 | 复杂（每个设备都要仲裁逻辑） |
| 实现难度 | 简单 | 复杂 |
| 典型总线 | PCI | FutureBus+ |

### 35.5 总线标准——常见总线速查

| 总线标准 | 类型 | 宽度 | 主要特点 | 典型应用 |
|---------|------|------|---------|---------|
| **PCI** | 并行系统总线 | 32/64 位 | 即插即用，33/66MHz | 早期扩展卡 |
| **PCIe（PCI Express）** | **串行**系统总线 | ×1/×4/×8/×16 | 点对点串行，**高带宽**，可扩展通道数 | 显卡、SSD、网卡 |
| **USB** | 串行通信总线 | 串行 | 热插拔，即插即用，可供电 | 键盘、鼠标、U 盘 |
| **SATA** | 串行通信总线 | 串行 | 取代 IDE/PATA，用于存储设备 | 硬盘、SSD |
| **AGP** | 并行系统总线 | 32 位 | 专用于显卡的高速总线（已被 PCIe×16 取代） | 早期显卡 |

> **PCIe 为什么用串行不用并行？** 并行总线在高频下信号同步困难（各线延迟不一致导致数据错位），串行总线可以跑更高频率，总带宽反而更大。

### 35.6 I/O 接口——功能与组成

**I/O 接口的连接位置**：CPU ↔ 系统总线 ↔ **I/O 接口** ↔ 外部设备

**I/O 接口的核心功能**：

| 功能 | 说明 |
|------|------|
| **数据缓冲/锁存** | CPU 和外设速度不匹配，接口做"中转站" |
| **信号格式转换** | 电平转换（如 5V→3.3V）、串并转换（USB 串行→内部并行） |
| **设备选择** | 根据地址码选中对应 I/O 设备 |
| **传送控制命令** | 接收 CPU 发来的启动/停止/读/写等命令 |
| **反映设备状态** | 告诉 CPU 设备是否忙、是否就绪、是否出错 |
| **中断逻辑** | 设备就绪后向 CPU 发出中断请求 |

**I/O 接口的基本组成**：
- 数据缓冲寄存器（数据传送）
- 控制寄存器（接收命令）
- 状态寄存器（反映设备状态）
- 设备选择电路（地址译码）
- 中断请求电路

### 35.7 中断系统——全流程详解

#### 中断的本质

> CPU 正在执行程序，外设突然"有事找你"（如键盘被按下、网卡收到数据），CPU 暂停当前工作去处理，处理完再回来。

**程序中断方式**：每次数据传送都由 CPU 亲自执行，但外设就绪时用中断"通知"CPU 来处理。

#### 中断全过程（5 个阶段）

```
第 1 步：中断请求 —— 外设发出中断请求信号
第 2 步：中断判优 —— 多个中断同时发生时，选优先级最高的
第 3 步：中断响应 —— CPU 执行完当前指令后响应（关中断、保存 PC/PSW）
第 4 步：中断服务 —— CPU 执行中断服务程序
第 5 步：中断返回 —— 恢复现场、开中断、返回原程序
```

#### 中断隐指令（CPU 硬件自动完成的三件事）

> 这三件事不需要程序员写代码，CPU 硬件自动完成。

| 步骤 | 操作 | 为什么 |
|------|------|------|
| ① **关中断** | 将 PSW 中的中断允许标志 IF 置 0 | 保护中断响应过程不被打断 |
| ② **保存断点** | PC 和 PSW 入栈保存 | 中断处理完要能回到原来位置继续执行 |
| ③ **引出中断服务程序** | 根据中断类型号→查中断向量表→取中断服务程序入口地址→送 PC | 找到处理这个中断的子程序 |

#### 中断向量

| 概念 | 定义 |
|------|------|
| **中断类型号** | 每个中断源的唯一编号（如键盘中断 = 09H） |
| **中断向量** | 中断服务程序的入口地址（即处理程序的起始地址） |
| **中断向量表** | 所有中断向量按类型号排列的表（存放在内存低地址区域） |

**中断向量地址计算**：中断服务程序入口地址存放地址 = 中断类型号 × 4（32 位系统中每个中断向量占 4 字节）

#### 中断优先级与屏蔽

**中断优先级**：当多个中断源同时发出请求时，CPU 优先响应优先级最高的。

**中断屏蔽**：通过设置中断屏蔽字，可以人为改变中断响应顺序。

**中断屏蔽字例题**：

设 4 个中断源 A、B、C、D，自然优先级从高到低为 A>B>C>D。写出各中断源的屏蔽字（1 表示屏蔽该中断源的中断，0 表示允许）。

| 中断源 | 屏蔽 A | 屏蔽 B | 屏蔽 C | 屏蔽 D | 说明 |
|--------|--------|--------|--------|--------|------|
| A | 1 | 1 | 1 | 1 | A 优先级最高，执行时屏蔽所有其他中断 |
| B | 0 | 1 | 1 | 1 | B 只能被 A 打断 |
| C | 0 | 0 | 1 | 1 | C 能被 A、B 打断 |
| D | 0 | 0 | 0 | 1 | D 能被所有中断打断 |

> **规律**：比自己优先级高的不屏蔽（0），比自己优先级低或相等的屏蔽（1）。注意：通常自己的位也屏蔽（1），防止重入。

#### 中断嵌套（多重中断）

> 高优先级的中断可以打断正在执行的低优先级中断服务程序。

必须满足的条件：
1. 低优先级中断服务程序在执行中
2. 高优先级中断源发出中断请求
3. **低优先级的中断屏蔽字没有屏蔽高优先级**（即允许被高优先级打断）
4. CPU 处于开中断状态（IF=1）

#### 中断响应优先级 vs 中断处理优先级

| 概念 | 含义 | 谁决定 |
|------|------|--------|
| **中断响应优先级** | 多个中断同时产生时，CPU 先响应哪个 | 硬件排队电路（不可改） |
| **中断处理优先级** | 中断处理过程中，谁可以打断谁 | 中断屏蔽字（可软件修改） |

> 通过中断屏蔽字，可以打乱"响应优先级"——优先级低的中断可以通过屏蔽所有其他中断来"霸占"CPU，不被更高优先级的中断打断。

**中断嵌套示例**：

4 个中断源 A、B、C、D，响应优先级 A>B>C>D。

若在 B 的中断服务程序中设置屏蔽字为（0,1,0,1），则：
- B 可以被 A 打断（屏蔽字对 A 为 0）
- B 不会被 C 打断（屏蔽字对 C 为 1）
- B 不会被 D 打断（屏蔽字对 D 为 1）
- 注意：B 自己被屏蔽（防止重入）

#### 中断响应时间分析

**中断响应时间** = 从中断请求发出到开始执行中断服务程序第一条指令的时间。

包括：
1. 执行完当前指令（最坏情况：正在执行一条最长的指令）
2. 中断隐指令（关中断 + 保存断点 + 取向量）——约 2~5 个机器周期
3. 若有更高优先级的中断正在处理，还需等待

**中断隐指令时间估算**（假设机器周期 = 4T）：
```
关中断（写 PSW）          = 1 机器周期 = 4T
保存 PC 入栈（写内存）     = 1 机器周期 = 4T
保存 PSW 入栈（写内存）    = 1 机器周期 = 4T
取中断向量（读内存）       = 1 机器周期 = 4T
────────────────────────────────────
中断隐指令总计             = 4 机器周期 = 16T
```

### 35.8 四种 I/O 控制方式——对比与进阶

| 方式 | CPU 参与度 | 数据传送路径 | 适用场景 | 传送单位 |
|--------|----------|------------|---------|---------|
| **程序查询** | CPU 全权负责（不断轮询设备状态） | CPU 读状态→CPU 传数据 | 简单嵌入式 | 字/字节 |
| **程序中断** | CPU 部分参与（设备就绪时中断 CPU） | CPU 读外设→CPU 写主存 | 低速 I/O（键盘、鼠标、串口） | 字/字节 |
| **DMA** | CPU 只在起止参与 | **DMA 控制器直接传送，不经过 CPU** | 高速 I/O（磁盘、网卡、显卡） | **数据块** |
| **通道** | CPU 几乎不参与 | 通道执行通道程序，独立管理 I/O | 大型主机 | 数据块/作业 |

#### 中断方式 vs DMA 方式——核心区别

| 对比维度 | 程序中断方式 | DMA 方式 |
|---------|------------|---------|
| **数据传送路径** | 外设 → CPU 寄存器 → 主存（CPU 中转） | 外设 → 主存（DMA 控制器直接控制，不经过 CPU） |
| **CPU 参与** | 每个数据传送 CPU 都要介入 | 只在传送**开始和结束**时各发一次中断 |
| **中断频率** | 每个数据产生一次中断 | 整块数据传完后产生一次中断 |
| **传送单位** | 字/字节 | 数据块（批量传送） |
| **适用设备** | 低速（键盘、鼠标、串口） | 高速（磁盘、网卡、显卡） |
| **传送速度** | 慢（CPU 频繁保存/恢复现场） | 快（硬件直接控制） |
| **对 CPU 的影响** | 占用 CPU，频繁打断 | CPU 可继续执行其他程序 |
| **硬件复杂度** | 简单（只需中断控制器） | 复杂（需要 DMA 控制器） |
| **总线控制权** | 始终由 CPU 控制 | 传送时 DMA 获总线控制权 |

**大白话类比**：
- **程序中断** = 老板（CPU）每收到一份文件就亲自送去档案室，每送一份工作就中断一次
- **DMA** = 老板安排专职跑腿（DMA 控制器），告诉他"把这堆文件全搬去档案室"。老板继续干活，跑腿搬完所有文件后才回来说一声"搬完了"

### 35.9 DMA 工作流程——详细步骤

**DMA 传送全过程（三步走）**：

#### 第 1 步：预处理（由 CPU 完成）

```
① CPU 准备数据缓冲区（在主存中分配空间）
② CPU 设置 DMA 控制器：
   - 主存起始地址 → DMA 的地址寄存器（AR）
   - 传送数据字数 → DMA 的字数计数器（WC）
   - 传送方向（读还是写）→ DMA 的控制/状态寄存器
③ 外设启动
④ CPU 继续执行其他程序
```

#### 第 2 步：数据传送（由 DMA 控制器独立完成）

```
循环执行，每传送一个字：
  ① DMA 控制器向 CPU 申请总线控制权（HRQ→HLDA）
  ② DMA 获得总线控制权
  ③ 将 AR 指向的内存地址数据送到数据总线（或从外设读取→写入内存）
  ④ AR ← AR+1（地址递增）
  ⑤ WC ← WC-1（计数器减 1）
  ⑥ 释放总线控制权（还给 CPU）
  ⑦ 若 WC ≠ 0，继续循环；若 WC = 0，进入第 3 步
```

#### 第 3 步：后处理（DMA 发中断）

```
① WC = 0 → 数据块传送完毕
② DMA 控制器向 CPU 发出"传送完成"中断
③ CPU 响应中断，执行中断服务程序：
   - 检查数据是否完整
   - 决定是否启动下一次 DMA 传送
   - 返回原程序继续执行
```

> **关键记忆**：DMA 传送过程中，CPU 只参与头尾（预处理 + 后处理），中间的数据传送完全由 DMA 控制器 + 总线控制权切换完成。整个过程中 CPU 只被中断 **1 次**（传送完成后）。

**周期窃取 / 周期挪用（Cycle Stealing）**：
- DMA 和 CPU 同时需要访问主存时，**DMA 优先**
- CPU 暂停一个总线周期，让 DMA 使用
- 对 CPU 的影响极小（只是暂停一个周期，不是整个指令）

### 35.10 通道方式简介

> 通道是比 DMA 更高级的 I/O 控制器，有自己的指令系统（通道指令），可以执行通道程序。

| 对比 | DMA | 通道 |
|------|-----|------|
| 控制能力 | 只能控制一台设备的一次数据块传送 | 可以控制多台设备、多个数据块的复杂 I/O |
| 程序能力 | 无（只做简单传送） | 有（可执行通道程序，支持分支） |
| CPU 参与 | 预处理+后处理 | 通道程序准备好后几乎不参与 |
| 适用场景 | 微型/小型机 | 大型/巨型机 |

### 35.11 总线与I/O——5 道例题 + 易错陷阱 + 记忆口诀

#### 例题 1：总线带宽计算

某总线数据宽度 32 位，时钟频率 100MHz，每个时钟周期传输 1 次数据。求总线带宽。

**解答**：
- 每次传输 = 32 bit = 4 Byte
- 每秒传输 = 100MHz × 4B = **400MB/s**

如果改为 64 位数据宽度 → 带宽 = 100MHz × 8B = **800MB/s**

#### 例题 2：地址总线宽度和寻址空间

(1) 地址总线 32 位，最大寻址空间？ → 2³² = **4GB**
(2) 地址总线 36 位，最大寻址空间？ → 2³⁶ = **64GB**
(3) 若需要支持 128GB 内存，地址总线至少多少位？
    - 128GB = 2³⁷ Bytes → 至少 **37 位**

#### 例题 3：中断屏蔽字设计

4 个中断源 P1、P2、P3、P4，优先级从高到低为 P1>P2>P3>P4。

(1) P2 执行中断服务程序时，屏蔽字应该怎么写？
    - P2 屏蔽 P3、P4（不屏蔽 P1，允许被 P1 打断）
    - 屏蔽字（对P1/P2/P3/P4）：**0, 1, 1, 1**

(2) P4 执行中断服务程序时，屏蔽字怎么写？
    - P4 优先级最低 → 屏蔽自己
    - 屏蔽字（对P1/P2/P3/P4）：**0, 0, 0, 1**

(3) 若屏蔽字设为（0, 0, 0, 0），这意味着什么？
    - 任何中断都不屏蔽 → **允许所有中断嵌套（最危险，可能打乱所有逻辑）**

#### 例题 4：DMA 传送时间计算

磁盘以 50MB/s 的速度传送数据，DMA 每次传送 4KB 的一个块。每次 DMA 初始化（预处理+后处理）需 2000 个时钟周期，时钟频率 2GHz。若传送 1MB 数据，CPU 被 DMA 占用的时间比例是多少？

**解答**：
- 1MB = 1024KB，每块 4KB → 1024/4 = **256 个块**
- 每块预处理+后处理 = 2000 个时钟周期
- 总共占用 = 256 × 2000 = 512000 个时钟周期
- 每个时钟 T = 1/2GHz = 0.5ns
- CPU 被占用的时间 = 512000 × 0.5ns = **256μs**
- DMA 实际传送时间 = 1MB / 50MB/s = 0.02s = **20000μs**
- CPU 占用比例 = 256 / 20000 ≈ **1.28%**

> DMA 虽然传输快，但只是传送过程中解放 CPU；预处理和后处理仍需 CPU 参与。

#### 例题 5：三种仲裁方式判断

(1) 哪种仲裁方式对故障最敏感？ → **链式查询**（中间设备故障→后面全不能工作）
(2) 哪种仲裁方式响应最快？ → **独立请求**（并行请求，独立响应）
(3) 哪种仲裁方式可动态改优先级？ → **计数器定时查询**（改初始计数值）和**独立请求**（编程更改）

#### 易错陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **地址总线 vs 寻址空间** | n 位地址总线 → 2ⁿ 个地址单元 ≠ 2ⁿ Byte（取决于编址方式） | 按字节编址时 2ⁿ Byte；按字编址时 2ⁿ 字 |
| **DMA ≠ 完全不用 CPU** | DMA 只是数据传送阶段不经过 CPU，**预处理和后处理仍需 CPU** | 整块传送中 DMA 占用总线，CPU 暂停（周期窃取） |
| **DMA 中断 2 次 vs 中断方式 每字 1 次** | DMA：开始前配置 1 次 + 完成后 1 次中断 = 共 2 次 | 中断方式：每个字都中断，N 字 = N 次中断 |
| **中断隐指令中的"关中断"** | 关中断是**自动关**（硬件做），不是程序员关 | 硬件事务——CPU 自动关中断以保护断点保存过程 |
| **屏蔽字：自己通常被屏蔽** | 中断服务程序通常不允许自己重入 | "自己不屏蔽自己"是错误的 |
| **中断优先级 ≠ 屏蔽优先级** | 自然优先级固定，但通过屏蔽字可以改实际响应顺序 | 屏蔽字可以创造"人为"优先级 |
| **PCIe ≠ PCI 升级版** | PCI 是并行总线，PCIe 是串行点对点总线 | PCIe 完全不同于 PCI，只是名字相似 |
| **总线的"分时共享"** | 同一时刻只有一组设备可使用总线 | 总线是共享资源，不是点对点链路 |

#### 记忆口诀

- **系统总线三线**："数数控——数据传内容、地址定位置、控制发信号"
- **总线仲裁**："链式简单怕故障，计数公平轮询忙，独立请求快但线多"
- **I/O 四种方式**："查询全包、中断半包、DMA 只头尾、通道全不管"
- **中断隐指令**："关保存取——关中断、保存断点、取向量"
- **DMA 三步**："CPU 设 → DMA 搬 → 中断回报"
- **DMA vs 中断**："DMA 搬砖不经过老板，中断每块砖都找老板"

## 知识点 36：并行计算架构

### 36.1 Flynn 分类法——按指令流和数据流分类

> 1966 年 Flynn 提出的计算机系统分类方法，按"指令流"和"数据流"两个维度分成 4 类。

| 分类 | 全称 | 指令流 | 数据流 | 核心特征 | 代表实例 |
|------|------|--------|--------|---------|---------|
| **SISD** | Single Instruction Single Data（单指令单数据） | 1 条 | 1 条 | 每个时钟周期处理一条指令、一个数据 | 传统单核 CPU（如 8086、单核 ARM） |
| **SIMD** | Single Instruction Multiple Data（单指令多数据） | 1 条 | 多条 | 一条指令同时操作多个数据（向量运算） | **GPU、MMX/SSE/AVX 指令集** |
| **MISD** | Multiple Instruction Single Data（多指令单数据） | 多条 | 1 条 | 多条指令同时处理同一条数据 | **理论上存在，实际几乎无实用案例** |
| **MIMD** | Multiple Instruction Multiple Data（多指令多数据） | 多条 | 多条 | 每个处理单元独立执行自己的指令和数据 | **多核处理器、分布式系统、集群** |

> 考试重点：**SISD = 单核、SIMD = GPU/向量运算、MIMD = 多核/分布式**。MISD 只作为理论存在。

**大白话类比**：Flynn 分类就像"老师布置作业"——
- **SISD** = 老师说"做第 3 题"，全班只有一个人，他自己做第 3 题（单核 CPU）
- **SIMD** = 老师说"做第 3 题"，全班 1000 个人**同时**做第 3 题，每人拿不同的数据（GPU 处理 1000 个像素，但执行同一着色程序）
- **MISD** = 多个老师对同一份作业打分——有理论意义但现实中几乎不这么干
- **MIMD** = 老师给不同的人布置不同的题，大家同时独立做（多核 CPU，每个核独立执行不同任务）

### 36.2 SIMD 指令集——MMX / SSE / AVX

> SIMD 指令是"单指令多数据"思想在 x86 指令集层面的体现：一条指令同时处理多个数据。

| 指令集 | 全称 | 推出时间 | 寄存器宽度 | 数据类型 | 核心能力 |
|--------|------|---------|-----------|---------|---------|
| **MMX** | MultiMedia eXtension | 1997（Pentium） | 64 位 | 整数 | 一次处理 8 个 8 位整数或 4 个 16 位整数 |
| **SSE** | Streaming SIMD Extensions | 1999（Pentium III） | **128 位**（XMM 寄存器） | **浮点数 + 整数** | 一次处理 4 个 32 位浮点数 |
| **SSE2/3/4** | SSE 的不断升级 | 2001~2008 | 128 位 | 双精度浮点、更丰富整数 | 覆盖更多运算类型 |
| **AVX** | Advanced Vector eXtensions | 2011（Sandy Bridge） | **256 位**（YMM 寄存器） | 浮点数 | 一次处理 8 个 32 位或 4 个 64 位浮点数 |
| **AVX-512** | AVX 512-bit | 2015（Xeon Phi） | **512 位**（ZMM 寄存器） | 浮点/整数 | 一次处理 16 个 32 位浮点数 |

**SIMD 的应用场景**：
- 图像处理：一张图片 1920×1080 = 200 万像素，每个像素做同样的颜色变换，SIMD 加速效果显著
- 音视频编解码：大量样本做同样的压缩/解压运算
- 科学计算：向量加、矩阵乘法
- 机器学习推理：矩阵运算、卷积

**SIMD 的本质理解**：
```
标量运算（普通指令）：ADD R1, R2    → R1 + R2 = 1 个结果
向量运算（SIMD 指令）：VADD V1, V2 → V1[0..7] + V2[0..7] = 8 个结果（一条指令）
```

### 36.3 GPU 架构与 GPGPU

#### GPU 为什么适合并行计算？

| 对比维度 | CPU（如 Intel Core i7） | GPU（如 NVIDIA RTX） |
|---------|------------------------|---------------------|
| 核心特点 | **少量强大的核心**（4~16 核） | **大量简单的核心**（数千个 CUDA 核心） |
| 单核性能 | **强**（高主频、复杂乱序执行） | 弱（简单顺序执行） |
| 并行度 | 低（几十个线程） | **极高**（数万个线程） |
| 擅长任务 | 复杂控制逻辑、串行任务 | **大规模数据并行、矩阵运算** |
| 缓存 | 大容量多级缓存 | 小缓存、高带宽显存 |
| 典型应用 | OS、浏览器、数据库 | 图形渲染、深度学习、科学计算 |
| 功耗/核 | 高（每核几十瓦） | 低（每核不到 1 瓦） |

**大白话类比**：CPU vs GPU 就像"博士 vs 一万个小学生"——
- **CPU** = 清华博士：什么复杂问题都能解，但一次只能做一个任务。让他算 10000 个简单加法，他会一个个算。
- **GPU** = 10000 个小学生：每个人只会做简单加减乘除，但 10000 人同时做，简单加法瞬间完成。
- 深度学习的矩阵运算 = 大量简单乘加运算 → GPU 的天然主战场。

#### GPGPU（通用计算 GPU）与 CUDA

| 概念 | 含义 |
|------|------|
| **GPGPU** | General-Purpose computing on GPU（用 GPU 做通用计算，不仅是图形） |
| **CUDA** | NVIDIA 推出的 GPU 编程框架（Compute Unified Device Architecture），用 C/C++ 写跑在 GPU 上的程序 |
| **流处理器（Streaming Processor / CUDA Core）** | GPU 中最小的计算单元，一个 GPU 有数千个 |
| **流式多处理器（SM）** | 多个 CUDA Core 组成一组，共享控制和缓存 |
| **线程束（Warp）** | NVIDIA GPU 中 32 个线程为一组，同时执行同一条指令（这是 SIMD 在 GPU 上的体现！） |

**GPU 的内存层次**：
```
全局内存（最大最慢）→ L2 缓存 → 共享内存（同一线程块内线程共享）→ 寄存器（每线程私有）
```

### 36.4 多核处理器架构

#### 多核处理器分类

| 类型 | 结构 | 特点 | 优势 | 挑战 |
|------|------|------|------|------|
| **同构多核** | 所有核心完全相同（如同型号 CPU 核心 × 4） | 设计简单，任务均匀分配 | 负载均衡容易、开发简单 | 能效比不够优化 |
| **异构多核** | 不同核心混合（大核+小核，如 ARM big.LITTLE、Intel P-core+E-core） | **性能功耗平衡** | 重任务用大核、轻任务用小核→省电 | 调度复杂（OS 需要智能地分配任务） |

#### 多核处理器的关键技术

**（1）缓存一致性（Cache Coherence）**

多个核心各自有独立的 L1/L2 Cache，但共享同一个主存。如果核心 A 修改了自己 Cache 中的数据，核心 B 的 Cache 中同一数据的副本就"过时"了——这就是**缓存一致性问题**。

**MESI 协议**（最经典的缓存一致性协议）：

| 状态 | 全称 | 含义 |
|------|------|------|
| **M（Modified）** | 已修改 | 数据只在本核心的 Cache 中，已被修改，与主存不一致 |
| **E（Exclusive）** | 独占 | 数据只在本核心的 Cache 中，但与主存一致 |
| **S（Shared）** | 共享 | 数据可能在多个核心的 Cache 中，与主存一致 |
| **I（Invalid）** | 无效 | 本 Cache 行中的数据无效（已被其他核心修改） |

**MESI 协议的基本规则**：
- 核心要写数据时，必须先获得"独占权"——通知其他核心将该数据的 Cache 行置为 I（无效）
- 核心要读数据时，如果其他核心有 M 状态的数据，必须先写回主存

**（2）内存一致性模型**

| 模型 | 规则 | 特点 |
|------|------|------|
| **顺序一致性** | 所有核心的执行结果看起来像是按某种顺序交织执行的 | 最严格、程序员最容易理解，但性能最差 |
| **弱一致性** | 只有同步操作（如锁）才保证顺序，其他操作可能乱序 | 性能好，但需要程序员显式同步 |

**（3）多核互连结构**

| 互连方式 | 结构 | 优点 | 缺点 |
|---------|------|------|------|
| **总线（Bus）** | 所有核心挂在一条共享总线上 | 简单 | 核心多了总线成为瓶颈 |
| **交叉开关（Crossbar）** | 每个核心有独立通道连到每个内存控制器 | 高带宽、非阻塞 | 成本随核心数平方增长 |
| **片上网络（NoC）** | 核心通过 mesh/torus 等网络拓扑互连 | 可扩展到大量核心 | 延迟较高、路由复杂 |

**ARM big.LITTLE 示例**：
- Cortex-A78（大核/性能核）：跑游戏、视频渲染
- Cortex-A55（小核/效率核）：跑后台任务、待机、消息推送
- 手机上 90% 的时间在用效率核，省电效果显著

**Intel 大小核**：
- P-core（Performance，性能核）：高单线程性能，类似大核
- E-core（Efficient，效率核）：多线程吞吐量高，类似小核
- 调度方式：Thread Director 技术——硬件监控线程状态，OS 根据建议动态调度

### 36.5 并行计算的两种基本模型

| 模型 | 通信方式 | 内存架构 | 编程复杂度 | 典型技术 | 适用场景 |
|------|---------|---------|-----------|---------|---------|
| **共享内存模型** | 所有处理器共享同一块**物理内存**，通过读写共享变量通信 | 统一地址空间 | 简单（但需要同步机制防竞争） | **OpenMP**、Pthreads | 单台多核机器 |
| **消息传递模型** | 每个处理器有**自己的私有内存**，通过显式发送/接收消息通信 | 分布式地址空间 | 复杂（需要显式编程通信） | **MPI（Message Passing Interface）** | **集群、分布式系统** |

**两种模型的对比**：

| 对比维度 | 共享内存 | 消息传递 |
|---------|---------|---------|
| 在哪用 | 多核 CPU（同一台机器内） | 集群（多个独立机器） |
| 数据共享 | 直接访问共享变量 | 显式发送/接收消息 |
| 同步方式 | 锁、信号量、屏障 | 消息排序、阻塞接收 |
| 性能 | 通信延迟低（直接读内存） | 通信延迟高（网络传输） |
| 扩展性 | 差（核心数增多→总线/内存带宽瓶颈→扩展到几十核困难） | **好**（可扩展到数千个节点） |
| 典型框架 | OpenMP | MPI |

#### OpenMP 编程模型详解

OpenMP 采用**fork-join 模型**：

```
主线程
  ├─ fork（创建多个工作线程）
  │    ├─ 线程1 处理迭代 0~999
  │    ├─ 线程2 处理迭代 1000~1999
  │    ├─ 线程3 处理迭代 2000~2999
  │    └─ 线程4 处理迭代 3000~3999
  └─ join（所有线程完成后汇合到主线程）
```

**OpenMP 常用指令**：

```c
#pragma omp parallel for        // 并行化 for 循环
#pragma omp parallel            // 创建并行区域
#pragma omp critical            // 临界区（一次一个线程执行）
#pragma omp barrier             // 同步屏障（所有线程在此等待）
#pragma omp atomic              // 原子操作
```

#### MPI 编程模型详解

MPI 采用 **SPMD（Single Program Multiple Data）** 模型：
- 所有进程运行同一份代码
- 每个进程有不同的 rank（编号 0, 1, 2, ...）
- 通过 `rank` 判断自己应该处理哪部分数据

**MPI 常用操作**：

```
MPI_Send()       — 发送消息
MPI_Recv()       — 接收消息
MPI_Bcast()      — 广播（一个进程发，所有进程收）
MPI_Scatter()    — 分散数据
MPI_Gather()     — 收集数据
MPI_Reduce()     — 归约操作（求和/求最大值等）
MPI_Barrier()    — 同步屏障
```

#### 并行计算中的同步原语

| 原语 | 含义 | 用途 |
|------|------|------|
| **锁（Lock/Mutex）** | 同时只能一个线程持有 | 保护临界区 |
| **信号量（Semaphore）** | 计数器，控制同时访问资源的线程数 | 有限资源的并发控制 |
| **条件变量（Condition Variable）** | 线程等待某个条件成立 | 生产者-消费者模式 |
| **屏障（Barrier）** | 所有线程到达同一点后才继续 | 阶段同步（如迭代算法） |

#### 并行计算常见问题

| 问题 | 含义 | 解决方案 |
|------|------|---------|
| **死锁（Deadlock）** | 线程互相等待对方释放资源 | 统一加锁顺序、超时机制 |
| **竞争条件（Race Condition）** | 结果取决于线程执行顺序 | 锁、原子操作 |
| **负载不均衡** | 各线程工作量不同，快的等慢的 | 动态任务分配（work stealing） |
| **伪共享（False Sharing）** | 两个线程修改同一 Cache 行的不同变量，导致 Cache 行频繁失效 | 数据填充对齐 |

### 36.6 阿姆达尔定律——并行计算的"天花板"

#### 核心公式

```
S = 1 / [(1-f) + f/k]

其中：
  f  = 可以并行化的部分占总执行时间的比例（0 ≤ f ≤ 1）
  k  = 并行部分的加速倍数（如用了 k 个处理器）
  S  = 整体加速比
  1-f = 不可并行化（必须串行执行）部分的比例
```

**当 k → ∞ 时（即并行部分被加速到无限快）**：

```
S_max = 1 / (1-f)
```

这就是阿姆达尔定律的核心结论：**整体加速比受限于不可并行化的部分**。

#### 例题 1：基本计算

某程序 80% 可以并行化，用 4 核 CPU。求整体加速比和极限加速比。

**解答**：
- f = 0.8, k = 4
- S = 1 / [(1-0.8) + 0.8/4] = 1 / [0.2 + 0.2] = 1/0.4 = **2.5 倍**
- S_max = 1/(1-0.8) = 1/0.2 = **5 倍**（即使有无穷多核，加速比不超过 5 倍）

#### 例题 2：不同并行化比例对比

用 16 核 CPU，计算 f=50%、80%、95%、99% 时的加速比和极限加速比。

| f | 1-f（串行） | S(16核) | S_max(∞核) | 结论 |
|---|------------|---------|------------|------|
| 50% | 0.50 | 2.00 / [0.50+0.13] ≈ **1.88** | **2.00** | 并行度太低，多核几乎没用 |
| 80% | 0.20 | 1 / [0.20+0.05] ≈ **4.00** | **5.00** | |
| 95% | 0.05 | 1 / [0.05+0.06] ≈ **9.14** | **20.00** | |
| 99% | 0.01 | 1 / [0.01+0.06] ≈ **14.04** | **100.00** | 即使 99% 可并行，16 核也只能加速 14 倍 |

> **关键洞察**：即使 95% 可并行化，用 16 核也只能加速约 9 倍（远不到 16 倍）。当 f<100% 时，加速比总是小于 min(k, 1/(1-f))。

#### 例题 3：给定加速比目标反推资源

某程序 90% 可并行化。若希望整体加速比达到 5 倍，至少需要多少核？

**解答**：
- S = 1 / [(1-0.9) + 0.9/k] ≥ 5
- 1 / [0.1 + 0.9/k] ≥ 5
- 0.1 + 0.9/k ≤ 0.2
- 0.9/k ≤ 0.1
- k ≥ 0.9/0.1 = **9 核**

> 即使 90% 可并行，要加速 5 倍也需要 9 个核——而极限加速比（∞核）也只有 10 倍。越接近极限，需要的资源呈指数增长。

#### 例题 4：改进某部件后整体加速比

某计算机系统，CPU 时间占总时间的 60%，I/O 时间占 40%。现 CPU 性能提升了 3 倍（即 CPU 部分快了 3 倍），I/O 部分不变。问整体加速比。

**解答**：
- 可改进部分 f = 60% = 0.6, k = 3
- S = 1 / [(1-0.6) + 0.6/3] = 1 / [0.4 + 0.2] = 1/0.6 ≈ **1.67 倍**

> 即使 CPU 快了 3 倍，整体只快 1.67 倍——因为 I/O 的 40% 没变，拖了后腿。

#### 例题 5：阿姆达尔定律在流水线中的应用

某 CPU 可以把 ALU 运算加速 5 倍。ALU 运算占总指令执行时间的 30%。问整体加速比。

**解答**：
- f = 0.3, k = 5
- S = 1 / [(1-0.3) + 0.3/5] = 1 / [0.7 + 0.06] = 1/0.76 ≈ **1.32 倍**

> 把 ALU 加速 5 倍（一听很厉害！），但整体只快了 32%——因为 ALU 只占 30%，还有 70% 的其他操作没变。这再次印证了"瓶颈优化优先"原则。

### 36.7 并行计算架构——5 道例题 + 易错陷阱 + 记忆口诀

#### 综合例题 1：Flynn 分类识别

判断以下系统属于 Flynn 分类的哪一类：
(1) Intel Core i9（16 核） → **MIMD**（多核，每个核独立执行不同指令和数据）
(2) NVIDIA RTX 4090 GPU → **SIMD**（数千个核心执行同一着色/计算程序）
(3) Intel 8086 单核处理器 → **SISD**（单指令单数据）
(4) SSE 指令做向量加法（8 个浮点数同时相加） → **SIMD**（单指令多数据）

#### 综合例题 2：加速比的误导

"某程序并行部分占 95%，用 100 核 CPU，加速比应该是 20 左右。"这个说法对吗？

**解答**：不对。
- S = 1/[(1-0.95) + 0.95/100] = 1/[0.05+0.0095] = 1/0.0595 ≈ **16.8 倍**
- 加速比受到 5% 串行部分的严重限制。即使 10000 核，极限加速比也只有 1/0.05=20 倍。
- 这个场景下，多投入 100 核却只能加速不到 17 倍——阿姆达尔定律的威慑力。

#### 综合例题 3：共享内存 vs 消息传递

(1) OpenMP 是哪种并行模型的实现？ → **共享内存模型**
(2) MPI 是哪种并行模型的实现？ → **消息传递模型**
(3) 单台 16 核服务器上做并行计算，应该选哪种模型？ → **共享内存**（同一台机器，内存共享，OpenMP 更合适）
(4) 100 台机器组成的集群上做并行计算，应该选哪种模型？ → **消息传递**（跨机器，各自拥有独立内存，MPI 更合适）

#### 综合例题 4：SIMD 计算加速比

某图像处理任务对 1024×1024 个像素做同样的颜色变换。CPU 标量指令一次处理 1 个像素，需 100ns。SSE 指令一次处理 4 个像素，需 100ns。AVX-512 指令一次处理 16 个像素，需 100ns。CPU 核心数不变（单核）。分别求 SSE 和 AVX-512 的加速比。

**解答**：
- 标量总时间 = 1024² × 100ns ≈ **104.86ms**
- SSE：每次处理 4 像素 → 1024²/4 × 100ns ≈ 26.21ms，加速比 = 104.86/26.21 = **4 倍**
- AVX-512：每次处理 16 像素 → 1024²/16 × 100ns ≈ 6.55ms，加速比 = 104.86/6.55 = **16 倍**

> SIMD 通过一条指令处理多个数据实现加速，本质上等于数据级的并行（每个像素的操作完全独立）。

#### 综合例题 5：同构 vs 异构多核

(1) 手机里的 4 个大核 + 4 个小核属于哪种架构？ → **异构多核**（ARM big.LITTLE）
(2) 服务器里 32 个完全相同核心属于哪种架构？ → **同构多核**
(3) 异构多核的最大优势是什么？ → **能效比高**（轻任务用小核省电，重任务用大核跑性能）

#### 易错陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **阿姆达尔定律 f 是比例不是绝对值** | f=80% 意味着参数取值 0.8，不是 80 | 公式中的 f 是小数（0~1） |
| **加速比极限是 1/(1-f)** | 即使 k→∞，S 有上限 | 问"最多能达到多少倍"时用 S_max=1/(1-f) |
| **MISD 几乎不存在** | 题目问"以下哪种 Flynn 分类不存在实际实现"，通常选 MISD | 记住：MISD 只是理论模型 |
| **SIMD ≠ MIMD** | SIMD 是一条指令处理多个数据（GPU 同时做同一件事）；MIMD 是多条指令处理多个数据（多核各干各的） | GPU=SIMD，多核 CPU=MIMD |
| **共享内存不适用跨机器** | 两台物理机器的内存无法直接共享 | 跨机器必须用消息传递模型（MPI） |
| **多核 ≠ 加速比等于核数** | 受阿姆达尔定律限制，16 核很少能加速 16 倍 | 先算串行部分占比再推算 |
| **异构多核不是所有核一起干同一件事** | 大核和小核分工：大核跑重活，小核跑轻活 | 异构调度是 OS 核心难题 |
| **CUDA Core ≠ CPU Core** | GPU 里 4096 个 CUDA Core 不等于 4096 个独立 CPU 核 | CUDA Core 只能做简单运算，不是通用核心 |

#### 记忆口诀

- **Flynn 分类**："单核 S(SISD)，GPU S(SIMD)，多核 M(MIMD)，MISD 没有用"
- **阿姆达尔定律**："并行无限快，串行拖后腿；1-f 是天花板，多核也白搭"
- **SIMD 指令**："一条指令多个数，MMX 整数 SSE 浮，AVX 更宽 256"
- **GPU vs CPU**："CPU 博士串行强，GPU 小学生并行走"
- **并行模型**："一台机器共享内存(OpenMP)，多台机器消息传递(MPI)"
- **加速比公式**："S = 1/(（1-f）+ f/k)，f=0.8,k=4 → S=2.5"

<details><summary>参考答案</summary>

1. 多核处理器 → **MIMD**（多指令多数据）；GPU → **SIMD**（单指令多数据）
2. S = 1/[(1-0.6)+0.6/8] = 1/[0.4+0.075] = 1/0.475 ≈ **2.11 倍**；S_max = 1/0.4 = **2.5 倍**
3. **共享内存**：单台多核机器内（OpenMP）；**消息传递**：多台机器集群（MPI）
4. SSE（128 位）：4 个（128÷32=4）；AVX（256 位）：**8 个**（256÷32=8）；AVX-512：**16 个**
</details>

## 附录：计算题公式速查

### 一、CPU 性能公式

| 公式 | 含义 | 说明 |
|------|------|------|
| **CPU 时间 = IC × CPI × T** | CPU 执行一个程序的总时间 | IC=指令条数，CPI=每条指令平均时钟数，T=时钟周期 |
| **T = 1/f** | 时钟周期 = 主频的倒数 | f=1GHz → T=1ns |
| **MIPS = f / (CPI × 10⁶)** | 每秒百万条指令 | 也可写成 MIPS = IC/(CPU时间×10⁶) |
| **MFLOPS = 浮点操作数/(CPU时间×10⁶)** | 每秒百万次浮点运算 | 浮点密集型程序的性能指标 |
| **CPI = 总时钟周期数/总指令数** | 平均每条指令的时钟周期数 | 不同指令 CPI 不同，取加权平均 |

**CPU 时间计算例题**：
- 某程序有 2×10⁶ 条指令，CPI=1.5，主频 3GHz（T=1/3 ns）
- CPU 时间 = 2×10⁶ × 1.5 × (1/3)ns = 1×10⁶ ns = **1ms**

### 二、阿姆达尔定律

| 公式 | 含义 |
|------|------|
| **S = 1 / [(1-f) + f/k]** | 整体加速比 |
| **S_max = 1/(1-f)** | 当 k→∞ 时的极限加速比 |

- f = 可改进部分占总时间的比例
- k = 改进部分的加速倍数

**关键结论**：即使把某部分加速到无限快（k→∞），整体加速比也不超过 1/(1-f)。改进受限于不可改进部分。

### 三、Cache 命中率公式

| 公式 | 含义 |
|------|------|
| **ta = h × tc + (1-h) × tm** | 单级 Cache 平均访问时间 |
| **ta = h1×t1 + (1-h1)×h2×(t1+t2) + (1-h1)×(1-h2)×(t1+t2+tm)** | 两级 Cache 平均访问时间 |

- h/h1/h2 = 命中率
- tc/t1/t2 = Cache 访问时间
- tm = 主存访问时间

**失效率** = 1-h（Cache 不命中的概率）。高命中率下，失效率才是关键——失效率减半，ta 中未命中部分就减半。

### 四、流水线公式

| 公式 | 含义 | 说明 |
|------|------|------|
| **T流 = k×Δt + (n-1)×Δt = (k+n-1)×Δt** | n 条指令流水线执行时间 | k=段数，Δt=每段时间（取最长段） |
| **T顺 = n × k × Δt** | n 条指令顺序执行时间 | 不用流水线 |
| **S = T顺/T流 = (n×k)/(k+n-1)** | 流水线加速比 | 当 n→∞ 时，S≈k |
| **E = S/k** | 流水线效率 | 理想情况 E=1 |
| **吞吐率 p = n/T流** | 单位时间完成指令数 | 当 n→∞ 时，p≈1/Δt |

**各段时间不等时**：Δt 取最长段的时间（瓶颈段），流水线时钟周期由最慢段决定。

**含阻塞**：T流_阻塞 = T流 + 阻塞总时钟数

### 五、其他常用公式

| 公式 | 含义 |
|------|------|
| **补码转原码** | 负数补码：取反+1；正数补码=原码 |
| **浮点数真值** | N = (-1)^S × 1.M × 2^(E-bias) |
| **海明码** | 2^k ≥ n+k+1（k=校验位数，n=数据位数） |
| **磁盘容量** | 磁头数 × 柱面数 × 每道扇区数 × 每扇区字节数 |
| **磁盘平均存取时间** | 寻道时间 + 旋转延迟（半圈时间）+ 传输时间 |

### 六、公式使用场景速查

| 题目类型 | 用什么公式 | 关键参数 |
|---------|-----------|---------|
| 算程序执行时间 | CPU 时间 = IC×CPI×T | 注意单位统一 |
| 算 MIPS | f/(CPI×10⁶) | f 用 Hz，CPI 是小数 |
| 提高了某部分性能整体快多少 | 阿姆达尔 S = 1/[(1-f)+f/k] | f 是比例不是绝对值 |
| 算 Cache 平均访问时间 | ta = h×tc+(1-h)×tm | 注意 h 是小数不是百分比 |
| 算流水线执行时间 | (k+n-1)×Δt | 各段时间不等时取最长段 |
| 算流水线加速比 | (n×k)/(k+n-1) | n 大时约等于 k |
| 算补码值 | 正数直接算，负数取反+1 | 先看符号位 |
| 判断溢出 | 双符号位法 / 进位判断法 | 正正得负溢，负负得正溢 |

### 一、补码计算题——解题模板与易错陷阱

#### 1.1 补码计算标准模板

**题型一：给定十进制数，求补码表示**

| 步骤 | 正数 | 负数 |
|------|------|------|
| 1 | 转二进制 | 先取绝对值转二进制 |
| 2 | 高位补 0 到指定位数 | 高位补 0 到指定位数 |
| 3 | 符号位固定为 0 | 按位取反 |
| 4 | 完成 | +1，完成 |

**题型二：给定补码，求十进制真值**

| 步骤 | 符号位=0（正数） | 符号位=1（负数） |
|------|-----------------|-----------------|
| 1 | 补码=原码，直接按权展开 | 方案A：取反+1得原码，再按权展开 |
| 2 | 结果即真值 | 方案B：按权展开（符号位权值为 -2^(n-1)） |
| 3 | — | 加负号，即真值 |

**方案B 示例**（更快捷）：
- 8 位补码 `1001 0110`：符号位权值 = -128
- 真值 = -128 + 0×64 + 0×32 + 1×16 + 0×8 + 1×4 + 1×2 + 0×1 = -128 + 16 + 4 + 2 = **-106**

> 方案B 更快：直接把符号位当作 -2^(n-1)，其余位正常按权展开相加。

**题型三：补码加减运算**

| 步骤 | 操作 |
|------|------|
| 1 | 将所有数转为补码 |
| 2 | 补码直接相加（减法转为加负数补码） |
| 3 | 判断溢出 |
| 4 | 若结果符号位为 1，转回原码得真值 |

#### 1.2 补码溢出判断——三种方法对比

| 方法 | 判断规则 | 示例 |
|------|---------|------|
| **单符号位法** | 正+正=负 → 正溢；负+负=正 → 负溢 | 正+正=负，错！ |
| **双符号位法** | 00=正常正，11=正常负，01=正溢，10=负溢 | 01=正溢，10=负溢 |
| **进位判断法** | 最高位进位 XOR 次高位进位 = 1 → 溢出 | 进位不同→溢出 |

**双符号位（变形补码）详细说明**：

变形补码使用两位符号位（00 表示正，11 表示负），两符号位同时参与运算：

```
正数：00 后跟数值位（如 00 1011 = +11）
负数：11 后跟数值位取反+1（如 11 0101 = -11）
```

运算后看两符号位：
- **00** = 结果为正，无溢出
- **11** = 结果为负，无溢出
- **01** = 正溢出（两个正数相加结果超出范围）
- **10** = 负溢出（两个负数相加结果超出范围）

#### 1.3 补码常见陷阱

| 陷阱 | 说明 | 避坑要点 |
|------|------|---------|
| **补码范围不对称** | 8 位补码：-128~+127（不是 -127~+127） | 补码比原码多一个负数 |
| **-128 没有对应的原码** | 8 位补码 1000 0000 = -128，无法用原码表示 | 题目问"补码 1000 0000 的真值"，直接写 -128 |
| **-128 取负会溢出** | 对 -128 取负（即求补码），结果仍是 -128（溢出） | 8 位补码中 128 不存在 |
| **零的补码唯一** | 00000000 的补码还是 00000000 | 不像原码/反码有 +0 和 -0 |
| **移码 = 补码符号位取反** | 移码 1000 0000 = 0，不是 -128 | 移码用来比较大小，最小的数移码全 0 |
| **减法变加法** | [X-Y]补 = [X]补 + [-Y]补 | 先对 Y 的补码取反+1 得到 [-Y]补，再相加 |

**真题陷阱示例**：

> 陷阱题：8 位补码 1000 0000 表示的真值是多少？
> - 常见错误回答：-0 或 -127
> - 正确答案：**-128**（补码比原码多一个负数，此数是 -128）
> - 解释：符号位 1，数值位全 0，权值 = -128 + 0 = -128

> 陷阱题：8 位补码中，对 -128 取负的结果是什么？
> - 常见错误回答：+128
> - 正确答案：**溢出（结果仍是 -128）**
> - 解释：对 1000 0000 取反+1 = 0111 1111 + 1 = 1000 0000 = -128（自己）

### 二、IEEE754 浮点数计算题——解题模板与真题

#### 2.1 IEEE754 核心公式速记

```
N = (-1)^S × 1.M × 2^(E - bias)

单精度 float：S=1位, E=8位, M=23位, bias=127
双精度 double：S=1位, E=11位, M=52位, bias=1023
```

**记忆口诀**：1-8-23-127（单精度），1-11-52-1023（双精度）

#### 2.2 题型一：十进制小数 → IEEE754 单精度浮点数

**例题**：将 -12.625 转为 IEEE754 单精度浮点格式。

**标准解题步骤**：

| 步骤 | 操作 | 结果 |
|------|------|------|
| ① 确定符号位 S | 负数 → S=1 | S=**1** |
| ② 十进制转二进制 | 整数 12=1100₂，小数 0.625=0.101₂ | 12.625 = 1100.**101**₂ |
| ③ 规格化到 1.M 形式 | 小数点左移 3 位：1.100101 × 2³ | M=**100101**（隐含 1 不存） |
| ④ 计算阶码 E | E = 实际指数 + bias = 3 + 127 = 130 | E = 130 = **1000 0010**₂ |
| ⑤ 尾数 M 补足 23 位 | 100101 后面补 0 到 23 位 | M = 1001010 00000000 00000000 |
| ⑥ 按 S-E-M 拼接 | S(1)  E(8)  M(23) | 完整结果 |

**最终结果**：
```
1 | 1000 0010 | 1001010 00000000 00000000
= 1100 0001 0100 1010 0000 0000 0000 0000
= 0xC14A0000
```

> **关键步骤**：规格化时要确保小数点前只有 1 位且为 1（即 1.xxx 形式），然后隐含这个 1 不存入尾数 M。

#### 2.3 题型二：IEEE754 浮点数 → 十进制真值

**例题**：已知单精度浮点数 `0xC1480000`，求十进制真值。

**标准解题步骤**：

| 步骤 | 操作 | 结果 |
|------|------|------|
| ① 十六进制转二进制 | 0xC1480000 | 1100 0001 0100 1000 0000 0000 0000 0000 |
| ② 拆分 S-E-M | S=1, E=10000010₂, M=1001000...0 | S=1（负数） |
| ③ 计算 E 的真值 | E=10000010₂=130, 实际指数=130-127=3 | 指数=**3** |
| ④ 还原尾数 | 隐含 1 + M = 1.1001 | 1.1001₂ |
| ⑤ 计算真值 | N = (-1)¹ × 1.1001₂ × 2³ | N = -1.1001₂ × 8 |
| ⑥ 二进制转十进制 | 1.1001₂ = 1 + 0.5 + 0 + 0 + 0.0625 = 1.5625 | N = -1.5625 × 8 = **-12.5** |

#### 2.4 IEEE754 特殊值速查

| 条件 | 含义 | S/E/M 特征 |
|------|------|-----------|
| E=0, M=0 | ±0 | S=0→+0, S=1→-0 |
| E=0, M≠0 | 非规格化数 | 实际尾数 = 0.M（非 1.M） |
| E=全1(255), M=0 | ±∞（无穷大） | S=0→+∞, S=1→-∞ |
| E=全1(255), M≠0 | NaN（非数） | 如 0/0 的结果 |

#### 2.5 IEEE754 常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **尾数隐含 1** | 规格化后尾数 1.M，1 不存 | 转换时别忘了加回隐含的 1 |
| **阶码用移码** | E 不是补码，是移码（真值+bias） | E = 真指数 + 127，不是补码 |
| **对阶方向** | 小阶向大阶看齐，不是反过来 | 口诀："小阶向大阶看齐，尾数右移" |
| **对阶丢失** | 小阶尾数右移时低位丢失 | 对阶时尾数右移，可能丢精度 |
| **规格化要求** | 结果尾数必须 1.xxx 形式 | 尾数加减后可能不是 1.xxx，要规格化 |
| **舍入方式** | 0 舍 1 入、恒置 1 法、截断法 | 题目会指定舍入方式 |
| **阶码全 0 和全 1** | 全 0=非规格化/±0，全 1=±∞/NaN | 规格化数的阶码不能是 0 或 255 |

### 三、Cache 命中率计算题——解题模板与真题变体

#### 3.1 基础公式速查

```
单级 Cache：ta = h × tc + (1-h) × tm

两级 Cache：ta = h1×t1 + (1-h1)×h2×(t1+t2) + (1-h1)×(1-h2)×(t1+t2+tm)

加速比（相比无 Cache）：S = tm / ta
```

#### 3.2 题型一：基本命中率计算

**解题模板**：
1. 确认 h、tc、tm 三个参数
2. 代入 ta = h×tc + (1-h)×tm
3. 注意 h 是小数（如 95% = 0.95），不是百分比

#### 3.3 题型二：已知 ta 反推命中率

**解题模板**：
1. 设不等式 ta ≤ 目标值
2. 代入公式，解出 h 的范围
3. 注意：h 必须 ≤ 1

**例题**：tc=1ns, tm=100ns，要求 ta≤2ns，求 h 最小值。
- h×1 + (1-h)×100 ≤ 2 → h + 100 - 100h ≤ 2 → 99h ≥ 98 → h ≥ 0.9899
- 命中率至少需要 **98.99%**

#### 3.4 题型三：多级 Cache 计算

**解题模板**：
1. 画访问路径图：L1→L2→主存
2. 每条路径算概率 × 时间
3. 注意：不命中时已经花掉了检查时间

**L1 不命中→L2 的访问时间**：t1 + t2（先花 t1 发现 L1 不命中，再花 t2 访问 L2）

#### 3.5 题型四：命中率变化对性能的影响

**关键结论**：失效率（1-h）才是关键指标。
- 失效率从 10% 降到 5%（减半），平均访问时间中"未命中部分"也减半
- 失效率从 1% 降到 0.5%，性能提升甚至比从 10% 降到 5% 更大（因为此时命中部分占比极高）

#### 3.6 Cache 计算常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **h 用百分比代入** | 把 h=95% 当成 95 代入公式 | h 必须用小数 0.95 |
| **多级 Cache 漏算检测时间** | L1 不命中后，访问 L2 还要加上 L1 的检测时间 | 路径时间 = t1+t2（不是 t2） |
| **混淆 h1 和 h2 的含义** | h2 是 L1 不命中后 L2 的命中率（局部命中率） | h2 = P(L2命中 | L1不命中) |
| **全局命中率 vs 局部命中率** | 题目可能给全局命中率（L2命中次数/总访问次数） | 仔细读题，区分"局部命中率"和"全局命中率" |
| **写策略影响** | 写回法（Write Back）和写直达（Write Through）的访问时间不同 | 写回法读不命中可能需要先写回脏块 |
| **TLB 和 Cache 串联** | 地址变换（TLB/页表）也需要时间 | ta = TLB访问时间 + Cache访问时间 |

### 四、流水线加速比计算题——解题模板与真题变体

#### 4.1 核心公式速查

```
各段时间相等时：
  T顺 = n × k × Δt
  T流 = k×Δt + (n-1)×Δt = (k+n-1)×Δt
  S = T顺/T流 = (n×k)/(k+n-1)
  E = S/k
  吞吐率 = n/T流

各段时间不等时：
  Δt = max(各段时间)  ← 瓶颈段决定时钟周期
  或：T流 = Σ(各段×1) + (n-1)×max(各段)  ← 准确公式
```

#### 4.2 题型一：标准流水线（各段时间相等）

**解题模板**：
1. 确认 k（段数）、n（指令数）、Δt（每段时间）
2. T顺 = n×k×Δt
3. T流 = (k+n-1)×Δt
4. 加速比 = T顺/T流

#### 4.3 题型二：各段时间不等的流水线（瓶颈段）

这是真题中最常见的变体，考察"时钟周期由最慢段决定"。

**解题模板**：
1. 找出各段中最长的时间 = Δt_max
2. 流水线时钟周期 = Δt_max（所有段必须按最慢段的节奏来）
3. T流 = k×Δt_max + (n-1)×Δt_max = (k+n-1)×Δt_max
4. 注意：T顺 仍按各段实际时间累加（因为顺序执行时各段是独立的）

**例题**：某流水线 4 段，各段时间为 2ns/3ns/4ns/1ns，执行 100 条指令。
- Δt_max = 4ns
- T顺 = 100×(2+3+4+1) = 1000ns
- T流 = 4×4 + 99×4 = 16+396 = 412ns
- 加速比 = 1000/412 ≈ **2.43**

#### 4.4 题型三：含阻塞的流水线

**解题模板**：
1. 先算无阻塞的 T流
2. 加上阻塞带来的额外时钟周期
3. 计算加速比

**常见阻塞场景**：
- 数据相关（RAW）：指令 B 需要等待指令 A 的结果
- 控制相关（分支）：分支预测失败，需要清空流水线
- 结构相关：资源冲突，需要等待

#### 4.5 题型四：超流水线 / 超标量

**超流水线**：将每段再细分，提高时钟频率。但 k 增大，建立时间也增大。

**超标量**：每个时钟周期可以发射多条指令（如双发射、四发射）。
- 理想情况下，执行 n 条指令的时间 = (k + n/m - 1)×Δt（m 为发射宽度）

#### 4.6 流水线计算常见陷阱

| 陷阱 | 说明 | 避坑 |
|------|------|------|
| **各段时间不等时，Δt 取最长段** | 很多人直接用平均值或各段实际时间 | 流水线时钟 = 最慢段的时间 |
| **T顺 ≠ k×Δt_max** | 顺序执行时各段独立，时间按实际累加 | T顺 = n×Σ(各段实际时间) |
| **n 较小时加速比远小于 k** | 建立时间（k-1 段）占比大 | n=10, k=5 时加速比只有约 3.57 |
| **加速比极限是 k** | 当 n→∞ 时，S→k | 不可能超过段数 k |
| **阻塞对性能影响很大** | 一次阻塞可能导致多条指令等待 | 每 1% 的指令阻塞，性能损失可能 >1% |
| **混淆超流水线和超标量** | 超流水线=细分流水段，超标量=多条流水线并行 | 超流水线增加 k，超标量增加 m |

### 五、各题型解题模板速查卡

#### 5.1 补码计算题

```
类型A：十进制→补码
  ① 绝对值转二进制 ② 高位补 0 到指定位数
  ③ 正数直接是补码 ④ 负数：取反+1（符号位不变）

类型B：补码→十进制
  方法1（按权展开）：符号位权值 = -2^(n-1)，其余按正权展开求和
  方法2（转原码）：负数取反+1得原码，再按权展开

类型C：补码加减
  ① 全部转补码 ② 直接相加 ③ 判断溢出 ④ 负数结果转回原码

类型D：溢出判断
  ① 单符号位：正正得负溢，负负得正溢
  ② 双符号位：看两位符号位，相同=正常，01=正溢，10=负溢
  ③ 进位法：最高位进位≠次高位进位→溢出
```

#### 5.2 IEEE754 浮点数计算题

```
类型A：十进制→浮点
  ① 确定 S（正0负1）
  ② 整数+小数部分分别转二进制
  ③ 规格化到 1.xxx×2^e 形式
  ④ E = e + 127（单精度）
  ⑤ M = xxx（省去隐含 1），补 0 到 23 位
  ⑥ 拼接 S(1)+E(8)+M(23)

类型B：浮点→十进制
  ① 十六进制转二进制
  ② 拆分：S=bit31, E=bit30-23, M=bit22-0
  ③ e = E - 127
  ④ 真值 = (-1)^S × (1 + M的二进制小数) × 2^e
```

#### 5.3 Cache 命中率计算题

```
类型A：求平均访问时间
  ta = h×tc + (1-h)×tm
  关键：h 用小数（0.95），不能用百分比（95）

类型B：反推命中率
  设不等式 ta ≤ 目标值 → 解出 h → 结果转百分比

类型C：多级 Cache
  画路径图 → 每条路径算(概率×总时间) → 求和
  注意：不命中时已花掉的检测时间要算进去

类型D：加速比
  加速比 = tm / ta（相对于全部访问主存）
```

#### 5.4 流水线加速比计算题

```
类型A：各段时间相等
  T顺 = n×k×Δt, T流 = (k+n-1)×Δt
  S = (n×k)/(k+n-1), E = S/k

类型B：各段时间不等（瓶颈段）
  Δt = max(各段), T流 = (k+n-1)×Δt
  T顺 = n×Σ(各段实际时间)  ← 注意：不是 n×k×Δt

类型C：含阻塞
  T流_阻塞 = T流 + 额外阻塞周期数

类型D：极限分析
  n→∞ 时，S→k，吞吐率→1/Δt
  加速比不可能超过段数 k
```

### 六、易错陷阱汇总（全题型）

| 题型 | 陷阱 | 正确做法 |
|------|------|---------|
| 补码 | 8 位补码范围误记为 -127~+127 | 正确范围是 **-128~+127** |
| 补码 | 补码 10000000 误认为 -0 | 真值是 **-128**（注意：无对应原码） |
| 补码 | 对 -128 取负以为得 +128 | 对 -128 取负会**溢出**，结果仍为 -128 |
| 补码 | 两个正数相加得"正数"就觉得没溢出 | 双符号位法才可靠：00=正常，01=正溢 |
| 补码 | 移码和补码混淆 | 移码 = 补码符号位取反，用来比较大小 |
| IEEE754 | 尾数忘了隐含的 1 | 转换时别忘了加回 1.M 中的 1 |
| IEEE754 | 阶码误用补码 | 阶码是**移码**，E = 真指数 + 127 |
| IEEE754 | 对阶方向搞反 | **小阶向大阶**看齐，尾数右移 |
| IEEE754 | 规格化判断错误 | 规格化后尾数必须 1.xxx 形式 |
| Cache | h 用百分比代入公式 | h 必须用**小数**（0.95 不是 95） |
| Cache | 多级 Cache 漏算检测时间 | 路径时间要**累加**已花掉的检查时间 |
| Cache | 混淆局部/全局命中率 | 读题仔细，确认 h2 是"L1不命中后L2命中率"还是"全局中L2命中率" |
| Cache | 以为命中率越高越好，忽略 tc 的影响 | 当 h 极高时，tc 比 tm 更重要 |
| 流水线 | 各段时间不等时 Δt 取平均值 | Δt 应取**最长段**（瓶颈段） |
| 流水线 | 各段时间不等时 T顺 用 n×k×Δt_max | T顺 应按各段**实际时间**累加 |
| 流水线 | 认为加速比可以超过段数 k | 加速比极限就是 k（n→∞ 时 S→k） |
| 流水线 | n 很小时套用 S≈k | n 小的时候建立时间占比大，S 远小于 k |
| 流水线 | 忘加阻塞周期 | 数据相关/控制相关导致的额外等待要算进去 |
| 通用 | 单位不统一 | 所有时间统一到同一单位（ns/μs/ms） |
| 通用 | 主频 f 和时钟周期 T 的关系 | T = 1/f，f=1GHz → T=1ns，不是 1μs |

#### 真题1：IEEE754 单精度浮点数转换 ⭐⭐⭐（必考）

**【题目】** 将十进制数 **-18.375** 转换为 IEEE754 单精度浮点数的 32 位二进制表示。

**详细解题步骤**：

**第一步：分别转换整数和小数部分为二进制**
```
整数部分 18：
  18 ÷ 2 = 9 ... 余 0
   9 ÷ 2 = 4 ... 余 1
   4 ÷ 2 = 2 ... 余 0
   2 ÷ 2 = 1 ... 余 0
   1 ÷ 2 = 0 ... 余 1
  从下往上读：18₁₀ = 10010₂

小数部分 0.375：
  0.375 × 2 = 0.75 → 取整 0
  0.75  × 2 = 1.5  → 取整 1
  0.5   × 2 = 1.0  → 取整 1
  从上往下读：0.375₁₀ = 0.011₂
```

**第二步：拼接并规格化**
```
-18.375₁₀ = -10010.011₂

规格化到 1.M 形式（小数点左移 4 位）：
  10010.011₂ = 1.0010011₂ × 2⁴
```

**第三步：确定三个部分**
```
① 符号位 S：负数为 1
② 阶码 E：实际指数 = 4，E = 4 + 127 = 131 = 1000 0011₂
③ 尾数 M：1.0010011 去掉隐含的 1，取 0010011，补足 23 位
   M = 0010011 000000000 00000000
```

**第四步：拼接为 32 位**
```
S(1) | E(8)     | M(23)
 1   | 1000 0011 | 0010011 000000000 00000000

16 进制：1100 0001 1001 0011 0000 0000 0000 0000₂ = 0xC1930000
```

**答案**：**0xC1930000**

#### 真题2：Cache 命中率计算 ⭐⭐⭐（必考）

**【题目】** 某 Cache 采用**直接映射**方式，共有 8 行（行号 0~7），每行 1 个字。主存按字编址，地址序列为：
`1, 8, 1, 5, 8, 1, 5, 8, 5, 1`
假设 Cache 初始为空，求访问完成后的**命中率**。

**详细解题步骤**：

**第一步：确定映射规则**
- 直接映射：主存地址 mod 8 → Cache 行号
- 即：Cache 行号 = 地址 % 8

**第二步：逐次模拟访问过程**

| 序号 | 地址 | Cache行号 | 状态 | 命中/缺失 | Cache内容变化 |
|------|------|-----------|------|-----------|--------------|
| 1 | 1 | 1%8=1 | 行1为空 | **缺失** | 行1 ← 主存块1 |
| 2 | 8 | 8%8=0 | 行0为空 | **缺失** | 行0 ← 主存块8 |
| 3 | 1 | 1%8=1 | 行1有块1 | **命中** | 不变 |
| 4 | 5 | 5%8=5 | 行5为空 | **缺失** | 行5 ← 主存块5 |
| 5 | 8 | 8%8=0 | 行0有块8 | **命中** | 不变 |
| 6 | 1 | 1%8=1 | 行1有块1 | **命中** | 不变 |
| 7 | 5 | 5%8=5 | 行5有块5 | **命中** | 不变 |
| 8 | 8 | 8%8=0 | 行0有块8 | **命中** | 不变 |
| 9 | 5 | 5%8=5 | 行5有块5 | **命中** | 不变 |
| 10 | 1 | 1%8=1 | 行1有块1 | **命中** | 不变 |

**第三步：计算命中率**
- 总访问次数 = 10 次
- 命中次数 = 7 次（第3, 5, 6, 7, 8, 9, 10次）
- 缺失次数 = 3 次（第1, 2, 4次）
- **命中率 = 7/10 = 70%**

**答案**：**命中率 = 70%**

**变体**：若改为 4 行 Cache（行号 0~3），命中率会降低（因为地址 1 和 5 会映射到同一行产生冲突）。这就是组相联映射的优势——减少冲突缺失。

#### 真题3：流水线加速比计算 ⭐⭐⭐（必考）

**【题目】** 某 CPU 采用 5 段流水线（IF, ID, EX, MEM, WB），每段耗时 2ns。执行 100 条指令。
(1) 求顺序执行和流水线执行时间
(2) 求加速比和效率
(3) 若 MEM 段因硬件瓶颈改为 5ns（其余段仍为 2ns），重新计算加速比

**详细解题步骤**：

**(1) 各段时间相等时（每段 2ns）**

```
T顺 = n × k × Δt = 100 × 5 × 2 = 1000ns

T流 = (k + n - 1) × Δt = (5 + 100 - 1) × 2 = 104 × 2 = 208ns
      └─ 首条:5段 ─┘└─ 后续99条:每条1段 ─┘

加速比 S = 1000 / 208 ≈ 4.81

效率 E = S / k = 4.81 / 5 ≈ 96.2%
```

**(2) 各段时间不等时（MEM=5ns，其余=2ns）**

关键：流水线时钟周期取最长段 = Δt = max(2,2,5,2,2) = **5ns**

```
T顺 = n × Σ(各段实际时间) = 100 × (2+2+5+2+2) = 100 × 13 = 1300ns
      ↑ 注意：顺序执行时各段按实际时间累加，不是 k×Δt

T流 = (k + n - 1) × Δt = (5 + 99) × 5 = 104 × 5 = 520ns
      ↑ 但流水线时钟 = 最慢段 = 5ns

加速比 S = 1300 / 520 = 2.50
效率 E = 2.50 / 5 = 50%
```

**答案**：(1) 加速比 **4.81**，效率 **96.2%**；(2) 瓶颈段下加速比 **2.50**，效率 **50%**。

**启示**：一个瓶颈段（MEM=5ns）把加速比从 4.81 拉低到 2.50，效率直接腰斩。优化瓶颈段收益最大。

#### 真题4：补码加减运算与溢出判断 ⭐⭐（高频）

**【题目】** 设 8 位补码，计算下列运算并**判断溢出**：
(1) 75 + 60
(2) -100 + (-50)

**详细解题步骤**：

**(1) 75 + 60**
```
75 的补码：  0100 1011  （符号位=0，正数）
60 的补码：  0011 1100  （符号位=0，正数）

  0100 1011
+ 0011 1100
───────────
  1000 0111  （符号位=1！）
```

两个正数相加，符号位变成了 1 → **正溢出！**
- 75 + 60 = 135，但 8 位补码范围是 -128~+127
- 135 > 127，确实溢出了

**(2) -100 + (-50)**
```
-100 的补码： 1001 1100
  （原码 1110 0100 = -100，取反 1001 1011，+1 = 1001 1100）

-50 的补码：  1100 1110
  （原码 1011 0010 = -50，取反 1100 1101，+1 = 1100 1110）

  1001 1100
+ 1100 1110
───────────
1 0110 1010  （符号位=0！）
```

两个负数相加，符号位变成了 0 → **负溢出！**
- -100 + (-50) = -150，超出 -128 下限

**双符号位法验证**：
```
(1) 75 + 60：
  00 1001011
+ 00 0111100
─────────────
  01 0000111  → 双符号位 = 01 → 正溢出 ✓

(2) -100 + (-50)：
  11 0011100
+ 11 0110010
─────────────
  10 1001110  → 双符号位 = 10 → 负溢出 ✓
```

**答案**：(1) **正溢出**；(2) **负溢出**。

#### 真题5：寻址方式判断题 ⭐⭐（高频）

**【题目】** 以下每条指令分别属于哪种寻址方式？并指出取操作数需要访存几次？

(1) `MOV AX, 100H`（将地址 100H 处的内容送入 AX）
(2) `MOV AX, #100H`（将常数 100H 送入 AX）
(3) `MOV AX, [BX]`（BX 寄存器存的是操作数地址）
(4) `MOV AX, @100H`（100H 处存的是操作数的地址）
(5) `JMP +8`（跳转到 PC+8）

**答案与解析**：

| 指令 | 寻址方式 | 访存次数 | 说明 |
|------|---------|---------|------|
| (1) MOV AX, 100H | **直接寻址** | **1 次** | EA = 100H，去 100H 取操作数 |
| (2) MOV AX, #100H | **立即寻址** | **0 次** | 操作数 100H 已在指令中，取指令时同时拿到 |
| (3) MOV AX, [BX] | **寄存器间接寻址** | **1 次** | BX 内容 = 地址，去该地址取数（寄存器取地址不需要访存） |
| (4) MOV AX, @100H | **间接寻址** | **2 次** | 先去 100H 取地址，再去该地址取数 |
| (5) JMP +8 | **相对寻址** | **0 次** | EA = (PC) + 8，修改 PC 值即可，不额外访存取操作数 |

**易错提醒**：
- `MOV AX, 100H` 和 `MOV AX, #100H` 的区别：带 `#` 表示立即数（常数本身），不带 `#` 表示地址（去那个地址取数据）
- 寄存器间接 vs 间接：寄存器间接只访存 1 次（寄存器已有地址），间接访存 2 次（先去内存取地址）

#### 9.1 原码/反码/补码/移码的表示范围与转换（3 道）

**题 1（表示范围判断题）**

**[题目]** 假设机器字长为 8 位（含 1 位符号位），下列关于定点整数表示范围的说法中，正确的是（ ）。

- A. 原码和反码的表示范围完全相同，均为 -128 ~ +127
- B. 补码的表示范围比原码多一个负数，即 -128 ~ +127
- C. 移码的表示范围与补码相同，也是 -128 ~ +127
- D. 8 位原码能表示的负数范围是 -128 ~ -1

**[答案]** B

**[解析]**
- 8 位定点整数（含 1 位符号位）：
  - 原码：-127 ~ +127（正负零表示不同，各占一个编码）
  - 反码：-127 ~ +127（同样存在正负零）
  - 补码：-128 ~ +127（零只有一种表示，多出一个负数编码 -128）
  - 移码：-128 ~ +127（移码通常用于浮点数阶码，补码符号位取反即得移码）
- A 错误：原码和反码范围是 -127 ~ +127，不是 -128。
- C 错误：移码表示范围虽与补码相同，但编码方式不同，此选项表述模糊——B 更准确。
- D 错误：原码负数范围是 -127 ~ -1，不包含 -128。

**题 2（补码转换计算题）**

**[题目]** 设机器字长为 8 位，已知某数 X 的补码为 `1001 0110`，则 X 的真值为（ ）。

- A. -22
- B. -106
- C. -86
- D. -118

**[答案]** B

**[解析]**
补码转换为真值有两种方法：

**方法一（转原码法）**：补码 = 1001 0110，符号位为 1，说明是负数。对数值位取反加一：`001 0110` 取反得 `110 1001`，加 1 得 `110 1010` = 106。所以真值为 **-106**。

**方法二（权值直接法，更快）**：补码 `1001 0110`，符号位权值 = -128。真值 = -128 + 0×64 + 0×32 + 1×16 + 0×8 + 1×4 + 1×2 + 0×1 = -128 + 16 + 4 + 2 = **-106**。

**题 3（移码与补码关系题）**

**[题目]** 若机器字长为 8 位，某数的补码为 `0000 1010`，则其移码表示为（ ）。

- A. `0000 1010`
- B. `1000 1010`
- C. `1111 0110`
- D. `0111 1010`

**[答案]** B

**[解析]**
移码与补码的关系：**移码 = 补码的符号位取反**（数值位不变）。
- 补码 `0000 1010`（真值 +10）
- 符号位取反得 `1000 1010`
- 验证：移码真值 = 移码值 - 偏移量。偏移量 = 2^(8-1) = 128。`1000 1010` = 128 + 8 + 2 = 138，138 - 128 = 10，正确。

#### 9.2 存储层次结构速度/容量/价格对比题（1 道）

**题 4**

**[题目]** 下列关于存储层次结构的描述中，正确的是（ ）。

- A. 从寄存器到辅存，访问速度越来越快，容量越来越大，单位价格越来越低
- B. CPU 可直接访问主存和辅存中的数据，但不能直接访问 Cache
- C. Cache 位于 CPU 和主存之间，其目的是弥合 CPU 与主存之间的速度差距
- D. 在存储层次中，越靠近 CPU 的层次，单位存储成本越低

**[答案]** C

**[解析]**
存储层次结构（从上到下）：

| 层次 | 速度 | 容量 | 单位价格 | 由谁管理 |
|------|------|------|----------|----------|
| 寄存器 | 最快（1ns 级） | 最小（几百字节） | 最贵 | 编译器/程序员 |
| Cache | 快（几 ns） | 小（几 MB~几十 MB） | 贵 | 硬件 |
| 主存 | 中等（几十~百 ns） | 中等（几 GB~几十 GB） | 中等 | 操作系统 |
| 辅存 | 慢（ms 级） | 大（TB 级） | 便宜 | 操作系统 |

- A 错误：速度是越来越慢，不是越来越快。
- B 错误：CPU 不能直接访问辅存，程序和数据必须先调入主存。
- C 正确：Cache 解决 CPU 高速与主存相对低速的"剪刀差"问题。
- D 错误：越靠近 CPU，速度越快，价格越贵。

#### 9.3 Cache-主存地址映射计算题（2 道）

**题 5（直接映射 Tag 计算）**

**[题目]** 某计算机按字节编址，Cache 容量为 8KB，每块大小为 32B，主存容量为 128MB，采用直接映射方式。则主存地址中，标记（Tag）字段的位数为（ ）。

- A. 10 位
- B. 12 位
- C. 14 位
- D. 16 位

**[答案]** C

**[解析]**
直接映射地址格式：`| Tag（标记）| 行号（块号）| 块内偏移 |`

计算步骤：
1. **块内偏移**：每块 32B = 2^5，需要 5 位。
2. **Cache 行数**：8KB / 32B = 256 行 = 2^8，行号字段需要 8 位。
3. **主存地址位数**：128MB = 128 × 1024 × 1024 = 2^27，需要 27 位。
4. **Tag 位数**：27 - 8 - 5 = **14 位**。

> **解题模板**：主存地址总位数 = 块内偏移位数 + 行号位数 + Tag 位数。先确定块内偏移（log₂(块大小)），再算行号（log₂(Cache行数)），最后 Tag = 总位数 - 行号 - 偏移。

---

**题 6（组相联映射组号计算）**

**[题目]** 某计算机的主存容量为 256MB，Cache 容量为 64KB，每块大小为 16B，采用 4 路组相联映射方式，按字节编址。则主存地址中组号字段的位数为（ ）。

- A. 8 位
- B. 10 位
- C. 12 位
- D. 14 位

**[答案]** B

**[解析]**
组相联映射地址格式：`| Tag | 组号 | 块内偏移 |`

1. **块内偏移**：16B = 2^4，4 位。
2. **Cache 总块数**：64KB / 16B = 4096 = 2^12 块。
3. **组数**：4 路组相联，组数 = 总块数 / 路数 = 4096 / 4 = 1024 = 2^10 组。
4. **组号字段**：log₂(1024) = **10 位**。
5. 主存地址总位数：256MB = 2^28，28 位。
6. Tag = 28 - 10 - 4 = 14 位（此题不问 Tag，但可一并验证）。

> **关键公式**：组数 = Cache 总块数 / 路数，组号位数 = log₂(组数)。

#### 9.4 指令寻址方式判断题（3 道）

**题 7（立即寻址）**

**[题目]** 下列关于立即寻址方式的描述中，正确的是（ ）。

- A. 指令中给出的地址就是操作数的有效地址
- B. 操作数直接包含在指令中，取指令的同时也就取出了操作数
- C. 指令的地址码字段给出的是操作数在主存中的地址
- D. 立即寻址方式中，操作数的地址存放在寄存器中

**[答案]** B

**[解析]**
- A 错误：这是直接寻址的描述，不是立即寻址。
- B 正确：立即寻址中，操作数（立即数）直接嵌入在指令的地址码字段中，不需要额外的访存操作。
- C 错误：这是直接寻址，操作数地址在指令中。
- D 错误：这是寄存器间接寻址，操作数地址在寄存器中。

**题 8（变址寻址 vs 基址寻址）**

**[题目]** 下列关于变址寻址和基址寻址的对比，错误的是（ ）。

- A. 变址寻址中，变址寄存器的内容可由程序员修改，指令中的形式地址 A 不变
- B. 基址寻址主要用于解决程序的逻辑地址到物理地址的转换，便于程序重定位
- C. 变址寻址适用于对数组等连续数据结构的访问
- D. 基址寻址中，指令中的基址值由程序员在程序中动态修改

**[答案]** D

**[解析]**
- A 正确：变址寻址中，有效地址 EA = (IX) + A，IX 可变，A 固定。
- B 正确：基址寻址 EA = (BR) + A，BR 由操作系统设置，实现地址重定位。
- C 正确：变址寻址通过修改 IX 可以遍历数组元素。
- D 错误：基址寄存器（BR）的内容通常由操作系统设定，不是程序员在程序中随意修改的。程序员修改的是变址寄存器。

**变址 vs 基址对比记忆**：

| 对比项 | 变址寻址 | 基址寻址 |
|--------|---------|---------|
| 有效地址 | EA = (IX) + A | EA = (BR) + A |
| 谁变 | IX（变址寄存器）变 | A（形式地址）视为基准偏移 |
| 用途 | 数组遍历、循环 | 程序重定位 |
| 谁设置 | 程序员 | 操作系统 |

**题 9（直接寻址识别）**

**[题目]** 指令中的地址码给出的是操作数所在主存单元的地址，CPU 需要根据该地址再次访问主存才能取出操作数。这种寻址方式称为（ ）。

- A. 立即寻址
- B. 寄存器寻址
- C. 直接寻址
- D. 寄存器间接寻址

**[答案]** C

**[解析]**
- A：立即寻址——操作数就在指令中，不访存。
- B：寄存器寻址——操作数在寄存器中，不需要访存。
- C：直接寻址——指令给出操作数在主存中的地址，需要一次访存取操作数。符合题意。
- D：寄存器间接寻址——指令给出寄存器号，寄存器中存的是操作数的地址，也需要访存，但指令给出的是寄存器号而非地址。

#### 9.5 总线标准和分类题（1 道）

**题 10**

**[题目]** 下列关于总线的分类与标准的描述中，正确的是（ ）。

- A. 按连接部件的不同，总线可分为片内总线、系统总线、通信总线三大类
- B. PCI 总线属于通信总线，用于连接计算机与外部设备
- C. USB 总线属于系统总线，用于连接 CPU、主存和 I/O 接口
- D. 系统总线按照传输内容又可分为地址总线、控制总线和 USB 总线

**[答案]** A

**[解析]**
- A 正确：总线按连接对象分为三类：
  - 片内总线：CPU 芯片内部连接各部件（如 ALU、寄存器）。
  - 系统总线：连接 CPU、主存、I/O 接口（如 PCI、ISA）。
  - 通信总线：连接主机与外部设备或系统间通信（如 USB、RS-232）。
- B 错误：PCI 是系统总线，不是通信总线。
- C 错误：USB 是通信总线，不是系统总线。
- D 错误：系统总线按传输内容分为地址总线、数据总线、控制总线，不是 USB 总线。

**常见总线标准速记**：
- 系统总线：PCI、PCI-Express、AGP、ISA
- 通信总线：USB、RS-232C、IEEE 1394（火线）、SATA
- 片内总线：AMBA（ARM）、CoreConnect（IBM）

#### 9.6 中断响应过程排序题（1 道）

**题 11**

**[题目]** 在 CPU 响应中断的过程中，下列步骤的正确顺序是（ ）。

1. 关中断（禁止响应新的可屏蔽中断）
2. 保存断点（保存 PC 和 PSW 的内容）
3. 识别中断源，取出中断向量
4. 转入中断服务程序入口
5. 执行完当前指令

- A. 5 → 1 → 2 → 3 → 4
- B. 1 → 5 → 2 → 3 → 4
- C. 5 → 2 → 1 → 3 → 4
- D. 1 → 2 → 5 → 3 → 4

**[答案]** A

**[解析]**
中断响应的标准流程（硬件自动完成）：

1. **执行完当前指令**：CPU 只在指令执行结束时检查中断请求，不会在指令执行中途响应。
2. **关中断**：进入中断周期后，首先关闭中断允许触发器，防止响应过程中被新的中断干扰（进入中断隐指令）。
3. **保存断点**：将当前程序计数器 PC 和程序状态字 PSW 压入堆栈。
4. **识别中断源，取中断向量**：通过中断向量表找到对应中断服务程序的入口地址。
5. **转入中断服务程序**：将中断向量装入 PC，开始执行中断服务程序。

**记忆口诀**：执行完 → 关中断 → 保断点 → 取向量 → 转服务。
