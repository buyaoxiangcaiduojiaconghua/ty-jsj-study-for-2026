## 知识点 16：计算机网络体系结构

### 计算机网络是什么？

把多台计算机用通信线路连起来，让它们能互相传数据。

按覆盖范围分：**局域网 LAN**（一个楼内）、**城域网 MAN**（一个城市）、**广域网 WAN**（跨国家）。

#### 按拓扑结构分类

网络拓扑是指网络中各节点之间的物理连接方式，直接影响可靠性、成本、扩展性。

| 拓扑结构 | 特点 | 优点 | 缺点 | 适用场景 |
|---------|------|------|------|---------|
| **星型** | 所有节点连到中心节点 | 单点故障不影响其他节点，易管理 | 中心节点故障全网瘫痪 | 局域网（交换机为中心） |
| **总线型** | 所有节点共用一条线路 | 布线简单，成本低 | 线路故障全网瘫痪，同一时刻只能一个节点发送 | 早期以太网 |
| **环型** | 节点首尾相连形成闭环 | 控制简单，无冲突 | 一个节点故障环就断了 | 令牌环网（IBM，已淘汰） |
| **网状** | 节点间多路径互联 | 容错性极强，可靠性高 | 布线复杂，成本极高 | 骨干网、军事网络 |
| **树型** | 星型 + 星型，分层结构 | 扩展性好，易隔离故障 | 高层故障影响大 | 大型企业网、校园网 |

**星型拓扑示意图：**
```
        [PC1]
          |
[PC2] -- [交换机] -- [PC3]
          |
        [PC4]
     中心节点是交换机，所有设备通过交换机互联
```

**总线型拓扑示意图：**
```
[PC1]    [PC2]    [PC3]
  |        |        |
==========================  共享总线
  |
[PC4]
```

**环型拓扑示意图：**
```
[PC1] --- [PC2]
  |          |
  |          |
[PC4] --- [PC3]
   数据单向绕圈传输
```

#### 按交换技术分类

| 交换方式 | 原理 | 特点 | 代表 |
|---------|------|------|------|
| **电路交换** | 通信前先建立一条专用物理通路，全程占用 | 实时性好，无延迟抖动；但线路利用率低，建立连接慢 | 传统电话网 |
| **报文交换** | 整份报文存储后转发，不占专用线路 | 线路利用率高；但延迟大，需要大缓存 | 电报 |
| **分组交换** | 将报文分成小分组，逐包存储转发 | 灵活高效，线路利用率高；但可能有额外开销 | **互联网（IP）** |

> **分组交换又分两种**：数据报方式（每个分组独立选路，如 IP）+ 虚电路方式（先建立逻辑连接再发送，如 X.25、ATM、帧中继）。

#### 协议的三要素

协议（Protocol）是通信双方约定的规则。一个协议包含三个要素：

| 要素 | 含义 | 大白话 | 例子 |
|------|------|--------|------|
| **语法** | 数据的格式和结构 | "数据长什么样？" | HTTP 请求行格式：`GET /index.html HTTP/1.1` |
| **语义** | 每部分数据的含义，该做什么动作 | "这个数据是什么意思？" | HTTP 状态码 200 表示成功，404 表示找不到 |
| **同步** | 事件发生的先后顺序 | "谁先说话，什么时候说？" | TCP 三次握手：先 SYN，再 SYN+ACK，最后 ACK |

> 类比：写信的协议——语法是"收件人→地址→正文→落款"的格式；语义是"收件人"字段表示信寄给谁；同步是"你先写→我收到→我回信"的顺序。

### 为什么要分层？

**类比**：盖房子不会把地基、墙体、水电混在一起干，而是分层施工，每层独立负责一件事。

三个好处：
- **各层独立**：改一层不影响其他层（HTTP 1.1 → HTTP/2 不关网线的事）
- **灵活性好**：每层可以选不同的实现方案
- **易于标准化**：每层有明确的接口和协议

**分层的核心原则**：
- 每层只使用下层提供的**服务**，向上层提供**服务**
- 对等层之间通过**协议**进行"虚拟通信"（实际上数据通过下层传输）
- 层与层之间通过**接口**（SAP，服务访问点）交互

### OSI 七层模型（理论标准）

**口诀**：应→表→会→传→网→数→物

| 层次 | 名称 | 功能（大白话） | 代表协议/设备 | 数据单元 |
|------|------|--------------|-------------|---------|
| 7 | 应用层 | 用户直接用的软件 | HTTP、FTP、DNS、SMTP | 报文 |
| 6 | 表示层 | 翻译官：加密解密、压缩、格式转换 | JPEG、ASCII、SSL/TLS | 报文 |
| 5 | 会话层 | 建立/维持/结束"对话" | RPC、SQL | 报文 |
| 4 | 传输层 | 端到端可靠传输 | TCP、UDP | 段 |
| 3 | 网络层 | 寻址 + 选路 | IP、路由器 | 包 |
| 2 | 数据链路层 | 相邻节点间可靠传输、组帧 | MAC、交换机、网桥 | 帧 |
| 1 | 物理层 | 传输 0/1 比特流 | 网线、光纤、集线器 | 比特 |

> **上 4 层**（应用/表示/会话/传输）→ 端到端  
> **下 3 层**（网络/数据链路/物理）→ 点到点

#### 各层详细解析

**第 7 层——应用层**

解决什么问题：用户如何使用网络。应用层是离用户最近的一层，为用户的应用进程提供网络服务。

核心设计思想：
- 不同的应用对应不同的协议（浏览网页用 HTTP，传文件用 FTP，发邮件用 SMTP）
- 应用层协议定义的是"应用进程之间交换的报文格式和交互顺序"
- 每个应用层协议都是为了解决某一类具体应用问题而设计的

与其他层的交互：
- 向下：调用传输层提供的端到端通信服务（TCP 或 UDP 的端口）
- 向上：直接面向用户，不需要再向上提供服务

---

**第 6 层——表示层**

解决什么问题：不同系统之间数据的"语言不通"问题。比如 Windows 用 GBK 编码，Linux 用 UTF-8 编码，它们之间怎么互相理解？表示层来做翻译。

核心设计思想：
- 数据格式转换（编码转换、数据压缩、加密解密）
- 让应用层不用关心数据在物理上怎么表示，只管内容
- 像一个"翻译官"，不管你说什么语言，都能翻译成对方能理解的

与其他层的交互：
- 从会话层接收数据 → 进行格式转换/加密/压缩 → 交给会话层
- 典型代表：SSL/TLS 加密、JPEG 图片压缩、ASCII 字符编码

> 注意：SSL/TLS 常被归为表示层，但其实它横跨会话层和表示层，因为它既加密数据（表示层功能），又管理会话密钥（会话层功能）。

---

**第 5 层——会话层**

解决什么问题：两个应用进程之间的"对话管理"。什么时候开始说话、什么时候结束、谁先说、说错了怎么回滚。

核心设计思想：
- 建立、维护、终止会话（Session）
- 会话同步：在长对话中插入"检查点"（checkpoint），断线后可以从中断点继续，而不是从头开始
- 会话控制：决定通信方式是单工、半双工还是全双工

与其他层的交互：
- 利用传输层提供的可靠连接来管理会话
- 为表示层提供稳定的对话环境

> 类比：打电话——先拨号建立连接（建立会话），通话中（维持会话），挂电话（终止会话）。如果在隧道里信号不好断了，可以接着刚才的话题继续聊，不用从头"你好"开始（检查点恢复）。

---

**第 4 层——传输层**

解决什么问题：两台主机上的进程之间怎么可靠地传输数据。网络层只负责把数据从一台主机送到另一台主机，但传输层负责"从哪个进程发出，送到哪个进程"。

核心设计思想：
- **端到端**：只关心起点和终点，不关心中间经过哪些路由器
- **复用和分用**：多个应用进程可以同时使用同一个传输层协议（通过端口号区分）
- TCP 提供可靠传输（确认、重传、排序、流量控制、拥塞控制）
- UDP 提供尽力而为的传输（快但不保证可靠）

与其他层的交互：
- 向下：使用网络层提供的"主机到主机"通信服务
- 向上：为应用层提供"进程到进程"的通信服务（通过端口号定位进程）

> 传输层是第一个也是唯一一个"端到端"的层，以上三层也是端到端，但它们的端到端能力依赖传输层。

---

**第 3 层——网络层**

解决什么问题：数据怎么从源主机经过网络中的多个路由器到达目的主机。核心是两个任务：**寻址**（给每台主机一个唯一地址，IP 地址）和**选路**（规划从源到目的的路径）。

核心设计思想：
- 每个数据包独立寻址和转发（IP 是无连接的，数据报方式）
- 路由协议负责构建和维护路由表（RIP、OSPF、BGP）
- 尽力而为服务（Best Effort）：不保证一定送达，不保证不乱序，不保证不重复

与其他层的交互：
- 向下：使用数据链路层提供的"相邻节点间"传输服务
- 向上：为传输层提供"主机到主机"的通信服务

> 网络层是第一个处理"跨网络"通信的层，数据链路层只管"相邻节点"，网络层管"全程路径"。

---

**第 2 层——数据链路层**

解决什么问题：相邻两个节点之间怎么可靠地传输数据帧。比如你的电脑到路由器之间、路由器到路由器之间。

核心设计思想：
- **封装成帧**：将网络层的 IP 数据报加上帧头帧尾，界定帧的边界
- **透明传输**：数据中如果出现了和帧定界符一样的比特序列，需要转义处理
- **差错检测**：使用 CRC 校验检测传输过程中是否出错（注意：只能检测，不能纠错）
- **流量控制**：协调发送方和接收方的速度（在数据链路层和传输层都有流量控制，但范围不同）

与其他层的交互：
- 向下：使用物理层提供的比特流传输能力
- 向上：为网络层提供"相邻节点间"的无差错帧传输服务

> 数据链路层又分为两个子层：**MAC 子层**（介质访问控制，控制谁先发）和 **LLC 子层**（逻辑链路控制，负责差错和流量控制）。

---

**第 1 层——物理层**

解决什么问题：怎么把 0/1 比特变成物理信号（电信号、光信号、无线电波）传出去，以及在接收端怎么把信号还原成比特。

核心设计思想：
- 定义物理接口的机械特性（接口形状、尺寸、引脚数）
- 定义电气特性（电压范围、信号速率）
- 定义功能特性（每个引脚干什么用）
- 定义规程特性（信号之间的时序关系）

与其他层的交互：
- 向下：直接操作物理介质（网线、光纤、无线电）
- 向上：为数据链路层提供比特流传输服务

> 物理层不关心数据内容，不关心比特组成的含义，只管"怎么把比特发出去"。物理层以下的传输介质（网线、光纤）本身不属于物理层，物理层是规范"怎么使用这些介质"。

### TCP/IP 四层模型（实际标准，互联网用的就是这个）

| 层次 | 对应 OSI | 代表协议 |
|------|---------|---------|
| 应用层 | 应用层 + 表示层 + 会话层 | HTTP、DNS、FTP、SMTP |
| 传输层 | 传输层 | TCP、UDP |
| 网际层 | 网络层 | IP、ICMP、ARP |
| 网络接口层 | 数据链路层 + 物理层 | 以太网、WiFi |

> TCP/IP 把 OSI 的上三层合并为"应用层"，下两层合并为"网络接口层"。

**OSI vs TCP/IP 对比**：OSI 是理论模型（先有模型后有协议），TCP/IP 是实际标准（先有协议后有模型）。OSI 分层更细但复杂，TCP/IP 分层更粗但实用。

#### OSI 与 TCP/IP 详细对比表

| 对比维度 | OSI 七层模型 | TCP/IP 四层模型 |
|---------|------------|---------------|
| 分层数 | 7 层 | 4 层 |
| 层次名称 | 应用层、表示层、会话层、传输层、网络层、数据链路层、物理层 | 应用层、传输层、网际层、网络接口层 |
| 产生时间 | 1984 年（ISO 制定） | 1970 年代（随 ARPANET 发展而来） |
| 产生顺序 | **先有模型，后有协议**（理论先行） | **先有协议，后有模型**（实践总结） |
| 设计理念 | 学院派，追求完美和通用性 | 工程派，追求实用和简洁 |
| 复杂程度 | 复杂，分层细致 | 简单，分层粗放 |
| 协议依赖性 | 不依赖特定协议 | 强依赖 TCP/IP 协议族 |
| 是否支持无连接服务 | 网络层支持无连接和面向连接 | 网络层（IP）仅支持无连接 |
| 会话层/表示层 | 有独立的会话层和表示层 | 合并到应用层，由应用自行处理 |
| 网络层功能 | 既支持无连接也支持面向连接 | 仅支持无连接（IP 协议） |
| 实际应用程度 | 教学模型，未实际部署 | **全球互联网的基础** |
| 安全设计 | 没有专门的安全层（后来补了） | 通过应用层协议（SSL/TLS、HTTPS）补充 |
| 服务/接口/协议 | 严格区分三种概念 | 未严格区分，协议即是接口 |
| 层次数量 | 过多（会话层和表示层多数应用中几乎为空） | 适中，每层都有明确职责 |

#### 五层模型（教学折中方案）

因为 OSI 七层太复杂，TCP/IP 四层的网络接口层又太笼统，教学中常采用**五层模型**作为折中。

| 五层模型 | 对应 OSI | 对应 TCP/IP | 功能 |
|---------|---------|------------|------|
| 应用层 | 5+6+7 | 应用层 | 为用户程序提供网络服务 |
| 传输层 | 4 | 传输层 | 进程到进程的可靠/不可靠传输 |
| 网络层 | 3 | 网际层 | 主机到主机的寻址和选路 |
| 数据链路层 | 2 | 网络接口层 | 相邻节点间的帧传输 |
| 物理层 | 1 | 网络接口层 | 比特流的物理传输 |

> 五层模型的优势：既保留了 OSI 中数据链路层和物理层的独立性（方便理解底层原理），又避免了表示层和会话层在实际中几乎为空的问题。**国网考试中，如果题目问"计算机网络体系结构分几层"，只要不明确指定 OSI 或 TCP/IP，一般按五层或七层回答都可以。但建议优先记 OSI 七层和 TCP/IP 四层，五层是教学用的。**

### 数据封装与解封装

**类比**：寄快递——物品放进快递盒 → 贴快递单 → 装车 → 发车。收件时反过来拆。

```
发送端（封装）：                  接收端（解封装）：
应用层：你好                      应用层：拿到"你好"
   ↓ 加 HTTP 头                      ↑ 去 HTTP 头
传输层：[TCP头|你好]                传输层
   ↓ 加 TCP 头                       ↑ 去 TCP 头
网络层：[IP头|TCP头|你好]           网络层
   ↓ 加 IP 头                        ↑ 去 IP 头
数据链路层：[帧头|IP头|TCP头|你好|帧尾]  数据链路层
   ↓                                  ↑
物理层：010101...  →  网线  →  物理层：010101...
```

> 考试重点：每层只认自己的"头"。下层不认识上层数据叫什么，统称为"**数据载荷**"（Payload）。


### 补充：各层 PDU 与 SDU 详解

### 5.1 各层 PDU 名称

| OSI 层级 | 层级名称 | PDU 名称 | TCP/IP 对应 |
|-----------|----------|----------|-------------|
| 第 7 层 | 应用层 | **数据/消息 (Data/Message)** | 应用层 |
| 第 6 层 | 表示层 | 数据 | 应用层 |
| 第 5 层 | 会话层 | 数据 | 应用层 |
| 第 4 层 | 传输层 | **段 (Segment)** — TCP / **数据报 (Datagram)** — UDP | 传输层 |
| 第 3 层 | 网络层 | **包/数据报 (Packet/Datagram)** | 网络层 |
| 第 2 层 | 数据链路层 | **帧 (Frame)** | 网络接口层 |
| 第 1 层 | 物理层 | **比特 (Bit)** | 网络接口层 |

### SDU 与 PDU 的关系

- **SDU（服务数据单元）**：上层传给下层的数据，下层不理解其内部结构，视为"载荷"
- **PDU（协议数据单元）**：下层在 SDU 上添加本层控制信息（头部/尾部）后形成的数据单元
- 关系：**第 N 层的 PDU = 第 N-1 层的 SDU + 第 N-1 层的头部/尾部**

### 5.2 封装与解封装流程

#### 发送方（封装过程）

```
应用层数据
    ↓
传输层：添加 TCP/UDP 头部（源端口、目的端口、序号等）
    → TCP 段 / UDP 数据报
    ↓
网络层：添加 IP 头部（源 IP、目的 IP、TTL、协议号等）
    → IP 数据报
    ↓
数据链路层：添加帧头部（MAC 地址）和帧尾部（FCS 校验）
    → 以太网帧
    ↓
物理层：转换为比特流（0/1 信号）
    → 比特流在线路上传输
```

#### 接收方（解封装过程）

```
物理层：接收比特流
    ↓
数据链路层：检查 FCS，去除帧头帧尾，提取 IP 数据报
    ↓
网络层：检查 IP 头部校验和，去除 IP 头部，提取 TCP 段
    ↓
传输层：检查 TCP 校验和，按序号重组，去除 TCP 头部，提取应用数据
    ↓
应用层：获得原始数据
```

```
传输层  |            [ TCP头 | 原始数据 ]           ← TCP 段 (Segment)
        |                         ↓
网络层  |    [ IP头 | TCP头 | 原始数据 ]             ← IP 数据报 (Packet)
        |                         ↓
链路层  | [ 帧头 | IP头 | TCP头 | 原始数据 | FCS尾 ] ← 以太网帧 (Frame)
        |                         ↓
物理层  |  101100101011010010101...                 ← 比特流 (Bits)
```

**各层添加的关键信息：**

| 层 | 添加的头部信息 |
|----|---------------|
| 传输层 | 源端口号、目的端口号、序号、确认号、窗口大小、校验和 |
| 网络层 | 源 IP 地址、目的 IP 地址、TTL、协议号、标识、片偏移 |
| 数据链路层 | 源 MAC 地址、目的 MAC 地址、类型字段、FCS 帧尾 |

### 5.4 完整封装示意图（含各层头部/尾部大小）

```
发送端主机 A（封装过程，从上到下，每层加头）：
═══════════════════════════════════════════════════════════════════
应用层：
  ┌──────────────────────────────────────┐
  │          应用数据 (Data)              │  ← 原始数据，无固定大小
  └──────────────────────────────────────┘
    ↓ 传给传输层（作为传输层 SDU）
传输层：
  ┌────────────┬─────────────────────────┐
  │ TCP/UDP 头  │     应用数据            │  ← TCP 段 (Segment)
  │  (20~60 B)  │                        │     TCP 头最小 20 字节
  └────────────┴─────────────────────────┘
    ↓ 传给网络层（作为网络层 SDU）
网络层：
  ┌──────────┬────────────┬──────────────┐
  │  IP 头    │ TCP/UDP 头  │   应用数据   │  ← IP 包 (Packet)
  │ (20~60 B) │            │              │     IP 头通常 20 字节
  └──────────┴────────────┴──────────────┘
    ↓ 传给数据链路层（作为链路层 SDU）
数据链路层：
  ┌──────┬──────┬──────┬──────────┬────────────┬──────────────┬──────┐
  │前导码 │目的MAC│源MAC │类型/长度  │  IP 头     │ TCP/UDP头+数据│ FCS  │
  │ 8 B  │ 6 B  │ 6 B  │   2 B    │ (20~60 B)  │   (可变)      │ 4 B  │
  └──────┴──────┴──────┴──────────┴────────────┴──────────────┴──────┘
  ← 帧头 18 B（不含前导码）→                              ← FCS 尾 4 B →
  ← 以太网帧 (Frame) 最小 64 B，最大 1518 B →
    ↓ 传给物理层
物理层：
  101100101011010010101110010010101...  ← 比特流 (Bits)
═══════════════════════════════════════════════════════════════════
```

**各层头部/尾部字节大小汇总：**

| 层 | 头部/尾部 | 典型大小 | 说明 |
|----|----------|---------|------|
| 应用层 | 由具体协议决定 | 可变 | HTTP 头通常几百到几千字节 |
| 传输层（TCP） | TCP 头部 | 20~60 字节 | 固定部分 20 字节，选项最多 40 字节 |
| 传输层（UDP） | UDP 头部 | 固定 8 字节 | 源端口 + 目的端口 + 长度 + 校验和 |
| 网络层（IPv4） | IP 头部 | 20~60 字节 | 固定部分 20 字节，选项最多 40 字节 |
| 数据链路层 | 帧头 + FCS 尾 | 帧头 14~18 字节 + 尾 4 字节 | 以太网帧头：目的MAC(6)+源MAC(6)+类型(2)=14 字节（不含前导码） |

> **注意**：前导码（8 字节）和帧间隙（12 字节）不计入帧长，帧长通常从目的 MAC 地址算到 FCS 尾。

### 5.5 协议栈（Protocol Stack）概念

**协议栈**就是把各层协议像搭积木一样堆叠起来，每一层使用下层提供的服务，同时向上层提供服务。

```
┌──────────────────────────────────┐
│  HTTP  │  FTP  │  DNS  │  SMTP  │  ← 应用层协议栈
├──────────────────────────────────┤
│         TCP    │    UDP         │  ← 传输层协议栈
├──────────────────────────────────┤
│              IP                  │  ← 网络层（网际层）
├──────────────────────────────────┤
│   以太网  │  WiFi  │  PPP        │  ← 数据链路层 + 物理层
└──────────────────────────────────┘
```

**协议栈的核心特点：**
- 各层协议可以**独立替换**。比如把 HTTP 替换成 HTTPS，下层 TCP/IP 完全不用改
- 下层为上层提供**服务**，上层调用下层的服务接口
- 同层之间通过**协议**通信（对等通信），实际上数据要经过下层传输
- 两个通信实体之间必须运行**相同的协议栈**

### 核心性能指标

| 指标 | 含义 | 单位 | 备注 |
|------|------|------|------|
| 带宽 | 最大数据率（理论上限） | bps | "水管粗细" |
| 时延 | 发送+传播+处理+排队 | 秒 | 四个部分的和 |
| 吞吐量 | 实际传输量 | bps | ≤带宽，受各种因素影响 |
| 时延带宽积 | 管道能容纳多少 bit | 比特 | = 时延 × 带宽 |
| RTT | 发送到收到确认的往返时间 | 秒 | Round-Trip Time |

> **发送时延** = 数据长度 / 发送速率（自己控制）  
> **传播时延** = 距离 / 传播速度（物理限制，光纤中约 2×10⁸ m/s）  
> **处理时延** + **排队时延** = 路由器处理时间

**时延带宽积**的理解：相当于"管道里正在路上的数据量"。一条时延 20ms、带宽 100Mbps 的链路，时延带宽积 = 0.02 × 100×10⁶ = 2×10⁶ bit，意味着发送方发了 2M 数据后第一个 bit 才到接收方。

#### 时延计算例题

**核心公式：总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延**

其中：
- 发送时延 = 数据长度 / 发送速率
- 传播时延 = 信道长度 / 电磁波传播速率
- 处理时延：路由器分析数据包头部的时间，通常很小
- 排队时延：数据包在路由器缓存队列中等待的时间，网络拥塞时可能很大

**例题 1：发送时延计算**

一台主机要通过一条带宽为 100Mbps 的链路发送一个 10MB 的文件，忽略其他时延，求发送时延。

**解：**
```
发送时延 = 数据长度 / 发送速率
        = (10 × 10^6 × 8) bit / (100 × 10^6) bps
        = 80 × 10^6 / 100 × 10^6
        = 0.8 秒
```

> 注意：10MB = 10 × 10^6 字节 = 80 × 10^6 bit。考试中字节到比特的换算（×8）经常被漏掉！

**例题 2：传播时延计算**

光纤长度为 2000km，电磁波在光纤中的传播速率约为 2×10⁸ m/s，求传播时延。

**解：**
```
传播时延 = 距离 / 传播速率
        = 2000 × 10^3 m / (2 × 10^8 m/s)
        = 2 × 10^6 / 2 × 10^8
        = 0.01 秒 = 10 ms
```

**例题 3：总时延综合计算**

主机 A 与主机 B 之间有一条 1000km 的光纤链路，带宽为 10Mbps，传播速率为 2×10⁸ m/s。A 向 B 发送一个 1MB 的文件，忽略处理时延和排队时延，求总时延。

**解：**
```
步骤 1：计算发送时延
发送时延 = (1 × 10^6 × 8) / (10 × 10^6) = 8 × 10^6 / 10 × 10^6 = 0.8 秒

步骤 2：计算传播时延
传播时延 = (1000 × 10^3) / (2 × 10^8) = 10^6 / (2 × 10^8) = 0.005 秒 = 5 ms

步骤 3：总时延
总时延 = 发送时延 + 传播时延 = 0.8 + 0.005 = 0.805 秒
```

> 思考：哪种场景下发送时延是主导？哪种场景下传播时延是主导？
> - 发送大文件、低带宽时 → 发送时延主导
> - 远距离（如卫星通信）、高带宽时 → 传播时延主导

#### 时延带宽积计算例题

**例题**：一条链路的传播时延为 30ms，带宽为 1Gbps，求时延带宽积。

**解：**
```
时延带宽积 = 传播时延 × 带宽
           = 30 × 10^(-3) × 1 × 10^9
           = 30 × 10^6 bit
           = 30 Mbit
```

> 这意味着：发送方发出 30Mbit 数据后，第一个 bit 才到达接收方。这 30Mbit 就是"正在管道里飞的数据"。

#### 利用率（Utilization）

**利用率 U** 表示信道被使用的程度。

- **U = 0**：信道完全空闲
- **U = 1**：信道完全饱和（100% 利用）
- 当 U 接近 1 时，时延急剧增大！

**公式关系：**
```
D0 = 信道空闲时的时延
D  = 信道利用率为 U 时的实际时延
D  = D0 / (1 - U)
```

**直观理解**：
- 当 U = 0.5（50% 利用率），D = D0 / 0.5 = 2D0，时延翻倍
- 当 U = 0.9（90% 利用率），D = D0 / 0.1 = 10D0，时延变成 10 倍！
- 当 U → 1（接近 100%），D → 无穷大，时延爆炸

> 这就是为什么网络不能满负荷运行——利用率越高，时延增长越快，最终导致网络拥塞崩溃。

**例题**：一条信道空闲时时延为 10ms，当利用率达到 80% 时，实际时延是多少？

**解：**
```
D = D0 / (1 - U) = 10 / (1 - 0.8) = 10 / 0.2 = 50 ms
```

> 利用率从 0 升到 80%，时延从 10ms 暴增到 50ms（5 倍），这就是拥塞控制要避免的情况。

### 端到端 vs 点到点

- **端到端通信**：A 主机逻辑上直接和 B 主机通信，中间不管经过多少跳。传输层及以上都是端到端。
- **点到点通信**：每一跳之间的通信（A→路由器1→路由器2→...→B）。网络层及以下都是点到点。

> 类比：你给朋友写信——端到端是你和朋友之间的通信；点到点是邮递员→分拣中心→运输司机每一段的交接。

### 考试真题精练

**第 1 题（单选题）**：OSI 参考模型中，负责为数据选择合适的传输路径的是哪一层？
A. 传输层
B. 网络层
C. 数据链路层
D. 物理层

**答案：B**

**解析**：网络层有两个核心功能——寻址（给每台主机分配 IP 地址）和选路（为数据包规划从源到目的地的路径）。传输层负责端到端的可靠传输，数据链路层负责相邻节点间传输，物理层负责比特流传输。选路功能（路由选择）是网络层的专属职责。

---

**第 2 题（单选题）**：主机 A 向主机 B 发送数据，数据经过一个路由器转发。当数据从 A 发出、经过路由器、到达 B 的过程中，封装与解封装的变化是？

A. A 封装所有层 → 路由器解封装到网络层再重新封装 → B 解封装所有层
B. A 封装到传输层 → 路由器逐层检查 → B 解封装
C. 数据在路由器中不需要解封装，直接转发
D. 路由器解封装到应用层，重新封装后再转发

**答案：A**

**解析**：路由器工作在网络层（第三层），所以它只解封装到网络层——剥离帧头帧尾，读取 IP 头部中的目的 IP 地址，查路由表决定从哪个接口转发，然后重新封装数据链路层帧头帧尾（因为源 MAC 和目的 MAC 变了）。它不会解封装 TCP/UDP 头部，更不会解封装到应用层。而交换机工作在第 2 层，只查 MAC 地址表，不解封装到网络层。

> 总结：路由器解封装到第 3 层（网络层），交换机解封装到第 2 层（数据链路层），集线器不解析任何头部（第 1 层）。

**第 3 题（计算题）**：主机 A 与主机 B 之间的光纤链路长度为 3000km，带宽为 100Mbps，电磁波在光纤中的传播速率为 2×10⁸ m/s。A 向 B 发送一个 500KB 的文件，忽略处理时延和排队时延。求：
（1）总时延是多少？
（2）时延带宽积是多少？

**答案：**
```
（1）发送时延 = (500 × 10^3 × 8) / (100 × 10^6) 
              = 4 × 10^6 / 100 × 10^6 = 0.04 秒 = 40 ms

     传播时延 = (3000 × 10^3) / (2 × 10^8) = 3 × 10^6 / 2 × 10^8 = 0.015 秒 = 15 ms

     总时延 = 40 ms + 15 ms = 55 ms

（2）时延带宽积 = 传播时延 × 带宽
                = 0.015 × 100 × 10^6
                = 1.5 × 10^6 bit = 1.5 Mbit
```

**第 4 题（单选题）**：以下关于各层 PDU 名称的说法，正确的是？
A. 传输层的 PDU 称为帧
B. 数据链路层的 PDU 称为包
C. 网络层的 PDU 称为数据报
D. 物理层的 PDU 称为段

**答案：C**

**解析**：各层 PDU 的规范名称：
- 应用层 → 数据/消息（Data/Message）
- 传输层 → 段（Segment，TCP）/ 数据报（Datagram，UDP）
- 网络层 → 包/数据报（Packet/Datagram）
- 数据链路层 → 帧（Frame）
- 物理层 → 比特（Bit）

选项 A 错误，传输层是段不是帧；B 错误，数据链路层是帧不是包；D 错误，物理层是比特不是段。C 正确，网络层的 PDU 可以称为数据报（Datagram），IP 协议的数据单元就叫 IP 数据报。

**第 5 题（多选题）**：以下关于 OSI 模型和 TCP/IP 模型的比较，正确的有？
A. OSI 是"先有协议后有模型"，TCP/IP 是"先有模型后有协议"
B. OSI 的网络层既支持无连接也支持面向连接，TCP/IP 的网络层仅支持无连接
C. TCP/IP 将 OSI 的表示层和会话层合并到应用层
D. OSI 模型有 7 层，TCP/IP 模型有 5 层
E. TCP/IP 是互联网的实际标准，OSI 是理论参考模型

**答案：B、C、E**

**解析**：
- A 错误：说反了！OSI 是"先有模型后有协议"（理论先行），TCP/IP 是"先有协议后有模型"（实践总结）。
- B 正确：OSI 的网络层设计支持两种服务，TCP/IP 的 IP 协议只提供无连接服务。
- C 正确：TCP/IP 把 OSI 的应用层、表示层、会话层合并为"应用层"。
- D 错误：TCP/IP 是 4 层模型（应用层、传输层、网际层、网络接口层），不是 5 层。5 层是教学用的折中模型。
- E 正确：OSI 是 ISO 制定的理论标准，从未实际部署过；TCP/IP 是互联网的基石。

### 易错陷阱

| 陷阱 | 错误理解 | 正确理解 |
|------|---------|---------|
| 交换机在 OSI 第几层 | 网络层 | **数据链路层**（第 2 层），交换机看 MAC 地址转发，不看 IP 地址 |
| 路由器在 OSI 第几层 | 数据链路层 | **网络层**（第 3 层），路由器看 IP 地址选路 |
| 集线器在 OSI 第几层 | 数据链路层 | **物理层**（第 1 层），集线器只是把信号复制到所有端口，不识别任何地址 |
| OSI 是协议标准 | OSI 就是互联网协议 | **错！** OSI 是参考模型（理论），不是协议。TCP/IP 才是协议栈 |
| SDU 和 PDU 的关系 | SDU = PDU | **第 N 层的 PDU = 第 N-1 层的 SDU + 第 N-1 层的头部**。SDU 是上层传下来的"裸数据"，PDU 是本层加上头以后的"成品" |
| TCP/IP 是 5 层 | TCP/IP 对应 OSI 少 2 层所以是 5 层 | **TCP/IP 是 4 层**（应用层、传输层、网际层、网络接口层），5 层是教学模型，不是 TCP/IP 的标准定义 |
| 封装顺序 | 从物理层往上封装 | **封装是从应用层向下**（数据 → 段 → 包 → 帧 → 比特），解封装是从物理层向上 |
| 端到端和点到点的分界线 | 全部层都是端到端 | **传输层及以上是端到端**（主机到主机），**网络层及以下是点到点**（每跳到每跳） |

## 知识点 17：物理层

> 物理层不关心数据内容，只管怎么把 0/1 比特变成信号发出去。

### 传输介质

| 介质 | 特点 | 适用场景 | 抗干扰 |
|------|------|---------|--------|
| 双绞线 | 便宜、易安装 | 局域网（网线） | 一般 |
| 同轴电缆 | 抗干扰强、贵 | 有线电视 | 强 |
| 光纤（单模） | 传输远（几十km）、纤芯细、贵 | 骨干网、城域网 | 极强 |
| 光纤（多模） | 传输近（几百m）、纤芯粗、便宜 | 楼内、数据中心 | 极强 |
| 无线（无线电/微波/红外） | 不用布线 | WiFi、4G/5G、卫星 | 弱 |

> **单模 vs 多模**：单模一条光路直走到底，距离远；多模多条光路反射，信号会散开所以距离近。

### 编码与调制技术

**编码和调制的区别：**
- **编码**：把数字数据变成数字信号（纯 0/1 方波信号），用在数字信道上
- **调制**：把数字数据变成模拟信号（连续波），用在模拟信道上

> **类比**：编码就像用开关灯发送摩斯密码（只有开和关两种状态）；调制就像用不同的口哨音调传递消息（音调可以连续变化）。

#### 数字编码方法

**（1）不归零编码（NRZ：Non-Return to Zero）**

- 规则：低电平 = 0，高电平 = 1（或反过来），整个 bit 周期内电平保持不变
- 波形特点：连续 1 时一直高电平，连续 0 时一直低电平，没有中间跳变
- **致命缺点**：没有同步时钟！如果发送方和接收方时钟有微小偏差，连续 16 个 1 在接收方可能被当成 15 个或 17 个。必须有额外的时钟线或使用含时钟的编码方式。

```
数据：  1    0    1    1    0    0    1
NRZ:  ─┐   ┌┐   ─┐                ┌┐
      │   ││   ││                ││
      │   ││   ││                ││
      ─┘   └┘   ─┘────────────────┘┘
高电平=1, 低电平=0, 整个bit周期不变
```

**（2）曼彻斯特编码（Manchester）**

- 规则：**每个 bit 中间一定有一次跳变**。上跳（低→高）= 0，下跳（高→低）= 1（或反过来，取决于定义）
- 波形特点：每个 bit 中间都有跳变，所以接收方可以从跳变中提取时钟信号
- **优点**：自带同步时钟（自同步），不需要额外的时钟线
- **缺点**：带宽利用率低，信号跳变频率是数据速率的两倍（波特率是比特率的两倍）

```
数据：  1    0    1    1    0    0    1
Manchester:
    ─┐   ┌─┐  ─┐   ─┐   ┌─┐  ┌─┐  ─┐
     │   │ │  │   │   │ │  │ │  │
     │   │ │  │   │   │ │  │ │  │
     ─┘   ┘ └─  ─┘   ─┘   ┘ └─  ┘ └─
上跳(低→高)=0, 下跳(高→低)=1
每个bit中间必有跳变！
```

**（3）差分曼彻斯特编码（Differential Manchester）**

- 规则：
  - 每个 bit **中间**一定有一次跳变（用于同步时钟）
  - bit **开始处**的跳变规则：有跳变 = 0，无跳变 = 1
- 波形特点：中间的跳变只用于同步，真正表示数据的是 bit 开始处有没有跳变
- **优点**：抗干扰更强，因为判断的是"有没有跳变"而不是"电平高低"，即使信号线接反了也能正确解码

```
数据：  1    0    1    1    0    0    1
Diff Manchester:
    ─┐   ─┐   ┌─┐  ─┐   ─┐   ┌─┐  ┌─┐
     │   │   │ │  │   │   │ │  │ │
     │   │   │ │  │   │   │ │  │ │
     ─┘   ─┘   ┘ └─  ─┘   ─┘   ┘ └─  ┘ └─
↑表示bit开始处：无跳变=1, 有跳变=0
中间跳变仅用于同步
```

**三种编码方法对比表：**

| 对比维度 | 不归零编码 NRZ | 曼彻斯特编码 | 差分曼彻斯特编码 |
|---------|:---:|:---:|:---:|
| 中间跳变 | 无 | 有（每个 bit 中间必有） | 有（每个 bit 中间必有） |
| 数据表示 | 高电平=1，低电平=0 | 上跳=0，下跳=1 | 开始处有跳变=0，无跳变=1 |
| 自同步能力 | **无**（需要额外时钟线） | **有**（从跳变中提取时钟） | **有**（从跳变中提取时钟） |
| 带宽效率 | 高（波特率=比特率） | 低（波特率=2×比特率） | 低（波特率=2×比特率） |
| 抗干扰 | 差 | 好 | **最好**（信号线接反也能解码） |
| 应用 | 早期简单场景 | 以太网（10Base-T） | 令牌环网 |

#### 模拟调制方法

把数字信号加载到载波（模拟波）上，三种基本方式：

| 调制方式 | 全称 | 原理 | 类比 |
|---------|------|------|------|
| **ASK** | 振幅键控 | 改变载波**振幅**：大振幅=1，小振幅=0 | 大声说话=1，小声说话=0 |
| **FSK** | 频移键控 | 改变载波**频率**：高频=1，低频=0 | 用高音调=1，用低音调=0 |
| **PSK** | 相移键控 | 改变载波**相位**：相位翻转=1，不翻转=0 | 点头=1，摇头=0 |

**QAM（正交振幅调制）**：把 ASK 和 PSK 结合起来，同时调整振幅和相位，每个码元可以表示多个 bit。比如 16QAM 每个码元可以表示 4bit（2^4=16 种状态），64QAM 每个码元可以表示 6bit。

> **记忆口诀**：A 振幅（声音大小）、F 频率（音调高低）、P 相位（点头摇头）、QAM 振幅+相位一起调

### 信道复用技术

**问题**：一根线怎么让多个人同时用？

| 复用技术 | 原理 | 类比 | 适用 |
|---------|------|------|------|
| FDM 频分复用 | 不同频率同时传 | 不同电台用不同频率 | 模拟信号 |
| TDM 时分复用 | 轮流用，每人分一小段时间片 | 轮流说话 | 数字信号 |
| WDM 波分复用 | 不同波长光（光纤专用） | 不同颜色的光同时射 | 光纤 |
| CDM 码分复用 | 不同编码区分，可以同时同频传输 | 不同语言各说各的 | 移动通信 |

#### 信道复用技术详细对比

| 复用技术 | 复用维度 | 是否同时传输 | 优缺点 | 典型应用 |
|---------|---------|:---:|------|---------|
| **FDM 频分复用** | 频率 | 是 | 优点：简单可靠；缺点：需要保护频带（防干扰），频带利用率不高 | 广播电台、有线电视、ADSL |
| **TDM 时分复用** | 时间 | 否（轮流） | 优点：适合数字信号；缺点：有空闲时隙（即使某个用户没数据也占着） | T1/E1 数字线路 |
| **STDM 统计时分复用** | 时间 | 否（动态分配） | 优点：按需分配，不浪费空闲时隙；缺点：需要额外信息标明"这是谁的" | 分组交换网络 |
| **WDM 波分复用** | 波长（光频） | 是 | 优点：光纤容量极大；缺点：设备昂贵 | 光纤骨干网 |
| **CDM 码分复用** | 编码 | 是（同时同频） | 优点：抗干扰强、保密性好；缺点：技术复杂 | 3G 移动通信（CDMA） |

**同步 TDM vs 统计 TDM（STDM）：**

| 对比维度 | 同步 TDM | 统计 TDM（STDM） |
|---------|---------|-----------------|
| 时隙分配 | 固定分配（每人一个固定时隙） | 动态分配（谁有数据就给谁） |
| 空闲时隙 | 浪费（即使某人没数据，时隙也占着） | 不浪费（没数据就跳过） |
| 额外开销 | 无需额外标识 | 需要地址信息标识"这个数据是谁的" |
| 适用场景 | 恒定速率业务（如语音） | 突发性业务（如上网） |

**WDM 波分复用波长范围：**

| 波段 | 波长范围 | 常用场景 |
|------|---------|---------|
| O 波段（原始波段） | 1260~1360nm | 早期光纤通信 |
| E 波段（扩展波段） | 1360~1460nm | 较少使用 |
| S 波段（短波波段） | 1460~1530nm | 较少使用 |
| **C 波段（常规波段）** | **1530~1565nm** | **最常用，DWDM 密集波分复用** |
| L 波段（长波波段） | 1565~1625nm | 扩展容量 |
| U 波段（超长波波段） | 1625~1675nm | 维护用 |

> **DWDM（密集波分复用）**：在 C 波段内把波长间隔压到极小（0.8nm 甚至 0.4nm），一根光纤可以同时传输几十甚至上百个波长，每个波长速率可达 10Gbps 以上。一根光纤总容量可达数百 Gbps 甚至 Tbps。

### 两大定理（考试必考计算 + 概念辨析）

**奈奎斯特定理**（理想、无噪声）：

> C = 2W × log₂V  

- W = 带宽（Hz），V = 离散电平数（码元状态数，信号有几个等级）  
- 二元信号（V=2）时：C = 2W  
- 含义：**在无噪声的理想信道中，码元速率上限为 2W 波特**
- **波特率（码元传输速率）上限 = 2W**，比特率 = 波特率 × log₂V

**香农定理**（现实、有噪声）：

> C = W × log₂(1 + S/N)  

- S/N = 信噪比（信号功率/噪声功率），是**比值，无单位**
- 常用单位 dB：**信噪比(dB) = 10 × log₁₀(S/N)**  
- 如 30dB → S/N = 10^(30/10) = 1000 → C = W × log₂(1+1000) ≈ W × 10  

**考试易错**：
- 奈奎斯特给的是**码元速率上限**（波特率），香农给的是**信息传输速率上限**（比特率）
- 实际最大速率 = **min(奈奎斯特上限, 香农上限)**，两者取小的那个
- 香农定理说明：**只要传输速率 ≤ 信道容量，就一定存在某种编码方法实现无差错传输**
- 提高信噪比 OR 提高带宽都可以提高信道容量，但提高带宽效果不如提高信噪比（因为是对数关系）

**dB 转换速查表：**

| dB 值 | S/N 比值 | 近似 log₂(1+S/N) |
|:---:|:---:|:---:|
| 10dB | 10 | ≈ 3.46 |
| 20dB | 100 | ≈ 6.66 |
| 30dB | 1000 | ≈ 10（最常考！） |
| 40dB | 10000 | ≈ 13.29 |
| 50dB | 100000 | ≈ 16.61 |

> **记忆技巧**：dB 每增加 10，S/N 比值乘以 10。30dB = 1000 是最高频考点，log₂(1001) ≈ log₂(1024) = 10。

#### 奈奎斯特与香农定理 - 计算例题详解

**例题 1（纯奈奎斯特）：** 一条无噪声信道带宽为 4kHz，使用 4 种码元状态（V=4），求最大数据传输速率。

**解：**
```
步骤 1：确认公式
奈奎斯特：C = 2W × log₂V

步骤 2：代入数值
W = 4kHz = 4000Hz
V = 4（4 种码元状态，每个码元表示 2 bit）

步骤 3：计算
C = 2 × 4000 × log₂4
  = 8000 × 2
  = 16000 bps
  = 16 kbps

答案：16 kbps
```

**例题 2（纯香农）：** 一个带宽为 3kHz 的信道，信噪比为 30dB，求信道容量（最大数据传输速率）。

**解：**
```
步骤 1：dB 转比值
S/N = 10^(30/10) = 10^3 = 1000

步骤 2：代入香农公式
C = W × log₂(1 + S/N)
  = 3000 × log₂(1 + 1000)
  = 3000 × log₂(1001)

步骤 3：近似计算
log₂(1001) ≈ log₂(1024) = 10
C ≈ 3000 × 10 = 30000 bps = 30 kbps

答案：约 30 kbps
```

**例题 3（奈奎斯特 + 香农结合）：** 一个带宽为 4kHz 的信道，信噪比为 30dB，使用 4 种码元状态（V=4），求实际最大数据传输速率。

**解：**
```
步骤 1：先算奈奎斯特上限
C_nyquist = 2W × log₂V = 2 × 4000 × log₂4 = 8000 × 2 = 16000 bps

步骤 2：再算香农上限
S/N = 10^(30/10) = 1000
C_shannon = 4000 × log₂(1001) ≈ 4000 × 10 = 40000 bps

步骤 3：取最小值
C = min(16000, 40000) = 16000 bps = 16 kbps

答案：16 kbps（瓶颈在奈奎斯特，码元状态数太少限制了速率）
```

**例题 4（反推信噪比）：** 一个带宽为 4kHz 的信道，要求信道容量不低于 40 kbps，求至少需要多大的信噪比（用 dB 表示）。

**解：**
```
步骤 1：代入香农公式
C = W × log₂(1 + S/N)
40000 = 4000 × log₂(1 + S/N)

步骤 2：解出 log₂(1 + S/N)
log₂(1 + S/N) = 40000 / 4000 = 10
1 + S/N = 2^10 = 1024
S/N = 1023

步骤 3：转为 dB
信噪比(dB) = 10 × log₁₀(1023) ≈ 10 × log₁₀(1000) ≈ 10 × 3 = 30 dB

答案：至少需要约 30 dB 的信噪比
```

**例题 5（综合 - 电话线路）：** 电话线路带宽为 3.1kHz，信噪比为 35dB，使用 64QAM（V=64）调制。求：① 奈奎斯特最大速率；② 香农信道容量；③ 实际最大速率。

**解：**
```
步骤 1：首先计算奈奎斯特上限
V = 64（64QAM，每个码元表示 log₂64 = 6 bit）
C_nyquist = 2W × log₂V = 2 × 3100 × 6 = 6200 × 6 = 37200 bps ≈ 37.2 kbps

步骤 2：计算香农信道容量
S/N = 10^(35/10) = 10^3.5 ≈ 3162
C_shannon = 3100 × log₂(1 + 3162) = 3100 × log₂(3163)

log₂(3163) ≈ log₂(2048) + 余量 ≈ 11 + 0.63 ≈ 11.63
（更精确：log₂(3163) ≈ 11.63）

C_shannon ≈ 3100 × 11.63 ≈ 36053 bps ≈ 36.1 kbps

步骤 3：取最小值
C = min(37.2, 36.1) = 36.1 kbps

答案：① 37.2 kbps；② 36.1 kbps；③ 实际最大约 36.1 kbps（瓶颈在香农）
```

> **核心结论**：奈奎斯特决定"码元能跑多快"，香农决定"信噪比条件下最多能传多少"。两者谁小听谁的。一旦 V 够大，瓶颈通常转到香农定理。

### 例题与解析

**例题 1（编码波形识别）：** 以下关于曼彻斯特编码和差分曼彻斯特编码的说法，正确的是？

A. 曼彻斯特编码每个 bit 开始处有跳变表示 1，无跳变表示 0  
B. 差分曼彻斯特编码中间跳变用于表示数据，开始处跳变用于同步  
C. 曼彻斯特编码自带同步时钟，差分曼彻斯特编码不自带同步时钟  
D. 差分曼彻斯特编码中，bit 开始处有跳变表示 0，无跳变表示 1，中间跳变仅用于同步

**解析：**
- A 错：这是差分曼彻斯特的规则，不是曼彻斯特。曼彻斯特是中间跳变表示数据（上跳=0，下跳=1）。
- B 错：差分曼彻斯特正好相反——中间跳变用于同步，开始处跳变用于表示数据。
- C 错：两种编码都自带同步时钟（都有中间跳变）。
- D 对：差分曼彻斯特编码的规则就是"bit 开始处有跳变=0，无跳变=1，中间跳变仅用于同步"。

**答案：D**

**例题 2（奈奎斯特计算）：** 一条无噪声信道带宽为 8kHz，使用 16 种码元状态，最大数据传输速率是多少？

**解析：**
```
C = 2W × log₂V = 2 × 8000 × log₂16 = 16000 × 4 = 64000 bps = 64 kbps
```

**答案：64 kbps**

**例题 3（香农计算）：** 带宽为 6kHz，信噪比为 20dB，求信道容量。

**解析：**
```
S/N = 10^(20/10) = 100
C = 6000 × log₂(1 + 100) = 6000 × log₂(101)
log₂(101) ≈ log₂(128) ≈ 7（近似）
C ≈ 6000 × 7 = 42000 bps = 42 kbps
```

**答案：约 42 kbps**

**例题 4（两种定理结合）：** 带宽为 3kHz，信噪比为 30dB，使用 8 种码元状态。实际最大速率是多少？

**解析：**
```
奈奎斯特：C₁ = 2 × 3000 × log₂8 = 6000 × 3 = 18000 bps
香农：S/N = 10³ = 1000，C₂ = 3000 × log₂(1001) ≈ 3000 × 10 = 30000 bps
实际 = min(18000, 30000) = 18000 bps = 18 kbps
```

**答案：18 kbps**

**例题 5（信道复用判断）：** 以下关于信道复用技术的说法，错误的是？

A. FDM 频分复用让不同用户用不同频率同时传输  
B. 统计时分复用 STDM 的时隙分配是固定的  
C. WDM 波分复用是光纤通信中 FDM 的变种  
D. CDM 码分复用可以实现同时同频传输

**解析：**
- A 对：FDM 就是按频率划分。
- B 错：STDM 的时隙分配是**动态的**（按需分配），不是固定的。同步 TDM 时隙才是固定的。
- C 对：WDM 本质就是光域的 FDM。
- D 对：CDM 通过不同编码实现同时同频传输。

**答案：B**

### 易错陷阱表

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 1 | 奈奎斯特定理的单位是 bps | **错！** 奈奎斯特给出的是**波特率（码元速率）上限 = 2W 波特**，要求比特率还需要乘以 log₂V |
| 2 | 信噪比给的是 dB，直接代入公式 | **错！** 必须先换算：S/N = 10^(dB/10)，dB 不能直接代入公式 |
| 3 | 奈奎斯特上限和香农上限取最大值 | **错！** 实际速率取 min(奈奎斯特, 香农)，两者中谁更严格听谁的 |
| 4 | 曼彻斯特编码的中间跳变是"高跳低=0，低跳高=1" | **需注意！** 不同教材定义可能相反，但核心是"中间跳变表示数据"。差分曼彻斯特的中间跳变只用于同步 |
| 5 | 统计时分复用 STDM 和同步时分复用没区别 | **错！** 同步 TDM 时隙固定分配，STDM 时隙动态分配（按需分配），STDM 效率更高但有额外地址开销 |
| 6 | 单模光纤用 LED 光源 | **错！** 单模用**激光（LD）**，多模才用 LED。因为单模纤芯极细，需要方向性更好的激光 |
| 7 | 光纤比双绞线便宜 | **错！** 光纤（尤其单模）设备和施工成本远高于双绞线。双绞线便宜是最大优势 |
| 8 | 物理层只关心传输介质 | **错！** 物理层还涉及编码（数字信号编码）、调制（模拟信号调制）、接口特性（机械/电气/功能/规程） |

## 知识点 18：数据链路层

### 三大基本问题

| 问题 | 解释 | 解决方案 |
|------|------|---------|
| 封装成帧 | 在数据前后加帧头和帧尾来界定边界 | 帧定界符 |
| 透明传输 | 数据里恰好出现了帧定界符怎么办？ | 字节填充/字符填充（加转义符） |
| 差错检测 | 传输过程中 bit 出错怎么发现？ | CRC 循环冗余校验 |

### CRC 循环冗余校验

**原理**：发送方用多项式除法算出余数（冗余码），附在数据后面。接收方用同样的除数去除，余数为 0 则没错。

**步骤**：
1. 发送方和接收方约定一个生成多项式 G(x)（如 CRC-16、CRC-32）
2. 在数据后面加 r 个 0（r = G(x)的最高次数），除以 G(x)
3. 得到的余数就是冗余码 FCS，附在数据后面发送
4. 接收方用收到的整个数据除以 G(x)，余数为 0 则无差错

> CRC 只能检测错误，**不能纠错**。它检测不到的误差概率极低。

### 停等协议与滑动窗口

**停等协议**：发一帧 → 等确认 → 再发下一帧。简单但效率低。

> 信道利用率 = 发送时延 / (发送时延 + RTT)，RTT 远大于发送时延时，利用率极低。

**滑动窗口机制**：

| 协议 | 窗口大小 | 确认方式 | 特点 |
|------|---------|---------|------|
| 停等 | 发送窗口=1，接收窗口=1 | 每帧确认 | 效率最低 |
| GBN（后退N帧） | 发送窗口>1，接收窗口=1 | 累积确认 | 出错重传 N 帧 |
| SR（选择重传） | 发送窗口>1，接收窗口>1 | 逐帧确认 | 只重传出错帧 |

> GBN 和 SR 的区别：GBN 接收方只接受按序到达的帧，"宁可错过不将就"；SR 接受方可以缓存失序帧，"来者不拒"。

### MAC 地址

- 48-bit（6 字节），通常用十六进制表示如 `00:1A:2B:3C:4D:5E`
- 前 24 位是厂商识别码（OUI），后 24 位厂商自行分配
- 全球唯一（出厂烧录在网卡 ROM 中）
- **MAC 地址是数据链路层地址，IP 地址是网络层地址**

| 对比 | MAC 地址 | IP 地址 |
|------|---------|---------|
| 层次 | 数据链路层 | 网络层 |
| 长度 | 48 bit（6字节） | 32 bit（IPv4）/ 128 bit（IPv6） |
| 类比 | 身份证号（硬件身份） | 住址（逻辑位置） |
| 可变性 | 出厂固定（可软件改） | 随网络环境变 |

### 以太网与 CSMA/CD

**以太网帧格式**：目的MAC(6字节) | 源MAC(6字节) | 类型(2字节) | 数据(46~1500字节) | FCS(4字节)

> 最短帧长 = 64 字节。为什么？因为 CSMA/CD 要求在发送完最短帧之前检测到碰撞。

**CSMA/CD**（载波侦听多路访问/碰撞检测）：
1. **先听后说**：发之前先侦听，信道空闲才发
2. **边发边听**：发送的同时也在监听，检测是否有碰撞
3. **碰撞则停**：一旦检测到碰撞，立即停止发送
4. **随机后退**：等待随机时间后重试（二进制指数退避算法）

> **争用期** = 2τ（两倍端到端传播时延），以太网规定为 51.2μs（对应 512 bit 时间 = 64 字节）
> **为什么最短帧长是 64 字节？** 因为要在争用期内检测到碰撞，发送 64 字节的时间 = 争用期

### 交换机 vs 网桥

| 对比 | 网桥 | 交换机 |
|------|------|--------|
| 端口数 | 少（2-4个） | 多（几十个） |
| 转发方式 | 软件转发 | 硬件转发（快） |
| 本质 | 交换机就是多端口网桥 | |
| 工作方式 | 自学习地址表（MAC表） → 查表 → 转发/过滤/泛洪 | |

**交换机自学习**：收到帧时，记录源 MAC 和到达端口 → 查目的 MAC → 有记录就转发到对应端口，没记录就泛洪（除收到端口外的所有端口广播）

### VLAN

虚拟局域网：把一台物理交换机逻辑上分成多个独立广播域。同一个 VLAN 内的主机可以通信，不同 VLAN 间需要通过路由器才能通信。

> 优点：隔离广播、提高安全性、灵活分组。


### 补充：数据链路层深入

### 1.1 封装成帧

数据链路层将网络层传下来的 IP 数据报组装成帧，在链路上传输。封装成帧有三种主要方法：

**（1）字符计数法**
- 在帧头部用一个字段标识帧内字符数
- 缺点：计数字段一旦出错，后续所有帧都会错位

**（2）字节填充法**
- 使用特殊字符 DLE STX 作为帧起始标记，DLE ETX 作为帧结束标记
- 数据中如果出现 DLE，需要再插入一个 DLE 进行转义
- 接收端收到连续两个 DLE 时，删除第一个，保留第二个作为数据

**（3）比特填充法（零比特填充法）**
- 使用特殊比特模式 `01111110`（即 0x7E）作为帧标志
- 发送端：数据中每出现连续 5 个 "1"，后面自动插入一个 "0"
- 接收端：每收到连续 5 个 "1"，删除后面的 "0"
- 这是 HDLC 和 PPP 协议使用的方法

**以太网帧格式：**

| 字段 | 前导码 | 目的MAC | 源MAC | 类型/长度 | 数据 | FCS |
|------|--------|---------|-------|-----------|------|-----|
| 字节 | 8 | 6 | 6 | 2 | 46-1500 | 4 |

- 前导码：7 字节同步码 + 1 字节帧起始定界符
- 类型字段：0x0800 表示 IPv4，0x0806 表示 ARP，0x86DD 表示 IPv6
- 数据字段最小 46 字节（不足时填充），最大 1500 字节（MTU）
- FCS：4 字节 CRC 校验

### 1.2 CRC 循环冗余校验

#### 核心原理

CRC 基于有限域 GF(2) 上的多项式除法。将数据当作一个二进制多项式，用生成多项式做模 2 除法，余数就是 CRC 校验码。

**GF(2) 运算规则：**
- 加法 = 减法 = 异或（XOR），无进位无借位
- 例如：1+1=0, 1-1=0, 1+0=1

#### 计算步骤

以生成多项式 `x^3 + x + 1`（二进制 `1011`），消息 `11010011101100` 为例：

**步骤 1：补零**
在消息末尾追加 n 个零（n 为 CRC 位数，即生成多项式次数 3）：

```
11010011101100 000    ← 输入补3位零
```

**步骤 2：模 2 除法**
除数 `1011` 放在最左端，逐位异或：

```
11010011101100 000
1011                 ← 除数 (4位) = x³ + x + 1
---- XOR
01100011101100 000   ← 结果
```

**步骤 3：循环移位除法**
除数右移，对齐结果中最高位的 1，重复异或：

```
 1011
00111011101100 000
  1011
00010111101100 000
   1011
00000001101100 000   ← 除到下一个1的位置
       1011
00000000110100 000
        1011
00000000011000 000
         1011
00000000001110 000
          1011
00000000000101 000
           101 1
------------------
00000000000000 100   ← 余数 = CRC校验码(3位)
```

**步骤 4：验证**
将 CRC 值 `100` 附加到原消息末尾，再次除法，余数为零则数据无误。

#### 常见生成多项式

| 名称 | 多项式 | 二进制 | 用途 |
|------|--------|--------|------|
| CRC-8 | x^8 + x^2 + x + 1 | 1 0000 0111 | |
| CRC-12 | x^12 + x^11 + x^3 + x^2 + x + 1 | | |
| CRC-16 | x^16 + x^15 + x^2 + 1 | | IBM |
| CRC-CCITT | x^16 + x^12 + x^5 + 1 | | HDLC/PPP |
| **CRC-32** | x^32 + x^26 + x^23 + x^22 + x^16 + x^12 + x^11 + x^10 + x^8 + x^7 + x^5 + x^4 + x^2 + x + 1 | | **以太网** |

#### 多项式选择原则

- 使用本原多项式：最大保护块长 = 2^r - 1（r 为多项式次数），可检测该长度内所有 1 位和 2 位错误
- 使用 g(x) = p(x)(1+x) 形式：可检测所有奇数位错误，但最大块长减半

### 1.3 CSMA/CD 协议

CSMA/CD = Carrier Sense Multiple Access with Collision Detection（载波监听多路访问/冲突检测）

#### 工作原理

**发送流程：**

```
有帧要发送？
  ↓ 是
监听信道
  ↓ 空闲
开始传输，同时监听冲突
  ↓
是否发生冲突？
  ├── 否 → 传输完成
  └── 是 → 发送干扰信号(jam)
            ↓
          重传计数器+1
            ↓
          超过最大重传次数？
            ├── 是 → 放弃发送
            └── 否 → 二进制指数退避等待
                     ↓
                   重新监听信道
```

#### 冲突检测

- **共享总线**：比较发送信号与接收信号，不一致则冲突
- **UTP 半双工**：发送和接收通道同时检测到信号时触发冲突
- **中继器/集线器**：自行检测冲突并传播干扰信号

#### 二进制指数退避算法

每次冲突后，退避时间从 0 到 (2^k - 1) 个时间片中随机选择，k = min(冲突次数, 10)：

| 冲突次数 | 退避窗口（时间片数） | 说明 |
|----------|---------------------|------|
| 第 1 次 | 0 ~ 1 | 2^1 - 1 |
| 第 2 次 | 0 ~ 3 | 2^2 - 1 |
| 第 3 次 | 0 ~ 7 | 2^3 - 1 |
| 第 4 次 | 0 ~ 15 | 2^4 - 1 |
| ... | ... | ... |
| 第 10 次 | 0 ~ 1023 | 窗口不再扩大 |
| 第 16 次 | 放弃发送 | 最大重传 16 次 |

**时间片（slot time）**：以太网中为 512 比特时间，即发送 512 比特所需的时间。

---

### 1.4 最短帧长与争用期

#### 争用期（冲突窗口）

争用期 = 2τ（端到端传播时延的 2 倍）

以太网中争用期 = **512 比特时间**（即时隙时间 slot time）。站点必须在发送完 512 比特（64 字节）之前检测到冲突。

#### 最短帧长公式

```
最短帧长 = 争用期 × 数据率
```

对于 10 Mbps 以太网：
- 争用期 = 2τ = 51.2 μs
- 最短帧长 = 51.2 μs × 10 Mbps = 512 bit = **64 字节**

**为什么是 64 字节？**
> 因为以太网端到端往返时间最大为 464 比特时间，加上 48 比特的干扰信号余量，总计 512 比特时间。如果帧长小于 64 字节，发送方在冲突发生前就已经发送完毕，无法检测到冲突。

#### 重要概念

| 术语 | 说明 |
|------|------|
| **本地冲突** | 发生在网卡端，TX 和 RX 同时检测到信号 |
| **远程冲突** | 帧长度 < 64 字节的帧在远端产生冲突，发送方无法检测 |
| **晚期冲突** | 发送超过 512 比特后才检测到的冲突，网卡不自动重传 |
| **干扰信号** | 4~6 字节的 1-0 交替模式，确保所有站点都能检测到冲突 |

#### 现代应用

随着交换机的普及，全双工通信成为主流，冲突域被隔离，CSMA/CD 已基本不再使用。IEEE 802.3 在 2011 年弃用了以太网中继器。

### 1.5 MAC 地址

- 长度：**48 位（6 字节）**
- 表示：通常用十六进制，如 `00-1A-2B-3C-4D-5E`
- 广播地址：**FF-FF-FF-FF-FF-FF**（全 1）
- 组播地址：第一个字节最低位为 1
- 单播地址：第一个字节最低位为 0
- 全球唯一：前 24 位为 OUI（组织唯一标识符），由 IEEE 分配
- 扁平地址：与 IP 地址不同，MAC 地址不包含网络拓扑信息

### 1.6 交换机自学习算法

**工作原理：**

1. 交换机内部维护一张 **MAC 地址表**（转发表），记录 MAC 地址与端口的对应关系
2. 收到帧时，记录**源 MAC 地址**和**接收端口**到地址表中
3. 查找**目的 MAC 地址**在地址表中的对应端口：
   - 找到：从对应端口**转发**（单播）
   - 未找到：向除接收端口外的所有端口**泛洪**（广播）
4. 如果目的 MAC 地址是广播地址，向所有端口转发
5. 地址表条目设有**老化时间**，超时自动删除

**交换机三种转发方式：**

| 方式 | 原理 | 特点 |
|------|------|------|
| 存储转发 | 接收完整帧，校验 CRC 后转发 | 延迟大，可靠性高 |
| 直通转发 | 读到目的 MAC 地址后立即转发 | 延迟小，不校验 |
| 无碎片转发 | 读取前 64 字节后转发 | 过滤冲突碎片 |

## 知识点 19：网络层

> 网络层的核心任务：**寻址**（给每台设备一个地址）+ **选路**（决定数据走哪条路到达目的地）。网络层是 OSI 七层中最复杂的层之一，也是考试计算题最多的章节。

### IP 地址分类详解

IP 地址（IPv4）由 32 位二进制组成，通常写成 4 个十进制数，用点分隔，如 `192.168.1.1`。每个十进制数对应 8 位二进制（即一个字节），取值范围 0~255。

**IP 地址 = 网络号 + 主机号**。网络号标识"哪个网络"，主机号标识"网络里的哪台设备"。

#### 五类地址详细表

| 类别 | 首字节范围 | 二进制首字节特征 | 默认掩码 | 网络号位数 | 每网络最大主机数 | 用途 |
|------|-----------|----------------|---------|-----------|----------------|------|
| A 类 | 1~126 | **0**xxxxxxx（0 开头） | 255.0.0.0 | 8 | 2²⁴-2 ≈ 1677 万 | 大型网络 |
| B 类 | 128~191 | **10**xxxxxx（10 开头） | 255.255.0.0 | 16 | 2¹⁶-2 = 65534 | 中型网络 |
| C 类 | 192~223 | **110**xxxxx（110 开头） | 255.255.255.0 | 24 | 2⁸-2 = 254 | 小型网络 |
| D 类 | 224~239 | **1110**xxxx（1110 开头） | - | - | - | 组播（一对多） |
| E 类 | 240~255 | **1111**xxxx（1111 开头） | - | - | - | 保留（实验） |

**首字节二进制特征记忆口诀**：A 类 0 开头，B 类 10 开头，C 类 110 开头，D 类 1110 开头，E 类 1111 开头。每多一个 1，类别往后挪一级。

> 127.x.x.x（即 127.0.0.0/8）是**环回地址**（Loopback），127.0.0.1 就是 localhost。虽然 127 按二进制看属于 A 类范围，但被保留用作环回测试，不属于任何可用类别。

#### A 类地址详解

- 范围：**1.0.0.0 ~ 126.255.255.255**
- 网络号占 8 位，但第一位固定为 0，可用的网络号只有 7 位 → 2⁷ - 2 = 126 个 A 类网络（减去全 0 的 0.0.0.0 和全 1 的 127.x.x.x）
- 主机号占 24 位，每个 A 类网络最多容纳 2²⁴ - 2 = **16,777,214 台主机**（约 1677 万台）
- 适合分配给国家级骨干网、超大型 ISP

#### B 类地址详解

- 范围：**128.0.0.0 ~ 191.255.255.255**
- 网络号占 16 位，前两位固定为 10，可用的网络号有 14 位 → 2¹⁴ = 16384 个 B 类网络
- 主机号占 16 位，每个 B 类网络最多容纳 2¹⁶ - 2 = **65,534 台主机**
- 适合大中型企业、高校

#### C 类地址详解

- 范围：**192.0.0.0 ~ 223.255.255.255**
- 网络号占 24 位，前三位固定为 110，可用的网络号有 21 位 → 2²¹ ≈ 209 万个 C 类网络
- 主机号占 8 位，每个 C 类网络最多容纳 2⁸ - 2 = **254 台主机**
- 适合小型公司、家庭网络

#### D 类和 E 类

- **D 类（224.0.0.0 ~ 239.255.255.255）**：组播地址，不区分网络号和主机号。用于一对多通信（如视频会议、在线直播）
- **E 类（240.0.0.0 ~ 255.255.255.255）**：保留地址，用于科研实验，不分配给普通用户

#### 特殊 IP 地址表

| 地址 | 名称 | 含义 | 用途 |
|------|------|------|------|
| **0.0.0.0** | 未指定地址 | "本机"或"任何 IP" | DHCP 请求时源地址；服务器监听所有网卡 |
| **127.0.0.0/8** | 环回地址 | 发给自己 | 本机 TCP/IP 协议栈测试（localhost） |
| **169.254.0.0/16** | 链路本地地址 | 自动分配失败 | DHCP 获取失败时 Windows 自动分配的临时地址 |
| **255.255.255.255** | 受限广播地址 | 发给本网段所有主机 | 本局域网内的广播（路由器不转发） |
| **主机号全 0** | 网络地址 | 标识一个网络 | 如 192.168.1.0 表示 192.168.1 这个网段 |
| **主机号全 1** | 广播地址 | 发给该网络所有主机 | 如 192.168.1.255 发给 192.168.1.0/24 所有主机 |

#### 私有地址范围（RFC 1918）

这些地址只能在内部网络使用，互联网路由器不会转发：

| 类别 | 私有地址范围 | CIDR 表示 | 可用地址数 |
|------|-------------|----------|-----------|
| A 类私有 | **10**.0.0.0 ~ **10**.255.255.255 | 10.0.0.0/8 | 约 1677 万个 |
| B 类私有 | **172.16**.0.0 ~ **172.31**.255.255 | 172.16.0.0/12 | 约 104 万个 |
| C 类私有 | **192.168**.0.0 ~ **192.168**.255.255 | 192.168.0.0/16 | 约 65536 个 |

> **记忆口诀**：10 开头全私有，172.16 到 31，192.168 全私有。三个范围记住就够。

### 子网划分（考试必出计算题）

**子网掩码**的作用：告诉路由器"IP 地址中哪部分是网络号，哪部分是主机号"。

> 子网掩码 & IP 地址 = 网络地址

**计算套路**（借位法）：
- 借 n 位 → 子网数 = 2ⁿ
- 主机位数 = 32 - 网络号位数
- 每个子网可用主机数 = 2^主机位数 - 2（减去全 0 网络地址和全 1 广播地址）

**例题**：192.168.1.0/26，求每个子网的主机数？
- /26 = 子网掩码 255.255.255.192
- 主机位数 = 32 - 26 = 6
- 每子网主机 = 2⁶ - 2 = 62 台
- 子网数 = 2² = 4 个（原本 /24，借了 26-24=2 位）

#### 子网划分详细例题（3 道）

**例题 1：给定 192.168.10.0/24，需要 5 个子网，每个子网至少 30 台主机，求子网掩码和每个子网范围**

解题步骤：
1. 先看主机需求：每个子网需要至少 30 台可用主机
2. 2^h - 2 >= 30 → h >= 5（因为 2⁵ - 2 = 30，刚好满足）
3. 主机位 = 5 位，网络位 = 32 - 5 = 27
4. 子网掩码 = /27 = 255.255.255.224
5. 验证子网数：借了 27 - 24 = 3 位，2³ = 8 个子网 >= 5 个，满足
6. 块大小 = 256 - 224 = 32

| 子网 | 网络地址 | 可用 IP 范围 | 广播地址 |
|------|---------|-------------|---------|
| 1 | 192.168.10.0 | 192.168.10.1 ~ 192.168.10.30 | 192.168.10.31 |
| 2 | 192.168.10.32 | 192.168.10.33 ~ 192.168.10.62 | 192.168.10.63 |
| 3 | 192.168.10.64 | 192.168.10.65 ~ 192.168.10.94 | 192.168.10.95 |
| 4 | 192.168.10.96 | 192.168.10.97 ~ 192.168.10.126 | 192.168.10.127 |
| 5 | 192.168.10.128 | 192.168.10.129 ~ 192.168.10.158 | 192.168.10.159 |

> 虽然划分出 8 个子网，但只需要 5 个，剩余的 3 个子网（160~223）可以留给未来扩展。

**例题 2：给定 172.16.0.0/16，划分 500 个子网，求新掩码、每子网主机数**

解题步骤：
1. 500 个子网需要借多少位？2^8 = 256 < 500，2^9 = 512 >= 500，所以借 **9 位**
2. 新掩码 = /16 + 9 = /25（即 255.255.255.128）
3. 主机位 = 32 - 25 = 7 位
4. 每子网可用主机数 = 2⁷ - 2 = **126 台**
5. 实际子网数 = 2⁹ = 512 个（前 500 个可用）

> 块大小法：掩码最后字节 128，块大小 = 256 - 128 = 128。每个子网 128 个地址，减去网络地址和广播地址，可用 126 个。

**例题 3：给定 IP 172.16.88.55/20，求网络地址、广播地址、可用 IP 范围**

解题步骤：
1. /20 的掩码 = 255.255.240.0
2. 关键字节是第三个字节：172.16.**88**.55
3. 块大小 = 256 - 240 = 16（第三个字节的块大小）
4. 172.16.88.55 的第三个字节 88：88 / 16 = 5 余 8
5. 网络地址第三个字节 = 5 × 16 = **80**
6. 广播地址第三个字节 = 80 + 16 - 1 = **95**
7. 网络地址 = **172.16.80.0**
8. 广播地址 = **172.16.95.255**
9. 可用 IP 范围 = 172.16.80.1 ~ 172.16.95.254（共 2¹² - 2 = 4094 台）

### CIDR 无分类编址

不再按 A/B/C 分类，而是用"网络前缀/前缀长度"表示。

> 192.168.1.0/24 = 前 24 位是网络前缀，后 8 位是主机号

**路由聚合（超网）**：把多个连续网段合并成一个更大的网段。前缀相同的路由可以聚合成一条，减少路由表条目。

**聚合判断方法**：N 个连续网络能聚合成一个超网，当且仅当 N 是 2 的幂且起始地址的网络号能被 N 整除。

#### CIDR 路由聚合例题（3 道）

**例题 1：聚合 192.168.0.0/24、192.168.1.0/24、192.168.2.0/24、192.168.3.0/24**

解题步骤：
1. 4 个网络，第三个字节分别是 0、1、2、3
2. 写出第三个字节的二进制：
   - 0 = 000000**00**
   - 1 = 000000**01**
   - 2 = 000000**10**
   - 3 = 000000**11**
3. 找共同前缀：前 6 位相同（000000），后 2 位不同
4. 192.168 占 16 位 + 第三字节前 6 位 = 22 位共同前缀
5. 聚合结果 = **192.168.0.0/22**
6. 掩码 = 255.255.252.0，覆盖 192.168.0.0 ~ 192.168.3.255

> 验证：4 是 2 的幂，且起始地址 0 能被 4 整除，满足聚合条件。

**例题 2：聚合 172.16.32.0/24、172.16.33.0/24、172.16.34.0/24、172.16.35.0/24**

解题步骤：
1. 4 个网络，第三个字节分别是 32、33、34、35
2. 写出二进制：
   - 32 = 001000**00**
   - 33 = 001000**01**
   - 34 = 001000**10**
   - 35 = 001000**11**
3. 共同前缀：前 6 位相同（001000），后 2 位不同
4. 聚合结果 = **172.16.32.0/22**
5. 掩码 = 255.255.252.0，覆盖 172.16.32.0 ~ 172.16.35.255

**例题 3：聚合 10.1.4.0/24、10.1.5.0/24、10.1.6.0/24、10.1.7.0/24**

解题步骤：
1. 第三个字节：4 = 000001**00**，5 = 000001**01**，6 = 000001**10**，7 = 000001**11**
2. 共同前缀：前 6 位相同（000001），后 2 位不同
3. 聚合结果 = **10.1.4.0/22**
4. 掩码 = 255.255.252.0，覆盖 10.1.4.0 ~ 10.1.7.255

### ARP 协议详解（Address Resolution Protocol）

**作用**：根据 IP 地址找出对应的 MAC 地址。ARP 解决的是"在同一局域网内，我知道目标 IP，但不知道目标 MAC"的问题。

**基本工作过程**：
1. 主机 A 要发包给 IP-B，但不知道 B 的 MAC 地址
2. A 广播一个 ARP 请求报文："谁是 IP-B？告诉我你的 MAC 地址"
3. B 收到后单播回复 ARP 应答："我是 IP-B，我的 MAC 是 xxx"
4. A 把 IP-MAC 映射缓存到 ARP 表中，后续直接查表

> ARP 请求是**广播**（目的 MAC 为 FF-FF-FF-FF-FF-FF），ARP 应答是**单播**。ARP 只在**本局域网**内有效。跨网段时，源主机把数据帧发给网关路由器的 MAC，由路由器继续转发。

#### ARP 报文格式

ARP 报文直接封装在以太网帧中（不属于 IP 层），帧类型字段为 0x0806。

| 字段 | 长度 | 说明 |
|------|------|------|
| 硬件类型 | 2 字节 | 以太网为 1 |
| 协议类型 | 2 字节 | IPv4 为 0x0800 |
| 硬件地址长度 | 1 字节 | MAC 地址 = 6 |
| 协议地址长度 | 1 字节 | IP 地址 = 4 |
| 操作码 | 2 字节 | 1=请求，2=应答 |
| 发送方 MAC | 6 字节 | 源 MAC |
| 发送方 IP | 4 字节 | 源 IP |
| 目标 MAC | 6 字节 | 请求时为全 0，应答时为目标 MAC |
| 目标 IP | 4 字节 | 目标 IP |

#### ARP 缓存和老化时间

- 每台主机维护一张 **ARP 缓存表**（arp -a 命令可查看）
- 动态条目有**老化时间**（通常 2~20 分钟），超时自动删除
- 静态条目可以手动配置，不会老化
- 每次收到 ARP 应答或 gratuitous ARP 时刷新对应的缓存条目

#### 免费 ARP（Gratuitous ARP）

免费 ARP 是一种特殊的 ARP 请求——主机**以自己的 IP 地址作为目标 IP** 发送 ARP 请求。

**两个主要作用**：
1. **IP 地址冲突检测**：主机启动时发送免费 ARP，如果收到应答，说明网络中已经有人用了这个 IP，操作系统会提示"IP 地址冲突"
2. **更新其他主机的 ARP 缓存**：当主机更换网卡（MAC 变了但 IP 不变）或做故障切换时，发送免费 ARP 让局域网内其他主机更新 ARP 表

> 类比：搬了新家但电话号码不变，免费 ARP 就是群发消息"我的新地址是 xxx，以后找我请来新地址"。

#### 代理 ARP（Proxy ARP）

代理 ARP 允许一台路由器代替另一个网络中的主机回复 ARP 请求。

**场景**：主机 A（192.168.1.10/16）以为自己和主机 B（192.168.2.10/16）在同一个网段（因为掩码是 /16），实际上它们被路由器分隔在不同的 /24 子网中。当 A 广播 ARP 请求 B 的 MAC 时，路由器代为回复自己的 MAC，之后 A 的数据都发给路由器，路由器再转发给 B。

> 代理 ARP 让子网划分对主机"透明"——主机不需要知道子网的存在。

#### ARP 欺骗攻击（ARP Spoofing）

攻击者发送**伪造的 ARP 应答**，将合法 IP 映射到攻击者的 MAC 地址，实现中间人攻击。

**攻击过程**：
1. 攻击者 C 向 A 发送伪造 ARP："网关 IP 的 MAC 是我 C"
2. 攻击者 C 向网关发送伪造 ARP："A 的 MAC 是我 C"
3. A 和网关之间的通信都经过 C，C 可以窃听、篡改数据

**防御措施**：静态 ARP 绑定、DAI（动态 ARP 检测）、ARP 防火墙。

### ICMP 协议详解

**作用**：报告网络层的差错和控制信息。ICMP 是 IP 层的辅助协议，ICMP 报文封装在 IP 数据报中（协议号为 1）。

> PING 用的是 ICMP 协议，**不是应用层协议**！ICMP 和 IP 同属网络层。

#### ICMP 报文类型分类

ICMP 报文分为两大类：**差错报告报文**和**查询报文**。

| 类型 | 报文分类 | 类型编号 | 名称 | 说明 |
|------|---------|---------|------|------|
| 差错报告 | — | 3 | **终点不可达** | 包无法到达目的地 |
| 差错报告 | — | 4 | 源点抑制 | 让发送方降低发送速率（已废弃） |
| 差错报告 | — | 5 | 重定向 | 告诉发送方有更好的路由 |
| 差错报告 | — | 11 | **超时** | TTL 减到 0，包被丢弃 |
| 差错报告 | — | 12 | 参数问题 | IP 头部有错误 |
| 查询 | — | 8 | **回显请求** | PING 发送的报文 |
| 查询 | — | 0 | **回显应答** | PING 收到的回复 |
| 查询 | — | 13/14 | 时间戳请求/应答 | 测网络时延 |

**重要规则**：以下情况**不发送** ICMP 差错报告报文：
- 对 ICMP 差错报文本身不再发送差错报文（防止无限嵌套）
- 对广播/组播地址的数据报不发送差错报告
- 对分片后的数据报，只对第一个分片发送
- 对源地址为 0.0.0.0、127.x.x.x、组播地址的数据报不发送

#### 终点不可达（类型 3）

当路由器或主机无法交付数据报时，丢弃该数据报并向源站发送 ICMP 终点不可达报文。其"代码"字段进一步说明原因：

| 代码 | 含义 |
|------|------|
| 0 | 网络不可达 |
| 1 | 主机不可达 |
| 2 | 协议不可达 |
| 3 | 端口不可达（UDP 常见，TCP 用 RST） |
| 4 | 需要分片但 DF 标志置位 |
| 13 | 通信被管理性禁止（防火墙拦截） |

#### 超时（类型 11）

当路由器收到 TTL=1 的数据报时，将 TTL 减 1 后变为 0，丢弃该数据报并向源站发送 ICMP 超时报文。

> Traceroute 就是巧妙利用了这个机制，依次发送 TTL=1, 2, 3... 的包，让每跳路由器都返回超时报文，从而追踪路径。

#### Traceroute 工作原理详解

**目的**：追踪从源主机到目标主机经过了哪些路由器（路径发现）。

**工作过程**（以 Windows 的 tracert 为例，使用 ICMP）：
1. 源主机发送 TTL=1 的 UDP 包（或 ICMP Echo Request），目标端口为不可达端口
2. 第一跳路由器收到后 TTL 减为 0，丢弃并返回 ICMP 超时报文
3. 源主机记录第一跳路由器的 IP 和 RTT
4. 源主机发送 TTL=2 的包...
5. 重复直到：收到目标主机的 ICMP 端口不可达报文（说明到达了目标），或超过最大跳数（默认 30）

> Linux 的 traceroute 默认使用 UDP（高端口），Windows 的 tracert 使用 ICMP Echo Request。

#### PING 的详细工作过程

**PING 是测试网络连通性的最常用工具，整个过程分四步**：

1. 源主机构建 ICMP 回显请求报文（类型 8，代码 0），包含一个序列号和可选数据
2. 目标主机收到后，构建 ICMP 回显应答报文（类型 0，代码 0），原样返回数据
3. 源主机收到应答，计算 RTT（往返时间）= 收到时间 - 发送时间
4. 统计结果：发送包数、收到包数、丢包率、最小/最大/平均 RTT

> PING 不通不代表目标一定不在线——可能是防火墙拦截了 ICMP 报文。PING 的结果中 TTL 值可以粗略判断目标操作系统（Linux 默认 TTL=64，Windows 默认 TTL=128）。

### DHCP 协议

**作用**：自动给主机分配 IP 地址、子网掩码、默认网关、DNS 服务器等配置。

**四步走（DORA）**：
1. **Discover**：主机广播"谁给我 IP？"（源 IP 为 0.0.0.0，目的 IP 为 255.255.255.255）
2. **Offer**：DHCP 服务器回复"我可以给你这个 IP"（提供 IP 地址和租约）
3. **Request**：主机确认"我就要这个了"（如果多台 DHCP 服务器都回复了，选第一个）
4. **ACK**：服务器确认"好，租约给你，有效期 xx 秒"

> DHCP 基于 UDP，服务端端口 67，客户端端口 68。租约到期前需要续约（Renew），通常到 50% 租期时开始尝试续约。

### 路由选择协议

**静态路由 vs 动态路由**：
- 静态路由：手动配置，简单但不灵活，适合小型网络
- 动态路由：自动学习，适应网络变化，适合中大型网络

**自治系统（AS）**的概念：一个组织管理下的一组路由器的集合，使用统一的内部路由策略。AS 内部用 IGP（如 RIP、OSPF），AS 之间用 EGP（如 BGP）。

| 协议 | 类型 | 算法 | 度量值 | 特点 |
|------|------|------|--------|------|
| RIP | 内部网关(IGP) | 距离矢量 | 跳数 | 最大 15 跳，16 跳=不可达 |
| OSPF | 内部网关(IGP) | 链路状态 | 开销(带宽相关) | SPF算法，收敛快 |
| BGP | 外部网关(EGP) | 路径矢量 | 多种属性 | 跨自治系统(AS)，互联网骨干 |

**RIP 核心**：
- 每 30 秒广播一次路由表
- 距离矢量算法（Bellman-Ford）
- **慢收敛**问题：好消息传得快，坏消息传得慢
- 限制跳数 15 防止无穷计数

**OSPF 核心**：
- 洪泛链路状态（LSA），每个路由器构建相同的拓扑图
- 用 Dijkstra（SPF）算法计算最短路径
- 分区域（Area），Area 0 是骨干区域
- 收敛快，支持负载均衡

> **RIP vs OSPF**：RIP 像"邻居口耳相传"，信息只要知道方向就行；OSPF 像"人手一张地图"，全局视野。

### 补充：路由协议详细对比

### 总览对比表

| 对比维度 | RIP | OSPF | BGP |
|----------|-----|------|-----|
| **协议类型** | IGP，距离矢量 | IGP，链路状态 | EGP，路径矢量 |
| **算法** | Bellman-Ford | Dijkstra (SPF) | 路径矢量 |
| **传输层** | UDP（端口 520） | 直接封装在 IP 中（协议号 89） | TCP（端口 179） |
| **度量值** | 跳数（最大 15 跳） | 链路开销（带宽） | 路径属性（AS_PATH 等） |
| **更新方式** | 定期广播/组播完整路由表 | 触发更新，泛洪 LSA | 增量更新，只发送变化的路由 |
| **收敛速度** | 慢（计数到无穷问题） | 快 | 较慢（侧重稳定性） |
| **网络规模** | 小型网络 | 中大型企业网络 | 全球互联网 |
| **分层支持** | 无 | 支持区域划分 | 支持 AS 自治系统 |
| **路由环路** | 可能发生（水平分割、毒性反转缓解） | 天然无环（LSDB 一致） | 通过 AS_PATH 防环 |
| **组播地址** | 224.0.0.9 (RIPv2) | 224.0.0.5 / 224.0.0.6 | 无（使用 TCP 单播） |
| **AD 管理距离** | 120 | 110 | 20 (eBGP) / 200 (iBGP) |
| **配置复杂度** | 简单 | 中等 | 复杂 |

### 管理距离（AD）概念

**管理距离（Administrative Distance）**：当路由器从多种路由协议学到同一条路由时，AD 值小的更可信。AD 是 0~255 的整数，数字越小越优先。

| 路由来源 | 管理距离 |
|---------|---------|
| 直连网络 | **0** |
| 静态路由 | **1** |
| EIGRP 汇总 | 5 |
| eBGP | **20** |
| EIGRP 内部 | 90 |
| IGRP | 100 |
| **OSPF** | **110** |
| IS-IS | 115 |
| **RIP** | **120** |
| EIGRP 外部 | 170 |
| iBGP | **200** |
| 未知/不可信 | 255（不使用） |

> 记忆技巧：直连最可信(0) → 静态也很信(1) → eBGP(20) → OSPF(110) → RIP(120) → iBGP(200) → 不知名的不信(255)

### 详细说明

#### RIP 防环机制详解

RIP 的距离矢量算法天生容易形成路由环路，需要使用以下机制来防止：

| 防环机制 | 原理 | 效果 |
|---------|------|------|
| **最大跳数** | 限制最大跳数为 15，16 跳 = 不可达 | 阻止环路无限循环 |
| **水平分割** | 从某个接口学到的路由，不再从该接口发回去 | 防止相邻路由器之间环路 |
| **毒性反转** | 把不可达路由的跳数设为 16（毒性），主动通告 | 比水平分割更激进，让对方立即知道路由失效 |
| **触发更新** | 路由变化时立即发送更新，不等 30 秒周期 | 加速全网收敛，减少不一致窗口 |
| **抑制计时器** | 路由失效后一段时间内不接受同一路由的更新 | 防止"翻动"路由导致全网不稳定 |

**"计数到无穷"问题**：
- 场景：A 和 B 相邻，A 到网络 X 的路由（1 跳）突然失效
- A 把 X 设为 16 跳（不可达），但还没来得及告诉 B
- B 发来更新："我可以通过 A 到达 X，2 跳"
- A 想："B 能到 X（2 跳），那我经过 B 也能到，3 跳"
- 如此循环，跳数不断增加直到 16
- 这期间数据包在 A 和 B 之间来回转发，浪费带宽

#### OSPF 区域类型详解

OSPF 将网络分成多个区域（Area），减少路由表大小和 LSA 泛洪范围。

| 区域类型 | 可接收的 LSA | 路由表内容 | 适用场景 |
|---------|------------|-----------|---------|
| **骨干区域（Area 0）** | 全部 LSA | 完整路由表 | 所有区域必须连接 Area 0 |
| **标准区域** | 全部 LSA | 完整路由表 | 默认区域类型 |
| **末梢区域（Stub）** | 1/2/3 类 LSA，无 4/5 类 | 内部路由 + 一条默认路由 | 只有一个出口的小网络 |
| **完全末梢（Totally Stubby）** | 1/2 类 LSA + 默认路由 | 内部路由 + 一条默认路由 | Cisco 专有，比末梢更精简 |
| **NSSA（非完全末梢）** | 可引入少量外部路由（7 类 LSA） | 内部路由 + 少量外部路由 | 需要连接外部网络但又想精简路由 |

**各类 LSA 说明**：
- 1 类（Router LSA）：每个路由器产生，描述自己的链路状态
- 2 类（Network LSA）：DR 产生，描述广播网络中的路由器
- 3 类（Summary LSA）：ABR 产生，汇总其他区域的路由
- 4 类（ASBR Summary LSA）：ABR 产生，告诉其他区域 ASBR 的位置
- 5 类（External LSA）：ASBR 产生，引入外部路由
- 7 类（NSSA External LSA）：NSSA 区域的 ASBR 产生，类似 5 类但在 NSSA 内使用

#### OSPF 邻居状态机

OSPF 路由器建立邻居关系要经过 8 个状态：

| 状态 | 含义 | 说明 |
|------|------|------|
| **Down** | 初始状态 | 未收到 Hello 报文 |
| **Init** | 收到 Hello | 收到邻居的 Hello，但自己的 Router ID 不在邻居列表中 |
| **2-Way** | 双向通信 | 双方都收到了对方的 Hello，邻居关系建立（DR/BDR 选举在此状态） |
| **ExStart** | 开始交换 | 协商主从关系，确定 DD 序列号 |
| **Exchange** | 交换 DD | 交换数据库描述报文（DD），了解对方有哪些 LSA |
| **Loading** | 加载 LSA | 请求对方有而自己没有的 LSA（LSR/LSU/LSAck） |
| **Full** | 完全邻接 | LSDB 完全同步，邻接关系建立完成 |

> 注意：邻居（Neighbor）和邻接（Adjacency）不同。所有路由器在 2-Way 状态都是邻居，但只有达到 Full 状态才算建立了邻接关系。在广播网络中，非 DR/BDR 之间只停留在 2-Way 状态。

#### DR/BDR 选举过程

**为什么需要 DR/BDR？** 在广播网络（如以太网）中，如果 n 个路由器都两两建立邻接关系，需要 n(n-1)/2 个邻接关系，LSA 泛洪量巨大。DR 作为"班长"，所有路由器只和 DR 建立邻接，LSA 由 DR 统一转发，将邻接数降为 n-1。

**选举规则**（按优先级）：
1. 比较**优先级**（Priority，0~255），越大越优先（0 表示不参与选举）
2. 优先级相同则比较 **Router ID**，越大越优先
3. DR 选举出来后，再选 BDR（备份 DR）
4. **选举是非抢占的**：新的路由器加入不会抢占已有的 DR/BDR，除非 DR 或 BDR 失效

#### BGP 选路原则详解（13 条）

BGP 选路从上到下依次比较，匹配到第一条就停止，不会继续往下比：

| 序号 | 选路原则 | 说明 |
|------|---------|------|
| 1 | **最高 Weight** | Cisco 私有，本地有效，越大越优先 |
| 2 | **最高 LOCAL_PREF** | 本地优先级，越大越优先，在 AS 内传播 |
| 3 | **本地始发** | 本地路由器产生的路由优先于学来的路由 |
| 4 | **最短 AS_PATH** | AS_PATH 越短越优先 |
| 5 | **最低 ORIGIN** | IGP(0) < EGP(1) < Incomplete(2) |
| 6 | **最低 MED** | 多出口鉴别器，越小越优先，跨 AS 传递 |
| 7 | **eBGP 优于 iBGP** | 外部 BGP 路由优先于内部 BGP 路由 |
| 8 | **最近的 IGP 下一跳** | 到 NEXT_HOP 的 IGP 度量值越小越优先 |
| 9 | **eBGP 最老路由** | 如果是 eBGP 路由，选择最老的那条（最稳定） |
| 10 | **最低 Router ID** | 如果是 iBGP 路由，Router ID 越小越优先 |
| 11 | **最短 Cluster List** | 路由反射器场景，Cluster List 越短越优先 |
| 12 | **最低邻居地址** | 从 BGP 邻居 IP 地址最小的那个学来的路由优先 |
| 13 | **最低 BGP Identifier** | 最后一条，BGP Router ID 最小的优先 |

> **记忆口诀**：WLP-ASO-MED-eBGP-IGP-El-RC-NA-ID（首字母联想法，考试记住前 7 条即可）

### 一句话总结

> **RIP** 靠数跳数，简单但只能管小网络；**OSPF** 靠全网地图，收敛快无环路，适合企业内网；**BGP** 靠策略和路径，跑在互联网骨干上连接全世界。

### NAT 网络地址转换

**作用**：把内网私有 IP 转成公网 IP，让多台设备共用一个公网地址上网。

**NAT 三种类型**：
| 类型 | 说明 | 特点 |
|------|------|------|
| **静态 NAT** | 一对一映射（一个内网 IP 固定对应一个公网 IP） | 公网 IP 利用率低，但外部可以主动访问内网 |
| **动态 NAT** | 从公网 IP 池中动态分配 | 利用率较高，但公网 IP 数量仍然有限 |
| **PAT/NAPT** | 端口多路复用（多个内网 IP 共用一个公网 IP，靠端口号区分） | 最常见的家庭路由器方式，最节省公网 IP |

> 你的家里路由器就是用的 PAT——内网 192.168.1.x 都通过路由器的公网 IP 上网，路由器用不同的端口号来区分不同的内网设备。

### IPv6 详解

#### 为什么需要 IPv6？

IPv4 只有 32 位（约 43 亿个地址），2011 年已经分配完毕。IPv6 用 128 位，地址数量是 2¹²⁸ ≈ 3.4×10³⁸ 个，相当于地球上每粒沙子都能分到一个 IP。

#### IPv6 地址格式

- 128 位，分为 8 组，每组 4 位十六进制数，用冒号分隔
- 例：`2001:0db8:0000:0000:0000:ff00:0042:8329`

**省略规则**：
1. **前导零省略**：每组中的前导零可以省略。如 `0042` → `42`，`0db8` → `db8`
2. **连续零压缩**：一段或多段连续的 0 可以用 `::` 代替（**只能出现一次**，否则无法还原）
3. 省略后：`2001:db8::ff00:42:8329`

**省略规则练习题**：
- 原始：`2001:0db8:0000:0000:0000:0000:0000:0001` → 压缩后：`2001:db8::1`
- 原始：`fe80:0000:0000:0000:0a00:27ff:fe8e:3b6c` → 压缩后：`fe80::a00:27ff:fe8e:3b6c`
- 原始：`0000:0000:0000:0000:0000:0000:0000:0001` → 压缩后：`::1`（回环地址）

> **陷阱**：`::` 只能出现一次！如果 `2001::1::2` 这种写法是错误的，因为无法判断中间省略了几个 0 段。

#### IPv6 地址类型

| 类型 | 说明 | 对应 IPv4 概念 |
|------|------|--------------|
| **单播（Unicast）** | 一对一通信 | 单播 |
| **组播（Multicast）** | 一对多通信（发给一组接口） | 组播 |
| **任播（Anycast）** | 一对最近通信（发给一组中最近的一个） | IPv6 新增，IPv4 无 |
| 广播 | IPv6 **取消了广播**，用组播替代 | 广播（IPv6 没有） |

#### IPv6 地址分类

| 地址类型 | 前缀 | 范围 | 说明 |
|---------|------|------|------|
| **全球单播地址** | 2000::/3 | 全球互联网 | 类似 IPv4 的公网地址，全球唯一 |
| **链路本地地址** | **fe80::/10** | 本链路内 | 类似 IPv4 的 169.254.x.x，自动配置，不可路由 |
| **唯一本地地址** | **fc00::/7** | 站点/组织内 | 类似 IPv4 的私有地址，只在内网使用 |
| **回环地址** | **::1/128** | 本机 | 类似 IPv4 的 127.0.0.1 |
| **未指定地址** | **::/128** | — | 类似 IPv4 的 0.0.0.0 |
| **组播地址** | ff00::/8 | — | 以 ff 开头 |

#### IPv6 vs IPv4 对比表

| 对比维度 | IPv4 | IPv6 |
|---------|------|------|
| 地址长度 | 32 位 | 128 位 |
| 地址数量 | 约 43 亿 | 约 3.4×10³⁸ |
| 表示方式 | 点分十进制（192.168.1.1） | 冒号十六进制（2001:db8::1） |
| 首部长度 | 20~60 字节（可变） | 固定 40 字节（简化） |
| 首部校验和 | 有 | **无**（由上层协议负责） |
| 分片 | 路由器可分片 | **路由器不分片**（源端发现 PMTU） |
| 广播 | 支持 | **不支持**（用组播替代） |
| ARP | 有 | **无**（用 NDP 邻居发现协议替代） |
| NAT | 大量使用 | 不需要（地址足够多） |
| 自动配置 | DHCP | SLAAC（无状态自动配置）+ DHCPv6 |
| IPSec | 可选 | 推荐/强制 |

#### 过渡技术详解

由于 IPv4 和 IPv6 不兼容，从 IPv4 过渡到 IPv6 需要以下技术：

| 过渡技术 | 原理 | 优点 | 缺点 |
|---------|------|------|------|
| **双栈** | 设备同时运行 IPv4 和 IPv6 协议栈 | 原生支持，性能最好 | 需要同时维护两套网络 |
| **6to4 隧道** | 将 IPv6 包封装在 IPv4 包中传输 | 自动隧道，配置简单 | 依赖中继路由器 |
| **ISATAP** | 将 IPv4 网络视为 IPv6 的链路层 | 适合内网过渡 | 需要 ISATAP 路由器 |
| **Teredo** | IPv6 包封装在 IPv4 UDP 包中，可穿透 NAT | 能穿透 NAT | 性能开销大，微软主导 |
| **NAT64** | IPv6 主机访问 IPv4 资源，通过 NAT64 网关转换 | 不需要 IPv4 地址 | 只能 IPv6→IPv4 单向发起 |

### 网络层经典例题（5 道）

**例题 1：子网划分计算题**

某公司获得 C 类地址 200.1.1.0/24，需要划分 6 个子网，每个子网至少 25 台主机。求子网掩码和最后一个子网的可用 IP 范围。

**解**：
1. 主机需求：2^h - 2 >= 25 → h >= 5 → 主机位 = 5 位
2. 网络位 = 32 - 5 = 27 → 掩码 = /27 = 255.255.255.224
3. 子网数验证：借了 27 - 24 = 3 位 → 2³ = 8 个子网 >= 6，满足
4. 块大小 = 256 - 224 = 32
5. 子网：0, 32, 64, 96, 128, 160, 192, 224
6. 最后一个子网（第 6 个）：网络地址 = 200.1.1.160，广播地址 = 200.1.1.191
7. 可用 IP = 200.1.1.161 ~ 200.1.1.190（共 30 个）

**例题 2：路由聚合题**

将以下路由聚合：`10.10.0.0/24`、`10.10.1.0/24`、`10.10.2.0/24`、`10.10.3.0/24`、`10.10.4.0/24`、`10.10.5.0/24`、`10.10.6.0/24`、`10.10.7.0/24`

**解**：
1. 8 个网络，第三个字节 0~7，二进制：00000000 ~ 00000111
2. 共同前缀：前 5 位相同（00000），后 3 位不同
3. 10.10 占 16 位 + 第三字节前 5 位 = 21 位共同前缀
4. 聚合结果 = **10.10.0.0/21**
5. 掩码 = 255.255.248.0，覆盖 10.10.0.0 ~ 10.10.7.255

**例题 3：RIP/OSPF/BGP 选择题**

下列关于路由协议的说法，正确的是（多选）：

A. RIP 使用链路状态算法，最大跳数 15
B. OSPF 使用 SPF 算法，支持区域划分，Area 0 是骨干区域
C. BGP 是路径矢量协议，基于 TCP 建立连接，端口 179
D. RIP 的管理距离（AD）是 110，OSPF 的管理距离是 120

**答案**：B、C

**解析**：
- A 错：RIP 使用**距离矢量**算法，不是链路状态算法
- B 对：OSPF 的特点描述完全正确
- C 对：BGP 的描述完全正确
- D 错：RIP 的 AD = **120**，OSPF 的 AD = **110**（数字越小越可信）

**例题 4：ICMP 应用题**

主机 A（192.168.1.10）PING 主机 B（10.0.0.5），A 和 B 不在同一网段，中间经过两台路由器 R1 和 R2。请描述 PING 过程中，从 A 发出的第一个 ICMP 回显请求报文，在到达 B 之前每一跳的封装变化。

**解**：
1. A 发现 B 不在同一网段，查路由表，走默认网关 R1
2. A 构建帧：目的 MAC = R1 的 MAC，载荷 = ICMP Echo Request（源 IP=A，目的 IP=B）
3. R1 收到后解封装，查路由表，下一跳 R2
4. R1 构建帧：目的 MAC = R2 的 MAC，载荷 = ICMP Echo Request（IP 头部不变，TTL 减 1）
5. R2 收到后解封装，查路由表，B 在直连网段
6. R2 构建帧：目的 MAC = B 的 MAC，载荷 = ICMP Echo Request（IP 头部不变，TTL 再减 1）
7. B 收到后回复 ICMP Echo Reply，沿原路返回

> 关键点：每跳 IP 源地址和目的地址不变，但 MAC 地址每跳都变。TTL 每跳减 1。

**例题 5：IPv6 地址简化/识别题**

将以下 IPv6 地址简化，并判断地址类型：
1. `2001:0db8:0000:0000:0a00:0000:0000:0001`
2. `fe80:0000:0000:0000:0000:0000:0000:0001`
3. `0000:0000:0000:0000:0000:0000:0000:0001`

**解**：
1. 简化：`2001:db8:0:0:a00:0:0:1` 或 `2001:db8::a00:0:0:1` → 类型：**全球单播地址**（2000::/3 范围内）
2. 简化：`fe80::1` → 类型：**链路本地地址**（fe80::/10 范围内），只能在本地链路使用
3. 简化：`::1` → 类型：**回环地址**，相当于 IPv4 的 127.0.0.1

### 易错陷阱表

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 1 | 子网可用主机数 = 2^主机位数 | **错！** 必须减 2（减去网络地址和广播地址） |
| 2 | 127.x.x.x 是 A 类地址 | **错！** 127.x.x.x 是环回地址，被保留，不属于任何可用类别 |
| 3 | ARP 请求是单播 | **错！** ARP 请求是**广播**（目的 MAC = FF-FF-FF-FF-FF-FF），ARP 应答才是单播 |
| 4 | PING 是应用层协议 | **错！** PING 使用的是 ICMP 协议，ICMP 属于**网络层**（和 IP 同级） |
| 5 | CIDR 聚合时，任何几个连续网络都能聚合 | **错！** 必须是 2^n 个连续网络，且起始地址能被 2^n 整除 |
| 6 | IPv6 的 `::` 可以出现多次 | **错！** `::` 只能出现一次，否则无法唯一确定被省略了多少个 0 段 |
| 7 | RIP 的 AD 是 110，OSPF 的 AD 是 120 | **反了！** RIP 的 AD = 120，OSPF 的 AD = 110（AD 越小越可信） |
| 8 | BGP 使用 UDP 通信 | **错！** BGP 使用 **TCP 179 端口**，保证可靠性 |
| 9 | 路由器收到分组后根据 MAC 地址转发 | **错！** 路由器根据**目的 IP 地址**查路由表转发（网络层）；交换机根据 MAC 地址转发（数据链路层） |
| 10 | 超时重传后 cwnd 减半，进入拥塞避免 | **错！** 超时重传后 cwnd = 1，重新进入慢开始；只有收到 3 个重复 ACK 才 cwnd 减半进入拥塞避免 |

## 知识点 20：传输层

> 传输层是考试中最重要的章节之一，TCP 的三次握手、四次挥手、拥塞控制是高频考点。

### TCP vs UDP

| 对比维度 | TCP | UDP |
|---------|-----|-----|
| 连接 | 面向连接（先握手） | 无连接（直接发） |
| 可靠性 | 可靠（确认+重传） | 不可靠（发了不管） |
| 顺序 | 有序 | 可能乱序 |
| 首部大小 | 20~60 字节 | 固定 8 字节 |
| 速度 | 慢 | 快 |
| 适用场景 | 网页、文件、邮件 | 视频流、DNS、在线游戏 |
| 是否支持广播/组播 | 不支持（一对一） | 支持 |

> **TCP 为什么可靠？** 确认应答 + 超时重传 + 流量控制 + 拥塞控制 + 序号保证有序

### 端口号

端口号标识主机上的**哪个应用进程**。IP 地址 + 端口号 = 唯一标识网络中的一个进程。

| 端口范围 | 分类 | 说明 |
|---------|------|------|
| 0~1023 | 知名端口 | 由 IANA 分配，需要管理员权限 |
| 1024~49151 | 注册端口 | 应用程序注册使用 |
| 49152~65535 | 动态端口 | 客户端临时使用 |

**必背端口**：

| 服务 | 端口 | 协议 | 说明 |
|------|------|------|------|
| HTTP | 80 | TCP | 网页 |
| HTTPS | 443 | TCP | 加密网页 |
| FTP | 21(控制)/20(数据) | TCP | 文件传输 |
| SSH | 22 | TCP | 安全远程登录 |
| Telnet | 23 | TCP | 远程登录（明文，不安全） |
| SMTP | 25 | TCP | 发邮件 |
| POP3 | 110 | TCP | 收邮件 |
| IMAP | 143 | TCP | 收邮件（比POP3好） |
| DNS | 53 | UDP/TCP | 域名解析 |
| DHCP | 67(服务端)/68(客户端) | UDP | 动态IP分配 |

### TCP 三次握手（高频！）

```
客户端                          服务器
  |                               |
  |--- SYN, seq=x --------------->|  ① SYN：我要连接
  |                               |
  |<-- SYN+ACK, seq=y, ack=x+1 --|  ② SYN+ACK：收到，同意
  |                               |
  |--- ACK, seq=x+1, ack=y+1 --->|  ③ ACK：好的，连接建立
  |                               |
```

**状态变化**：
- 客户端：CLOSED → SYN_SENT → ESTABLISHED
- 服务端：CLOSED → LISTEN → SYN_RCVD → ESTABLISHED

**为什么是三次不是两次？**
因为要防止**已失效的连接请求**到达服务器。假设第一次握手的 SYN 由于网络延迟很久后才到服务器，如果只有两次握手，服务器收到后直接建立连接分配资源，但客户端已经不认这个连接了，服务器资源就浪费了。三次握手让客户端再确认一次。

### TCP 四次挥手

```
客户端                          服务器
  |                               |
  |--- FIN, seq=u --------------->|  ① 客户端：我没数据要发了
  |                               |
  |<-- ACK, seq=v, ack=u+1 ------|  ② 服务器：收到（但服务端可能还有数据要发）
  |                               |
  |<-- FIN, seq=w, ack=u+1 ------|  ③ 服务器：我也没数据了，关闭
  |                               |
  |--- ACK, seq=u+1, ack=w+1 --->|  ④ 客户端：好的，关闭
  |                               |
```

**状态变化**：
- 客户端：ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED
- 服务端：ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED

**TIME_WAIT 为什么等 2MSL？**
1. 确保最后一个 ACK 能到达服务器（如果丢了服务器会重传 FIN，客户端还能收到再回 ACK）
2. 让本次连接所有报文都在网络中消散，不影响下一次新连接

> MSL（报文最大生存时间）通常为 2 分钟，所以 TIME_WAIT 约 4 分钟。

### TCP 可靠传输机制

| 机制 | 作用 |
|------|------|
| 序号 | 每个字节编号，保证有序 |
| 确认应答 | 收到数据回 ACK |
| 超时重传 | 超时没收到 ACK 就重发 |
| 滑动窗口 | 批量发送提高效率 |

### TCP 流量控制

**目的**：防止发送方发太快，接收方处理不过来。

通过**接收窗口 rwnd** 告诉发送方："我还能接收多少"。rwnd=0 时发送方暂停，定期发零窗口探测报文。

### TCP 拥塞控制（高频！）

**目的**：防止网络中流量过大导致拥塞。

四个算法阶段：

| 阶段 | cwnd 变化 | 触发条件 |
|------|----------|---------|
| 慢开始 | cwnd 从 1 开始，每轮**翻倍** | 新建连接 / 超时后 |
| 拥塞避免 | cwnd 每轮**+1** | cwnd ≥ ssthresh |
| 快重传 | 收到 3 个重复 ACK，立即重传 | 个别报文丢失 |
| 快恢复 | ssthresh = cwnd/2, cwnd = ssthresh | 快重传后 |

> **ssthresh**（慢开始门限）：cwnd < ssthresh 用慢开始，cwnd ≥ ssthresh 用拥塞避免。
> 超时后：ssthresh = cwnd/2，cwnd = 1，重新慢开始。
> 快重传后（收到3个重复ACK）：ssthresh = cwnd/2，cwnd = ssthresh，进入快恢复（不是从1开始！）。

### UDP

- 首部仅 8 字节（源端口、目的端口、长度、校验和）
- 无连接、无确认、不排序
- 适合实时应用：DNS、视频直播、VoIP、在线游戏

> 为什么 DNS 用 UDP？请求和响应都很短（一个包搞定），用 TCP 的三次握手开销太大。


### 补充：TCP 拥塞控制详解

### 核心概念

- **拥塞窗口 cwnd**：发送方根据网络拥塞程度动态维护的状态变量
- **慢开始门限 ssthresh**：慢开始与拥塞避免的分界线
- **发送窗口**：swnd = min(cwnd, rwnd)，rwnd 为接收方通告窗口
- **判断拥塞的依据**：发送方发生超时重传

---

### 2.1 慢开始 Slow Start

**触发时机：** 连接建立后，或发生超时重传后重新开始。

**核心规则：** 每收到一个 ACK，cwnd 加 1（MSS 为单位）。

**增长特性：** **指数增长**。

```
cwnd=1 → 收到1个ACK → cwnd=2
       → 收到2个ACK → cwnd=4
       → 收到4个ACK → cwnd=8
       → 收到8个ACK → cwnd=16
```

**状态转换：** 当 cwnd >= ssthresh 时，切换为拥塞避免算法。

---

### 2.2 拥塞避免 Congestion Avoidance

**触发时机：** cwnd 达到或超过 ssthresh 时进入。

**核心规则：** 每收到一个 ACK，cwnd 增加 1/cwnd（即一轮 RTT 后 cwnd 加 1）。

**增长特性：** **线性增长**（从指数增长变为线性增长，增长速度放缓）。

```
cwnd=8 → 一轮RTT后收到8个ACK，各增1/8 → cwnd=9
       → 一轮RTT后收到9个ACK，各增1/9 → cwnd=10
```

**状态转换：** 当发生丢包时，进入拥塞发生阶段。

---

### 2.3 快重传 Fast Retransmit

**触发条件：** 发送方连续收到 **3 个重复 ACK**（共 4 个相同 ACK），不等超时就立即重传。

**工作原理：**
- 接收方收到失序报文段时，立即发送重复 ACK（期望的下一个序号）
- 发送方收到 3 个重复 ACK 后，推断该报文段丢失，立即重传

**参数变化：**
- cwnd = cwnd / 2
- ssthresh = cwnd（即与原 cwnd/2 相同）
- 进入快速恢复算法

---

### 2.4 快恢复 Fast Recovery

快重传和快恢复同时使用，进入前 cwnd 和 ssthresh 已更新为原先的一半。

**算法步骤：**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | cwnd = ssthresh + 3 | 3 代表确认有 3 个数据包已被接收 |
| 2 | 重传丢失的数据包 | |
| 3 | 再收到重复 ACK → cwnd += 1 | 尽快将丢失的包发出去 |
| 4 | 收到新数据 ACK → cwnd = ssthresh | 结束恢复，进入拥塞避免 |

**关键理解：**
- 步骤 3 中 cwnd 每次 +1 是为了在关键时期能继续发送数据
- 步骤 4 收到新数据 ACK 后，将 cwnd 设回 ssthresh，恢复过程结束

---

### 2.5 状态转换图

```
连接建立
    ↓
  慢开始 (cwnd 指数增长)
    ↓ cwnd >= ssthresh
  拥塞避免 (cwnd 线性增长)
    ↓ 丢包
    ├─────────── 超时重传 ───────────┐
    │                                 │
    ↓                                 ↓
 ssthresh = cwnd/2             收到3个重复ACK
 cwnd = 1                       (快重传)
    ↓                                 ↓
  慢开始                       cwnd = cwnd/2
                                 ssthresh = cwnd
                                    ↓
                                快速恢复
                                 cwnd = ssthresh + 3
                                 收到重复ACK → cwnd += 1
                                    ↓
                                 收到新数据ACK
                                 cwnd = ssthresh
                                    ↓
                                拥塞避免
```

### 2.6 典型计算题

**例题 1：无丢包情况**

设 ssthresh 初始 = 8，MSS = 1，cwnd 初始 = 1，无丢包：

| 轮次 | 当前 cwnd | 发送 MSS 数 | 阶段 | 下轮 cwnd |
|------|-----------|------------|------|-----------|
| 1 | 1 | 1 | 慢开始 | 2 |
| 2 | 2 | 2 | 慢开始 | 4 |
| 3 | 4 | 4 | 慢开始 | 8 |
| 4 | 8 | 8 | 拥塞避免 | 9 |
| 5 | 9 | 9 | 拥塞避免 | 10 |

**例题 2：超时重传**

设 cwnd = 16，ssthresh = 8，发生超时重传：
- ssthresh = 16 / 2 = 8
- cwnd = 1
- 重新进入慢开始

**例题 3：快重传 + 快恢复**

设 cwnd = 16，ssthresh = 8，收到 3 个重复 ACK：
- cwnd = 16 / 2 = 8
- ssthresh = 8
- 进入快恢复：cwnd = 8 + 3 = 11
- 此后再收到重复 ACK：cwnd += 1（如 11 → 12）
- 收到新数据 ACK：cwnd = ssthresh = 8，进入拥塞避免

**例题 4：综合计算**

设 ssthresh = 16，cwnd = 1，MSS = 1KB，RTT = 100ms。

| 轮次 | cwnd | 发送窗口 | 阶段 | 说明 |
|------|------|----------|------|------|
| 1 | 1 | 1KB | 慢开始 | |
| 2 | 2 | 2KB | 慢开始 | |
| 3 | 4 | 4KB | 慢开始 | |
| 4 | 8 | 8KB | 慢开始 | |
| 5 | 16 | 16KB | 慢开始(达到门限) | cwnd=16=ssthresh |
| 6 | 17 | 17KB | 拥塞避免 | 16个ACK各增1/16 |
| 7 | 18 | 18KB | 拥塞避免 | 17个ACK各增1/17 |

## 知识点 21：应用层

### DNS 域名解析

**作用**：把域名（如 www.baidu.com）翻译成 IP 地址。

**解析流程**：
1. 先查浏览器缓存 → 操作系统 hosts 文件 → 本地 DNS 服务器
2. 本地 DNS 没记录 → **递归查询**：替你去问根域名 → 顶级域 → 权威域名服务器
3. 或者用**迭代查询**：告诉你去找谁，你自己一个个问

| 查询方式 | DNS 服务器怎么做 | 类比 |
|---------|----------------|------|
| 递归查询 | 服务器替你问到最终结果 | "帮我查一下" |
| 迭代查询 | 服务器告诉你去哪查，你自己去 | "你去那个窗口问" |

> 通常：主机 → 本地 DNS 是递归；本地 DNS → 根/顶级/权威 DNS 是迭代。

### HTTP 协议

**特点**：无状态（每次请求独立，不知道你上次做了什么）。所以需要 Cookie/Session 来保持状态。

**请求报文结构**：
```
GET /index.html HTTP/1.1        ← 请求行（方法 + URL + 版本）
Host: www.example.com            ← 首部（头部字段）
Connection: keep-alive
                                 ← 空行
                                 ← 实体主体（GET 一般没有，POST 有）
```

**响应报文结构**：
```
HTTP/1.1 200 OK                  ← 状态行（版本 + 状态码 + 原因）
Content-Type: text/html          ← 首部
Content-Length: 1234
                                 ← 空行
<html>...</html>                  ← 实体主体
```

**HTTP 方法**：

| 方法 | 作用 | 幂等性 | 安全性 |
|------|------|--------|--------|
| GET | 获取资源 | ✅ | ✅ |
| POST | 创建资源/提交数据 | ❌ | ❌ |
| PUT | 更新（完整替换） | ✅ | ❌ |
| DELETE | 删除 | ✅ | ❌ |
| HEAD | 只获取响应头 | ✅ | ✅ |

> 幂等：执行多次和执行一次效果相同。GET 查 10 次和查 1 次结果一样。POST 提交两次会创建两条。

### 4.7 常见面试题

**Q1: 301 vs 302 vs 307 vs 308 的区别？**

| | 临时 | 永久 |
|---|---|---|
| **方法可变** | 302 Found | 301 Moved Permanently |
| **方法不变** | 307 Temporary Redirect | 308 Permanent Redirect |

**Q2: 401 vs 403 的区别？**
- 401：用户**未认证**（不知道你是谁），需要登录
- 403：用户**已认证但无权限**（知道你是谁但不让你访问）

**Q3: 502 vs 504 的区别？**
- 502：网关收到上游服务器的**无效响应**
- 504：网关在超时时间内**未收到**上游响应

**Q4: 304 Not Modified 的工作原理？**
用于缓存验证。客户端发送带 `If-Modified-Since` 或 `If-None-Match` 的条件请求，若资源未变化，服务器返回 304（无响应体），客户端继续使用本地缓存。

**Q5: RESTful API 状态码最佳实践？**

| 场景 | 状态码 |
|------|--------|
| 成功获取资源 | 200 |
| 成功创建资源 | 201 |
| 异步处理中 | 202 |
| 成功删除（无内容返回） | 204 |
| 验证失败 | 422 |
| 资源不存在 | 404 |
| 未认证 | 401 |
| 无权限 | 403 |
| 限流 | 429 |
| 服务器错误 | 500 |

**Q6: 418 I'm a teapot 是什么？**
来自 1998 年愚人节 RFC 2324（HTCPCP 超文本咖啡壶控制协议），规定茶壶拒绝煮咖啡时应返回此状态码。是 HTTP 文化中的经典彩蛋。

---

**HTTP 状态码**：

| 类别 | 含义 | 常见状态码 |
|------|------|-----------|
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | **200** OK, **201** Created, **204** No Content |
| 3xx | 重定向 | **301** 永久重定向, **302** 临时重定向, **304** 未修改（用缓存） |
| 4xx | 客户端错误 | **400** 请求错误, **401** 未认证, **403** 禁止, **404** 找不到 |
| 5xx | 服务端错误 | **500** 服务器内部错误, **502** 网关错误, **503** 服务不可用 |

### HTTPS

HTTPS = HTTP + SSL/TLS（加密层）。端口 443。

**TLS 握手过程（简化）**：
1. 客户端发送支持的加密算法列表
2. 服务器选一个算法，发回数字证书（含公钥）
3. 客户端验证证书，生成随机密钥，用公钥加密发给服务器
4. 之后双方用这个密钥对称加密通信

> HTTPS 混合使用非对称加密（交换密钥）+ 对称加密（传输数据），因为非对称加密太慢了。

### HTTP 版本演进

| 版本 | 特点 |
|------|------|
| HTTP/1.0 | 每次请求一个 TCP 连接，用完就关 |
| HTTP/1.1 | **持久连接**（Keep-Alive），一个连接可发多个请求 |
| HTTP/2.0 | 二进制分帧、多路复用、头部压缩、服务器推送 |
| HTTP/3.0 | 基于 UDP（QUIC 协议），减少连接建立时延 |

### FTP 协议

- 使用两个 TCP 连接：**控制连接**（端口 21，传命令）+ **数据连接**（端口 20，传文件）
- 主动模式：服务器主动连接客户端的数据端口
- 被动模式：客户端主动连接服务器的数据端口（更常用，不受客户端防火墙限制）

### 邮件协议

| 协议 | 端口 | 方向 | 作用 |
|------|------|------|------|
| SMTP | 25 | 客户端→服务器 | 发送邮件 |
| POP3 | 110 | 服务器→客户端 | 下载邮件（下载后服务器上可能删除） |

- **明文传输**（用户名密码都不加密），已被 SSH（端口 22）替代

## 知识点 22：网络管理与网络安全

> 网络安全的本质是"在不可信的网络中建立可信通信"，核心围绕 CIA 三要素展开。

### 一、网络安全基本概念

#### 1.1 CIA 三要素

网络安全的核心目标，缺一不可：

| 要素 | 英文 | 含义 | 类比 | 破坏方式 |
|------|------|------|------|---------|
| 机密性 | Confidentiality | 信息不泄露给未授权者 | 信只有收信人能看 | 窃听、截获 |
| 完整性 | Integrity | 信息不被篡改 | 信的内容没被修改 | 篡改、插入 |
| 可用性 | Availability | 授权用户随时可用 | 邮局 24 小时开门 | DoS/DDoS 攻击 |

> 记忆口诀："机完可"——机密性（不泄露）、完整性（不篡改）、可用性（不中断）。

#### 1.2 被动攻击 vs 主动攻击

| 类型 | 特点 | 是否改变数据 | 常见手段 | 类比 |
|------|------|------------|---------|------|
| 被动攻击 | 只窃听，不破坏 | 否 | 网络嗅探、流量分析 | 偷听别人打电话，不插嘴 |
| 主动攻击 | 篡改/伪造/中断 | 是 | 篡改、伪造、重放、DoS | 剪断电话线、冒充别人说话 |

> 被动攻击比主动攻击更难被发现，因为数据流本身没变化。

#### 1.3 OSI 安全体系结构

ISO 定义了五类安全服务 + 八种安全机制：

| 安全服务 | 说明 | 对应的安全机制 |
|---------|------|--------------|
| 认证 | 确认通信对方身份 | 数字签名、口令 |
| 访问控制 | 限制对资源的访问权限 | 防火墙、ACL |
| 数据保密 | 防止数据泄露 | 加密 |
| 数据完整性 | 防止数据被篡改 | 数字签名、MAC |
| 不可否认性 | 发送方不能赖账 | 数字签名 |

---

### 二、常见攻击类型

| 攻击 | 特点 | 类比 |
|------|------|------|
| DoS | 一个攻击者让服务器瘫痪 | 一个人不停打电话占线 |
| DDoS | 多个攻击者同时打（僵尸网络） | 几十万人同时打电话，彻底崩 |
| 中间人攻击 | 在通信双方之间截获/篡改信息 | 邮递员偷偷拆信、改信 |

#### 2.1 常见网络攻击详解

**SQL 注入**：攻击者在输入框输入恶意 SQL 代码，绕过验证直接操作数据库。

- 原理：`SELECT * FROM users WHERE name='admin' AND pwd='' OR '1'='1'`
- 防御：参数化查询（预编译语句）、输入校验、最小权限原则

**XSS 跨站脚本攻击**：攻击者把恶意脚本注入网页，当用户访问时自动执行。

| 类型 | 特点 | 典型场景 |
|------|------|---------|
| 反射型 XSS | 恶意脚本在 URL 参数中，一次性触发 | 点击钓鱼链接 |
| 存储型 XSS | 恶意脚本存储在服务器（如评论区），所有人访问时触发 | 论坛留言板 |
| DOM 型 XSS | 纯前端问题，修改 DOM 结构触发 | 前端拼接 HTML |

- 防御：输出编码、CSP 内容安全策略、HttpOnly Cookie

**CSRF 跨站请求伪造**：攻击者诱导用户点击链接，利用用户已登录的身份发请求。

- 类比：你登录了银行，攻击者骗你点击"转账"按钮，银行以为是你操作的
- 防御：CSRF Token、SameSite Cookie、Referer 校验

**ARP 欺骗**：攻击者冒充网关，告诉你的电脑"我是网关，把数据发给我"。

- 原理：ARP 协议无认证机制，收到 ARP 回复就更新缓存
- 防御：静态 ARP 表、ARP 防火墙、交换机端口绑定

**DNS 劫持/污染**：篡改 DNS 解析结果，把用户引导到假网站。

- DNS 劫持：攻击 DNS 服务器本身
- DNS 污染（缓存投毒）：向 DNS 缓存注入错误记录
- 防御：DNSSEC、使用可信 DNS 服务器

**缓冲区溢出攻击**：向程序输入超长数据，覆盖相邻内存区域，执行恶意代码。

- 原理：C 语言中 `strcpy()` 不检查边界，超出缓冲区就覆盖返回地址
- 防御：使用安全函数（`strncpy`）、地址随机化（ASLR）、栈保护（Canary）

---

### 三、防火墙

网络边界上的安全设备，根据规则允许/拒绝流量。

#### 3.1 三种防火墙对比

| 类型 | 工作层次 | 检查内容 | 优点 | 缺点 | 类比 |
|------|---------|---------|------|------|------|
| 包过滤防火墙 | 网络层+传输层 | IP 地址、端口号、协议类型 | 快、简单、成本低 | 只看头部，不检查内容 | 门卫只看身份证 |
| 状态检测防火墙 | 网络层+传输层 | 跟踪连接状态表，动态判断 | 比包过滤更安全、效率高 | 仍然不检查应用层内容 | 门卫记住谁进来过 |
| 应用层网关（代理防火墙） | 应用层 | 检查应用层数据内容 | 最安全，深度检查 | 慢、每种应用需单独代理 | 安检员开箱检查 |

> 包过滤只看"信封"（IP/端口），代理防火墙还看"信的内容"（应用数据）。

#### 3.2 防火墙部署策略

- **DMZ（非军事区）**：在外部网络和内部网络之间的隔离区，放对外服务的服务器（Web、邮件），两头受限。
- **边界防火墙**：部署在内外网边界，防护外部威胁。
- **内部防火墙**：部署在内网不同区域之间，隔离重要网段。

> DMZ 的典型规则：外网可访问 DMZ、DMZ 不能主动访问内网、内网可访问 DMZ 和外网。

### 四、VPN 虚拟专用网

在公共网络（互联网）上建一条加密的"专用隧道"，远程办公的典型场景。

- 核心原理：隧道技术 + 加密 + 认证
- 常见协议：IPSec VPN、SSL VPN、L2TP
- IPSec VPN 工作在网络层，SSL VPN 工作在传输层/应用层

### 五、加密技术详解

#### 5.1 对称加密

加密和解密用同一把密钥，就像两个人共用一把钥匙开门。

**常用对称加密算法：**

| 算法 | 密钥长度 | 分组大小 | 结构 | 安全性 | 现状 |
|------|---------|---------|------|------|------|
| DES | 56 位 | 64 位 | Feistel 结构，16 轮 | 已破解（穷举可行） | 已淘汰 |
| 3DES | 112/168 位 | 64 位 | 加密-解密-加密，三重 DES | 中等 | 逐步淘汰 |
| AES | 128/192/256 位 | 128 位 | SP 结构（替代-置换网络） | 安全 | 当前主流标准 |
| RC4 | 可变（40-2048 位） | 流加密 | 伪随机密钥流 | 已破解 | 已禁用（WEP/TLS 已弃用） |
| SM4 | 128 位 | 128 位 | 32 轮迭代 | 安全 | 中国国密标准 |

**DES 详解：**
- 64 位明文分组，56 位有效密钥（8 位奇偶校验）
- 采用 Feistel 结构：每轮将数据分左右两半，右半经过轮函数 f 后与左半 XOR
- 16 轮迭代，每轮使用不同的 48 位子密钥（由 56 位密钥生成）

**3DES 详解：**
- 加密过程：E(K1, D(K2, E(K3, 明文))) 即加密→解密→加密
- 使用解密中间步骤是为了兼容 DES（K1=K2=K3 时退化为 DES）
- 速度约为 DES 的 1/3

**AES 详解：**
- 分组大小固定 128 位，密钥 128/192/256 位，轮数 10/12/14
- 每轮包含：字节代换（S 盒）、行移位、列混合、轮密钥加
- 最后一轮省略列混合
- 不是 Feistel 结构，是 SP 结构（所有位都被处理，扩散更快）

**对称加密的优缺点：**
- 优点：速度快（比非对称快 100-1000 倍），适合加密大量数据
- 缺点：密钥分发困难（如何安全地把密钥告诉对方？）

#### 5.2 非对称加密

加密和解密用不同密钥：公钥加密、私钥解密。公钥公开，私钥保密。

**RSA 详解：**
- 基于大整数分解的数学难题：两个大素数相乘很容易，但把乘积分解回两个素数极难
- 密钥生成过程：
  1. 选两个大素数 p 和 q（通常 1024 位以上）
  2. 计算 n = p×q，φ(n) = (p-1)(q-1)
  3. 选 e（1 < e < φ(n)，且 e 与 φ(n) 互质），通常 e=65537
  4. 计算 d = e⁻¹ mod φ(n)（d 是 e 的模逆元）
  5. 公钥 = (e, n)，私钥 = (d, n)
- 加密：c = m^e mod n
- 解密：m = c^d mod n
- 安全性依赖：已知 n 但无法分解出 p 和 q

**ECC 椭圆曲线加密：**
- 基于椭圆曲线上的离散对数问题
- 更短的密钥达到相同安全强度：256 位 ECC 安全性约等于 3072 位 RSA
- 计算量小、存储空间小、带宽低，适合移动设备
- 代表算法：ECDSA（数字签名）、ECDH（密钥交换）
- SM2：中国国密标准的椭圆曲线算法

**非对称加密的优缺点：**
- 优点：解决密钥分发问题（公钥公开即可），支持数字签名
- 缺点：速度慢，不适合加密大量数据

#### 5.3 对称加密 vs 非对称加密对比

| 对比维度 | 对称加密 | 非对称加密 |
|---------|---------|-----------|
| 密钥 | 加密解密用同一把 | 公钥加密，私钥解密 |
| 速度 | 快（软件实现 ~100MB/s） | 慢（~1KB/s） |
| 密钥分发 | 困难（需安全信道） | 简单（公钥公开） |
| 代表算法 | DES（已淘汰）、**AES**、SM4 | **RSA**、ECC、SM2 |
| 密钥长度 | 128/256 位 | 2048/3072 位（RSA）、256 位（ECC） |
| 用途 | 加密实际数据 | 加密密钥、数字签名、身份认证 |
| 数学基础 | 置换、代换 | 大数分解、离散对数 |

#### 5.4 混合加密

实际应用中，两者结合使用：

1. 用非对称加密（RSA/ECC）安全传输"对称密钥"
2. 之后用对称加密（AES）加密实际数据
3. HTTPS 就是典型的混合加密：RSA/ECDH 交换密钥 + AES 加密数据

> 类比：非对称加密是"保险箱"（安全但容量小），把钥匙（对称密钥）放进去；对称加密是"大卡车"（快但钥匙需要安全传递），真正运货。

#### 5.5 Diffie-Hellman 密钥交换

不直接传输密钥，而是双方各自生成公私钥对，通过公开交换部分信息，各自计算出相同的共享密钥。

- 原理：基于离散对数问题
- 过程：A 选 a，发送 g^a mod p；B 选 b，发送 g^b mod p；双方各自计算 (g^b)^a 和 (g^a)^b，结果相同
- 缺点：DH 本身不认证身份，需配合数字签名防中间人攻击（ECDHE 中的 E 是临时密钥）

### 六、数字签名与消息认证

#### 6.1 哈希函数

把任意长度的消息压缩成固定长度的"指纹"（摘要），不可逆。

| 算法 | 输出长度 | 安全性 | 现状 |
|------|---------|------|------|
| MD5 | 128 位 | 已破解（2004 年王小云找到碰撞） | 禁止用于安全领域 |
| SHA-1 | 160 位 | 已破解（2017 年 Google 实现碰撞） | 已淘汰 |
| SHA-256 | 256 位 | 安全 | 当前主流 |
| SHA-3 | 224/256/384/512 位 | 安全 | 新一代标准 |
| SM3 | 256 位 | 安全 | 中国国密标准 |

**哈希函数特性：**
- 单向性：从摘要反推原文不可能
- 抗碰撞性：找不到两个不同原文产生相同摘要
- 雪崩效应：原文改一个 bit，摘要至少一半 bit 改变

#### 6.2 消息认证码 MAC

- MAC = 消息 + 共享密钥 → 哈希 → 认证码
- 接收方用相同密钥重新计算，比对是否一致
- 验证：消息未被篡改（完整性）+ 消息来自共享密钥的人（认证）
- HMAC：基于哈希函数的 MAC（如 HMAC-SHA256）
- 局限：无法防止抵赖（双方都有密钥，无法证明谁发的）

#### 6.3 数字签名

**数字签名详细过程：**

1. 发送方对原文计算哈希（摘要）
2. 发送方用**自己的私钥**加密摘要 → 数字签名
3. 发送方将原文 + 签名一起发给接收方
4. 接收方对原文计算哈希，得到摘要1
5. 接收方用发送方的**公钥**解密签名，得到摘要2
6. 比对摘要1 和摘要2：一致则验证通过

> 注意：数字签名是"私钥加密摘要"，不是"私钥加密原文"（加密全文太慢了）。

**数字签名三大特性：**

| 特性 | 原理 | 类比 |
|------|------|------|
| 防伪造 | 私钥只有签名者持有，别人造不出 | 只有你的笔迹别人模仿不了 |
| 防篡改 | 改一个字，哈希就变了，签名对不上 | 合同改一个字，印章就失效 |
| 防抵赖 | 私钥签名不可否认，公钥验证能证明 | 签了字就不能赖账 |

**数字签名的局限性：** 签名能证明"这个公钥对应的私钥签了名"，但不能证明"这个公钥确实属于王天宇"。需要一个权威机构来证明"公钥-身份"的绑定关系，这就是数字证书。

### 七、数字证书与 PKI

#### 7.1 数字证书 X.509 格式

数字证书 = 互联网上的"身份证"，由 CA 签发。

| 字段 | 含义 | 类比 |
|------|------|------|
| 版本 | X.509 版本号 | 身份证格式版本 |
| 序列号 | 证书唯一编号 | 身份证号 |
| 签名算法 | 用哪种算法签名（如 SHA256-RSA） | — |
| 颁发者 | CA 的名称 | 签发机关 |
| 有效期 | 起止时间 | 身份证有效期 |
| 主体 | 证书拥有者名称 | 姓名 |
| 主体公钥 | 持有者的公钥 | — |
| 扩展 | 用途限制（如仅用于 TLS 服务器） | — |

#### 7.2 CA 证书认证中心

- CA 用自己的私钥给用户证书签名，证明"这个公钥确实属于这个人"
- 根 CA 自签名（自己给自己签），信任的起点
- 浏览器/操作系统预装根 CA 证书（信任锚点）

#### 7.3 证书链验证过程

```
根 CA 证书（自签名，预装在系统中）
    ↓ 用根 CA 私钥签名
中间 CA 证书
    ↓ 用中间 CA 私钥签名
服务器证书（网站用的）
```

验证时：用根 CA 公钥验证中间 CA 证书 → 用中间 CA 公钥验证服务器证书 → 信任链成立。

> 类比：你要证明你是你，你爸（中间 CA）给你担保，你爷爷（根 CA）给你爸担保，大家都信你爷爷。

#### 7.4 PKI 公钥基础设施

| 组件 | 作用 |
|------|------|
| CA（认证中心） | 签发、吊销证书 |
| RA（注册中心） | 验证用户身份，向 CA 提交申请 |
| 证书库 | 存储已签发证书（目录服务） |
| 密钥恢复 | 备份私钥，防止丢失 |
| CRL（证书吊销列表） | 记录已吊销的证书 |

### 八、网络安全协议

#### 8.1 IPSec（网络层安全）

工作在网络层，为 IP 通信提供加密和认证。

| 协议 | 功能 | 保护内容 |
|------|------|---------|
| AH（认证头） | 认证+完整性，不加密 | IP 头部 + 数据 |
| ESP（封装安全载荷） | 加密+认证+完整性 | 只保护数据，不保护 IP 头 |

**两种工作模式：**

| 模式 | 特点 | 应用场景 |
|------|------|---------|
| 传输模式 | 只加密 IP 数据部分，IP 头不变 | 端到端通信（主机到主机） |
| 隧道模式 | 整个 IP 包加密，外加新 IP 头 | VPN（网关到网关、远程接入） |

> 隧道模式 = 把整个包裹（含原地址）装进新信封，只写新地址，原地址加密隐藏。

#### 8.2 SSL/TLS（传输层安全）

SSL 是旧名称，TLS 是新版本（TLS 1.2/1.3 是当前标准）。

**TLS 握手过程（简化）：**

1. Client Hello：客户端发送支持的加密套件、随机数
2. Server Hello：服务器选择加密套件、发随机数、发证书
3. 客户端验证证书，生成预主密钥，用服务器公钥加密发送
4. 双方用三个随机数生成会话密钥（主密钥）
5. 之后全部用对称加密（AES）通信

> TLS 1.3 简化握手为 1-RTT，去掉不安全的加密套件，更加安全高效。

#### 8.3 PGP 电子邮件加密

- 为电子邮件提供加密和签名
- 混合加密：用对称加密加密邮件正文，用非对称加密加密对称密钥
- 支持数字签名验证发件人身份

#### 8.4 SSH 安全远程登录

- 替代 Telnet 的不安全明文登录
- 端口：22
- 使用非对称加密验证服务器身份（首次连接问"是否信任服务器指纹"）
- 之后用对称加密保护整个会话

#### 8.5 安全协议层次总结

| 层次 | 协议 | 端口 | 保护范围 |
|------|------|------|---------|
| 网络层 | IPSec | — | IP 包级别 |
| 传输层 | SSL/TLS | 443 | 端到端传输 |
| 应用层 | SSH | 22 | 远程登录会话 |
| 应用层 | PGP | — | 电子邮件 |
| 应用层 | HTTPS | 443 | Web 通信 |

### 十一、SNMP 详解

SNMP 基于 UDP（端口 161/162），用于远程监控和管理网络设备。

#### 11.1 版本对比

| 版本 | 安全性 | 特点 |
|------|------|------|
| SNMPv1 | 明文团体名认证 | 最原始，几乎没安全 |
| SNMPv2 | 明文团体名 | 增加了批量操作，效率更高 |
| SNMPv3 | 加密+认证 | 支持 USM（用户安全模型），安全 |

#### 11.2 SNMP 操作

| 操作 | 方向 | 说明 |
|------|------|------|
| GET | 管理站→Agent | 查询某个变量的值 |
| GETNEXT | 管理站→Agent | 查询下一个变量的值（遍历表） |
| SET | 管理站→Agent | 修改变量的值（配置设备） |
| TRAP | Agent→管理站 | 主动上报异常事件（告警） |
| INFORM | Agent→管理站 | 加强版 TRAP，需要确认 |

#### 11.3 MIB 管理信息库

- 管理对象的集合，用树形结构组织
- 每个对象有唯一 OID（对象标识符），如 `1.3.6.1.2.1.1.1`（系统描述）
- 类比：MIB 是设备的信息"字典"，OID 是"页码"，GET 是"查字典"

#### 11.4 SNMP 架构

```
管理站（NMS）←→ Agent（在被管理设备上）←→ MIB（管理信息库）
```

- 管理站：运行网管软件的服务器，主动查询/设置
- Agent：运行在被管理设备上的进程，响应查询、发送 Trap
- MIB：被管理对象的数据库

### 十二、例题精讲

#### 例题 1：对称加密 vs 非对称加密

**题目**：以下关于对称加密和非对称加密的说法，正确的是（ ）

A. 对称加密用公钥加密、私钥解密
B. RSA 是对称加密算法的代表
C. 对称加密速度快，适合加密大量数据；非对称加密速度慢，适合加密密钥和数字签名
D. 非对称加密的密钥分发比对称加密更困难

**答案：C**

**解析：**
- A 错：公钥加密私钥解密是非对称加密；对称加密用同一把密钥
- B 错：RSA 是非对称加密的代表
- C 正确：这正是混合加密的思想
- D 错：非对称加密的公钥公开即可，密钥分发更简单

#### 例题 2：数字签名原理

**题目**：以下关于数字签名的说法，错误的是（ ）

A. 数字签名可以防止发送方抵赖
B. 数字签名是发送方用私钥对原文全文加密
C. 数字签名具有防伪造、防篡改、防抵赖三大特性
D. 数字签名通过哈希函数生成消息摘要，再对摘要签名

**答案：B**

**解析：**
- B 错误：数字签名是对"消息摘要"签名，不是对原文全文加密（那样太慢且不必要）
- A、C、D 均正确

#### 例题 3：防火墙类型应用题

**题目**：某公司内网有一台 Web 服务器需要对外提供服务，同时要保证内网其他服务器的安全。以下部署方案最合理的是（ ）

A. 将 Web 服务器放在内网，通过路由器端口映射
B. 将 Web 服务器放在 DMZ 区，防火墙限制 DMZ 只能访问外网，不能主动访问内网
C. 将 Web 服务器放在外网，取消防火墙
D. 将 Web 服务器和内网服务器放在同一网段

**答案：B**

**解析：**
- A 有一定风险，端口映射让外网流量直接进入内网
- B 正确：DMZ 是隔离区，Web 服务器被攻破也不会影响内网
- C 完全无保护
- D 内网服务器直接暴露在风险中

#### 例题 4：网络安全协议匹配题

**题目**：将以下安全协议与其工作层次/端口匹配：

| 协议 | 工作层次/端口 |
|------|-------------|
| IPSec | ① 传输层 / 443 端口 |
| SSL/TLS | ② 应用层 / 22 端口 |
| SSH | ③ 网络层 |
| HTTPS | ④ 传输层 |

正确的匹配是（ ）

A. IPSec-③, SSL/TLS-④, SSH-②, HTTPS-①
B. IPSec-④, SSL/TLS-③, SSH-①, HTTPS-②
C. IPSec-③, SSL/TLS-①, SSH-②, HTTPS-④
D. IPSec-①, SSL/TLS-④, SSH-②, HTTPS-③

**答案：A**

**解析：**
- IPSec 工作在**网络层**
- SSL/TLS 工作在**传输层**
- SSH 工作在**应用层 / 22 端口**
- HTTPS 工作在**传输层 / 443 端口**（HTTPS = HTTP over TLS）

#### 例题 5：攻击类型识别题

**题目**：以下攻击场景对应的攻击类型，匹配正确的是（ ）

场景 1：攻击者在购物网站评论区输入 `<script>alert('XSS')</script>`，所有访问该页面的人都会弹出对话框
场景 2：攻击者伪造银行转账请求，诱导已登录用户点击链接，用户账户资金被转走
场景 3：攻击者通过大量伪造的请求，耗尽服务器资源，使正常用户无法访问

A. 场景1-SQL注入，场景2-CSRF，场景3-DoS
B. 场景1-XSS，场景2-CSRF，场景3-DoS
C. 场景1-XSS，场景2-中间人攻击，场景3-DDoS
D. 场景1-SQL注入，场景2-中间人攻击，场景3-DDoS

**答案：B**

**解析：**
- 场景 1：在评论区注入脚本，所有访问者触发 → **存储型 XSS**
- 场景 2：诱导用户点击，利用已登录状态发请求 → **CSRF**
- 场景 3：耗尽资源使正常用户无法访问 → **DoS**（题目没说多个攻击源，不算 DDoS）

### 十三、易错陷阱表

| 序号 | 陷阱 | 正确理解 |
|------|------|---------|
| 1 | 数字签名 = 公钥签名 + 私钥验证 | 错误！数字签名是**私钥签名** + **公钥验证**（私钥只有自己有，用来签名才能防抵赖） |
| 2 | 对称加密用公钥私钥 | 错误！对称加密只有一把密钥，公钥私钥是非对称加密的概念 |
| 3 | HTTPS 只用非对称加密 | 错误！HTTPS 是**混合加密**：非对称加密交换密钥，对称加密传输数据 |
| 4 | 数字证书能证明"消息内容正确" | 错误！数字证书只证明"这个公钥属于这个人"，不证明消息内容 |
| 5 | 防火墙工作在应用层 | 错误！只有应用层网关工作在应用层，包过滤和状态检测工作在网络层+传输层 |
| 6 | IDS 和 IPS 是一样的 | 错误！IDS 旁路检测+告警，IPS 串联检测+阻断（一个只报警，一个直接拦） |
| 7 | 数字签名 = 加密原文 | 错误！数字签名是加密**消息摘要**（哈希值），不是加密原文全文 |
| 8 | 被动攻击容易发现 | 错误！被动攻击不改变数据，比主动攻击更难被发现 |
| 9 | SNMP 基于 TCP | 错误！SNMP 基于 **UDP**，端口 161/162 |
| 10 | 3DES 的中间步骤是加密 | 错误！3DES 是加密→**解密**→加密，中间用解密是为了兼容 DES |
| 11 | DH 密钥交换能认证身份 | 错误！DH 本身只负责密钥交换，不认证身份，需配合数字签名防中间人攻击 |

### 十四、记忆口诀

**CIA 三要素：**
> "机完可"——机密性（不泄露）、完整性（不篡改）、可用性（不中断）

**对称加密算法（DES→3DES→AES 演进）：**
> "DES 老了，3DES 撑了，AES 接班了"——DES（56位）→ 3DES（三重）→ AES（128/256位，当前主流）

> "RSA 靠大数分解，ECC 靠椭圆曲线，短小精悍是 ECC"——256位 ECC 安全性约等于 3072位 RSA

**防火墙三层递增：**
> "包过滤看门牌，状态检测记日志，应用网关翻箱子"——工作层次越来越高，检查越来越深

**数字签名三防：**
> "私签公验，三防不赖"——私钥签名、公钥验证，防伪造、防篡改、防抵赖

**常见攻击速记：**
> "SQL 注入拼接字符串，XSS 注入脚本跑，CSRF 借你身份发请求，ARP 冒充网关骗电脑"

**安全协议口诀：**
> "IPSec 在网络层加密 IP，SSL 在传输层加密 TCP，SSH 安全登录 22 端口，PGP 加密邮件保隐私"

## 🧮 子网划分快速计算法（块大小法）

## 二、子网划分 -- 快速计算技巧与例题

### 2.1 核心概念

子网掩码（Subnet Mask）的左边是连续的 1（网络位），右边是连续的 0（主机位）。

**CIDR 表示法**：`192.168.1.0/24`，其中 `/24` 表示前 24 位是网络位，后 8 位是主机位。

### 2.2 核心公式

- **可用主机数** = 2^h - 2（h = 主机位数，减去全 0 的网络地址和全 1 的广播地址）
- **子网数** = 2^n（n = 从主机位借给网络位的位数，即子网位数）
- **块大小（Block Size）** = 256 - 掩码中非 255 的那个字节的值

### 2.3 快速计算技巧：块大小法

这是最实用的方法，不需要转二进制。

**步骤：**
1. 找到掩码中不是 255 的那个字节，用 256 减去它，得到"块大小"（即每个子网的大小）
2. 从 0 开始，每次加块大小，得到每个子网的网络地址
3. 广播地址 = 下一个子网网络地址 - 1
4. 可用 IP 范围 = 网络地址 + 1 到 广播地址 - 1

### 2.4 常见掩码速查表

| CIDR | 子网掩码 | 块大小 | 可用主机数 | 主机位数 |
|------|----------|--------|-----------|---------|
| /24 | 255.255.255.0 | 256 | 254 | 8 |
| /25 | 255.255.255.128 | 128 | 126 | 7 |
| /26 | 255.255.255.192 | 64 | 62 | 6 |
| /27 | 255.255.255.224 | 32 | 30 | 5 |
| /28 | 255.255.255.240 | 16 | 14 | 4 |
| /29 | 255.255.255.248 | 8 | 6 | 3 |
| /30 | 255.255.255.252 | 4 | 2 | 2 |
| /31 | 255.255.255.254 | 2 | 2（点对点,无网络/广播地址） | 1 |
| /32 | 255.255.255.255 | 1 | 1（单主机） | 0 |

**记忆技巧**：掩码中特殊字节的值 = 256 - 2^(8 - CIDR后缀)

例如 `/26`：8 - 2（26-24）= 2，2^2 = 4，256 - 4 = 252... 不对，让我重新算。

实际上 `/26` 借了 2 位（26-24=2），块大小 = 2^(8-2) = 2^6 = 64，掩码 = 256 - 64 = 192。

**更简单的记忆**：记住块大小 = 2^(8 - 借位数)，掩码 = 256 - 块大小。

### 2.5 例题详解

**例题 1：** 将 `192.168.1.0/24` 划分为 4 个子网，求每个子网的网络地址、广播地址、可用 IP 范围。

**解：**
- 4 个子网需要借 log2(4) = 2 位，新掩码 = /24 + 2 = /26
- 掩码 = 255.255.255.192，块大小 = 256 - 192 = 64

| 子网 | 网络地址 | 广播地址 | 可用 IP 范围 |
|------|---------|---------|-------------|
| 1 | 192.168.1.0 | 192.168.1.63 | 192.168.1.1 ~ 192.168.1.62 |
| 2 | 192.168.1.64 | 192.168.1.127 | 192.168.1.65 ~ 192.168.1.126 |
| 3 | 192.168.1.128 | 192.168.1.191 | 192.168.1.129 ~ 192.168.1.190 |
| 4 | 192.168.1.192 | 192.168.1.255 | 192.168.1.193 ~ 192.168.1.254 |

**例题 2：** 某部门需要 30 个可用 IP，应使用什么掩码？

**解：**
- 30 个可用 IP，需要 2^h - 2 >= 30，即 h >= 5（2^5 - 2 = 30）
- 主机位 5 位，网络位 = 32 - 5 = 27
- 掩码 = /27，即 255.255.255.224，块大小 = 32

**例题 3：** `172.16.0.0/16` 需要划分 512 个子网，每个子网最大主机数是多少？

**解：**
- 512 个子网需要借 9 位（2^9 = 512），新掩码 = /16 + 9 = /25
- 主机位 = 32 - 25 = 7 位
- 可用主机数 = 2^7 - 2 = 126 台

### 2.6 常见陷阱

- **忘记减 2**：可用主机数 = 2^h - 2，不是 2^h。全 0 是网络地址，全 1 是广播地址，都不能配给主机。
- **子网数和主机数的取舍方向**：借位越多，子网越多，但每个子网的主机越少。这是此消彼长的关系。
- **/31 掩码的特殊性**：点对点链路中，/31 不需要减 2，两个地址都可以用。
- **非连续子网掩码**：实际中不常见，但理论上子网掩码的 1 不一定是连续的（考试中一般只考虑连续的情况）。

## 📐 奈奎斯特与香农定理计算技巧

## 三、奈奎斯特与香农定理 -- 计算题公式与解题步骤

### 3.1 两个定理的区别

| | 奈奎斯特定理（Nyquist） | 香农定理（Shannon） |
|------|------|------|
| **适用场景** | 理想信道，无噪声 | 实际信道，有噪声 |
| **核心变量** | 带宽 W，码元状态数 V | 带宽 W，信噪比 S/N |
| **公式** | C = 2W * log2(V) | C = W * log2(1 + S/N) |
| **单位** | C = bps，W = Hz | C = bps，W = Hz |
| **本质** | 码元速率上限 | 信道容量极限 |

### 3.2 公式详解

**奈奎斯特定理（无噪声）：**

```
最大数据传输速率 C = 2W * log2(V)
```

- W：信道带宽（单位：Hz）
- V：码元的状态数（离散电平数），如二进制 V=2，四进制 V=4
- 当 V=2 时，C = 2W（这也是最常见的考察形式）

**香农定理（有噪声）：**

```
信道容量 C = W * log2(1 + S/N)
```

- W：信道带宽（单位：Hz）
- S/N：信噪比，是**比值（无单位）**，不是 dB
- 如果题目给的是 dB，需要先转换：**S/N = 10^(dB/10)**

**注意：** 实际最大速率取两者中较小的那个。

### 3.3 信噪比 dB 转换（重点）

题目经常给信噪比为 30dB，需要换算成比值：

```
S/N = 10^(dB/10)

例如：30dB → S/N = 10^(30/10) = 10^3 = 1000
      20dB → S/N = 10^(20/10) = 10^2 = 100
      10dB → S/N = 10^(10/10) = 10^1 = 10
```

**记忆技巧**：dB 值每增加 10，S/N 比值乘以 10；每增加 3，S/N 比值约乘以 2。

### 3.4 例题详解

**例题 1（香农定理）：** 一个带宽为 3kHz 的信道，信噪比为 30dB，求最大数据传输速率。

**解：**
```
步骤 1：将 dB 转换为比值
S/N = 10^(30/10) = 10^3 = 1000

步骤 2：代入香农公式
C = W * log2(1 + S/N)
  = 3000 * log2(1 + 1000)
  = 3000 * log2(1001)
  ≈ 3000 * 10        （因为 log2(1001) ≈ log2(1024) = 10）
  ≈ 30000 bps
  ≈ 30 kbps
```

**例题 2（奈奎斯特+香农结合）：** 一个带宽为 4kHz 的信道，信噪比为 30dB，使用 4 种码元状态（V=4），求最大数据传输速率。

**解：**
```
步骤 1：先算奈奎斯特上限
C_nyquist = 2W * log2(V) = 2 * 4000 * log2(4) = 8000 * 2 = 16000 bps

步骤 2：再算香农上限
S/N = 10^(30/10) = 1000
C_shannon = W * log2(1 + S/N) = 4000 * log2(1001) ≈ 4000 * 10 = 40000 bps

步骤 3：取较小值
C = min(16000, 40000) = 16000 bps = 16 kbps
```

**例题 3（纯奈奎斯特）：** 一条无噪声信道带宽为 6MHz，使用 QPSK 调制（4 种相位状态，V=4），求最大速率。

**解：**
```
C = 2W * log2(V) = 2 * 6*10^6 * log2(4) = 12*10^6 * 2 = 24 Mbps
```

### 3.5 常见陷阱

- **dB 忘记转换**：最常见的错误！题目给的是"dB"，代入公式前必须换算成比值。
- **log2 近似值**：考试中 log2(1001) 通常近似为 log2(1024) = 10，这是合理的近似。
- **取最小值**：如果同时给了奈奎斯特和香农的条件，要取两者中较小的。因为实际速率受限于最严格的那个条件。
- **单位换算**：带宽常用 kHz 或 MHz，结果单位是 bps（或 kbps/Mbps）。3kHz 要写成 3000Hz 代入公式。
- **V 的含义**：V 是码元状态数，不是比特数。二进制 V=2，QPSK 的 V=4，16QAM 的 V=16。

## ⚠️ 常见易错陷阱 12 条

## 十四、常见易错陷阱总结

1. **OSI 模型不是协议，是参考模型**；TCP/IP 才是协议栈
2. **交换机工作在数据链路层**（看 MAC），**路由器工作在网络层**（看 IP），不要搞混
3. **子网可用主机数 = 2^n - 2**，减去的 2 是网络地址和广播地址，千万别忘
4. **TCP 三次握手不是四次，是三次**（服务器把 SYN+ACK 合并了）
5. **四次挥手是四次，因为全双工，ACK 和 FIN 必须分开**
6. **TIME_WAIT 在主动关闭方**，持续 2MSL
7. **DNS 默认用 UDP 53 端口**（不是 TCP）
8. **HTTP 是明文，HTTPS 是加密**（HTTPS = HTTP + SSL/TLS）
9. **DHCP 是 UDP 协议**（67/68 端口），不是 TCP
10. **私有 IP 地址**：10.x.x.x、172.16-31.x.x、192.168.x.x
11. **RIP 最大跳数 15**，16 跳视为不可达
12. **集线器是物理层设备**（不识别地址），交换机是数据链路层设备（识别 MAC）

### 无线局域网基本架构

| 组件 | 全称 | 功能 |
|------|------|------|
| AP | Access Point（接入点） | 无线网络的基站，连接有线网络和无线设备 |
| STA | Station（站点） | 无线终端，如手机、笔记本 |
| BSS | Basic Service Set | 一个AP覆盖的范围（基本服务集） |
| ESS | Extended Service Set | 多个BSS通过有线网络互联（扩展服务集） |

### CSMA/CA vs CSMA/CD

> 无线网络为什么不直接用 CSMA/CD？因为无线环境检测碰撞很难（发送时自己的信号太强，听不到别人的）。

| 对比维度 | CSMA/CD（有线） | CSMA/CA（无线） |
|---------|----------------|----------------|
| 全称 | 碰撞检测 | **碰撞避免** |
| 使用环境 | 以太网 | WLAN（Wi-Fi） |
| 碰撞检测 | 能检测（边发边听） | **无法检测**（无线信号自身太强，遮蔽了碰撞） |
| 策略 | 检测到碰撞→停止→随机后退 | **检测信道空闲→等待随机时间→发送→等ACK确认** |
| 确认机制 | 不需要ACK | **需要ACK确认** |
| 隐藏终端 | 不关心 | 存在隐藏终端问题 |

**CSMA/CA 的四个要点**：
1. 信道空闲且持续 DIFS 时间 → 开始发送
2. 信道忙 → 随机退避
3. 发送后等 ACK
4. 没收到 ACK → 重传

**RTS/CTS 机制**（解决隐藏终端问题）：
- 发送方先发 RTS（请求发送）→ 接收方回 CTS（允许发送）→ 第三方听到 CTS 就闭嘴

### 移动 IP 基本概念

> 手机从北京移动到上海，怎么还能用原来的 IP 收到数据？移动 IP 解决这个问题。

| 角色 | 功能 |
|------|------|
| 归属代理（HA） | 记录移动节点的老家，收到发给移动节点的包后转发 |
| 外地代理（FA） | 移动节点当前所在地，提供临时地址（转交地址 CoA） |
| 隧道 | HA → FA 之间的传送通道 |

**移动 IP 三步走**：
1. 代理发现：移动节点发现自己在外地
2. 注册：移动节点向归属代理报到，
3. 隧道：归属代理把数据包通过隧道转给外地代理，再交给移动节点

### 一、子网划分真题计算题（3道典型题）

#### 真题1：已知IP和掩码求网络地址/广播地址

**题目**：某主机 IP 为 `192.168.15.130/27`，求该主机所在子网的网络地址和广播地址。

**解题步骤**：
1. /27 = 掩码 255.255.255.224，块大小 = 256 - 224 = **32**
2. 关键字节是最后一个（130），子网划分：0, 32, 64, 96, **128**, 160, 192, 224
3. 130 落在 128~159 区间
4. **网络地址** = 192.168.15.128
5. **广播地址** = 192.168.15.159（下一个子网网络地址 - 1）
6. 可用 IP 范围 = 192.168.15.129 ~ 192.168.15.158（共 30 个）

> **速算技巧**：用 IP 的关键字节 130 除以块大小 32，商 4 余 2。网络地址关键字节 = 4 × 32 = 128，广播地址 = 128 + 32 - 1 = 159。

---

#### 真题2：根据需求反推子网掩码

**题目**：某公司有 5 个部门，每个部门最多 25 台主机。使用 C 类地址 `192.168.10.0/24` 划分子网，应使用的子网掩码是？

**解题步骤**：
1. 先看主机需求：每个子网需要 25 台可用主机
2. 2^h - 2 >= 25 → h >= 5（2^5 - 2 = 30 >= 25）
3. 主机位 = 5 位，网络位 = 32 - 5 = **27**
4. 子网掩码 = /27 = **255.255.255.224**
5. 验证子网数：借了 3 位（27 - 24 = 3），2^3 = 8 个子网 >= 5 个部门，满足

> **易错提醒**：主机数需求优先于子网数需求！先算主机位够不够，再检验子网数够不够。很多人先算子网数导致主机位不够。

---

#### 真题3：超网聚合（路由聚合）

**题目**：将以下 4 个网络聚合成一个超网：`192.168.4.0/24`、`192.168.5.0/24`、`192.168.6.0/24`、`192.168.7.0/24`

**解题步骤**：
1. 写出第三字节的二进制：
   - 4 = 000001**00**
   - 5 = 000001**01**
   - 6 = 000001**10**
   - 7 = 000001**11**
2. 找共同前缀：前 22 位完全相同（192.168 的 16 位 + 第三字节前 6 位 = 22 位）
3. 聚合结果 = **192.168.4.0/22**
4. 掩码 = 255.255.252.0，块大小 = 256 - 252 = 4，覆盖 4.0 ~ 7.255

> **判断方法**：N 个连续网络能聚合成一个超网，当且仅当 N 是 2 的幂且起始地址能被 N 整除。4 能被 4 整除，所以 4 个网络可以聚合。

### 二、TCP 拥塞控制计算题（典型题）

#### 真题：拥塞窗口变化全过程

**题目**：TCP 连接建立后，ssthresh 初始 = 16（MSS），cwnd 初始 = 1。假设所有报文段都成功发送直到第 7 轮（RTT），第 7 轮发送后发生**超时**。请写出每轮发送时的 cwnd 值。

**解题步骤**：

| 轮次 | cwnd（发送时） | 阶段 | 说明 |
|------|:---:|------|------|
| 1 | 1 | 慢开始 | 初始 cwnd=1 |
| 2 | 2 | 慢开始 | 指数增长：1→2 |
| 3 | 4 | 慢开始 | 指数增长：2→4 |
| 4 | 8 | 慢开始 | 指数增长：4→8 |
| 5 | 16 | 慢开始 | 指数增长：8→16，达到 ssthresh=16 |
| 6 | 17 | 拥塞避免 | 线性增长：16+1=17 |
| 7 | 18 | 拥塞避免 | 线性增长：17+1=18，**本轮发送后超时** |
| — | — | — | 超时后：ssthresh = 18/2 = 9，cwnd = 1 |
| 8 | 1 | 慢开始（重来） | 重新从慢开始 |

> **关键区分**：
> - **超时** → cwnd = 1，ssthresh = cwnd(旧)/2，回到慢开始
> - **3个重复ACK**（快重传）→ cwnd = cwnd(旧)/2，ssthresh = cwnd(新)，进入拥塞避免（不是慢开始！）

---

#### 补充：快重传+快恢复示例

**题目**：某时刻 cwnd = 24，ssthresh = 16，发送方收到 3 个重复 ACK。求快重传和快恢复后的 cwnd。

**解**：
1. 快重传：ssthresh = 24/2 = 12，cwnd = 12
2. 快恢复：cwnd = ssthresh + 3 = 12 + 3 = **15**
3. 再收到重复 ACK 时：cwnd += 1（如 15→16→17...）
4. 收到新数据 ACK 后：cwnd = ssthresh = 12，进入拥塞避免

| 7 | 应用层 | HTTP、FTP、DNS、SMTP、POP3、IMAP、Telnet、SNMP | — | 数据/报文 | **应**用 |
| 6 | 表示层 | SSL/TLS、JPEG、ASCII、加密/压缩 | — | 数据 | **表**演 |
| 5 | 会话层 | RPC、SQL、NetBIOS | — | 数据 | **会**话 |
| 4 | 传输层 | **TCP、UDP** | — | 段/数据报 | **传**输 |
| 3 | 网络层 | **IP、ICMP、ARP、RARP、IGMP** | **路由器**、三层交换机 | 包/数据报 | **网**络 |
| 2 | 数据链路层 | **MAC、PPP、HDLC、VLAN、STP** | **交换机**、网桥 | 帧 | **链**路 |
| 1 | 物理层 | RS-232、RJ-45、802.11 | **集线器**、中继器、网线、光纤 | 比特 | **物**理 |

> **设备口诀**：**集**（集线器）**物**（物理层）→ **交**（交换机）**链**（数据链路层）→ **路**（路由器）**网**（网络层）
> 即：集线器在物理层，交换机在数据链路层，路由器在网络层。三种设备对应三层，往上走一层多一个功能。

### 五、易错陷阱大全（16条）

#### 5.1 模型与体系结构

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 1 | OSI 七层模型是协议标准 | **错！** OSI 是参考模型（理论），TCP/IP 才是协议栈（实际标准） |
| 2 | TCP/IP 是四层，OSI 是七层所以 TCP/IP 少实现了几层 | **错！** TCP/IP 把 OSI 上三层合并为应用层，下两层合并为网络接口层，功能都有 |
| 3 | 物理层以上的设备叫"物理层设备" | **错！** 集线器和中继器是物理层设备；交换机是数据链路层；路由器是网络层 |

#### 5.2 子网划分

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 4 | 可用主机数 = 2^主机位数 | **错！** 要减 2：2^h - 2（减去全 0 网络地址和全 1 广播地址） |
| 5 | 子网越多，每个子网主机越多 | **错！** 借位越多 → 子网越多 → 但主机位越少 → 每子网主机越少。此消彼长 |
| 6 | 192.168.1.0/24 的第一个可用 IP 是 192.168.1.0 | **错！** 192.168.1.0 是网络地址，不能配给主机。第一个可用是 192.168.1.1 |

#### 5.3 TCP 三次握手与四次挥手

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 7 | 服务器 SYN+ACK 算两次握手 | **错！** 服务器把 SYN 和 ACK 合并成一个报文，所以是三次握手（不是四次） |
| 8 | 四次挥手可以合并成三次 | **错！** 因为 TCP 是全双工，服务端 ACK 和 FIN 必须分开：先 ACK 表示"收到你关闭请求"，数据发完后再 FIN 表示"我也关了" |
| 9 | TIME_WAIT 在被动关闭方 | **错！** TIME_WAIT 在**主动关闭方**（先发 FIN 的一方），持续 2MSL（约 4 分钟） |
| 10 | 三次握手第三次可以省略 | **错！** 第三次 ACK 防止已失效的 SYN 报文到达服务器造成资源浪费 |

#### 5.4 协议与端口

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 11 | DNS 用 TCP 53 端口 | **错！** DNS 默认用 **UDP** 53 端口（区域传送用 TCP 53，但常规查询是 UDP） |
| 12 | PING 是应用层协议 | **错！** PING 用的是 ICMP 协议，ICMP 属于**网络层**（和 IP 同级） |
| 13 | DHCP 是 TCP 协议 | **错！** DHCP 是 **UDP** 协议，服务器端口 67，客户端端口 68 |
| 14 | FTP 只用 21 端口 | **错！** FTP 用两个端口：**21**（控制连接）+ **20**（数据连接） |

#### 5.5 设备与层次

| # | 陷阱 | 正确理解 |
|---|------|---------|
| 15 | 交换机看 IP 地址转发 | **错！** 交换机看 **MAC 地址**转发（数据链路层）；路由器看 **IP 地址**转发（网络层） |
| 16 | 集线器能隔离冲突域 | **错！** 集线器是物理层设备，**不能隔离冲突域**（所有端口共享带宽）；交换机能隔离冲突域（每个端口一个冲突域） |

### 六、高频考点一句话速记

| 考点 | 一句话 |
|------|--------|
| 三次握手 | SYN → SYN+ACK → ACK（防止旧连接请求） |
| 四次挥手 | FIN → ACK → FIN → ACK（全双工各关各的） |
| TCP 可靠机制 | 序号+确认+重传+流量控制+拥塞控制 |
| 拥塞控制四阶段 | 慢开始(指数) → 拥塞避免(线性) → 快重传(3个重复ACK) → 快恢复(cwnd减半后继续) |
| 超时 vs 3个重复ACK | 超时→cwnd=1重新慢开始；3个重复ACK→cwnd减半进入拥塞避免 |
| 奈奎斯特 vs 香农 | 奈奎斯特=无噪声码元上限；香农=有噪声信道容量；实际速率取min |
| 子网划分核心 | 块大小=256-掩码特殊字节；可用IP=2^(32-前缀)-2 |
| DNS 解析 | 递归：你问我我帮你查到底；迭代：我告诉你去找谁你自己去 |
| ARP 作用 | 已知 IP 求 MAC，广播请求，只在局域网有效 |
| RIP vs OSPF | RIP 看跳数(最多15)、OSPF 看带宽(SPF算法)；RIP 慢收敛、OSPF 快收敛 |
| IPv4 vs IPv6 | IPv4=32位点分十进制；IPv6=128位冒号十六进制 |
| HTTP 状态码 | 2xx成功、3xx重定向、4xx客户端错、5xx服务端错 |
| 私有地址 | 10.x.x.x、172.16~31.x.x、192.168.x.x |
| 对称 vs 非对称加密 | 对称：同一把钥匙，快（AES）；非对称：公钥加密私钥解密，慢（RSA） |
| HTTPS | HTTP + SSL/TLS，443端口，混合加密（非对称交换密钥+对称传输数据） |
| CSMA/CD vs CSMA/CA | 有线用CD（碰撞检测），无线用CA（碰撞避免，因为无线无法检测碰撞） |
