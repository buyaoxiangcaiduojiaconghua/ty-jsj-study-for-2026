## 知识点 1：数据结构基本概念

### 知识点 1：1 大白话理解

**数据结构**就是"数据怎么存放"的方案。就像你搬家时，衣服可以叠放（栈）、挂起来（链表）、分类放抽屉（数组），不同的摆放方式会影响你找衣服的速度。

### 知识点 1：2 数据结构三要素

| 要素 | 含义 | 生活类比 |
|------|------|----------|
| **逻辑结构** | 数据之间的逻辑关系（与人脑想的一致） | 家族树——爷爷、爸爸、儿子之间是父子关系 |
| **存储结构（物理结构）** | 数据在计算机内存里实际怎么存 | 家族树在内存里可能存成连续格子（数组）或分散格子+指针（链表） |
| **运算** | 对数据能做什么操作 | 增、删、改、查 |

**考试重点**：三要素是什么（逻辑结构、存储结构、运算），能区分逻辑结构和存储结构。

### 知识点 1：3 逻辑结构的四种类型

| 类型 | 含义 | 举例 |
|------|------|------|
| **集合** | 元素属于同一组，没有其他关系 | 全班同学花名册 |
| **线性结构** | 元素一对一 | 排队买奶茶 |
| **树形结构** | 一对多 | 公司组织架构 |
| **图结构** | 多对多 | 地铁线路图 |

### 知识点 1：4 存储结构的两种基本类型

| 类型 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **顺序存储** | 所有元素放在连续的内存里（像一排连着的储物柜） | 查找快，直接用编号定位 | 插入/删除慢，要移动元素 |
| **链式存储** | 每个元素存自己的值 + 下一个元素的地址（像寻宝游戏，每张纸条告诉你下一张在哪） | 插入/删除快，不用移动 | 查找慢，得从头顺着找 |
| **索引存储** | 建一张索引表，存关键字→地址的映射 | 查找快 | 额外空间开销 |
| **散列存储** | 通过哈希函数算出地址 | 查找极快 | 可能冲突 |

### 知识点 1：5 时间复杂度 O(?)

**大白话**：时间复杂度是"数据量变大时，程序运行时间增长得多快"的衡量。不是精确秒数，而是**增长趋势**。

| 复杂度 | 含义 | 数据翻 10 倍，时间约 | 典型例子 |
|--------|------|---------------------|----------|
| O(1) | 常数时间，跟数据量无关 | 不变 | 数组按下标访问 `a[5]` |
| O(log n) | 对数时间，增长很慢 | 约增长 1 倍 | 二分查找 |
| O(n) | 线性时间 | 约增长 10 倍 | 遍历数组 |
| O(n log n) | 对数线性 | 约增长 10倍多一点 | 快速排序、归并排序 |
| O(n²) | 平方时间 | 约增长 100 倍 | 冒泡排序、两重循环 |
| O(2ⁿ) | 指数时间，增长爆炸 | 增长 1024 倍 | 穷举所有子集 |

**易错点**：计算 O 时"只保留最高阶、去掉常数系数"。比如 `3n² + 2n + 1`，时间复杂度是 O(n²)。

**考试重点**：给一段循环代码，能口算时间复杂度。

---

**自测题 1**：以下代码的时间复杂度是？
```c
for (i = 0; i < n; i++) {
    for (j = 0; j < n; j++) {
        printf("%d", i + j);
    }
}
```
A. O(n)　B. O(log n)　C. O(n²)　D. O(n log n)

> **答案**：C。两重循环每层都跑 n 次，n × n = n²。

**自测题 2**：以下代码的时间复杂度是？
```c
for (i = 0; i < n; i = i * 2) {
    printf("%d", i);
}
```
A. O(n)　B. O(log n)　C. O(n²)　D. O(1)

> **答案**：B。i 每次翻倍（1, 2, 4, 8...），大概 log₂n 次就超过 n 了，所以循环约执行 log n 次。

## 知识点 2：线性表

### 知识点 2：1 什么是线性表

大白话：线性表就是 **"一个连一个"** 的数据队列。每个元素有且只有一个前驱和一个后继（第一个和最后一个除外）。

### 知识点 2：2 顺序表（数组实现）

**原理**：用一块连续内存存放元素。

**考试重点**：
- **插入**：平均移动 n/2 个元素，时间复杂度 O(n)
- **删除**：平均移动 (n-1)/2 个元素，时间复杂度 O(n)
- **查找（按下标）**：O(1)
- **查找（按值）**：O(n)

> **生活类比**：电影院一排连着的座位。要找第 5 个座位很轻松（O(1)），但要让一个人插到第 3 个位置，后面所有人都得往后挪（O(n)）。

### 知识点 2：3 单链表

**原理**：每个节点存两样东西——自己的值和下一个节点的地址（指针）。

```
[值|指针] → [值|指针] → [值|指针] → NULL
```

**考试重点**：
- 插入/删除：O(1)（如果已经找到位置），O(n)（如果需要先找到位置）
- 查找：O(n)，只能从第一个顺着找
- 头插法、尾插法建表

**易错点**：删除节点时，必须先把要删节点的 next 赋值给前一个节点的 next，不然链表会断。

### 知识点 2：4 双链表

每个节点存三样：前一个的地址 + 自己的值 + 下一个的地址。

```
NULL ← [prev|值|next] ←→ [prev|值|next] ←→ [prev|值|next] → NULL
```

**优点**：双向遍历，删除某节点时不需要单独找前驱节点。

### 知识点 2：5 循环链表

单循环：尾节点指向头节点。
双循环：头节点的 prev 指向尾节点，尾节点的 next 指向头节点。

**判断为空**：头节点的 next 指向自己。

### 知识点 2：6 静态链表

用数组模拟链表。数组元素里存数据和下一个元素的"下标"（而不是真正的地址指针）。

> **使用场景**：某些没有指针类型的早期语言（如早期 BASIC）中使用。

### 知识点 2：7 顺序表 vs 链表——终极对比表

| 对比项 | 顺序表（数组） | 链表 |
|--------|---------------|------|
| 内存 | 连续，需要一整块 | 分散，用多少占多少 |
| 查找（按下标） | O(1) | O(n) |
| 查找（按值） | O(n) | O(n) |
| 插入/删除 | O(n)，要挪位置 | O(1)，改指针就行 |
| 空间 | 可能浪费（预留空间） | 每个节点多占一个指针空间 |
| 缓存友好 | 是（连续存放） | 否（分散存放） |
| 适合场景 | 数据量变化不大、经常查找 | 频繁插入/删除 |

---

**自测题 3**：在单链表中，要在指针 p 所指节点后插入新节点 s，以下哪个操作是正确的？
A. `s->next = p; p->next = s;`
B. `s->next = p->next; p->next = s;`
C. `p->next = s; s->next = p->next;`
D. `p->next = s->next; s->next = p;`

> **答案**：B。先把新节点的 next 指向 p 后面的节点，然后让 p 的 next 指向新节点。顺序不能反！

## 知识点 3：栈和队列

### 知识点 3：1 栈（Stack）——后进先出

**大白话**：栈就像一叠盘子，后放上去的先拿下来。

**简称**：LIFO（Last In, First Out）

| 操作 | 含义 |
|------|------|
| push | 入栈（放盘子） |
| pop | 出栈（拿盘子） |
| peek/top | 看栈顶元素（不拿走） |

**考试重点**：
- **顺序栈**：数组实现，需要 `top` 指针。判空：`top == -1`；判满：`top == MaxSize-1`
- **链栈**：链表实现，入栈=头插法，出栈=删除头节点，不会满

### 知识点 3：2 队列（Queue）——先进先出

**大白话**：队列就像排队买奶茶，先来的先买到。

**简称**：FIFO（First In, First Out）

| 操作 | 含义 |
|------|------|
| enqueue | 入队（排在队尾） |
| dequeue | 出队（队头离开） |

**考试重点**：

**循环队列**（用数组实现，头尾连成环）：

- `front` 指向队头元素，`rear` 指向队尾的下一个位置（或队尾元素，看具体实现约定）
- **判空**：`front == rear`
- **判满**：`(rear + 1) % MaxSize == front`（牺牲一个位置来区分空和满）
- **元素个数**：`(rear - front + MaxSize) % MaxSize`
- 入队：`rear = (rear + 1) % MaxSize`
- 出队：`front = (front + 1) % MaxSize`

**链队**：链表实现，有 front 和 rear 指针，插入删除 O(1)，不会满。

### 知识点 3：3 表达式求值——栈的经典应用

**中缀转后缀（逆波兰）**：`3 + 4 × 2` → `3 4 2 × +`

转换规则口诀：
1. 操作数直接输出
2. 遇到操作符，比栈顶优先级高就入栈，比栈顶低或相等就弹出栈顶再比较
3. 遇到 `(` 直接入栈，遇到 `)` 弹出直到 `(`

**后缀表达式求值**：
1. 遇到操作数入栈
2. 遇到操作符弹出两个，计算后结果入栈
3. 最后栈里只剩一个数，就是结果

### 知识点 3：4 应用场景对比

| 数据结构 | 典型应用场景 |
|----------|-------------|
| 栈 | 函数调用（递归）、括号匹配、表达式求值、浏览器的后退、撤销操作 |
| 队列 | 排队系统、打印机任务队列、BFS（广度优先搜索）、消息队列 |

---

**自测题 4**：循环队列的数组大小为 n，front 指向队头，rear 指向队尾的下一个位置。该队列最多能放多少个元素？
A. n　B. n-1　C. n+1　D. 不确定

> **答案**：B。标准实现中牺牲一个位置用于区分空和满，所以最多 n-1 个。

**自测题 5**：中缀表达式 `a+b*c-(d+e)` 转后缀表达式结果是什么？
A. `abc*+de+-`　B. `abc*+de+-`　C. `abc*+de+-`（其实就是 `abc*+de+-`）

> **答案**：`abc*+de+-`。按优先级一步步转换。

## 知识点 4：数组、数组的压缩存储与字符串

### 知识点 4：1 数组的存储

**二维数组内存存放方式**（考试常考地址计算）：

| 方式 | 含义 | 地址公式 |
|------|------|----------|
| **行优先** | 一行一行存 | `LOC(a[i][j]) = 起始地址 + (i × 列数 + j) × 元素大小` |
| **列优先** | 一列一列存 | `LOC(a[i][j]) = 起始地址 + (j × 行数 + i) × 元素大小` |

> **易错点**：下标从 0 还是从 1 开始计算，结果不一样。看清题意。

### 知识点 4：2 特殊矩阵的压缩存储

很多矩阵有很多重复元素，不需要完整存储。

| 矩阵类型 | 特点 | 存储策略 |
|----------|------|----------|
| **对称矩阵** | `a[i][j] == a[j][i]` | 只存下三角（或上三角），约存 n(n+1)/2 个元素。`a[i][j]` 在下三角中的下标：`i(i-1)/2 + j - 1`（下标从 0 开始） |
| **三角矩阵** | 上三角或下三角全是同一个常数 | 类似对称矩阵，再额外存一个常数值 |
| **三对角矩阵** | 只有主对角线及相邻斜线有值 | 用三个一维数组分别存三条对角线 |
| **稀疏矩阵** | 绝大多数元素为 0 | 用**三元组**（行号、列号、值）存储 |

### 知识点 4：3 稀疏矩阵的三元组表示

```
(行号, 列号, 值)
```

比如矩阵只有三个非零元素：
```
(0, 0, 5)
(1, 3, 8)
(2, 1, 3)
```

> **考试可能考**：三元组的转置操作。

### 知识点 4：4 字符串与 KMP 算法

**朴素模式匹配**：主串每个位置作为起点，尝试匹配模式串。最差 O(mn)。

**KMP 算法核心思想**：已经匹配过的部分，失败时不回退主串指针。通过 `next` 数组记录"匹配失败时模式串应该跳到哪个位置继续比"。

| next 值规律 | 含义 |
|-------------|------|
| next[1] = 0 | 第一个字符就失败，主串前进一位 |
| next[j] = k | 第 j 个字符前有长度为 k-1 的相同前后缀 |

> **考试重点**：给定模式串，能手算出 next 数组。时间复杂度 O(m+n)。

### 知识点 4：5 广义表

**定义**：表元素可以是单个元素（原子），也可以是另一个表（子表）。

```
A = ()           // 空表，长度为 0
B = (a, b)       // 线性表，长度为 2
C = (a, (b, c))  // 嵌套，长度为 2（a 是原子，(b,c) 是子表）
D = (a, D)       // 递归表，无限深
```

**考试重点**：
- **表头 Head**：第一个元素
- **表尾 Tail**：去掉第一个元素后剩下的部分（一定是个表）
- **长度**：最外层逗号分隔的元素个数
- **深度**：括号嵌套的最大层数

---

**自测题 6**：广义表 `(a, (b, c, (d)))` 的长度和深度分别是多少？
A. 长度 2，深度 3　B. 长度 3，深度 3　C. 长度 2，深度 2　D. 长度 3，深度 2

> **答案**：A。长度=2（a 和 (b,c,(d))）；深度=3（a=1, (b,c,(d))=2, (d)=3，取最大）。

## 知识点 5：树和二叉树

### 知识点 5：1 树的基本概念（大白话）

树是一对多的**层次结构**。像家族谱——爷爷是根，下面连着爸爸、叔叔，再往下是孙子。

| 术语 | 含义 | 生活类比 |
|------|------|----------|
| 根节点 | 最顶层节点，唯一的 | 祖先 |
| 叶子节点 | 没有子节点的节点 | 家族里最年轻的一辈 |
| 父/子节点 | 上下层的直接关系 | 爸爸 → 儿子 |
| 度 | 一个节点有几个孩子 | 这个人有几个子女 |
| 树的度 | 所有节点中最大的度 | 家族里最多子女的那个人有几个孩子 |
| 深度 | 从根到该节点的层数 | 第几代 |
| 高度 | 从该节点到最深叶子 | 往下还有几代 |
| 森林 | 多棵树的集合 | 多个大家庭 |

### 知识点 5：2 二叉树

**定义**：每个节点最多只有两个子节点的树（最多两个孩子，可以没有）。

**考试重点——二叉树主要性质**：

1. 第 k 层最多有 `2^(k-1)` 个节点
2. 深度为 h 的二叉树最多有 `2^h - 1` 个节点
3. `叶子数 = 度为 2 的节点数 + 1`（n₀ = n₂ + 1）
4. n 个节点的完全二叉树深度为 `⌊log₂n⌋ + 1`

**满二叉树 vs 完全二叉树**：

| 类型 | 定义 | 记忆技巧 |
|------|------|----------|
| **满二叉树** | 每一层都满了，节点数为 2^h - 1 | 像一把完整的伞，严丝合缝 |
| **完全二叉树** | 只有最后一层可以不满，且靠左排列 | 编号和满二叉树一致 |

**二叉树存储方式**：

| 存储方式 | 原理 | 使用场景 |
|----------|------|----------|
| 顺序存储 | 用数组，`i` 的左孩子在 `2i+1`，右孩子在 `2i+2` | 完全二叉树（堆） |
| 链式存储 | 每个节点存值 + 左孩子指针 + 右孩子指针 | 一般二叉树 |

### 知识点 5：3 二叉树的四种遍历——超级重点

**大白话记忆法**：
- **前序遍历**（根左右）：先看自己，再看左边，最后看右边
- **中序遍历**（左根右）：先看左边，再看自己，最后看右边
- **后序遍历**（左右根）：先看左边，再看右边，最后看自己
- **层次遍历**（逐层）：一层一层看，从上到下，从左到右

```
       A
     /   \
    B     C
   / \   / \
  D   E F   G

前序：A B D E C F G
中序：D B E A F C G
后序：D E B F G C A
层次：A B C D E F G
```

**必考点**：
- 给中序 + 前序/后序，能唯一画出二叉树
- **前序+后序不能唯一确定二叉树**
- 非递归遍历用**栈**辅助

### 知识点 5：4 线索二叉树

**为什么要用**：普通二叉树有很多空指针浪费空间（n 个节点有 n+1 个空指针）。线索二叉树用这些空指针指向遍历的前驱/后继，加快遍历。

| 线索标记 | 含义 |
|----------|------|
| ltag = 0 | 左指针指向左孩子 |
| ltag = 1 | 左指针指向前驱 |
| rtag = 0 | 右指针指向右孩子 |
| rtag = 1 | 右指针指向后继 |

> **考试重点**：理解线索化的概念，中序线索二叉树最常见。

### 知识点 5：5 树和森林 → 二叉树转换

**核心转换方法——"左孩子右兄弟"**：
1. 同一个节点的所有孩子，第一个作为左孩子
2. 其余孩子依次作为右边兄弟（右孩子的右孩子链）

```
树：                    转换后的二叉树：
    A                        A
   /|\                      /
  B C D         →          B
    |                       \
    E                        C
                              \
                               D
                              /
                             E
```

**森林 → 二叉树**：先把每棵树转成二叉树，再依次把后面的二叉树的根作为前面二叉树的右孩子。

### 知识点 5：6 BST（二叉排序树 / 二叉查找树）

**定义**：左子树所有值 < 根 < 右子树所有值。

**核心操作及复杂度**：

| 操作 | 平均 | 最差（退化成链表） |
|------|------|-------------------|
| 查找 | O(log n) | O(n) |
| 插入 | O(log n) | O(n) |
| 删除 | O(log n) | O(n) |

**删除三种情况**：
1. 叶子节点 → 直接删
2. 只有一个孩子 → 孩子顶上来
3. 有两个孩子 → 找右子树最小值（或左子树最大值）顶上来

### 知识点 5：7 AVL 树（平衡二叉树）——必考旋转

**平衡因子** = 左子树高度 - 右子树高度，只允许 -1、0、1。

**四种失衡 + 对应的旋转**：

| 失衡类型 | 判断 | 操作 |
|----------|------|------|
| LL（左左） | 左子树的左边插入导致失衡 | 右旋一次 |
| RR（右右） | 右子树的右边插入导致失衡 | 左旋一次 |
| LR（左右） | 左子树的右边插入导致失衡 | 先左旋左子树，再右旋根 |
| RL（右左） | 右子树的左边插入导致失衡 | 先右旋右子树，再左旋根 |

> **记忆口诀**：LL-右旋，RR-左旋，LR-左右旋，RL-右左旋。两个字母的旋转方向跟第二个字母相反。

### 知识点 5：8 哈夫曼树（最优二叉树）

**大白话**：给每个字符分配编码，出现次数多的用短编码、少的用长编码，让整体编码最短。

**构造步骤**：
1. 所有节点按权值排序
2. 每次取最小的两个，合并成一个新节点
3. 重复直到只剩一个节点

**哈夫曼编码**：左分支标 0，右分支标 1。**前缀编码**——任何一个编码都不是另一个编码的前缀。

**带权路径长度 WPL** = 所有叶子节点的 权值 × 路径长度的总和。

### 知识点 5：9 堆

**定义**：一种特殊的完全二叉树。

| 堆类型 | 条件 |
|--------|------|
| **大顶堆** | 每个节点 ≥ 其子节点，根最大 |
| **小顶堆** | 每个节点 ≤ 其子节点，根最小 |

**堆的操作**：

| 操作 | 过程 | 时间复杂度 |
|------|------|-----------|
| 插入 | 放最后 → 从下往上调整（上浮） | O(log n) |
| 删除堆顶 | 最后一个元素移到堆顶 → 从上往下调整（下沉） | O(log n) |
| 建堆 | 从最后一个非叶节点开始，逐个下沉 | O(n) |

> **易错点**：建堆的时间复杂度是 O(n) 不是 O(n log n)。考试常考这个坑。

### 知识点 5：10 并查集

**用途**：快速判断两个元素是否属于同一个集合，合并两个集合。（朋友圈问题）

**基本操作**：
- `Find(x)`：找到 x 所属集合的代表（根），路径压缩优化
- `Union(x, y)`：把 x 和 y 所在集合合并

> **考试重点**：理解概念，知道适合用于等价关系判断、图中连通分量判断。

## 知识点 6：图

### 知识点 6：1 基本概念

| 术语 | 含义 |
|------|------|
| 顶点 | 图的节点（城市） |
| 边 | 顶点之间的连线（道路） |
| 无向图 | 边没有方向，A→B 和 B→A 是同一回事 |
| 有向图 | 边有方向，用弧表示 |
| 连通图 | 无向图中任意两点之间都有路径 |
| 强连通图 | 有向图中任意两点之间双向都有路径 |
| 度 | 无向图中多少条边连着这个点 |
| 生成树 | 包含所有顶点的极小连通子图（边最少） |

### 知识点 6：2 图的存储

| 存储方式 | 原理 | 空间 | 适合场景 |
|----------|------|------|----------|
| **邻接矩阵** | 用二维数组 `edge[i][j]` 存边 | O(n²) | 稠密图（边多） |
| **邻接表** | 每个顶点一个链表存邻居 | O(n+e) | 稀疏图（边少） |

**邻接矩阵 vs 邻接表**：

| 操作 | 邻接矩阵 | 邻接表 |
|------|---------|--------|
| 判断 i、j 是否相邻 | O(1) | O(deg(i)) |
| 找某个顶点的所有邻居 | O(n) | O(deg) |
| 空间 | O(n²) | O(n+e) |

### 知识点 6：3 图的遍历

**DFS（深度优先搜索）**：
- 类似走迷宫，"一条路走到黑，走不通再回头"
- 用**栈**（递归本身也是栈）实现
- 邻接矩阵 O(n²)，邻接表 O(n+e)

**BFS（广度优先搜索）**：
- 类似水波扩散，"一层一层往外探索"
- 用**队列**实现
- 邻接矩阵 O(n²)，邻接表 O(n+e)

### 知识点 6：4 最小生成树（MST）——考试重点

**问题**：用最少的边建一条路，连通所有城市，且总距离最短。

| 算法 | 核心思路 | 时间复杂度 | 适合 |
|------|----------|-----------|------|
| **Prim（普里姆）** | 从一点出发，每次选到已选集合最近的顶点加入 | O(n²) | 稠密图 |
| **Kruskal（克鲁斯卡尔）** | 所有边排序，按权重从小到大选，不形成环就加入 | O(e log e) | 稀疏图 |

> **记忆技巧**：Prim 加**点**、Kruskal 加**边**。

### 知识点 6：5 最短路径

**单源最短路径——Dijkstra**：
- 从一个起点出发，到所有其他点的最短路径
- 不能有负权边（有负权要用 Bellman-Ford）
- 时间复杂度：朴素 O(n²)，堆优化 O((n+e)log n)

**所有点对最短路径——Floyd**：
- 计算任意两点的最短路径
- 三重循环，核心思想：`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`
- 时间复杂度：O(n³)
- **可以处理负权边**（但不能有负权回路）

### 知识点 6：6 拓扑排序

**大白话**：排一个"有先决条件"的任务顺序。比如大学选课，某些课必须先修完前序课程才能选。

**实现**：每次选入度为 0 的顶点输出，删掉它和它连出的边。重复直到所有顶点都输出。

**应用**：判断图中是否有环。如果拓扑排序输出顶点数 < 总顶点数，说明有环。

### 知识点 6：7 关键路径

**大白话**：项目管理中"哪些工作不能耽误"——AOE 网中从起点到终点的最长路径，工期的最短完成时间。

| 概念 | 含义 |
|------|------|
| 最早开始时间 `ve(i)` | 最早什么时候可以开始 |
| 最晚开始时间 `vl(i)` | 最晚什么时候必须开始，否则延期 |
| 关键活动 | `ve == vl` 的活动，一天都不能拖 |

## 知识点 7：查找

### 知识点 7：1 顺序查找

从头到尾依次比较。O(n)。适合无序数据。

### 知识点 7：2 二分查找（折半查找）——必考

**前提**：数据必须**有序**！在顺序表中每次取中间值比较，每次排除一半。

- 时间复杂度：O(log n)
- 判定树：是一棵平衡二叉树

**ASL（平均查找长度）**：查找成功时约 log₂(n+1) - 1

### 知识点 7：3 分块查找（索引顺序查找）

把数据分块，每块内可以无序，但块之间有序。先查索引确定在哪块，再在块内顺序查找。

### 知识点 7：4 B 树（多路平衡查找树）——重点

**为什么用 B 树**：数据量太大内存放不下，要存磁盘上。B 树每个节点存更多键值，减少磁盘 I/O 次数。

**m 阶 B 树特性**：
- 每个节点最多 m 个孩子，最多 m-1 个关键字
- 每个节点（除根外）至少 ⌈m/2⌉ 个孩子
- 根至少 2 个孩子（除非是叶子）
- 所有叶子在同一层
- 节点内关键字递增排列

**B 树 vs B+ 树——高频考点**：

| 对比项 | B 树 | B+ 树 |
|--------|------|-------|
| 关键字分布 | 每个节点都存关键字和数据 | 只有叶子存数据，非叶子只存索引 |
| 叶子链接 | 不链接 | 叶子之间用链表串起来 |
| 查找稳定性 | 可能在非叶子层就找到 | 必须查到叶子层 |
| 范围查询 | 需要中序遍历 | 叶子链表直接扫描，效率高 |
| 主要用途 | 文件系统 | **数据库索引**（MySQL 的 InnoDB） |

### 知识点 7：5 哈希表（散列表）

**核心思想**：通过哈希函数把关键字直接映射到存储地址。查找 O(1)！

**哈希函数构造方法**：
- **除留余数法**：`H(key) = key % p`（p 一般取质数）
- 直接定址法、数字分析法、平方取中法等

**冲突解决方法——必考**：

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **开放定址法** | 冲突了往下一个位置找 | 不用额外空间 | 容易堆积 |
| ——线性探测 | `(H + i) % m` | 简单 | "二次聚集"现象 |
| ——平方探测 | `(H + i²) % m` | 缓解聚集 | 不一定能找到空位 |
| ——双散列 | 用第二个哈希函数算步长 | 避免聚集 | 计算多一步 |
| **拉链法** | 每个地址挂一个链表 | 不会堆积，删除方便 | 额外指针空间 |

**装填因子 α** = 表中记录数 / 表长。α 越大，越容易冲突，查找越慢。

### 知识点 7：6 ASL（平均查找长度）计算

| 查找方式 | ASL 成功（约） | ASL 失败（约） |
|----------|---------------|---------------|
| 顺序查找 | (n+1)/2 | n |
| 二分查找 | log₂(n+1) - 1 | log₂(n+1) |
| 哈希表（拉链法） | 1 + α/2 | α + e^(-α) |
| 哈希表（线性探测） | (1 + 1/(1-α))/2 | (1 + 1/(1-α)²)/2 |

> **考试重点**：会给哈希表序列，手算成功/不成功的 ASL。

## 知识点 8：内部排序

### 知识点 8：1 八大排序终极对比表——考试最常考点

| 排序算法 | 平均时间 | 最好 | 最坏 | 空间 | 稳定性 | 核心思想 |
|----------|---------|------|------|------|--------|----------|
| **直接插入排序** | O(n²) | O(n) | O(n²) | O(1) | **稳定** | 像打牌理牌，每张牌插到已排序序列的正确位置 |
| **希尔排序** | O(n^1.3) | - | O(n²) | O(1) | 不稳定 | 分组然后插入排序，增量递减 |
| **冒泡排序** | O(n²) | O(n) | O(n²) | O(1) | **稳定** | 相邻两两比较，大的往后沉 |
| **快速排序** | O(n log n) | O(n log n) | O(n²) | O(log n) | 不稳定 | 选基准，小的放左边、大的放右边，递归 |
| **简单选择排序** | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 | 每轮选最小的放最前面 |
| **堆排序** | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 | 建堆，反复取堆顶 |
| **归并排序** | O(n log n) | O(n log n) | O(n log n) | O(n) | **稳定** | 分到最小，两两有序合并 |
| **基数排序** | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(r) | **稳定** | 按位排，从低位到高位 |

### 知识点 8：2 快速排序详解

**本质**：分治思想——"选一个基准（pivot），左边全比它小，右边全比它大，然后对左右递归。"

**最坏情况**：序列已经有序（或逆序），退化成 O(n²)。
- 优化：三数取中法选 pivot、随机选取 pivot

**空间复杂度**：O(log n) 是递归栈的深度。

### 知识点 8：3 归并排序详解

**本质**："分而治之"——不断对半分，分到只有一个元素（自然有序），然后两两合并有序序列。

**空间复杂度 O(n)** 的原因：合并时需要临时数组存放结果。

> **归并排序是外部排序的基础**（数据太大放不下内存时，用归并思想分块排序再合并）。

### 知识点 8：4 堆排序详解

**步骤**：
1. 建大顶堆 O(n)
2. 交换堆顶和最后一个元素
3. 重新调整堆 O(log n)
4. 重复 n-1 次

总时间 O(n log n)。

### 知识点 8：5 排序算法的适用场景——考试常考选择题

| 场景 | 推荐算法 | 原因 |
|------|---------|------|
| 数据量小（n<50） | 直接插入排序 | 实现简单，常数因子小 |
| 数据基本有序 | 直接插入排序 / 冒泡排序 | 接近 O(n) |
| 需要稳定 | 归并排序 / 插入排序 / 冒泡排序 | 快排、堆排、希尔、选择都不稳定 |
| 内存有限 | 堆排序 / 快速排序 | 空间复杂度低 O(1) / O(log n) |
| 数据量大且要求最差 O(n log n) | 堆排序 / 归并排序 | 快排最差 O(n²) |
| 外部排序（数据在磁盘） | 归并排序 | 天然支持多路归并 |
| 数字范围有限 | 基数排序 | O(d(n+r)) 接近线性 |

### 知识点 8：6 稳定性口诀

> **"不稳快堆希，选来也不稳"** —— 不稳定的是：**快**速排序、**堆**排序、**希**尔排序、**选**择排序。其余稳定。

## 知识点 9：算法设计与分析基础

### 知识点 9：1 分治法（Divide and Conquer）

**大白话**：把大问题拆成小问题，各自解决后把答案合并起来。

**三步走**：
1. 分解：把原问题分成若干子问题
2. 解决：递归解决子问题（子问题足够小就直接求解）
3. 合并：把子问题的解合并

**经典例子**：归并排序、快速排序、二分查找、大整数乘法。

**如何看是不是分治**：每个子问题都是独立的原问题的缩小版，合并子解得到最终答案。

### 知识点 9：2 动态规划（DP）

**大白话**：把复杂问题分解，但子问题之间有重叠。用一张表记录已解决子问题的答案，避免重复计算。

**适用条件**：
1. **最优子结构**：问题的最优解包含子问题的最优解
2. **重叠子问题**：递归过程中会反复遇到同样的子问题

**DP vs 分治**：

| 对比项 | 分治 | 动态规划 |
|--------|------|---------|
| 子问题关系 | 独立不重叠 | 重叠 |
| 求解方向 | 自顶向下递归 | 自底向上填表 |
| 解题步骤 | 分解→解决→合并 | 定义状态→状态转移方程→填表 |
| 经典题 | 归并排序 | 背包问题、最短路径、斐波那契 |

### 知识点 9：3 贪心算法（Greedy）

**大白话**：每一步都选"当前看起来最好"的选择，希望最终也最好。

**特点**：
- 不回溯，不反悔
- 不一定能得到全局最优解
- 如果问题有**贪心选择性质**（局部最优→全局最优），贪心就是正确的

**DP vs 贪心**：

| 对比项 | 动态规划 | 贪心 |
|--------|---------|------|
| 选择 | 每步考虑所有可能，填表 | 每步只选当前最优 |
| 是否反悔 | 可以（通过填表比较） | 不能反悔 |
| 结果 | 全局最优 | 不一定最优 |
| 速度 | 较慢 | 较快 |
| 经典题 | 01 背包问题 | 分数背包问题、找零钱（部分情况） |

### 知识点 9：4 回溯法（Backtracking）

**大白话**：走迷宫，一个一个试，走不通就退回上一步换别的路。

**核心**：深度优先搜索 + 剪枝（提前排除不可能的分支）。

**特点**：
- 系统地搜索所有解
- 用**解空间树**表示所有可能解
- 剪枝函数减少搜索量

**经典题**：N 皇后问题、全排列、0/1 背包、图的着色。

### 知识点 9：5 分支限界法（Branch and Bound）

**大白话**：类似回溯，但用 BFS（广度优先）搜，每次扩展"最有希望"的节点。

**回溯 vs 分支限界**：

| 对比项 | 回溯法 | 分支限界法 |
|--------|--------|-----------|
| 搜索方式 | DFS（深度优先） | BFS（广度优先）或最佳优先 |
| 目标 | 找所有解 / 任一解 | 找最优解 |
| 存储 | 存当前路径 | 需要存储所有活节点，空间大 |
| 应用 | N 皇后、图着色 | 旅行商问题、任务调度 |

**自测题 13**：以下哪个问题最适合用贪心算法解决？
A. 0/1 背包问题（每个物品只能选一次）　B. 最短路径（Dijkstra）　C. 斐波那契数列

> **答案**：B。Dijkstra 算法本身就是一个贪心策略（每次选当前最近的顶点）。0/1 背包贪心不一定最优，斐波那契适合 DP。

**自测题 14**：说到"自底向上填表"、"状态转移方程"这两个特征词，说的是哪个算法思想？
A. 分治　B. 贪心　C. 动态规划　D. 回溯

> **答案**：C。DP 的两个标志性特征。
